# OpenCorvus Mission 科普动画创意简报 V2

状态：`SUPERSEDED`。本文件只保留调研、品牌事实、案例口径和失败历史；V9 自写分镜已被用户否决，不得用于生产。当前唯一前期事实源是 `preproduction-v3.zh-CN.md`。`standard-shot-table-v3.zh-CN.md` 是失效的过早草案，只能作为审查证据。新的角色卡、场景卡、镜头表和文本分镜必须按 Skill 顺序产生并更新当前事实源。

## 1. 这支片只解决一个传播问题

让第一次听说 OpenCorvus 的个人技术用户在 3–5 分钟内明白：

> 长任务不是一次更长的聊天，而是一场必须能交接、恢复和验收的接力赛；Mission 是承担这场接力的运行层。

目标观众：正在用 AI 做毕业论文、个人开源项目、副业应用、求职作品集或独立研究的个人用户。

观众看完应完成的唯一动作：打开 OpenCorvus，创建一个 Mission。

## 2. 真实品牌事实

- 官方定位：面向长程任务的开源 Agent Harness。
- 官方承诺：跑得久的工作、能核对的结果，以及会按反馈修订的专家团。
- Mission 把一个目标拆成有依赖的 Task；Task 固定责任和专家团版本。
- Task 间交接的是带来源与精确定位的 Artifact，不是“完成了”的口头自述。
- 本片展示的 DeBERTa ABSA Mission 有六个真实阶段：获取模型与数据、CUDA 训练及网页、图表、论文、审校、GitHub 发布。
- 可展示的真实结果仅限：selected validation Macro-F1 0.8343、test Macro-F1 0.8361、seed 42，以及已经存在的网页、图表、论文和公开仓库。

禁止口径：100% autonomous、production-ready、保证成功、未经验证的性能提升、把模型自述当运行证据、把 H3 合成 UI 当真实产品。

## 3. 调研后采用的创作原则

1. 前 5 秒先呈现观众熟悉的失败，不先报品牌名或功能清单。
2. 一条主张贯穿全片；每个镜头只负责一个动作和一个因果关系。
3. 观众是主角，产品是帮助观众完成转变的机制。
4. 先展示结果为什么可信，再展示 logo 与行动指令。
5. 真实 UI、指标和产物只承担 Proof；H3 只承担隐喻、空间、动作和情绪。
6. 屏幕文字只保留能在静音时复述主张的短句；不常驻大标题、段落字幕或卡片列表。
7. H3 镜头按 4–6 秒独立生成，使用逐秒动作、明确机位、空间锚点、环境声和音乐描述；先做低分辨率验证，再升级通过的镜头。
8. 每个昂贵阶段之前确认创意简报、风格帧和镜头表；不再边生成边猜方向。

## 4. 当前视觉方向

唯一允许继续的方向是明亮的 2C 角色动画：同一个卡通个人用户、同一套卡通 Agent、同一份项目和同一个可见工作空间贯穿全片。用户从“不得不替 Agent 收尾”出发，依次经历工具选择、创建 Mission、查看具名 Agent、验收产物与发布成果。产品机制由角色行动和连续事件表现；真实 WebUI 不再承担叙事画面，案例只在结尾用极短的确定性文字与产物图标提供事实证明。

视觉使用暖白、浅灰和自然肤色，OpenCorvus 青色作为品牌识别，橙色只承担用户行动。禁止暗色渐变模板、扫描线、霓虹描边、中心节点图、功能卡片墙、采购表、伪 HUD、玩具隐喻和脱离人物的芯片空镜。用户已明确要求立即看完整视频，因此本轮直接渲染整片并以逐段抽帧和全尺寸人工复核作为视觉门。

所有已否决路线及证据统一记录在对应 spec，不在当前创意事实源保留可误用的平行方案。

## 5. 约 3 分 30 秒旁白 V9 · 技术因果线

> Agent 已经可以自动完成很多任务。写代码、查资料、分析数据，它们都很快。
>
> 但把任务拉长到几个小时、几天，问题就出现了。
>
> Agent 能看到的上下文是有限的。新信息不断进入，最早的目标、约束和计划会被挤出去。它可能忘记必须使用 GPU，跳过测试，偏离原来的步骤；也可能在局部结果看起来不错时，擅自宣布完成。
>
> 于是你得到的往往不是项目，而是半成品：调研缺证据，代码没测完，部署没发生，论文停在草稿。你只能反复解释、检查遗漏、重新派活。最后，你成了 Agent 的项目经理。
>
> 多开几个 Agent，也不自动等于协作。如果它们没有共享且持久的最终目标、责任、依赖和完成标准，就会重复工作、互相等待，或者把一句“我完成了”当成交接。Agent Team 可以并行处理眼前的工作，却不等于能管理一串持续很久的重型任务。
>
> OpenCorvus Mission 就是为这个问题设计的。
>
> 你只写下最终目标、硬约束和验收标准。Mission 把它们持久保存，再拆成有依赖关系的重型 Task。每一个 Task 都不是交给单个 Agent，而是交给一个版本锁定的完整专家团，由不同角色共同调研、实现、测试和复核。
>
> 上游 Task 没有交付，下游就不会被错误唤醒。依赖满足后，调度器才把任务放入队列。每一次执行都有独立 occurrence：运行到哪里、调用了什么工具、得到了什么结果，都会保存。
>
> 服务中断、认证更新或者机器重启后，Mission 不是从头猜，而是从持久状态找到未完成的 occurrence，在正确位置恢复。重试不会偷偷复制一份任务；终态也必须真正收敛。
>
> 专家团之间交接的不是一句“完成了”。Artifact 会记录文件、来源和精确 locator，让下一组 Agent 能找到并消费真正的产物。独立复核角色会按照验收标准检查结果；不合格就退回、修复、重新验证，直到完整交付。
>
> 你对专家团的长期反馈，还能形成一次版本化、可回退的修订。只有你确认，它才会安装。
>
> 这和常见工具解决的层次不同。WorkBuddy 更强调从一句话交付办公成品；DeepSeek Harness 提供可组合的开发者运行时；Codex 和 Claude Code 擅长软件工程与并行编码协作。OpenCorvus 关注的是：一个跨领域长目标，怎样由多个专家团连续推进、恢复、交接并验收。
>
> 它最大的杀手锏是开源。OpenCorvus 使用 MIT 许可证，可以自托管、审计和 fork。模型、工具、权限与专家团都能替换；任务可以运行在你的机器上；不可逆操作必须先确认；每次工具调用、参数和结果都能回看。
>
> 我们用一条真实 Mission 做过验证：在 12 小时 45 分钟里，6 个重型 Task 依次完成，使用 3 个内置专家团，形成 46 个 Agent 会话和 20 种角色。它下载 DeBERTa ABSA 模型和数据，只用 RTX 5090 完成三组 CUDA 实验，交付训练监控与推理网页、两张图表、五页 ACL 风格论文、测试报告和公开 GitHub 仓库。
>
> 最佳实验的验证 Macro-F1 是 83.43%，测试 Macro-F1 是 83.61%。这是单随机种子、1800 条训练样本预算下可复验的结果，不是夸张承诺。
>
> 毕业论文、课程项目、个人开源软件、副业应用、求职作品集、独立研究——只要它需要跨越调研、设计、实现、测试、修改和发布，你需要的就不只是一个更会回答的 Agent。
>
> 你需要一个能让多支专家团把长任务真正推进到完成的 Mission。
>
> OpenCorvus。别再给 Agent 当项目经理。

目标成片约 3 分 20 秒至 3 分 50 秒，上限 5 分钟。正式配音后以实测语速调整停顿与镜头，不强行加速旁白。

### 5.1 技术机制必须怎样被看见

| 机制 | 角色事件 | 禁止替代 |
| --- | --- | --- |
| 上下文有限 | 同一 Agent 的上下文容器被新信息填满，最早的目标、GPU 约束和测试计划被推出；随后角色做出与原要求冲突的动作 | 只显示“上下文不足”标题 |
| 多 Agent 不等于协作 | 多个同模 Agent 在没有共享责任与依赖时重复实现、互相等待，并用口头完成状态交接；用户继续搬运上下文 | 泛化机器人流水线 |
| 持久目标与 Task 依赖 | 用户输入一次长 Mission；最终目标、硬约束、验收标准固定在持久 Mission 账本；有依赖的重型 Task 在同一空间展开 | 静态 DAG、功能卡片 |
| 完整专家团 | 每个 Task 展开的是一个完整小组，角色在 Task 内共同调研、实现、测试和复核；不是“一只机器人等于一个专家团” | 四只机器人各做一步 |
| 调度、队列与唤醒 | 下游 Task 先保持等待；上游 Artifact 就绪后，调度器才唤醒并入队；镜头明确显示先后因果 | 只在旁白念术语 |
| occurrence 与恢复 | 执行中断前保存精确 occurrence；服务恢复后同一 Task 从相同工具结果继续，既不从头开始也不生成重复 Task | 断电后直接跳到完成 |
| Artifact 交接 | 产物带文件路径、来源与 locator；下一专家团打开该定位并消费同一份文件 | 搬一个没有信息的箱子 |
| 独立验收与收敛 | 未参与实现的复核角色按验收标准拒绝缺陷；原团队修复、重验；所有依赖和验收完成后 Mission 才进入终态 | 盖章即完成 |
| 反馈修订 | 用户反馈生成新专家团版本；显示差异、可回退与确认安装 | 自动静默改写专家团 |
| 开源运行控制 | 用户查看源码、替换模型/工具、选择权限；不可逆动作停在确认点；工具参数与结果可回放 | “开源、可控、透明”四宫格 |

视频不使用“功能打勾越多越好”的采购表，也不宣称其他工具无法完成长任务。画面采用一条动态定位带，让同一个个人项目依次经过五个不同重心：

| 产品 | 官方资料支持的主重心 | 视频中的克制表述 |
| --- | --- | --- |
| WorkBuddy | 商业云端桌面产品，从一句话出发交付办公成品，并在平台内封装 Expert Group | 一句话交付办公成品 |
| DeepSeek Harness | 面向 Agent Harness 开发者的插件化运行时；模型、工具、技能、会话、沙箱、存储、循环、调度和 UI 均可组合，运行轨迹可追踪 | 开发者可组合运行时 |
| Codex | 在隔离云环境中并行运行编码任务，可后台继续并在结果可审阅时返回 | 软件工程 Agent |
| Claude Code | 通过 subagent、agent view、实验性的 Agent Teams 和动态工作流并行或协调编码会话 | 编码与并行协作 |
| OpenCorvus | MIT 开源、可自托管的长程 Harness；以 Mission 将一个跨领域长目标拆成有依赖的重型 Task，由多个版本锁定的专家团接力，并以可定位产物和独立验收收敛 | 开源的跨领域长程 Mission |

## 7. H3 生产方式

- H3 只生成无文字、明亮自然的卡通个人工作空间和角色动作；最终故事镜头只能使用角色设定图派生关键帧，再通过 I2V/FL2VA 锁定人物、Agent、环境与相机路径。独立 T2V 只能做废弃探索，不能进入成片。H3 不得生成 UI、代码、热图、CUDA 时序、指标、模型架构、论文、logo 或任何可读文字。
- 上下文占用、执行中断、Provider/CUDA 活动和训练时序若作为机制图，必须由真实遥测驱动或在后期按公开契约确定性绘制，并清楚标注“机制示意”；不得把 H3 生成的假热图或假时序当运行证据。
- 提示词使用官方三段结构：`integrated_multimodal_description`、`overall_soundscape`、`non_diegetic_music`。
- 每个镜头明确：构图、主体、环境、动作起点与终点、机位类型/幅度/速度、逐秒节点、物理声效。
- 不使用空泛的 `cinematic, beautiful, premium` 词堆；必须描述能看见和能听见的事实。
- 不让 H3 生成产品 UI、指标、logo 或小字。真实 UI 由后期透视合成进 H3 场景。
- 先生成一个 4 秒风格验证镜头，抽取首/中/尾帧并检查主体一致性、运动、文字污染、黑帧和音轨；风格确认后才批量生产。

## 8. 当前生产约束

1. 视觉方向：2C 用户视角的明亮角色动画正在做一致性样片；样片通过前不得进入整片生产。
2. 时长与画幅：3–5 分钟、16:9；网站可在成片批准后另裁 15 秒无声预览。
3. CTA：“别再给 Agent 当项目经理”，同时在收束画面展示 GitHub、官网与作者入口。
4. 音频：中文旁白 + 真实/生成镜头物理 SFX + 一条克制的连续音乐；不使用粉红噪声冒充正式配乐。
5. 推送：用户必须先看到并批准视频；批准前只允许本地提交，不得 push。

## 9. 失败证据

纸艺、3D 接力工厂、Silicon to Delivery 和暗色卡片 animatic 的文件、接触表与拒绝原因均保留在 spec 和外部演示目录中。它们不再作为当前视觉参考，也不得通过生产入口重新生成。
