# OpenCorvus Mission 科普动画创意简报 V2

状态：用户已否决 `papercraft-stop-motion-explainer` 路线 D，原因是视觉与科技、AI 和计算运行无关。当前切换到 MiniMax 官方 `brand-promo-video-generator` 的 AI/SaaS 路线并结合 `h3-prompt-writing`；新科技方向未获用户确认前禁止生成。

## 1. 这支片只解决一个传播问题

让第一次听说 OpenCorvus 的技术用户在目标 78–82 秒内明白：

> 长任务不是一次更长的聊天，而是一场必须能交接、恢复和验收的接力赛；Mission 是承担这场接力的运行层。

目标观众：正在用 AI 完成训练、研究、开发或交付的技术负责人、研究者和高级开发者。

观众看完应完成的唯一动作：打开 OpenCorvus，创建一个 Mission。

## 2. 真实品牌事实

- 官方定位：面向长程任务的开源 Agent Harness。
- 官方承诺：跑得久的工作、能核对的结果，以及会按反馈修订的专家团。
- Mission 把一个目标拆成有依赖的 Task；Task 固定责任和专家团版本。
- Task 间交接的是带来源与精确定位的 Artifact，不是“完成了”的口头自述。
- 本片展示的 DeBERTa ABSA Mission 有六个真实阶段：获取模型与数据、CUDA 训练及网页、图表、论文、审校、GitHub 发布。
- 可展示的真实结果仅限：selected validation Macro-F1 0.8343、test Macro-F1 0.8361、seed 42，以及已经存在的网页、图表、论文和公开仓库。

禁止口径：100% autonomous、production-ready、保证成功、未经验证的性能提升、把模型自述当运行证据、把 H3 合成 UI 当真实产品。

## 3. 调研后采用的创作原则

1. 前 5 秒先呈现观众熟悉的失败，不先报品牌名或功能清单。
2. 一条主张贯穿全片；每个镜头只负责一个动作和一个因果关系。
3. 观众是主角，产品是帮助观众完成转变的机制。
4. 先展示结果为什么可信，再展示 logo 与行动指令。
5. 真实 UI、指标和产物只承担 Proof；H3 只承担隐喻、空间、动作和情绪。
6. 屏幕文字只保留能在静音时复述主张的短句；不常驻大标题、段落字幕或卡片列表。
7. H3 镜头按 4–6 秒独立生成，使用逐秒动作、明确机位、空间锚点、环境声和音乐描述；先做低分辨率验证，再升级通过的镜头。
8. 每个昂贵阶段之前确认创意简报、风格帧和镜头表；不再边生成边猜方向。

## 4. 三个视觉方向

### A. 3D 接力工厂（已否决）

一个发光的“任务核心”进入漫长隧道：单一通道过载、断电、丢件；Mission 把它变成六站接力，Artifact 像带封签的实体容器在站间传递，最后组装成模型、网页、图表、论文和仓库。高端 C4D/Octane 风格，非卡通人物片，画面由物体运动讲逻辑。

真实 H3 风格测试把这个隐喻生成成琥珀胶囊与青色滑轨，呈现玩具感、缺少工作的真实压力，也没有表现专家团协作。用户明确不认可，本方向不得继续迭代。拒绝证据：`h3-local/style-test.mp4`、`h3-local/frames/style-test/contact-sheet-9.jpg`。

### B. 编辑纸拼贴接力

把长任务画成层层组装的纸质机械：聊天纸带越堆越长并撕裂，六个具名工位依次压印 Artifact，真实证据像档案页装订进最终交付。用定格纸张 SFX，不靠平滑数字漂移。

优点：科普感强、风格鲜明、H3 官方已有专门工作流。风险：与真实深色 WebUI 的视觉连接需要精心过渡。

### C. 技术剖面动画

用透明剖面展示 Session、Task、Artifact 和验收回路，辅以真实 UI。优点是技术准确；风险是最接近被否决的“动效 PPT”，除非加入强叙事角色，不推荐。

### D. 一份交付的一生（已否决）

一只成熟、克制的黑色任务档案袋贯穿全片，经过六个纸艺工作台积累证据。三张预览虽然摆脱 BPPT 和玩具感，但用户指出其视觉语义属于档案馆手工艺，与 AI 计算、GPU、模型训练和 Agent Runtime 无关。本方向不得继续迭代或进入 H3。

拒绝证据：`assets/previews/papercraft-v2/`。这些图片只保留为失败记录，不再作为风格或 H3 参考图。

### E. Silicon to Delivery（候选，待确认）

真实 Mission 长命令是视觉主角。字符在真实 WebUI 中输入并提交后，镜头沿一次真实的计算动作进入硅芯片、显存、CUDA kernel 与训练数据面；再通过匹配剪辑返回多个真实子会话、Provider Activity、训练监控、架构图、论文和发布回执。专家团协作不画成节点或玩具隐喻，而是用真实子会话同时工作、具名责任、Artifact 来源定位和独立复核的可见证据表现。

视觉采用高端科学仪器与计算摄影语言：石墨黑、冷白、深硅灰，状态色只使用 OpenCorvus 青色和少量验证绿色；宏观芯片摄影、受控体积光、显存热图、CUDA 时序、真实屏幕反射和高密度但可读的 UI。禁止纸艺、玩具、发光球、赛博朋克城市、霓虹 HUD、伪代码、假 UI、抽象粒子网络和节点连线图。

## 5. 约 3 分 30 秒旁白 V7

> Agent 已经会写代码、做研究、跑分析。真正的问题是：它能不能把一件大事做完？
>
> 对一次问答来说，生成答案就是终点。对一个项目来说，答案只是开始。
>
> 任务一旦变重、变长，有限的上下文就会挤掉早期信息：约束被忘记，计划在执行中走样，工作没完成却提前收尾。最后交出的，可能只是看起来完整、实际上无法验收的半成品。
>
> 软件工程尤其典型。调研、设计、实现、测试、部署，少一环都不算完成。这不是五次独立的问答，而是一条必须衔接、可以恢复、能够验收的工作链。一次遗忘、一次错误交接、一次提前停止，都会被后续阶段继续放大。
>
> 会写一段代码，不等于能交付一个项目。如果运行层只提供当前会话，无论是单一 Agent，还是临时组成的 Agent Team，都不会自动获得四种能力：持久保存责任和状态；从中断处恢复；让下游准确消费上游产物；再由独立角色判断任务是否真的完成。这不是模型够不够聪明的问题，而是系统有没有长程交付机制。
>
> 所以，我们设计了 Mission。
>
> Mission 不让一支团队从头硬撑到尾。它把目标拆成有依赖的重型 Task；每个 Task 锁定一支精确版本的专家团和工作流。状态持久保存，失败后可以恢复；团队用带来源的 Artifact 交接；关键结果进入独立验收。上一个团队的产物，会成为下一个团队可以检查、可以复现的输入。
>
> 这不是概念演示。我们用一个真实 Mission，完成了 DeBERTa ABSA 模型的端到端交付。
>
> 从派发到最终收敛，墙钟时间约 12 小时 45 分——这不是纯 GPU 训练时间。6 个重型 Task 只使用 3 个内置专家团，实际形成 46 个 Agent 会话、20 种角色。
>
> 它们完成了模型与数据准备、RTX 5090 上的三组 CUDA 实验、自动更新的训练监控和推理网页、模型架构与实验生命周期两张论文图表、五页 ACL 风格短论文、独立审校，以及公开 GitHub 仓库。每项产物都能被打开、定位和核对。
>
> 质量也不是由 Agent 自己宣布。最佳实验的验证集 Macro-F1 达到 83.43%，比基线提升 1.47 个百分点；测试集 Macro-F1 为 83.61%。实验只有一个随机种子和 1800 条训练样本，所以我们只报告这次可复验的结果，不把它包装成普遍结论。
>
> 发布前，114 个文件通过公开安全审计；CUDA 训练链路在 RTX 5090 的干净环境中复验；最终提交从 GitHub 匿名回读确认。
>
> 这正是只靠一次会话的回答式 Agent 最容易失守的部分：难的不是生成某一段漂亮结果，而是在十几个小时里，让几十个会话始终围绕同一个目标；失败后恢复，交接时不丢证据，最后把代码、模型、网页、论文和发布状态一起推进到可检查、可验收的终点。
>
> 我们的愿景，是把这种编排扩展到更多团队、更长工作链，未来支撑几十、甚至上百支 Agent Team。无论是大型软件工程、机器学习研发、数据治理、安全审计、系统迁移，还是合规交付——别只让 Agent 回答。让它把结果交出来。

目标成片 3 分 20 秒至 4 分钟，上限 5 分钟；正式配音后以实测语速锁定逐镜时间，不以字符数代替音频事实。

## 7. H3 生产方式

- H3 只生成无文字的硅芯片微距、计算环境和四类科技工作空间；T2VA 用于独立科技 B-roll，I2VA/FL2VA 只用于锁定真实屏幕周围的环境与相机路径。H3 不得生成 UI、代码、热图、CUDA 时序、指标、模型架构、论文、logo 或任何可读文字。
- 上下文占用、执行中断、Provider/CUDA 活动和训练时序若作为机制图，必须由真实遥测驱动或在后期按公开契约确定性绘制，并清楚标注“机制示意”；不得把 H3 生成的假热图或假时序当运行证据。
- 提示词使用官方三段结构：`integrated_multimodal_description`、`overall_soundscape`、`non_diegetic_music`。
- 每个镜头明确：构图、主体、环境、动作起点与终点、机位类型/幅度/速度、逐秒节点、物理声效。
- 不使用空泛的 `cinematic, beautiful, premium` 词堆；必须描述能看见和能听见的事实。
- 不让 H3 生成产品 UI、指标、logo 或小字。真实 UI 由后期透视合成进 H3 场景。
- 先生成一个 4 秒风格验证镜头，抽取首/中/尾帧并检查主体一致性、运动、文字污染、黑帧和音轨；风格确认后才批量生产。

## 8. 确认门

正式生成前需要确认：

1. 视觉方向：D 已否决，不可选择；E「Silicon to Delivery」为候选，等待用户确认。
2. 时长与画幅：约 80 秒、16:9 已批准；正式旁白后锁定 78–82 秒，网站另裁 15 秒无声预览。
3. CTA：推荐“创建一个 Mission”，同时在收束画面展示 GitHub/官网入口。
4. 音频：推荐中文旁白 + H3 原生物理 SFX + 一条克制的连续音乐；不使用粉红噪声假装配乐。
