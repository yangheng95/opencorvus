# OpenCorvus Mission 科普动画创意简报 V2

状态：一致角色动画故事版设计中。用户要求故事为绝对主体，案例只占结尾十几秒，且不得用 WebUI、训练页、论文页等截图充片长。全片只能出现同一个卡通主角和同一造型体系的卡通 Agent；除片头片尾官方品牌 Logo 外，故事中禁止渡鸦、鸟或 Corvus 化身。必须先冻结角色设定图，再使用参考图驱动动画，禁止以独立 T2V 镜头拼接人物。失忆、停工、追问、交接、恢复、独立复核和完整交付都必须通过角色事件表现。暗色 PPT、浅色 PPT、采购表、节点图、截图拼贴、真人、人物漂移、渡鸦编排器、3D 接力与纸艺方向均只保留为失败证据。

## 1. 这支片只解决一个传播问题

让第一次听说 OpenCorvus 的个人技术用户在 3–5 分钟内明白：

> 长任务不是一次更长的聊天，而是一场必须能交接、恢复和验收的接力赛；Mission 是承担这场接力的运行层。

目标观众：正在用 AI 做毕业论文、个人开源项目、副业应用、求职作品集或独立研究的个人用户。

观众看完应完成的唯一动作：打开 OpenCorvus，创建一个 Mission。

## 2. 真实品牌事实

- 官方定位：面向长程任务的开源 Agent Harness。
- 官方承诺：跑得久的工作、能核对的结果，以及会按反馈修订的专家团。
- Mission 把一个目标拆成有依赖的 Task；Task 固定责任和专家团版本。
- Task 间交接的是带来源与精确定位的 Artifact，不是“完成了”的口头自述。
- 本片展示的 DeBERTa ABSA Mission 有六个真实阶段：获取模型与数据、CUDA 训练及网页、图表、论文、审校、GitHub 发布。
- 可展示的真实结果仅限：selected validation Macro-F1 0.8343、test Macro-F1 0.8361、seed 42，以及已经存在的网页、图表、论文和公开仓库。

禁止口径：100% autonomous、production-ready、保证成功、未经验证的性能提升、把模型自述当运行证据、把 H3 合成 UI 当真实产品。

## 3. 调研后采用的创作原则

1. 前 5 秒先呈现观众熟悉的失败，不先报品牌名或功能清单。
2. 一条主张贯穿全片；每个镜头只负责一个动作和一个因果关系。
3. 观众是主角，产品是帮助观众完成转变的机制。
4. 先展示结果为什么可信，再展示 logo 与行动指令。
5. 真实 UI、指标和产物只承担 Proof；H3 只承担隐喻、空间、动作和情绪。
6. 屏幕文字只保留能在静音时复述主张的短句；不常驻大标题、段落字幕或卡片列表。
7. H3 镜头按 4–6 秒独立生成，使用逐秒动作、明确机位、空间锚点、环境声和音乐描述；先做低分辨率验证，再升级通过的镜头。
8. 每个昂贵阶段之前确认创意简报、风格帧和镜头表；不再边生成边猜方向。

## 4. 当前视觉方向

唯一允许继续的方向是明亮的 2C 角色动画：同一个卡通个人用户、同一套卡通 Agent、同一份项目和同一个可见工作空间贯穿全片。用户从“不得不替 Agent 收尾”出发，依次经历工具选择、创建 Mission、查看具名 Agent、验收产物与发布成果。产品机制由角色行动和连续事件表现；真实 WebUI 不再承担叙事画面，案例只在结尾用极短的确定性文字与产物图标提供事实证明。

视觉使用暖白、浅灰和自然肤色，OpenCorvus 青色作为品牌识别，橙色只承担用户行动。禁止暗色渐变模板、扫描线、霓虹描边、中心节点图、功能卡片墙、采购表、伪 HUD、玩具隐喻和脱离人物的芯片空镜。用户已明确要求立即看完整视频，因此本轮直接渲染整片并以逐段抽帧和全尺寸人工复核作为视觉门。

所有已否决路线及证据统一记录在对应 spec，不在当前创意事实源保留可误用的平行方案。

## 5. 约 3 分钟旁白 V8 · 2C 用户视角

> 你有没有遇到过这样的 Agent？
>
> 你把一长串要求交给它。它回复得很快，代码也写得像模像样。可等你真正检查：资料没查全，测试没跑，网页打不开，论文还是草稿。你追问一次，它修一点；再换一个会话，它已经忘了你最初的要求。
>
> 最后，不是 Agent 在帮你做项目，而是你在给 Agent 当项目经理。
>
> 但你真正想要的很简单：把自己的项目做完。
>
> 可能是毕业论文、个人开源项目、一个副业产品，或者一份真正能放进作品集的成果。它们都不是一次问答。你要调研、设计、实现、测试、修改、发布；任何一环没做完，最后留下的就只是半成品。
>
> 你也可以同时打开很多 Agent。但如果它们只靠眼前这一次对话，就不会自动记住谁负责什么、失败后从哪里继续、上一组 Agent 交付了哪些文件，也没有另一个 Agent 替你检查：它到底做完了没有。
>
> 现在你也有不少选择。WorkBuddy 强调一句话交付办公成品；DeepSeek Harness 提供插件化的开发者运行时；Codex 擅长隔离环境里的并行编码；Claude Code 提供多种并行协作方式。它们重心不同。
>
> OpenCorvus 解决的是跨调研、训练、网页、论文和发布的多专家团接力与验收。
>
> 所以，我们做了 OpenCorvus Mission。
>
> 你先写下最终目标。Mission 会把它拆成一组彼此衔接的重型 Task，交给不同的专家团。你可以点开每一个具名 Agent，看它正在调研、实现、测试还是复核。任务中断，状态仍然保留；上一组 Agent 交付的文件，带着来源进入下一组；关键结果还可以交给没有参与实现的 Agent 独立验收。
>
> 而且，OpenCorvus 完全开源。MIT 许可证，全部源码公开，可以自托管、审计和 fork；模型、工具、权限与专家团都能定制；任务跑在你的机器上，不可逆操作先问你；每次工具调用、参数和结果全程可回看。你给专家团的长期反馈，还能形成一次可回退的修订，只有你确认才安装。开源、定制、可控、透明，是你能把长期项目真正交给它的前提。
>
> 你不必再靠反复复制上下文来维持协作，也不用把每个 Agent 的一句“完成了”当成唯一依据。
>
> 我们真的用它跑了一个很重的个人项目：下载 DeBERTa ABSA 模型和数据，只用 RTX 5090 训练；比较三组实验；做一个自动更新的训练监控和推理网页；绘制论文图表；写完并审校一篇五页 ACL 风格论文；最后整理成公开 GitHub 仓库。
>
> 这条 Mission 从派发到最终收敛，跨越 12 小时 45 分钟。6 个重型 Task，3 个内置专家团，实际形成 46 个 Agent 会话、20 种角色。你可以从界面里点开它们，看到谁做了什么，以及产物交给了谁。
>
> 最终留下的不是一句“任务完成”。而是模型检查点、三组 CUDA 实验、训练和推理网页、两张论文图表、五页论文、测试报告，以及一个可以匿名访问的公开仓库。
>
> 最佳实验的验证 Macro-F1 是 83.43%，比基线高 1.47 个百分点；测试 Macro-F1 是 83.61%。这是单个随机种子、1800 条训练样本的受限结果，所以我们只展示能够复验的事实。
>
> 如果你正在做毕业论文、课程大作业、开源项目、副业应用、求职作品集，或者任何需要连续几小时、几天才能完成的个人项目——你需要的可能不只是一个更会回答的 Agent。
>
> 你需要的是一群 Agent，真的把结果交到你手里。
>
> OpenCorvus。别再给 Agent 当项目经理。让 Mission 帮你把项目推进到可检查、可验收的交付。

目标成片 3 分钟至 4 分钟，上限 5 分钟；正式配音后以实测语速锁定逐镜时间，不以字符数代替音频事实。

| --- | --- | --- |
| WorkBuddy | 商业云端桌面产品，从一句话出发交付办公成品，并在平台内封装 Expert Group | 一句话交付办公成品 |
| DeepSeek Harness | 面向 Agent Harness 开发者的插件化运行时；模型、工具、技能、会话、沙箱、存储、循环、调度和 UI 均可组合，运行轨迹可追踪 | 开发者可组合运行时 |
| Codex | 在隔离云环境中并行运行编码任务，可后台继续并在结果可审阅时返回 | 软件工程 Agent |

规模口径：当前仓库没有单个 Mission 已真实调度几十或上百个 Agent Team 并完成交付的证据。宣传片不得使用这一完成式口径，除非补充对应 Mission ID、持久化活动、Provider 活动和交付证据。

## 6. 本轮镜头门

`storyboard.zh-CN.json` 仍处于 rejected，旧分镜不得进入生产。当前先锁定角色设定与一个 H3 I2V 动态样片；通过后再将下列故事事件写回唯一 storyboard：

1. 用户痛点：具体个人在真实生活空间里检查 Agent 半成品，不出现功能卡片。
2. 工具选择：同一用户在同一项目上切换 WorkBuddy、DeepSeek Harness、Codex、Claude Code 与 OpenCorvus 的不同工作方式，不出现采购表。
3. 开源动作链：GitHub 源码被拉到本机，随后出现权限确认、完整调用记录和可撤销修订；不出现中心节点图。

这些场景必须由同一主角与同模 Agent 的动作连续演出；品牌 Logo、网站和仓库地址只在片头片尾以确定性图层出现。每个昂贵 H3 镜头都必须使用已冻结的角色/场景参考图，并通过完整接触表和全尺寸关键帧人工复核。

## 7. H3 生产方式

- H3 只生成无文字、明亮自然的卡通个人工作空间和角色动作；最终故事镜头只能使用角色设定图派生关键帧，再通过 I2V/FL2VA 锁定人物、Agent、环境与相机路径。独立 T2V 只能做废弃探索，不能进入成片。H3 不得生成 UI、代码、热图、CUDA 时序、指标、模型架构、论文、logo 或任何可读文字。
- 上下文占用、执行中断、Provider/CUDA 活动和训练时序若作为机制图，必须由真实遥测驱动或在后期按公开契约确定性绘制，并清楚标注“机制示意”；不得把 H3 生成的假热图或假时序当运行证据。
- 提示词使用官方三段结构：`integrated_multimodal_description`、`overall_soundscape`、`non_diegetic_music`。
- 每个镜头明确：构图、主体、环境、动作起点与终点、机位类型/幅度/速度、逐秒节点、物理声效。
- 不使用空泛的 `cinematic, beautiful, premium` 词堆；必须描述能看见和能听见的事实。
- 不让 H3 生成产品 UI、指标、logo 或小字。真实 UI 由后期透视合成进 H3 场景。
- 先生成一个 4 秒风格验证镜头，抽取首/中/尾帧并检查主体一致性、运动、文字污染、黑帧和音轨；风格确认后才批量生产。

## 8. 当前生产约束

1. 视觉方向：2C 用户视角的明亮角色动画正在做一致性样片；样片通过前不得进入整片生产。
2. 时长与画幅：3–5 分钟、16:9；网站可在成片批准后另裁 15 秒无声预览。
3. CTA：“别再给 Agent 当项目经理”，同时在收束画面展示 GitHub、官网与作者入口。
4. 音频：中文旁白 + 真实/生成镜头物理 SFX + 一条克制的连续音乐；不使用粉红噪声冒充正式配乐。
5. 推送：用户必须先看到并批准视频；批准前只允许本地提交，不得 push。

## 9. 失败证据

纸艺、3D 接力工厂、Silicon to Delivery 和暗色卡片 animatic 的文件、接触表与拒绝原因均保留在 spec 和外部演示目录中。它们不再作为当前视觉参考，也不得通过生产入口重新生成。
