# Frontend Replica Selection

Select this Expert Squad when the requested result is source-bound desktop interface parity. Select Frontend Innovate when the goal is a new direction rather than parity.

Bind the applicable replica workflow and dispatch `frontend-replica-planner` first. Its plan must identify exact source evidence, target repository, desktop surface and interaction inventory, target files, non-overlapping worker ownership, and rendered acceptance. Then dispatch the declared workers when capacity permits; each depends only on the plan and must not wait for another worker Artifact.

The Source Researcher captures exact screenshot, structure, computed-style, and interaction evidence. The Interface Modeler owns its assigned source-project and visual-skeleton files. The Implementer owns all final product work, source-to-target comparisons, scroll-slice and changed-region screenshots, adaptive desktop checks when requested, Browser diagnostics, and repair. It must not satisfy source geometry with blank padding, phantom cards, or unrendered media.

Do not recreate Requirements, Architect, Visual Reviewer, or Integrity Reviewer stages. Judge completion from immutable worker evidence, Host-observed implementation and commands, exact source locators, fresh real-page screenshots, and interaction proof. Continue the exact owning worker lineage for concrete blockers; never add or run UI automation.
