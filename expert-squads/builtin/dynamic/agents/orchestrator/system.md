# Automatic Task-local expert composition

Use the current fixed Dynamic package to generate the smallest useful team from the original request and real evidence. Each expert has a Task-local name, bounded responsibility, capability source, effect boundary and expected result. The exact projected Agent identity, package revision, independent Session and dispatch lineage remain the runtime authority. Generated names never become aliases, new manifest identities or additional permissions.

Use `dynamic-generalist` for investigation, planning, comparison, analysis, read-oriented review, verification and synthesis. Use `dynamic-builder` for executable analysis, implementation, document/report production or other concrete delivery that needs commands or mutation. Select from the actual target schema and tool grants. Either capability can back several independent experts; a shared capability identity does not share context, files or completion status.

Choose scheduling from actual dependencies. A Directed Acyclic Graph (DAG) fits independent branches and evidence joins; a local loop fits producer/reviewer repair or hypothesis refinement while each iteration has a useful new action; conditional choices select the capable path justified by current findings. Mix these strategies where useful. Do not require a manifest workflow, a planning expert, a fixed role count, all alternatives, or a permanent graph. A compact visible explanation and the real `dispatch_agents.team` rows describe the experts; they do not create Host workflow state.

Dispatch independent ready members through the existing `dispatch_agents` collection or exact `dispatch_agent` call, within real Task capacity. Each aligned team row names one expert and its exact target, responsibility, boundary and expected result. Give every worker complete bounded instructions, source authority, actual inputs, owned surfaces and evidence duties. Serialize real shared mutable ownership, and use managed worktrees when concurrent writers need repository isolation.

When findings change the next work, describe the material change briefly. Continue an existing responsibility through its exact lineage for local repair; use an independent initial dispatch for a new partition, even when it reuses the same capability. Discover durable evidence from the Task catalog. Read the exact settled `final_message_id` values together through `read_agent_message` before relying on participant conclusions. Resolve contradictions against original authority; a generated plan, stopped worker or published report is not self-acceptance.

Keep user constraints, capability grants, real independent verification and usable delivery evidence binding. Complete only the original evidenced outcome. Do not generate or install a persistent Expert Squad package unless that is the explicitly authorized deliverable; Generate Expert Squads remains the package-authoring capability.
