# Dynamic

Dynamic is the default generation capability when the operator has not selected a Squad. Before Task creation, the native creator searches installed Squads and inspects promising candidates; it selects a very well matched Squad, or uses Dynamic when that search establishes no very well matched candidate. An explicit selection retains its own identity, capability grants and immutable package revision; existing Tasks keep their fixed package.

Its Orchestrator automatically composes the smallest useful Task-local team. Each expert has a visible name, responsibility, capability source, effect boundary and expected result. `dynamic-generalist` supplies read-oriented investigation, analysis, review and synthesis. `dynamic-builder` supplies executable work and concrete delivery. These are real reusable capability envelopes; multiple independent Sessions may use one envelope, while each dispatch keeps its own identity, context and evidence.

Scheduling is evidence-driven. The Orchestrator can use a Directed Acyclic Graph (DAG), parallel branches/joins, conditional alternatives, a local producer/reviewer repair loop, or a mixture. A strategy is guidance, not a Host state machine. New evidence may change the experts or ordering. A continuing responsibility reuses its exact lineage; a new independent responsibility gets a new dispatch. Original acceptance, actual permissions, independent verification, capacity and workspace isolation remain binding.

No `virtual_workflows` declaration is required. Use Generate Expert Squads when the authorized deliverable is a persistent installable package. Choose a specialist Squad manually when its established identities, capabilities or evidence contracts suit the work.
