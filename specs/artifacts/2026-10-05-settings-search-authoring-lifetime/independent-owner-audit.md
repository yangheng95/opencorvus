## What is and is not demonstrated

Source supports deterministic component recreation for a query which excludes the current tab, plus exact local owner loss for the listed inline forms. It does not itself establish the rendered user symptom; root's actual Scheduled marker sequence is required. Merely inspecting createSignal/unmount would miss modal protection, immediate saves, shared settingsStore inputs and deliberate Cancel actions; those are excluded above.

An eventual search-specific correction should avoid implicitly replacing an authored page just while typing. The existing activeTab is already the selected-page authority; visible results should not create a second selection source. However, preserving active content while its tab is filtered has accessibility/labeling and result-presentation implications that need a concrete UI plan. Blind forceMount of every settings panel would eagerly run all loaders, retain stale project/auth-scoped forms and create hidden controls; do not introduce it as a generic repair. A page draft store copying every local field would likewise be a second owner. No implementation is selected until root qualifies the actual issue and approves exact scope.

Explicit tab switching, page Back/Escape and command/rail navigation are separate departure semantics; a fix only to transient search does not promise those preserve drafts. If they are included later, admission must occur at the sole settings navigation boundary and use the active authoring component's own current value/baseline, not parallel dirty state; all explicit callers must be audited then.
