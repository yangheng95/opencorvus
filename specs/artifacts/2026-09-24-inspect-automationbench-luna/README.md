# Inspect AutomationBench Luna calibration

**Results:** [Chinese performance report](REPORT.md), [combined measurement JSON](pilot-summary.json). Strict 2/6, partial 81.51%, with the three operator-cancelled first-attempt slots transparently recovered. First-attempt coverage and all attempt costs remain separate.

Experiment plan and results: [record](../../records/2026-09/2026-09-24-inspect-automationbench-luna-calibration.md).

`host.ts` provisions an isolated production server using existing runtime and Provider audit primitives. It does not run or score benchmark samples; use the registered Inspect task. It requires explicit `INSPECT_LUNA_AUTH_SOURCE` and `INSPECT_LUNA_EVIDENCE` paths. Credentials and matching model catalog are copied to a temporary isolated home and removed when the experiment-owned host settles. Send shutdown by creating `stop-host` only after its Tasks settle. Start Bun with the repository's `packages/opencorvus/tsconfig.json` override. No prompts, credentials or raw Provider bodies are retained in provider audit records.

Calibration uses the existing three-case smoke manifest. The pilot manifest is selected with Python `random.Random(20260924)`, one sorted-pool draw per domain (finance, sales, marketing, operations, support, hr), excluding calibration members, before scores are observed. Pilot membership is frozen once generated.

`observe.py --host <host.json> --output <observation.json>` reads only the isolated database's Task/Session identities, then obtains status, Task closure and participant messages through public HTTP endpoints. Its evidence omits user message bodies and all reasoning parts; it retains actual Tool calls/results and assistant final text. Token fields are the runtime's reported usage (uncached input, cache read/write, output and reasoning); reported cost may be zero for subscription-backed authentication and must not be represented as a verified monetary price.

`summarize.py --log <run.eval> --observation <observation.json> --output <summary.json>` verifies exact cohort membership and actual per-Session model identities, recomputes the original strict/partial rubric from every scored snapshot, and reports the fixed denominator and unscored errors separately. Summary role evidence retains final participant text and tool counts, not reasoning bodies. Different calibration/pilot cohorts do not establish a paired improvement estimate.

The first host had a 600-request accounting cap shared by preflight, diagnostics, pilot and background work. At 581 actual requests it was normally stopped after cancelling the three remaining unscored pilot members; all completed scores were preserved. `pilot-first-summary.json` reports this incomplete first-attempt coverage explicitly. Recovery selects only those cancelled/unscored identities in `recovery-manifest.json`, with the same frozen squad and model, and no score-based retries. The recovery host uses `INSPECT_LUNA_MAX_REQUESTS=619`, the remainder of the corrected 1,200-request experiment allowance. Both attempts' usage and time must remain visible in final reporting.

`combine.py` checks that recovery membership is exactly the originally cancelled/unscored set and retains all original scored results. It writes `pilot-summary.json` with separate first-attempt coverage, completed measurements, cumulative times and both Provider audits. Total actual experiment requests: 812. Both host cleanup receipts are saved; their temporary credential/catalog copies are removed. The `.eval` logs, independent re-scored logs, manifests, summaries and receipts are the portable evidence; full non-reasoning observation snapshots remain under the experiment's `.tmp` directory.
