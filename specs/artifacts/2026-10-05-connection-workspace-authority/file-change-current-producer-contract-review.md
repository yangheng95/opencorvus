## Alias audit: exact source support

* `before ?? oldContent`, `after ?? newContent`: only before/after are emitted by current Edit and apply_patch. Internal Patch implementation uses oldContent/newContent but deliberately maps them before emitting. Repository source search found no current emitted Tool diff under oldContent/newContent. Remove these aliases when replacing the reducer; do not retain internal variables as compatibility wire contracts.
* `file ?? filePath ?? path`: file is current Edit/Snapshot schema; filePath is current apply_patch wire field. These are two explicit producer contracts, not aliases for arbitrary unknown objects. No current structured diff producer emits path. Write emits lowercase filepath, which current reducer does not accept and, without original body, is not a valid substitute diff. Artifact inventory path fields do not authorize treating inventory as text diff. Remove generic path alias rather than accidentally absorbing unrelated file inventory.
* `type/status`: current normalizer uses raw.type ONLY; it ignores raw.status. apply_patch supports add/update/move/delete. Edit lacks both. Snapshot has optional status and current producer emits it, but those session rows arrive through their own persisted group path, not Tool normalization. Therefore optional status support is real for Snapshot FileDiff, not a license to accept arbitrary raw status alias on Tool results. add/added, delete/deleted/remove/removed generic aliases exceed the Tool producer's actual type values. update/move currently collapse to modified while displayPath represents move arrow.
* `relativePath/movePath`: supported by apply_patch only, relative to Instance.worktree; filePath remains original absolute path, movePath actual destination. Do not erase this rename identity or silently use selected directory as authoritative new source root. Existing display strings may differ between absolute Tool and relative Snapshot path; path display is not causal identity.
* counts: producer counts are actual diffLines or Git statistics. Defaulting absent counts to0 does not manufacture real zero-change evidence; optional/unknown should be represented honestly if a producer only gives paths.

Empty-text guessing is unsupported as file operation inference. Existing empty file→nonempty content is modified, yet normalizer returns added. Existing nonempty file→empty content is modified, yet returns deleted. Empty-file deletion and empty-file creation also evade those guesses. A modified binary Snapshot row may have both bodies empty. Apply_patch has explicit type and Snapshot has explicit status/existence objects; only Edit's emitted operation is underdetermined. Defaults to modified may describe regular edits but cannot accurately represent its create branch. Do not infer file absence from an empty string.

## Public relay and ordering boundary

Tool metadata is a generic record in Message ToolState; `normalizeToolResult` preserves result.metadata without renaming filediff/file/filePath/before/after. Processor completion persists the original normalized metadata and generates end=Math.max(Date.now(),start+1). Public `conversation/transport.ts` preserves small states; for large completed state it replaces metadata with a bounded record plus an explicit deferred marker and preserves original state.time. Bounded metadata key list omits files/filediff, so live summary over that relay has no diff until canonical Tool state is fetched. InlineToolPart fetches the deferred canonical Part on disclosure, then calls the same toolFileChangesFromState; aggregate collection over card parts does not by itself fetch that state. Never interpret missing deferred metadata as no file change or synthesize body from model output/input.

MessageStore orderKey uses persisted Part row.time_created plus ID, not last Tool completion/update. A part may be created before filesystem mutation. state.time.end is completion/persistence timing after work and can be ordered differently from actual writes under concurrency. Exact call/part identity can deduplicate replay, but no current general file-level operation ordinal exists. Sequential Tool body chains can establish compatible endpoints; last-wins by part creation, generic end timestamp or sorted display path cannot establish universal causal order. Root's actual sequential Write→Read→Edit facts qualify that run only. No per-file sequence/causality fact may be invented in this reducer.

PatchPart current `patchPartFileChanges` maps string files through an object-only parser, so all canonical strings become null. That path is ineffective for canonical PatchPart. Removing its attempted object normalization loses no currently decoded canonical diffs. Either show path-only observation with its own honest content-unavailable contract or retain Snapshot as its sole net diff authority; do not make a string path claim before/after or add an alias pretending PatchPart emitted objects. There is no current producer of object-valued PatchPart.files under its canonical schema.

## Sole replacement contract and deletion impact

There is no single existing universal Tool metadata shape. The safe current replacement is one reducer with explicit typed producer inputs: Edit's filediff, apply_patch's files, Snapshot/session net rows, and immutable artifact observations only at their known boundaries. These adapters are validation of actual producers, not generic aliases or fallback compatibility readers. Prefer a single canonical internal endpoint record with path/side content plus known explicit operation/existence/provenance; retain unknown when current source omitted a fact. A truly single wire shape requires updating current producers together and deleting old readers in the same admitted change. It cannot be achieved by declaring one old alias canonical and silently dropping the other current producer.

If Root admits producer consolidation, use existing Snapshot FileDiff field vocabulary file/before/after/additions/deletions/status plus explicit side existence/operation as necessary for move and empty-file correctness. Write must emit actual prewrite body and prewrite existence while it already owns the operation; Edit must emit its verified create/update operation; apply_patch maps actual type/move authority to that one shared schema. Establish one metadata property across these current tools and remove previous filediff/files readers together. This is a backend/public-contract change requiring all definition/caller/transport searches, positive data tests and size/relay review; not an already authorized UI-only cleanup. Do not derive Write before from current disk, or after from a narrated reply. Updating Write input parsing alone cannot recover its old body.

* collectAgentFileChanges/collectAgentFileChangeGroups/FromNodes/currentConversationAgentChangeGroups traverse card parts and exact agent IDs. mergeFileChange currently retains first defined after while summing counts; duplicates have sources incremented with no call identity, and rename destination key can merge unrelated history.
