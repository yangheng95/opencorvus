## Producer evidence: what can actually be proven

1. **Canonical Edit/ApplyPatch completed metadata.** Edit returns filediff before/after from actual read/write/read path and counts; Add File path uses exclusive create, ordinary existing edit reads both sides. ApplyPatch supplies files old/new text, explicit add/delete/update/move type and target. Each Tool result is immutable occurrence evidence, so complete textual endpoints can be proven when both strings present and operation facts provide existence. Empty string alone cannot prove absent versus an empty existing file. Existing Edit filediff omits explicit operation type, so input oldString or empty before is not enough to infer a general added/deleted status. Actual oldString==newString is rejected; clear existing text to empty is a valid modification and should not become deletion by content heuristic.
2. **Canonical Write.** metadata contains filepath/exists, receipt text; no files/filediff. Its submitted content is not independently observed after evidence. Current toolFileChangesFromState does not produce a change from it. Snapshot/Session observation may later cover it; do not invent full diff from content or assume Write never appears in inventory.
3. **Real Patch Part.** Snapshot.Patch schema files is string[] plus immutable hash (snapshot/types.ts:71). session processor persists this actual path inventory. Current normalizeToolDiff rejects string entries, so patchPartFileChanges silently yields no changes for canonical Patch. This producer can prove affected path/event, but cannot prove text/endpoints/counts/existence. Future adapter should retain an explicit incomplete path observation; must not synthesize empty sides/net zero or call disk to fill it.
4. **Snapshot.diffFull → SessionSummary.** It resolves Git from/to tree statuses/object texts then returns required strings. index.ts:368–382 explicitly sets binary sides to empty strings and binary counts0; missing map/object text also coalesces to empty. Thus current public FileDiff erases binary classification and absent/missing-text distinctions. Frontend cannot prove those erased facts from this DTO alone, even if both strings exist. Text known object success/status may be complete, but generic Session endpoint casting must not automatically assert all FileDiff complete textual. This is a current producer limitation, not permission to create a compatibility read. Backend schema improvement is a separate public-contract scope if required.
5. **Build agent immutable observations.** build/agent.ts:1289–1373 obtains Git raw object IDs/status, maps all-zero OID to null, resolves actual Git object sizes, parses numstat binary marker and builds strict observation. Here required before:null/after:null means actual absent side, versus object bytes0 means existing empty file. is_binary is explicit; binary numeric0 is current wire contract, so proposed nullable UI net count should represent nontext/unknown rather than display0 as measured text delta. No body hydration needed to prove immutable existence/ref identity.
6. **Content resolver.** engine/build-observation-content.ts accepts only exact Task Artifact observed file/side; absent side returns typed side_absent, objects permit bounded range reads. services/diff hydrates known text from immutable object endpoint, not current disk. This is canonical authority to preserve. Null absence can legitimately become an empty diff side at rendering, but missing/invalid object reference cannot. Current artifactChangeGroups maps invalid/missing object to null, losing that distinction; current readObservedTextSide treats all falsy refs as empty. These must tighten to verified null versus unknown.
7. **Workbench board.** engine/store/persist parse canonical BuildFileObservation; workbench/board.ts forwards these Artifact payloads and also compact path/status/count/isBinary projections for review associations. Compact projection does not add body; cannot be cast complete just because counts exist. Session board route session.ts:1073 obtains SessionSummary.diff; ordinary Overlay board hydration stores it unchanged via conversation.ts. boardStore.changes/setChanges are any[]; consumers currently cast to FileChange. Explicit adaptation must occur at one truthful input boundary, not scatter casts/fallbacks.

## Contract decision and limits

Complete must describe provable evidence, not “has a string somewhere”. An immutable two-sided ref/absence can be complete without eagerly loaded text; resolved text requires verified present content and actual absent side rendering. Incomplete preserves known path/owner/activity and unknown endpoints; nullable net counts mean unknown/nontext, never coalesced0. A counted activity observation is not automatically a net diff. Different groups and artifacts are distinct subjects; sequential same-owner changes require chronological/cause facts, not universal last-wins.

Current Snapshot Session DTO cannot reconstruct erased binary/missing-object evidence; mark that limit explicitly or approve a real source contract repair, not add aliases/caches/currentdisk. Current Patch has only filenames; keep incomplete inventory, not discard or manufacture full result. Scope recommendations above are exact current callers, with backend widening clearly separated from mandatory Overlay mechanical adaptation.
