## Correction to the earlier boundary hypothesis

The earlier review identified a new fatal TextDecoder for every 64 KiB artifact chunk. This is real source behavior, but its assumed ordinary-route trigger is not established: artifact-catalog/index.ts utf8Chunk (1379) validates the requested offset and retreats the end until the chunk is complete UTF-8. textReadResult is used for snapshot manifests and text resources. Engine artifacts separately use boundedEngineArtifactTextReadResult (1753), also retreating to a complete code point. Both use fatal:true, ignoreBOM:true. orchestrator.ts artifact-read (841) reencodes chunk.text into exact UTF-8 bytes and verifies its declared range length. Thus current canonical route text chunks are already independently decodable; a Unicode character crossing the nominal 65536-byte budget yields a shorter first response rather than a split character. A split-byte service test is useful decoder-contract qualification, but cannot be presented as a reproduced canonical-route defect.

There is a separate source-proven byte-preservation discrepancy: conversation-artifact.ts creates TextDecoder with default ignoreBOM:false for EACH response. UTF-8 bytes EF BB BF at the beginning of the resource, or at the beginning of any later returned chunk, are stripped. Backend deliberately preserves these bytes with ignoreBOM:true. The service's final TextEncoder length check then reports an error despite a valid immutable resource; without that check content would be lost. Boundary-leading U+FEFF can be legitimate content, not an encoding header. Real reproduction has not run; this is a deterministic source contract mismatch, not a claim about a saved UI incident.

## Bounded implementation recommendation, pending admission

1. Keep the one artifact loader and all current range/authority contracts. Allocate one fatal UTF-8 decoder per logical text load with ignoreBOM:true; decode with stream while more bytes remain, flush at actual final range including empty input. Preserve literal BOM/code points and final byte-count verification. Do not normalize text or re-fetch current disk. A decoder TypeError is a positive invalid-UTF8 error contract; retaining native TypeError/cause is sufficient unless Root explicitly admits a public typed wrapper. Never relabel decoding/range errors as HTTP or authority errors.
2. Permit a caller-supplied existing ApiAuthority on this same loader (as the mature API blob loader already does), capturing at entry only when omitted. Download entry captures original authority and exact task/locator/resource identity; supplies authority to loader and asserts it immediately before download/error publication. Retire component/source changes through the existing lifecycle and exact original request ownership, with AbortSignal cleanup. Finally releases only its own busy occurrence. No owner registry, shadow current source, cache, queue or fallback. Root must choose the minimal actual Solid prop/cleanup identity contract before edits; no file-clock or JSON hash is a replacement for actual scope.
3. Audit/admit the analogous remote artifactExportBlob→ArtifactActions continuation in the same slice, passing the same original token through blob acquisition and final action. Reuse canonical blob loader/cache and downloadBlob. Do not add a parallel runner/export loader. Typed original ApiAuthorityChangedError must stay private and must not be serialized as user error/outcome text. Current-scope genuine errors remain visible through canonical diagnostics; retired publication is simply retired.
4. Preserve exact range/header checks. A response beginning at the wrong offset, changing ETag/total/media, inconsistent body length, malformed disposition/range, or incomplete attachment must retain a precise current error; do not retry another source. A source change and a malformed response are distinct outcomes with original request ownership.
