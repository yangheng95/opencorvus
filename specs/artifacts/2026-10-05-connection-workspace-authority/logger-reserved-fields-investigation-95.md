## Proven data-flow cause

Session.persistPreparedNextInTransaction at src/session/index.ts:559 passes the entire persisted Info as log.info("created", result). Info.time is its subject entity lifecycle object. Log.emit util/log.ts:395 builds attributes by spreading sanitizeRecord(extra) then ambient SessionObservability tags. sanitizeRecord:378 redacts values but does not distinguish reserved envelope keys. Pino10.3.1 installed lib/tools.js:_asJson first appends canonical level/time, then child bindings, then every object field. This deliberately permits later object fields to win after JSON.parse. Thus the subject time is emitted as a duplicate top-level time key after Pino's ISO timestamp. JSON.parse returns the object, causing Root's strict DateTime.Parse consumer to fail. This is source-correlated with the two real records; the parsed evidence alone cannot recover the discarded canonical timestamp.

The Session caller is not the whole shared cause: Log.create arbitrary tags, .tag(key,value), extra and pendingRecords accept reserved keys. level can be overwritten the same way. message is explicitly appended last when supplied, so actual message precedence differs from time; missing message permits an attribute message. service tags can be overwritten by extra. Ambient sessionID/logDomain currently win over extra by the spread order, but arbitrary child tags can still create duplicate fields. Error/err are intended diagnostic serializers, not authority timestamps. A Session-only rename fixes this one observed call but leaves the arbitrary shared envelope contract unsafe.

## Minimum single-authority repair candidate and scope decision

The root repair must define envelope ownership in util/log.ts once: Pino owns time/level/message, explicit logger service and ambient SessionObservability own their actual binding fields, structured caller subject fields are data rather than competing envelope keys. Do not create a second timestamp clock, timestamp fallback, keyword strip or alternate logger. Session-created Info should be passed as an explicitly nested subject so its full lifecycle facts remain visible.

A complete schema choice requires Root admission because current consumers expect arbitrary extra flattened. The robust single-current contract is to namespace all caller attributes under one mandatory structured-data field at the logger boundary (Pino's mature nestedKey mechanism can supply object separation), with canonical service/ambient bindings outside; mechanically adapt actual consumers and tests to that one shape. Keep no flat/nested compatibility double-reader. Tags also need the same reserved-name ownership rule; applying nestedKey only to extras would leave .create({time:...}) unsafe. Preserve arbitrary diagnostic subject values and existing canonical redaction, rather than dropping a colliding time or throwing from routine logging.

If Root prefers a smaller collision-only migration, it must explicitly define how caller data survives and how tags/attributes are validated without introducing a dual protocol or failing a Session transaction. Current source provides no already-existing generic subject namespace schema, so this report does not pretend such a field or exact mechanical consumer count has been admitted. A caller-only Session nesting can be an immediate scoped improvement but cannot be declared the complete shared reserved-field fix.
