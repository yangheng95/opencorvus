# Connection B independent read-only design review

Reviewed 2026-10-05 by settings_audit. This is an ignored investigation note, not an implementation authorization or actual HTTP/UI qualification. No source/spec changes, builds, services, browser actions, credentials or model calls were made for this review. The connection-save-authority record, current source and existing non-UI admission tests are the evidence. A's local editor and serialized onConfirmed publication are now implemented separately; they do not close B.

## Observable and shared root cause

The existing pure production loadMeta snapshot demonstrates A path/VCS output committed while configured API is B and directoryEpoch remains 0. It uses controlled memory responses and dummy domains, not an HTTP backend. Endpoint publication bypasses workspace/file admission and leaves selectedSource, workspace/directory epochs and several resource owners unchanged. activeDirectory prefers selected Task/Session directory, so changing settings.directory alone is insufficient. Source inspection additionally establishes a GET-config -> PATCH-config retarget opportunity, pending list reuse, old source stream retry and file Save target reuse; these are not yet actual cross-backend mutation findings.

Definitions/callers: api-state.configure is the one URL/credential/directory owner; main and init project settings into it. Network Save now publishes through settingsSaveTail.onConfirmed. Other URL writers are settings.load/applySettings, native syncLocalServerUrl and restartLocalServer. Workspace/config/SkillMarket configure calls update only directory. resolveAutoServer has no production caller. Settings persist one server URL and one saved directory/workspace, not a per-server profile. Do not create such a profile incidentally.

## Identity: proved boundaries and unresolved product decision

1. Public global health (global.ts 511-546) exposes healthy/version/paths and optional databaseUnavailable. There is no dataScope field or public stable logical ID. Database health deliberately avoids opening SQLite (db.ts 1257). Paths and ports cannot establish logical identity across hosts, aliases or database replacement.
2. Database.Identity (db.ts 1182-1200) is the existing persistent authority singleton; it opens Client and uses a transaction to create/read the primary UUID. Reopen preserves it; a new DB at the same path does not. Calling it from current health would change the no-open/no-create boundary and is not authorized. A separate approved projection would have to reuse this exact authority, not invent URL/path hashing. Cloned databases and external filesystem ownership would still need an explicit contract; DB identity alone does not prove every file target is the same resource.
3. Native overlay_server_info/restart calls the host's owned server manager; spawned backend uses overlay_runtime_paths.root via OPENCORVUS_HOME (main.rs 4890). Normal port/PID rotation therefore has a known same-owned-root purpose and should retain workspace/drafts while invalidating transport responses. This is code evidence, not a new native restart execution or proof against an independently replaced DB.
4. Backend basic auth is one process-configured pair, not a per-user namespace selector. Credential edits against an unchanged configured backend are transport reauthentication; arbitrary reverse-proxy tenant behavior is unknown. Do not infer namespace change solely from changed credentials or assume aliases are equal.
5. Minimal current-contract policy: an explicit operator endpoint retarget may deliberately depart to directory-free mode after admission, even if its URL is an alias. That is an explicit navigation policy, not an inferred different physical DB. Native managed restart and credential-only reauthentication preserve the workspace and refresh transport ownership. If product requires automatic alias identity preservation, a stable public authority contract and its cold-start persistence semantics must be approved first. Do not sneak dataScope into health or reset because health fails.

## Atomic admission across asynchronous persistence

Current requestWorkspaceSelection increments workspaceAdmissionSequence, asks closeFileEditor, and synchronously closes the file plus advances selectEpoch after isCurrent. file-workbench FileEditorCommitBoundary is synchronous; it has no reservation while a later settings.save awaits native persistence. FileEditorPane's updateDraft freely advances draftRevision. Thus neither 'admit then persist' nor 'persist then ask admission' is correct: the former can discard/close before failure, the latter can persist B while Cancel retains A. An extra post-await epoch check cannot undo the durable preference fact.

Extend the existing admission owner with an explicit prepare/reserve/commit-or-release lifecycle, not another dirty buffer or URL store. The exact approved file resource/draft and pending workspace departure must remain reserved across the persistence await. The existing component owner must make that short reservation visible and prevent edits, saves and superseding file/workspace navigation from changing the approved resource while persistence is admitted. Before durable write admission, normal cancellation/supersession is allowed. After the write begins, an unmounted settings view may suppress feedback but cannot cancel its required factual activation.

Integrate preparation within the existing settingsSaveTail transaction before its snapshot/native write, or use an equally explicit scoped action in that same queue; do not add a second queue. Never recursively await saveSettings while holding its tail. Approved old-file Save happens against A before B publication. Failure releases the reservation and preserves the existing file/source; Discard becomes effective only with confirmed departure. onConfirmed synchronously commits the reserved file close, one existing workspace selection/directory/workspace epoch transition, clears old projection owners and publishes the confirmed connection fields in a single batch before tail release. Keep A's sole reactive API projection; arrange invalidation synchronously before that effect can dispatch B requests. Subsequent queued preferences must snapshot confirmed B and the new directory-free saved workspace fields. No async health work belongs in onConfirmed. Activation failure remains the existing honest saved-but-not-applied error, never a fabricated persistence rollback.

The reservation is data integrity for an existing file owner, not a Task/Session execution gate. It must cover non-settings navigation entry points while held; a local disabled Save button alone does not close the race. Credential-only or native same-owned-backend transport changes do not require discarding file drafts, but their late reads/saves still require the same authority revision and correct receipt handling.

## One applied authority revision; existing epochs remain resource owners

Add one monotonically increasing applied connection revision at api-state.configure, emitted through the existing auth-change mechanism when URL/credentials actually change. This is the revision of the sole applied authority, not a second URL source. Directory remains under its existing epochs. An operation captures a token once, checks it before follow-on requests and before both success/error publication; direct transport streams capture the same token. Do not attach URL comparison code to each caller or bypass current route construction with hard-coded full URLs (requestTarget currently strips origins).

On explicit workspace departure, advance the existing admission, selection, directory and workspace owners once and clear the retained source/resources as above. Stream closure/retry and loader finally must only settle their own operation. Central HTTP fencing by itself cannot clear retained UI or fix unconditional finally ownership; reset by itself cannot stop a compound operation from starting its next PATCH against B. The solution needs both, without duplicating ownership facts. For preserved same-backend restart/reauthentication, invalidate old transport results and deliberately rebind current source/loaders; keep unsaved content. An already dispatched mutation is not known to have failed merely because the connection changed: do not replay it automatically.

## Horizontal execution audit and qualification limits

All scopes (directory-free/global, selected Project and selected Task/Session/Mission) share this client API state. Backend writers and transaction/project isolation are unchanged; bytes already sent to A are not retargeted by later configure. Serial GET->PATCH, parallel loads, old finally/new request races, ABA, pagination, stream retry and native restart must all be qualified. Identical directory/source IDs on A/B should deliberately be tested because equality-only guards otherwise mask the issue. Normal completion and terminal/idle events from A must not mutate B's projection or start follow-on B requests. This does not establish a scheduler/immutable occurrence bug.

Important existing execution exception: panel/message/stream disconnect creates requestAbort (panel.ts 103,121-130); ControlMessage.handleStream calls terminateOwnedSessionPromptInScope with origin control.message_stream_disconnect (control/message.ts 78-101) and awaits settlement. Current auth-change already closes this POST stream. Preserve and separately qualify this exact control-Session terminal contract; do not claim every execution is unaffected, add a gate, cancel Task/Mission executions or synthesize messages. Ordinary abortChatRequest is local; explicit stopChatRequest carries remote cancellation. No evidence found that B requires changes to backend Task/Mission scheduler recovery/leases/immutable Fire/Run or multi-project isolation.

Required non-UI positive contracts: exact prepare/persist/commit ordering and epochs; Cancel/Save failure/native persistence rejection keep original file/source; edits/navigation during reserved persistence observe the one reservation; queued preferences see committed B; late A success/error/finally/retry and compound config continuation settle as explicit stale/cancelled ownership; healthy->healthy global rows load under B; ABA and same-directory/source IDs; native transport rotation and credential change retain drafts with fresh response ownership. Do not add UI/DOM/source-string tests.

Required real qualification by root after an approved implementation: two owned empty backends and owned files/projects, actual Save transition, dirty Save/Discard/Cancel and delayed durable preference write, held real A metadata/config/list response, explicit B readback and unchanged A/B file bytes as appropriate, healthy->healthy global refresh, normal/terminal selected stream behavior plus separate control POST disconnect, native same-home port restart, reload of the one saved preference document. Genuine UI screenshots and manual review remain required. Public identity, credential/proxy tenant semantics and main draft/quote detachment behavior are unresolved choices; no pure fixture can stand in for those outcomes.
