## Proven identity flow

SessionContext owns the sole ambient Session via Context.create→AsyncLocalStorage.run. Prompt run and SessionWake establish SessionContext.provide; shell continuation also establishes it. SessionObservability is only a low-level read bridge returning `{id}`. It neither owns agent/request/attempt nor proves which caller made a request. The fetch wrapper executes within whichever ambient async scope spawned SDK work, so it can read that ambient Session ID when present. Detached Project memory organization runs under Project/background owner and passes an explicit organizer sessionID to LLM.stream; there is no source-proven SessionContext.provide around that helper. Its ambient Session may be absent or differ from explicit request Session. Therefore ambient ID is safe only as `ambient_session` diagnostic with explicit unknown meaning, not as authoritative request origin.

LLM.stream input owns real sessionID, agentID, user.id or real requestID, model and small flag. It resolves config and invokes applyRequestHooks once BEFORE streamText. PhysicalProviderRequest includes Session/request/agent/model/provider/message; physical internal hooks receive this even for tool-free helpers, while user-message hooks are skipped when there is no user. Despite its name, this physical hook is at logical LLM invocation preparation, not a callback at every SDK model.doStream or global fetch. It has no activity attempt/SDK step ordinal/stream finish and no closure return around subsequent provider execution.

Plugin.applyPhysicalProviderHooks simply awaits internal hook functions then returns params/headers. AsyncLocalStorage.run inside such a hook covers only hook-created async work; it does not wrap the later LLM.stream SDK call in the caller's resumed continuation. enterWith or assigning a global latest origin would instead contaminate sibling/concurrent work. Neither can accurately bind source-owned physical fetch identity.

ProviderLLM.wrapModel already owns one actual LanguageModelV3 middleware. Its wrapStream receives doStream/params, awaits the real call, then passes its original stream through existing local Tool normalization. This is the true existing boundary for each SDK model stream step. It currently receives only language/model/options, without LLM Session/request/agent/activity context. SDK lazy producer work may begin after streamText returns, so merely wrapping streamText invocation in a short-lived lexical variable is insufficient. AsyncLocalStorage.run can carry a closure through async descendants IF placed around actual doStream and validated; no current provider-origin scope exists there.

OpenAI custom fetch eventually calls global fetch after resolving access/headers/url. Current audit intercepts that physical call. Existing Session metadata/context can survive descendants, but no actual full origin object is installed. No origin is extracted from credentials/url. OpenAI path does not receive the special x-opencorvus Session/request headers unless providerID starts with opencorvus; vendor sticky Session headers are not agent/attempt identity. Do not add an audit header to compensate.

withLLMActivity owns actual activityID and attempt; run.attempt is passed explicitly into processor/collectLLMText start callback. It does not publish those as AsyncLocalStorage. Context supplied to activity has Session/provider/model, not actual agent/request. Existing activity event sink publishes started/heartbeat/terminal with activityID and true attempts but is not keyed to a physical fetch. Processor has run.attempt, while title/memory helper start callbacks likewise have it; LLM.stream currently receives their signal but not attempt/activityID. Using retries count or request array position as attempt would be false.

AgentTrace.recordLLMRequest receives explicit Session/parent/Task/agent/requestMessageID/small/model/tools at LLM.stream entry, validates ambient Session consistency, and writes canonical trace events. It is auto-enabled unless opt-out (the earlier diagnosis's generic conditional statement is refined: isEnabled depends on this opt-out, not default-off). It retains no physical fetch ID/SDK step/activity attempt. AgentTrace termination records real agent/turn outcomes, not HTTP stream completion for each request. Importing/reading trace files to guess association is excluded. UsageLedger onStepFinish records model/purpose/session/agent through explicit usageAttribution; it is a post-SDK-step receipt and separate fact, not available to global fetch by default.

## One audit record source, ceiling and blocked attempt contract

Current requests array records admitted attempts only; requests.length is the ceiling source. Blocked attempt sets exhausted but records no entry. Adding a second independent attempts counter or duplicated physical record store is forbidden. Recommended schema replacement is one canonical discriminated observation sequence in the existing audit: model request records with admission `sent` or `budget_blocked`, copied exact origin state, observed model/stream/declarations, sent HTTP outcome optional. The cumulative ceiling derives from count(admission=sent) in that SAME sequence. No additional mutable counter. Blocked is never assigned an upstream status or stream finish. Preserve every attempted refusal, rather than overwrite a single last blocked record or invent a retry.

This changes current audit API expectations. All existing audit.requests.length/slice/status users in preflight/real-checker scripts/native publisher/tests must be searched and adapted to the one canonical observation source; derived readonly sent projection/count is allowed, a retained legacy independently mutable array is not. Do not merely append blocked into current requests while leaving length as ceiling/actual-request count: that falsifies reported admissions and future counts. Existing published snapshots need an explicit current schema/version and corrected consumers, no compatibility double-write.

Alternative narrower admission may retain requests array and add a bounded last-blocked scalar only if Root explicitly wants last refusal rather than all attempts; it would lose repeated history and is not the recommended full contract. Do not claim complete attempted topology from that choice.

## Stream outcome: exact attainable evidence

fetch resolves at response headers, so status200 is not finish. At existing middleware stream boundary one can observe actual SDK model stream finish/error/cancel, while wrapping/passing original parts unchanged. Keep this outcome distinct from host Tool/usage/persistence/assistant final completion. A model stream finish callback and actual scalar SDK step origin can be recorded in the same audit observation lifecycle only with proved identity to its originating doStream/physical record.

Do not consume/tee full response bodies at audit fetch just to parse private output. A transparent stream wrapper at the existing canonical model boundary can inspect discriminated finish/error tags without saving text/reasoning/Tool args. Cancel/drain lifetime must preserve backpressure, abort reason and physical settlement; it needs positive tests before admission. A doStream may make multiple fetches internally (vendor retry/redirect/auth behavior); origin scope identifies their participant/attempt but doesn't by itself define which physical response owns the final model finish. In that case record stream outcome once on a logical doStream occurrence and explicitly link all physical children; do not copy one finish onto every status200. A new doStream occurrence identity must be a real invocation label attached by this boundary, not inferred timestamp or another budget counter. Exact multiple-fetch behavior currently unknown for all adapters; no broad claim is allowed.

For smallest next diagnostic run, actual origin on physical and blocked requests can be implemented first, with stream_finish explicitly unavailable; current actual durable assistant/Tool facts remain independent. Do not promise complete stream finish without this extra lifetime work.
