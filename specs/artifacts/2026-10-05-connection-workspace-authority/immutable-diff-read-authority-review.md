## Confirmed root cause and exact limits

apiRequest captures `init.authority ?? captureApiAuthority()` separately per call. It asserts before dispatch, after a transport rejection (retaining actual outcome) and after response. Therefore a connection change DURING one request returns ApiAuthorityChangedError, with before_dispatch/response/transport_failure phase, expected/current revision and original outcome; it does not silently return a successor response. However an operation with several calls that omit authority can accept an earlier A response, then call again under B after A's request finished. One-call correctness does not establish compound-read authority.

ApiAuthority is the existing frozen revision token. configure rotates on connection URL/username/password changes and explicit native renewal also rotates; directory alone deliberately does not. It is not a URL/credential snapshot and must remain this existing primitive. requestTarget honors explicit directory query, while taskScopedPath requires supplied owning directory. Selection retirement belongs to existing workspace/selectEpoch/resource owners, separate from API rotation.

`diff.ts resolveDiff` identifies group/change synchronously, then launches before/after Promise.all. Each side loops 256KiB ranges using apiRequest without authority. Each chunk calls taskOwningDirectory(input.taskID) afresh. That helper reads current Task row/board/selectedSource facts and rejects conflicting directories; it does not retain this operation's entry directory. Thus source confirms compound scope gaps. A directory-only switch may make the old Task unknown (honest error), or a later current projection could provide a different directory for that ID; it is not proven that every ordinary switch actually mixes bytes. Separate servers could have an observation under colliding identities and matching sizes, so successor bytes can pass the current length check. No real reproduction is saved here.

Before and after initial calls execute synchronously to their first await and ordinarily capture the same revision then. Later chunks are independent; one side may finish under A while the other continues under B between calls. Promise.all rejects when one rejects but does not cancel/join the other side; read-only requests may finish physically after the aggregate rejects. No mutation/cleanup or physical cancellation receipt may be inferred. Current resolver checks length/fatal streamed UTF-8 but ignores response x-opencorvus-git-object/object-bytes/Content-Range headers; backend emits exact identity headers. Those ignored checks are a distinct immutable response identity opportunity, not a prerequisite to proving authority drift. Do not add mutable-source hash gates.

`conversation-artifact.ts` captures activeProjectDirectory ONCE at entry and retains it for all 64KiB reads; existing scope test positively proves that directory retention. It omits authority on each chunk, so same connection drift exists. It checks Content-Range continuity, ETag SHA256/mediaType/total stability and byte sizes. These immutable protocol checks are valid, but do not authorize using B when B returns matching metadata/content. It also references mutable locator input through the chain; current callers pass locator objects without modifying them in the inspected path, so actual locator drift is unproven. Do not snapshot URL/credentials or create another artifact cache.

Artifact text currently constructs a fresh fatal TextDecoder per chunk. A UTF-8 character split at the server's 64KiB boundary can fail despite valid combined bytes. This is a distinct source-supported decoding risk, not connection root cause; preserve as a separate future bounded fix/positive byte fixture, not broaden the current authority slice. diff.ts already uses one streamed decoder per side.

## Current caller retirement/error behavior

DiffPreviewPanel captures target/groups/scopeKey through existing Solid resource request; scope changes replace resource selection. resolveDiff has no explicit authority supplied by caller, resource key does not explicitly contain authority revision, and component shows loading/item without a dedicated changed-authority error UI. Connection reset likely retires its props via the existing namespace transition, but no actual late-response page exercise was performed here. Service must reject retired compound reads independent of that projection lifecycle; do not assume createResource proves original authority.

ConversationArtifactInspector uses one active AbortController per resource, aborts previous on replacement/empty/cleanup and deletes current pointer by identity. Existing signal cancellation is legitimate, but no captured API authority appears in the loader. ArtifactResourceDownload has local busy plus an imperative load→downloadBlob→reportError→finally; it does not capture/assert authority after await or scope retirement, and reports every error then clears busy. A load returned under current A may be retired before the caller resumes and downloads/reports in B. Correct compound reader rejects many stale cases but cannot alone prove caller feedback/download continuation ownership. Root should separately admit caller token capture/propagation and existing current guards around these continuation effects. Do not mark old download failed because A's bytes were physically read; retirement is a client projection outcome.

The private error outcome can retain original response/cause; do not flatten ApiAuthorityChangedError into fake HTTP failure, automatically retry on B, or globally suppress independent current transport errors. No service here should capture fresh B authority on catch/finally to publish A's result. Typed retirement checks/current-token guard are existing single primitives.

## Minimal implementation proposal

Use `captureApiAuthority/assertApiAuthorityCurrent` and existing directory owner directly; no new owner/store/helper abstraction needed.

1. In resolveDiff, capture one entry authority and one taskOwningDirectory(group.taskID) before launching both reads. Pass both into readObservedTextSide; use that authority in every apiRequest, and captured directory in every taskScopedPath. Assert entry authority before returning composed before/after (covers asynchronous continuation and zero-byte/null sides). Keep per-request phase/outcome handling and existing real error contracts. Inline-body resolveDiff returns no network work; whether caller needs authority for its UI projection remains its existing resource owner, not a server reader exception.
2. In loadConversationArtifactContent, capture one entry authority alongside current directory; pass it through readChunk and each apiRequest; assert current before each final return. Preserve its existing signal/range/ETag/body behavior. An optional supplied authority is warranted only if existing callers need to extend entry across modal/download; default captures once at this operation entry, never per chunk. No fallback fresh capture during the chain.
3. For imperative ArtifactResourceDownload, Root may admit capturing one token at click, supplying it to loader and guarding download/error/finally against that same current token using existing scope lifetime. Inspector/DiffPreview projection retirement requires actual owner/key audit and Root real page qualification before claiming current UI feedback. Do not add a disclosure generation just for this service fix or assume API authority detects same-connection selected-project retirement.

Smallest service slice files: services/diff.ts and services/conversation-artifact.ts, existing pure data test files diff-resolution.test.ts/conversation-artifact-scope.test.ts. No api-state/transport/backend classifier change needed. Caller continuation slice, if admitted, additionally ArtifactResourceDownload.tsx and any proven missing existing resource-key owner; no component automated tests. Optional backend-header identity checking/UTF-8 artifact fix are separate explicit scope choices, not secretly included.
