## Minimal single-source getter

Prefer an exported read-only snapshot getter adjacent to the existing hasProjectedPart/projectedConversationPartSnapshot accessors (`tree-writer.ts:599–612`). It reads the existing Map and returns only facts needed by the reducer: id, actual sessionID/agent identity, actual acceptedInputMessageIDs, role, orderKey, created time and explicit completed/finish/error state. Scope lookup must match actual Session and current canonical projected message membership, not parent-derived occurrence or selected display directory. Missing/malformed facts return explicit unknown qualification data. A missing accepted field is distinct from a valid empty array; error absence must be represented from the actual message projection, not guessed from card status.

Use a snapshot-list getter for the involved Session/message set so the reducer can see relevant intervening Read/normal boundary messages, not only messages that carry file changes. Copy the selected scalars and accepted-ID arrays on each derivation; do not return mutable MessageInfo or the Map, and do not retain these copies in another owner. Snapshot allocation is transient input, not a second message store. Project the newly required facts into the **existing Map entries** in both existing adapters using one normalization function if that extraction is truly duplicated. No part.metadata enhancement is legitimate: Tool metadata remains the actual Tool receipt.

At the currentConversationAgentChangeGroups boundary, read `publishedCardTreeVersion()` before deriving roots plus the getter snapshot. Pass that explicit snapshot into the pure collector/reducer. This gives the normal UI memo/resource an existing reactive dependency even for metadata-only updates, while the pure reducer consumes ordinary input without global state. Alternatively the public getter can itself read the token, but use exactly one documented subscription boundary; the preferred collector-boundary read makes pure contracts and reactive ownership clearer. No new revision signal/generation/event bus is needed. Derivation may recompute more often because publication is conversation-wide; existing coalescing limits that work, and correctness does not justify a new cache.

The token is a publication notification, not immutable snapshot isolation: nested reactive card reads may cause an earlier recomputation within a batch. Conservatively incomplete while facts/Parts are incomplete is correct; the final existing publication must recompute the complete projection. Do not make the getter publish or settle frames as a side effect. Explicit nonreactive callers obtain a current snapshot when called and cannot claim a subscription. Async resolveDiff continues using its existing structured endpoint/evidence revision key; visibleVersion drives derivation but does not replace exact selected-source resolution identity.

## Lifecycle and module edge

Session/card filters must never expose detached old messages as current selected-source evidence.
