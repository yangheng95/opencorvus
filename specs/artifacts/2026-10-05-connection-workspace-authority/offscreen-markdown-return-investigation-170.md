## Cache facts and limits

services/markdown-render.ts owns one module worker and owner-specific subscriber/inFlight/latest queued request. Each new model receives a new owner; dispose removes its subscriber and sends dispose to the worker. When no subscriber remains, the worker terminates and its cache is lost. No accepted document cache exists on the main-thread renderer interface.

services/markdown-render.worker.ts has one bounded512-entry token HTML cache. Key includes locale, actual copyLabel/copyIcon and lexer-wide reference links, plus token.raw. A new owner may reuse token HTML if that worker still lives and entries remain; it still lexes the full document, schedules worker messages and mounts accepted blocks on frames. The cache accelerates rendering, not presentation continuity. Eviction and worker termination are legitimate misses. Streaming excludes the last visible token as a raw active tail, so streaming mode is part of any accepted document-result qualification.

utils/markdown.ts also contains renderMarkdown's bounded synchronous whole-document cache, used by ArchitectPanel, InteractionCard, dialog, ExpertSquadPanel and ReleaseNotesPanel. Transcript worker uses lexMarkdown/renderMarkdownToken instead; switching transcript to this clipped synchronous path would change full-text/off-thread/error contracts and create a parallel rendering route. It is not a suitable ready-made fix. No new cache or alternate parser is admitted here.

Potential root-level direction, ONLY if actual return pixels prove the problem: retain accepted render artifacts through the existing single renderer authority, with exact actual render inputs, bounded ownership and explicit cache miss/error behavior. Reusing worker token cache alone cannot remove initial main-thread frame/message waits. Making accepted results available on remount requires an interface/lifetime design, not pretending the worker is synchronous; a separate model cache would duplicate authority. LocaleSeq must qualify same-tag resource updates while copyLabel/icon/reference inputs remain true HTML inputs.
