## Confirmed control-flow root cause

1. disposeEntry creates one Error as entry.lifecycle.signal.reason, aborts that existing owner, stops timers and waits for starting/active task Promises to physically unwind. Same-ID runs are serialized through activeByTask/starting and coalesced demand; aborted entries cannot start a successor.
2. The active message poll executes settledWork with its same signal and configured concurrency. Every worker checks signal.throwIfAborted before/after iterator.next. schedulerDiscovery also rejects its wait with input.signal.reason. An async generator is shared by concurrent workers, so multiple slots may independently reject with the same exact owner cancellation reason while discovery unwinds.
3. settledWork deliberately awaits all workers with Promise.allSettled, returns the iterator, then gathers worker rejection reasons. One fault is rethrown unchanged; more than one becomes a new AggregateError, even when all faults are the identical signal.reason. Concurrency thus changes the public cancellation identity.
4. Scheduler.run's catch recognizes expected cancellation only when signal.aborted AND error===signal.reason. The new AggregateError fails that exact test, so the expected lifecycle abort is classified as run failed.
5. pollSchedulerMessageDeliveries contains a post-await if(signal.aborted) throw signal.reason. It cannot repair this path: settledWork has already rejected before that line. Directly matching shutdown text would be wrong; the exact reason identity originates from the real lifecycle owner.

Serialized log cannot itself retain JavaScript object identity, but source throwIfAborted/abort reason plus the four exact originating stacks account for the actual aggregate without inventing a transport or model failure. There is no logged independent work/DB failure among these four leaves. This exact error is confirmed expected-cancellation misclassification in shared discovery aggregation. Normal shutdown completion does not make that logging defect acceptable, nor prove broader pending-delivery safety.

Old path had already fixed physical unwind: Promise.allSettled keeps Project scope alive; scheduler has admission fencing/physical-idle timeout and exact direct cancellation filtering. These mechanisms prevent early owner release but fail to retain identity when parallel discovery duplicates the reason.
