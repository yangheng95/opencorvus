## Primary evidence

[Official GHSA-6qxp-vccf-f47h](https://github.com/modelcontextprotocol/typescript-sdk/security/advisories/GHSA-6qxp-vccf-f47h) lists SDK >=1.12.0,<1.31.0 as affected and1.31.0 as patched. The advisory says custom providers must persist issuer on tokens/client information; pre-registered clients must return their actual issuer. Previously saved credentials lacking issuer need explicit migration from trusted provenance or clearing/re-authorization. This task has no such provenance and must not guess it from an MCP resource URL. Upgrade alone is insufficient. Stdio servers are outside this OAuth client issue; no assertion is made about prior exposure or real credential compromise.

[Official1.31.0 auth source](https://raw.githubusercontent.com/modelcontextprotocol/typescript-sdk/1.31.0/src/client/auth.ts): OAuthClientProvider uses OAuthClientInformationMixed; save/read must retain issuer. discardIfIssuerMismatch excludes bound credentials for another issuer, but accepts legacy unstamped values. auth stamps registration/exchange/refresh outputs. Dynamic mismatches may re-register; configured non-registerable mismatches throw a generic Error. There is no exported IssuerMismatchError. Connection-mode project guards may produce UnauthorizedError when the SDK requests registration. Tests must reflect these real branches rather than invent an SDK error class.

## Current root and impact

McpAuth.Tokens and ClientInfo schemas omit issuer. Provider saveClientInformation and saveTokens explicitly map fields without issuer; reads likewise return only SDK ID/secret/token fields. Merely adding a field to one schema leaves the other conversions losing provenance. credentialIdentity currently binds resource server URL plus configured client/secret/scope, not authorization-server issuer. These are distinct authorities.

Pre-registered configuration has no issuer field in the existing strict mcp.oauth schema. Provider clientInformation prioritizes configured clientId/secret, so stored token binding alone cannot protect that configured secret. Production constructors occur in index.ts connection (~3264), begin authorization (~4424) and durable finish (~5294); credential identity creation/parsing/recovery must propagate the same added configuration field. Both remote HTTP transport families reuse the provider. Static non-OAuth credentials and stdio are different contracts and should remain outside this patch.

Auth updateTokens preserves token-bound client snapshots and compares expected refresh inputs under the shared JSON fact lock. Issuer must participate in those existing schema/value comparisons, snapshots, rollback/uncertain-commit verification and callback credential identity. No new issuer cache, lease, provider map or parallel refresh owner is justified. Same revision alone is insufficient when a newer callback replaced the actual credential set.

## Minimal proposed contract

1. Upgrade the single SDK dependency/lock resolution through Root's separately admitted dependency work; inspect current patched types before edits. Do not backport an independent OAuth parser.

Require new credential writes to carry valid explicit issuer; old optional reads exist only to diagnose and retire legacy material, never to pass it to SDK first-use stamping.
3. Connection use of legacy unbound token/client material must return a clear typed re-authorization-required result/error through the existing OAuth lifecycle. Retire only the exact captured credential snapshot with current revision, preserving newer callback state. Authorization mode must perform a new actual registration/sign-in rather than reusing unbound saved client secrets. Do not auto-bind to current discovery or resource URL.
4. Add explicit issuer in the existing mcp.oauth configuration for pre-registered clientId/secret, with a positive typed configuration error when required binding is absent. Include it in credentialIdentity serialization/parsing and every configuration projection. No separate expected-issuer setting. Return it in clientInformation; let patched SDK validate discovered issuer. Preserve native SDK mismatch error unless a deliberate project-owned typed boundary is separately admitted; no keyword error classification.
5. Keep callback state/verifier/single-use, broker binding, finishing lease, flow revision and accepted/uncertain receipts unchanged. Changing issuer is a material credential configuration change and must use current revision retirement, not silently rebind existing credentials.
