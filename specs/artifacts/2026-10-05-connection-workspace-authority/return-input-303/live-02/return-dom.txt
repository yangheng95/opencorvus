        - heading "3. ResizeObserver 观察的是尺寸，不是正文内容" [level=2]
        - paragraph:
          - strong: 文档事实
          - text: ：文档 A 的定义是报告元素内容盒或边框盒的尺寸变化，也可以报告 SVG 元素包围盒的变化。内容盒不包含内边距和边框，边框盒则包含这些部分。这一对象边界很重要：观察结果描述的是指定元素的尺寸，而不是文本含义、网络传输阶段或者消息生成状态。
        - paragraph:
          - strong: 设计建议
          - text: ：流式正文不断增加时，可以观察承载正文的内容区域，以获知尺寸变化的结果。但不能将一次观察通知理解为“一段文字已经完整生成”，也不能将没有通知理解为“没有新内容”。如果观察的是固定高度的滚动容器，其内部文字增加未必改变容器自身盒子；因此应先明确观察目标，再决定它能支持什么判断。
        - heading "4. 流式更新与布局通知不是一一对应关系" [level=2]
        - paragraph:
          - strong: 文档事实
          - text: ：文档 A 的示例通过滑块改变容器宽度，再按照观察到的尺寸调整字体。正文特别说明，元素尺寸变化可以与视口变化无关。该示例说明观察器能够响应元素局部变化，但没有承诺每个字符、每个传输片段或每个语义段落都会对应一次独立回调。
        - paragraph:
          - strong: 设计建议
          - text: ：应把“收到正文片段”和“布局出现尺寸变化”作为不同事件处理。文字可能先填满现有行再换行，也可能在同一高度内替换内容；这些场景说明尺寸信号不足以承担内容状态判断。产品可用正文更新记录表达生成进度，用尺寸观察表达布局结果，避免以回调次数估算生成速度或完成程度。
        - heading "5. 用户上翻不能由尺寸变化推断" [level=2]
        - paragraph:
          - strong: 文档事实
          - text: ：文档 A 列出的能力是开始观察指定元素、停止观察某个元素，以及断开全部观察目标。其定义和示例都没有把尺寸通知描述为滚动事件或用户意图事件。因此，ResizeObserver 不是滚动意图检测机制；它也没有说明如何判断用户正在阅读历史消息、拖动滚动条或准备返回底部。
        - paragraph:
          - strong: 设计建议
          - text: ：可将界面分为“追随最新内容”和“阅读历史内容”两种状态，并由独立的用户操作与位置判断决定切换。用户上翻后，正文即使继续变高，也不应仅因观察通知而把视口拉回底部。提供明确的“返回最新”操作，是让用户重新表达追随意愿的方案；具体阈值和恢复规则则需要产品自行定义。
        - heading "6. 保持阅读位置不等于保持一个固定数字" [level=2]
        - paragraph:
          - strong: 文档事实
          - text: ：文档 A 提供尺寸变化信号，但正文没有给出完整的滚动位置保持算法，也没有承诺保存某个滚动偏移量即可保持同一阅读内容。尺寸观察本身不标识用户正看的句子，更不解释变化发生在阅读点之前还是之后。因此，它只能是位置维护的输入之一，而不是完整解决方案。
        - paragraph:
          - strong: 设计建议
          - text: ：对正在上翻核对来源的用户，优先考虑保留“哪条消息、哪个段落及其附近位置”，而不只是记录一个像素数。如果阅读点之前的内容展开，原偏移量可能仍然有效却对应不同文字
