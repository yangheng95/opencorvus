## Current request topology

Normal SessionLoop resolves model/tools and calls processor.process for a provider turn. Processor invokes LLM.stream→canonical llm/api streamText→AI SDK. It persists Tool result and step finish, then returns continue unless an actual stop/park/handoff/error/compaction disposition applies. SessionLoop reloads durable history/continuation and prepares the next turn. Consequently a model-selected Edit call normally needs one streamed request to select it and a later streamed request consuming its actual result to produce final reply. Completed Edit is not a final assistant reply and cannot be rolled back or called failed mutation because continuation budget ran out.

Ordinary loop processor input supplies no stopWhen. LLM passes input.stopWhen through; installed SDK streamText default is stepCountIs(1) (AI SDK dist line6398). Thus normal one-step SDK request does not secretly promise a final response in the same request after Edit; ordinary tool-result continuation is handled by the existing host loop. Do not diagnose an SDK runaway multi-step loop from these counts. Compaction deliberately supplies its own step conditions; generic streamText callers that explicitly supply stopWhen may legitimately make multiple SDK steps. Tool declaration normalization/repair itself is not proof of an additional model call: repair lives at the canonical wrapper, and actual continuation must be observed.
