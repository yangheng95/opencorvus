## Direct control-flow cause

`packages/opencorvus/script/run-tests.ts:35–46` calls the current host command wrapper once per file. It uses Bun `--timeout=60000 --parallel=1` and inactivityTimeoutMs360000, forwarding stdout/stderr. The outer file loop is sequential. The comment distinguishes Bun expired-entry behavior; the case timeout is not a cancellation/join boundary for the entire file.

`src/shell/command-inactivity.ts:19–20` explicitly says elapsed process time is never a deadline. resetInactivity89–93 clears and replaces the timer; recordOutput102–111 resets it for every nonempty output chunk. There is no operation duration timer. Current failure union is inactivity/spawn/output/exit. Thus a healthy-looking stream of hook failures can keep an irrecoverable test process owned forever. Reclassifying error text as inactivity would be a keyword workaround and is rejected.

A second gap must be addressed in the same logical command owner: the execution wait ends on proc.exited, after which142–148 performs proc.dispose and final settled/output wait. Those final direct awaits are not themselves wrapped by a remaining deadline. A new exit-only Promise.race would leave admission, late child/output settlement, and cleanup outside the bound. Conversely returning immediately on a deadline without joining disposal would publish a false terminal and permit deletion of the owned runtime while children still use it.
