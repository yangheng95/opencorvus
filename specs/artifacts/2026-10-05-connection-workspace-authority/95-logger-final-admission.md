# 95 logger final admission design

## Recall

Root selects one current envelope: Pino owns time/level/message, explicit Log.create service is canonical service, existing SessionObservability owns ambient sessionID/logDomain, and caller tags/extra fields are structured data. This note is read-only design following pushed89; source/tests/checks/SDK/dependencies/runtime/Provider/UI/Git remain untouched. The earlier actual malformed Session log records and unknown chronology remain immutable. No alternative timestamp, clock, reader, cache or identity source is proposed.

## Exact library behavior

[Official Pino10.3.1 API](https://raw.githubusercontent.com/pinojs/pino/v10.3.1/docs/api.md) documents nestedKey for isolating log-method objects, mixin values also being nested, and property-level serializers. [Official child documentation](https://raw.githubusercontent.com/pinojs/pino/v10.3.1/docs/child-loggers.md) explains duplicate binding keys and last-value JSON parsing. Installed lib/tools.js:_asJson corroborates that child bindings remain outside nestedKey; serializers run on original method-object properties before the object fragment is wrapped. Hence merely adding nestedKey while leaving arbitrary ownTags in root.child is incomplete. Mixin cannot move ambient identity outside data. Manually emitting {data:attributes} with nestedKey causes double nesting and moves error/err below serializer matching.

## Caller session identity and precedence

Production .tag search finds one request chain in session/llm.ts:196–200: providerID/modelID/sessionID/small/agent. Its sessionID comes from the actual StreamInput, not from SessionContext lookup. Preserve it as data.sessionID even when no ambient Session exists. Canonical top-level logDomain then truthfully stays non-session and has no ambient sessionID. When ambient exists, top sessionID is that ambient owner; data.sessionID remains the explicit request trace and can expose a real disagreement. Never promote caller tag/extra sessionID to ambient authority or discard it because the two normally match.

All non-service create tags and later .tag values are caller data. Explicit own service remains the one canonical service; extra.service stays data.service. Existing child-tag versus extra priority is preserved inside data: extra wins over same-key caller tags. Ambient identity no longer overwrites caller data; the two authorities occupy separate namespaces. OwnTags containing time/level/message are data. .tag("service",value) is still an explicit service-owner update through current create, not an extra override. Missing explicit service remains absent; no invented default field is needed beyond existing Log.Default usage.

## One preparer and single producer

Add one local pure preparation helper in util/log.ts, conceptually:

`prepareRecord(tags, extra, ambient) -> { bindings: { service?, logDomain, sessionID? }, attributes: Record<string,unknown> }`

It applies the current sanitizeRecord/sanitizeMessage policy, extracts only explicit tag.service, merges remaining safe tags with safe extra, and accepts only the existing ambient snapshot as envelope bindings. No Zod parse or reserved-key exception may escape routine logging inside Session transactions. Do not discard reserved caller values. Preserve serializers error/err by passing prepared attributes directly to Pino's method with nestedKey:"data". User-supplied data property consequently becomes data.data, which is honest subject nesting rather than a second protocol.

Capture SessionObservability.logTags once at emit, before buffering. PendingRecord stores those prepared bindings/attributes/message/level. Drain uses that same prepared record and root.child(bindings), without rereading ambient context or running a different merge algorithm. Normal emission uses the same dispatch shape. Logger generation caching may retain service-only child; attach captured ambient through child for that emission, avoiding a cache keyed by mutable context. Simpler root.child(prepared.bindings) per emitted record also reuses mature child behavior and avoids a new cache. Child bindings contain only trusted service/ambient; no arbitrary caller tags. Clone/tag keep sanitized ownTags under the existing logger closure and route through this preparer. Timers retain their existing Date.now duration calculation/status semantics; those values become data.duration/status, not a second envelope clock. Pending time stays original Pino drain-time semantics, explicitly not source event chronology.

The canonical parsed shape is `{time:string,level:string,message?,service?,logDomain:string,sessionID?,data?:Record<string,unknown>}`. Pino omits nestedKey when its method object has no serializable properties, so data is optional for a genuine no-subject record. Missing data is empty subject, not a flat-data fallback. Reserved names inside data are legitimate subjects. Current redaction remains in front of Pino and no raw APICallError is introduced.

Existing arbitrary objects/getters/serializer I/O errors are separate runtime risks; ordinary reserved fields must not introduce a new throw or alter the producer's original result.
