# 支持工单处理时长复核报告

## 数据来源与统计口径

数据来源为当前项目的 `support-tickets.csv`，包含 T101 至 T108 共 8 条虚构工单。根据 `README.md`，priority 越小优先级越高，minutes 为处理时长。本报告仅按输入给定的 priority 和 minutes 统计，不推断工单状态、等待时长或服务级别达标情况。

## 处理优先建议

按给定 priority，建议依次优先处理 P1、P2、P3。P1 包括 T101、T103、T107；P2 包括 T102、T105、T108；P3 包括 T104、T106。同级工单的数据不足以确定进一步的处理顺序；处理时长不代表紧急程度，也不据此推断哪些工单尚待处理。

## 实际复核过程

1. 实际读取 `README.md` 与原始 CSV，确认统计口径和全部 8 条输入记录。
2. 逐项加总：P1 为 45 + 90 + 35 = 170 分钟；P2 为 30 + 60 + 25 = 115 分钟；P3 为 15 + 20 = 35 分钟。工单数为 3 + 3 + 2 = 8，分钟数为 170 + 115 + 35 = 320。
3. 使用 Python 标准库独立解析原始 CSV，重新计算分组数量与分钟合计，结果与逐项加总一致；同时确认工单编号无重复、priority 仅为 P1/P2/P3、分钟数均为非负整数。
