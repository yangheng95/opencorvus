## Standards and root-cause assessment

- [CSS Positioned Layout: containing blocks](https://www.w3.org/TR/css-position-3/#def-cb): an absolute box uses the nearest ancestor establishing an absolute-position containing block; relative positioning establishes that context without moving the box when offsets are auto.
- [CSS Grid: absolute children](https://www.w3.org/TR/css-grid-2/#static-position): an absolute child is out of grid flow; its auto static position is based on the grid's content box. Grid alone is not the required local positioning context. With a relative grid parent, its default absolute containing block is the grid padding box.
- [CSS Overflow](https://www.w3.org/TR/css-overflow-3/#valdef-overflow-hidden): hidden overflow is still programmatically scrollable. It is not equivalent to clip.
- [CSS2 overflow and clipping](https://www.w3.org/TR/CSS2/visufx.html#overflow): intermediate overflow ancestors between an absolute box and its containing block do not necessarily clip that box.
- [HTML focus API](https://html.spec.whatwg.org/multipage/interaction.html#focus-management-apis): ordinary focus scrolls its target into view unless preventScroll is requested. This supports the installed Checkbox's explicit focus path. Native radio focus behavior is observed directly in Root's actual ArrowDown sequence, not inferred solely from the scripted focus API.

The **proven local defect** is that a focusable, absolutely positioned hidden input lacks a local option containing block and its real geometry is detached from its visible Control. The strongest current explanation for the whole-Side movement is: Input remains positioned in the outer TabPanel coordinate system while the visible option is scrolled in the inner transcript; native focus makes the outer hidden-overflow panel scroll to that input. This also accounts for header and composer displacement. The exact outer scroll mutation remains pending the fresh pre/post chain, so do not claim it already measured.

The missing local position is not introduced by U2's aria-label lines. `git show HEAD:.../card.css` shows the old inline option had no position either; the old Dialog grid also lacked a local position. `65d0bfc98` already has the same absolute native-input primitive with no positioned root, and `36753fcea` changes only border colors there. U1 lifts the existing Dialog grid into the shared option and changes wrapping/height; this can expose existing coordinate ownership more visibly. There is no actual pre-U1 native-arrow Side geometry baseline, so “pre-existing symptom” versus “newly exposed by layout change” remains unproved.

## Smallest implementation candidate, awaiting Root evidence/approval

Add only `position: relative` to the existing `.interaction-card__option` rule in **already-owned `styles/surfaces/card.css`**. This gives both the direct Radio input and Kobalte Checkbox input a containing block inside the correct inner scroll owner. It preserves the same native control, registration, short name, original description, state, reply, dimensions and grid flow.

Do not initially add inset coordinates: the absolute grid child already has a defined auto static position and the parent is align-items:start. The one declaration addresses coordinate ownership without introducing new geometry values. Root must inspect the actual post-change Input/Control pair; if it remains displaced, analyze that measured result before adding offsets. No change to RadioGroup, Checkbox, selection-control.css, SideChatPanel, DOM scroll controller or outer overflow is required by the currently established defect.

Avoid changing outer overflow to clip, intercepting ArrowDown, forcing scrollTop back, adding focus preventScroll globally, moving focus to the visible span, or a focus timer. Those would mask the misplaced input or alter native keyboard/accessibility behavior. Correct focus should still reveal a genuinely offscreen option **inside the transcript**, while leaving Side chrome at its original position.
