# 内部主张—证据矩阵说明

机器权威为 [`claim-evidence-matrix.json`](claim-evidence-matrix.json)。状态只允许“已实现 / 部分实现 / 规划中 / 概念设计”，引用性只允许“可直接引用 / 仅线索 / 需外部或用户权威”。

## 可直接引用的内部事实

- Task 是唯一业务生命周期所有者；Goal 是不可变 Delivery Slice contract，不是执行实例。
- Task 创建固定 Expert Squad package revision，Artifact 使用不可变 locator、完整读取和显式选择。
- 默认 embedded Expert Squad 恰为 `base`、`advanced`、`research-studio`、`squad-sdk` 四个。
- 七角色运行真实交付报告并存在 566,808 ms analyst 重叠；同一记录也证明 fact checker 和 writer 越过 synthesizer terminal predecessor。因此它是“表面交付成功、过程依赖失败”反例。

## 只能作线索

- AutomationBench 的 `100 / 8.07% / 34.00%` 当前仅有网站 typed 常量、用户更正来源和正向算术测试。它可证明页面展示一致，不可证明实验复现或统计显著性。

## 仍需权威

- AutomationBench immutable version、100 个 case、评价协议、逐 case 结果、重复运行和统计。
- 30+ Expert Squad 的正式 mission-oriented taxonomy、权限、覆盖与当前四个默认团映射；116 个作者源不能替代该设计。
- 自进化效果量：当前有机制原语，但 projection test 漂移且没有重复 accepted campaign。

## 关键矛盾处理

声明 DAG 持久存在，但 Host 不自动准入 frontier；七角色历史运行证明 Orchestrator 可越序而仍完成 Task。因此“Completion Decision 存在”只证明接受闭包，不证明依赖顺序正确。机制与效果始终分别分级。
