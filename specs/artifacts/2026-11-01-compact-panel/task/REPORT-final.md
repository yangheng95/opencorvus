# 销售结算修复报告

## 结算口径

- 输入为原始 `orders.csv`，使用 Python 标准库 `csv` 读取。
- 对 `status` 去除两侧空白后，仅计入 `paid` 和 `refunded`，忽略 `cancelled`。不改变状态大小写，也不改写原始文件。
- 逐笔由金额原始字符串构造 `Decimal` 并累加，不经由二进制浮点数。
- 退款金额已经为负数，直接相加，不再次取负。
- 按 `(team, currency)` 独立分组，不跨币种求和。JSON 分组键为 `team/currency`，金额为固定两位小数的字符串。
- `summary.csv` 列为 `team,currency,net_amount`，按 team、currency 升序排列。CSV 本身没有数值类型，金额字段文本保留两位小数。
- 执行入口为 `python sales_summary.py orders.csv`：标准输出为 JSON，同时在当前工作目录写入或覆盖 `summary.csv`。

## 修复点

1. 以 `Decimal` 替换 `float`，消除原程序出现的 `30.299999999999997` 等浮点尾差。
2. 状态先执行 `strip()`，使 A09 的 ` paid ` 正确计入。
3. 纳入 `refunded`，使 A03 的 -5.05 和 A08 的 -1.25 正确参与结算。
4. 内部以 team、currency 二元组分组，修复仅按 team 汇总导致的混币问题。
5. 排序并统一输出两位小数字符串；增加 CSV 写出，保留 JSON 命令接口。
6. 增加 `test_sales_summary.py`，用标准库 `unittest`、`subprocess` 和项目内临时输入验证真实命令入口及其 JSON、CSV 产物。临时目录在测试结束后自动删除。

## 原数据与支持边界

- 原数据共 10 笔：7 笔 paid（含 1 笔两侧带空白）、2 笔 refunded、1 笔 cancelled；实际计入 9 笔。
- A05 的 999.99 完全排除，不影响 South/CNY；A08 为仅含退款的 North/USD 分组，因此允许负结算值。
- 原数据币种只有 CNY 和 USD，所有金额最多两位小数；没有缺列、空金额、非法数字或未知状态。本次没有为这些未定义输入新增业务规则。
- 当前实现对 paid/refunded 之外的状态不计入；缺失必要字段或非法的已计入金额会报错，不默认为零。
- README 未指定超过两位小数金额的逐笔舍入规则；当前原始数据和上述测试不涉及此业务边界，不宣称已验证该场景。最终金额格式统一为两位小数。
- team、currency 不做空白清理或大小写归一化；仅 status 按要求去除两侧空白。
- 本程序是批量汇总，使用固定输出文件名；运行会覆盖当前目录的 `summary.csv`。原始 CSV 仅以只读方式打开。
- 仅使用 Python 标准库，未委派、未创建子任务或额外 agent，未提交或推送。
