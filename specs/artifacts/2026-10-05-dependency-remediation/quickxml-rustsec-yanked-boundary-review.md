## Source mechanism and strongest explanation

Installed cargo-audit0.22.2 config.rs:322–337 defaults YankedConfig enabled=true/update_index=true. auditor.rs:126–156 calls CachedIndex::fetch when enabled/update/fetch are true. If index initialization fails, it warns only when output is not quiet and stores registry_index=None. config.rs:167–168 treats JSON/SARIF output as quiet even without --quiet. auditor.rs:348 onward then only checks yanks if Some(index); None returns an empty vector. JSON report settings do not serialize whether registry initialization/checking succeeded. Therefore actual JSON exit0 with no yanked category is insufficient proof of complete yanked checking; empty stderr does not exclude that quiet initialization failure.

rustsec0.33 cached_index.rs:85–110 initializes tame_index::IndexUrl::crates_io(None,None,None), an AsyncRemoteSparseIndex and a default reqwest client. populate_cache/find_yanked subsequently performs per-crate remote/cache lookup and emits errors for uncheckable packages, but initialization failure occurs earlier in cargo-audit and can be quiet. It does not directly read Cargo net.offline at this layer. tame-index0.26.3 index/location.rs:59–100 selects protocol from explicit CARGO_REGISTRIES_CRATES_IO_PROTOCOL, public Cargo protocol config, or cargo version detection. utils.rs:261–283 launches CARGO if configured, otherwise PATH cargo -V; nonzero result returns an index initialization error.

Root's recorded environmentNames omit CARGO and CARGO_REGISTRIES_CRATES_IO_PROTOCOL. Fresh owned HOME now contains .rustup/settings.toml with version12 and empty overrides, no default toolchain. This is consistent with PATH resolving a rustup cargo shim, which creates the owned settings file but cannot resolve a default installed toolchain under that fresh HOME. That cargo-version detection failure would produce exactly a quiet registry-index skip. No actual subprocess trace/failure stderr was retained, so this remains a **source-proven quiet-skip risk and candidate cause, not proven actual failure attribution**. PATH executable resolution, same-home lock contention or other initialization failure remains unverified. No cargo -V/process probe was run to fill the gap.

Owned CARGO_HOME config net.offline=true alone is not proven to disable cargo-audit's yank checks: the inspected rustsec remote code uses reqwest directly rather than invoking Cargo for index fetch, and the inspected tame-index protocol code does not read net.offline. The copied cache already contains the known positive yank row. Do not blame offline settings or fresh HOME categorically; the precise missing evidence is successful actual registry-index initialization/coverage.
