## 唯一最小实施建议：entry地址与目标parent的依赖图

### A. 物理 entry 地址（不follow terminal）

定义 `entryAddress(p) = join(await fs.realpath(dirname(p)), basename(p))`。实际operand先经过既有path.join/一般准入/root guard；地址只把真正parent变成实体parent，保终端名。比较key在这之后 **仅** namespace去前缀、trim尾分隔符、Win大小写规范；禁止canonicalPath/normalizeCanonicalPath/Filesystem.normalizePath再次follow整个地址。返回/键不写进Node，不改源/目标字符串或readlink。

source事实是这个address加现lstat的dev/inode/kind。相同inode只是inode事实：hardlink不同parent/name是独立directory entry，不会因搬另一个名字退休。只有访问到了同一个将退休的address且lstat身份一致，才得到依赖witness。另一个alias访问同一个physical(parent)+basename可正确指认同entry；两个独立link到同D不会因为followed target相同被拒。

建议身份读使用成熟lstat `{bigint:true}`，避免64位inode被number舍入。现assertFileMutationPaths私有返回值只有move/copy/remove消费kind，可改其内部lstat/返回为BigIntStats并直接传给move validator；三调用者的isDirectory/isSymbolicLink保持。不要以 `BigInt(number ino)` 恢复已舍入数字，也不要另存一个source身份缓存。若正式选择保现Stats，必须说明实际可安全整数范围，不能宣称通用64位精确。

### B. 只验证将退休source与当前target parent访问链

新增私有 `assertMoveDestinationIndependent({source,target,sourceEntry})`，只move调用；copy不退休source，不走此新guard。放在既有path/root/parent准入、existing-target conflict之后、shared relocation/native rename之前，保原正常一般错误顺序。ordinary file/source不存在/physical root仍由现准入处理；validator不是新的权限root。

从 **raw targetFull的dirname** 开始验证当前访问namespace。对这个namespace的每个完整祖先prefix用lstat：

1. prefix为操作中的真实entry，比较其parent实体地址+终端name及lstat身份。精确等于source退休地址时，抛FileInvalidPathError400（path=newPath，建议message `Destination parent depends on the source entry being moved: ${newPath}`）。source为实体directory时，目的链能到其本体或其后代，必有精确source祖先地址；同规则正确拒绝，不另加ultimate-target equality。

### C. host选择、dot语义与未知项必须公开

Windows当前证明相对link按 **指定访问path中的context** 解释，而同entry的实体浅访问是另一个context。依赖hop应从当前logical prefix的dirname按Windows path分量/dot规则展开readlink；POSIX（Portable Operating System Interface，可移植操作系统接口）相对hop从实际containing parent解释，使用 `fs.realpath(dirname(prefix))` 作为锚点。这是对不同host语义的单一选择，绝不在失败后改用另一坐标、并行读取选一个成功或形成两root配置。

POSIX link文本若含`component-link/..`，不能先用path.resolve整串折掉dot然后再说已观测那些link hops；应保readlink原分量，让原lstat/realpath确认component traversal。Windows指定path的dot替换与POSIX同样的字符串不是同一合同。node:path只分root/dirname/basename/平台separator，不编写NTFS（New Technology File System，Windows文件系统）reparse parser。实现时这段需独立源码review，不能用一个“resolve所有字符串”的general resolver覆盖两者。

有明确证据限制：原case的Windows ancestor为junction/root-back；未实际覆盖“absolute dir symlink祖先再遇带`..`的relative hop”、复杂绝对symlink替换prefix、UNC（Universal Naming Convention，通用命名约定）/卷挂载、POSIX实机、Darwin大小写不敏感volume的entry basename比较。Microsoft公开文档指出absolute symlink替换prefix而relative替换其所在指定path分量，不能据junction一个样本声称所有Windows reparse组合均已实测。正式测试应增加直接host语义正向cases（含independent与dependent），未知标未覆盖；不得以关键词/NTFS tag猜测或纯Ultimate equality代替。Windows casefold仅key；POSIX不能因Win经验lowercase真实名。

source/parent在验证期间已知missing对应现source404或target parent400；保持精确path和当前Parent directory错误，不能missing→independent。EACCES/EIO/ELOOP/未知readlink/realpath原throw；source/hop前后identity变化也不能当成功witness。它是当时metadata验证，不承诺外部并发retarget/change与之后rename之间的原子快照；没有新锁、native parent handle绑定或完整publication原子性授权。

## shared relocation：唯一实体声明目标坐标

这与上面 **当前访问namespace依赖** 是两个被验证对象，不是双源。目的链依赖决定退休source后raw入口能否存活；实体relocation决定发布link本体的原text在自身实体parent下是否仍属于当前权限。rawcontext仍可有另一个合法target，不能据其在A就允许同entry的实体target在B。

保留唯一 `assertRelocatedSymlinkTargetsAllowed` 的lstat/readlink/普通目录遍历、current.file错误路径、两declared targets及现isPathAllowed，替换其词法parent计算：

```text
futureRoot = join(realpath(dirname(targetRoot)), basename(targetRoot))
sourceLinkParent = realpath(dirname(currentSourceEntry))
futureLink = join(futureRoot, relative(sourceRoot, currentSourceEntry))
futureLinkParent = dirname(futureLink)
sourceDeclared = absolute text ? text : resolve(sourceLinkParent, text)
futureDeclared = absolute text ? text : resolve(futureLinkParent, text)
check sourceDeclared via existing isPathAllowed
check futureDeclared via existing isPathAllowed
```

## 权威资料与推导边界

- [Node.js fs 文档](https://nodejs.org/api/fs.html#fspromisesrealpathpath-options)：promise realpath用native语义；lstat检查link本体；BigInt Stats可保inode。它不暴露所有hop，也不证明Windows本文每个样本结果。Node [源文档](https://github.com/nodejs/node/blob/main/doc/api/fs.md?plain=1)给dev/ino/nlink类型，不能裸inode推出entry名退休。
- [Microsoft Creating Symbolic Links](https://learn.microsoft.com/en-us/windows/win32/fileio/creating-symbolic-links)：Windows指定路径的absolute/relative分量替换、dot与junction合成、relative单卷限制。与本轮实际raw/physicalcontext不同相吻合，支持分开访问依赖与实体声明；不承诺所有reparse组合样本已跑。
- [path-scurry官方文档](https://isaacs.github.io/path-scurry/)和[作者源码库](https://github.com/isaacs/path-scurry)：readlink/lstat/realpath读失败返回undefined及缓存语义是排除该库的明确合同，不凭库名字排除。
- Open Group当前pathname章节链接本次浏览403，未取得正文；没有把它写成已核权威内容或用模型记忆填POSIX全部未知。POSIX实现应凭现成熟fs的实际parent原语及正式正向host资格，本文未声称实机跑过。
