# Fixed business and state semantics

events.csv fields row_id,tenant,event_id,order_id,revision,released_at,status,amount,currency. Required identities nonempty; revision is nonnegative whole decimal; released_at canonical valid UTC; currency USD; exact ordinary decimal converts to whole cents. Reject invalid identity/revision/clock/currency/status/amount/amount_grid/missing_payload/cancel_payload with row identity and typed code. missing has empty amount; cancelled has0. No binary floating money or huge-number formatting puzzle.

Journal all admitted immutable rows. Exact repeated normalized row counts once, every first request records received/new_records/rejected/equivalent_repeats. Retrying identical request_id returns its original receipt and no new state change. Different tenants can share event/order IDs. Retain rows and receipts across process exit; do not reset state after lost acknowledgement. A logical schema1 checkpoint contains journal,receipts,rejected,audit and can restore into a fresh state.

Only received rows released<=as_of are currently eligible. For each (tenant,event_id), different semantic payloads (order/revision/release/status/cents, excluding row_id) quarantine every claimed tenant/order as wire_conflict, until separately resolved; this archive has no adjudication. Other rows of affected orders do not silently release. For other joint(tenant,order) keys select highest revision including missing/cancelled. Highest distinct status/cents payloads conflict; same normalized payload repeats give one state with all selected source_ids. active→ready/amount, cancelled→cancelled/0, missing→missing/null, conflict/wire_conflict→null. Held states contribute0, not an invented known demand. Totals are cents by every published tenant. Lower revision late arrivals remain in the journal but do not replace higher revision. Future rows remain in the journal and enter eligibility only when the supplied clock advances.

The six packets: W1 admits first source, W2 SQL query without new rows, W3 admits incremental corrections/repeats and is deliberately terminated after real commit before acknowledgement, then same-key resume, W4 admits late/conflicting/future rows, W5 performs real principal-scoped queries/audit, W6 applies higher corrections and advances clock. Every later stage consumes the actual prior state. A teacher may independently restore the W3 checkpoint before W4.

principal roles come from the packet, not a caller-selected target. tenant role may read only its exact tenant; admin may read all; unknown/cross-tenant returns permission_denied with empty states/totals. Log query_id/principal/requested_tenant/allowed-or-denied. This is a constrained instructional access interface, not a hardened production IAM system. No delete/rewrite of accepted history to make a final total look right.
