# 真实错误控制的局部鉴别

`bad_worker.py`是明确故意错误的可执行对照，不是当前参考、fallback或生产路径。`qualify_counterexamples.py`为每种错误新开自有HTTP/两个SQLite，通过`current-source/check_l05_state.py`读取真实终态；checker以accepted-events的完整tenant分区逐身份/载荷/receipt核对，不将其他独立协议探针算这个分区。

1. `global_event_id`实际用event_id作全局主键，A/E1后把B/E1误当重复；正常HTTP交付剩余A动作后，checker返回exit2/business_mismatch，具体B/E1的local_entry_missing、remote_effect_missing。
2. `early_sent`在真实HTTP请求前提交本地sent，发自有PID/阶段握手后被执行器结束；新进程返回already_sent，接收服务对A/E1实际GET404/unknown。同一checker返回A/E1、A/R1、B/E1三个remote_effect_missing。没有以“未调用函数”或静态关键词验收。

主方两项已真实执行，正确参考同checker返回exit0/business_success；源/命令/库/HTTP和逐身份判定在[主方原件](../qualification/main/README.md)。[单层独立复核](../independent-review/REVIEW.md)已实际另执行两控制并加五个checker错误探针，通过当前范围。换新key、历史修复、lease/epoch/监测等仍未资格，不能把两项当全L05错误覆盖或正式rubric。
