# Delivery schema and human equivalence

1. manifest.json: exact component schema in COMPONENT. history.json: original progress facts with task/start/end/resources/cost/status. paid-ledger.json: original seven payment_id/day/source/amount records. Preserve all facts and types; ordering is free.
2. plans.json: object keyed by all event IDs. Each value {"tasks":[{"task":ID,"mode":approved mode,"start":integer,"end":integer}]}. Mandatory tasks exactly once, F01 zero/once. Do not put historical tasks here.
3. execution.json: per scenario {scenario,errors:[],tasks,cash_ledger,finish,extension_requested,extension_approved,optional_retained,total_cost,history,paid_ledger,checkpoint_cash,component_accepted}. tasks are the submitted tasks plus resources and mode_cost from quotes. cash_ledger has every day12..finish-1: {day,inflow,expense,cash_end,cumulative_cost}. history and paid_ledger retain the original records. All monetary/time/count fields integers, approval/retention/acceptance booleans. errors must reflect real violations if present; self-declaration cannot authorize acceptance. No credit for a feasible plan accompanied by a false ledger or approval claim.
4. schedule.csv columns scenario,task,mode,start,end,resources (semicolon-separated approved resource set); cash-ledger.csv columns scenario,day,inflow,expense,cash_end,cumulative_cost. Full machine accounts, not selected favorable days.
5. A report, readable in Markdown/PDF/HTML or equally clear machine-indexed tables/formulas, with source trace, sunk/conditional money reconciliation, the actual limited acceptance findings, minimum-date proof and feasible witness, F01/budget choices, original vs requested/approved dates, quantified triggering risks/owners/actions and a reproducible operator handover. Correct JSON/formulas can carry the complete argument without duplicating every number in prose. Label assumptions/limitations; no unsupported client approval, payment guarantee or whole-platform acceptance.
6. Real generated schedule and cash graphics, with units, scenarios and interpretable labels, consistent with actual accounts. Alternative clear plots/formats are accepted; include a readable artifact index if names differ. Charts must be rendered and visually assessed, not merely named in a manifest. The reference uses gantt.png, cash.png and REPORT.md; these names for human prose/graphics are examples, not privileged scoring formats.

Feasibility is independent of narrative style. No matching of reference Gantt rows, chosen mode IDs beyond the source mode contract, posting counts or exact solver trajectory. Row order/resource-set order is immaterial. Amounts are small exact whole cost units; do not create artificial fractional precision requirements. Input changes may add task/tenant identities. Update all dependent outputs from raw facts.
