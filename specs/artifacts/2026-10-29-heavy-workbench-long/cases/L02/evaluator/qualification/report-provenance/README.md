# L02 报告实际来源与原输入恢复（局部资格）

本阶段只实现报告来源数据流、prepare-once输入恢复和唯一sealed reader，不是完整case冻结或新的候选研究。完整正式12outer清洁管线、职业研究成品、全grader及人评校准仍待，正式成绩null；套件开发冻结1/10、候选有效小时0/10。

[主方记录](REPORT.md)、[机器结论](assessment.json)及[原始执行与源码](originals.zip)保留真实进程/原ZIP/初源/最终边界。输入是先前baseline1的10个真实numeric accepted对象；没有新forecast/selector。主方新report4.797秒、两次prepare发布边界真实owner退出与恢复6.646秒、captured/native边界6.636秒均只为组件资格。检查数不是独立统计样本数，时间不相加当难度。

`l02_execution.Executor.invoke`只在原prepared尚不存在时调用唯一factory；已有prepared或verified继续原输入。原表/phase/registration/results格式不变，schema1与原数据保留，无双协议兼容执行器。发布前退出恢复消费second，发布后退出恢复消费first，实际都一次create/start/rm；旧verified report只在复制目录恢复，原对象不变、未提供新来源的事实保持`not_delivered`。

`l02_pipeline`是执行与只读审计共用的唯一矩阵组装；实际捕获的forecast packet/method、selector inner事实/预测按权威分配与唯一发布时间投影/SQL核验。`l02_sealed.read_completed`从原SQLite和registration/prepared/accepted重建同一矩阵；私有诊断即使全覆盖也不被标为正式研究。`l02_report`只投影原numeric output、逻辑身份和收窄native事实，不给报告私有grader/权重/外部参照、原inspect/env/host路径。

新的作者reporter消费原fit/诊断，输出36行拟合来源、逐节点/逐origin损失、168行动账、相对路径来源副本及实际六panel图。候选方法/语言自由，不要求它们输出作者的fit格式，来源文件也不证明声明真实。主第一次组件报告笼统称全部programme预测前冻结，超过“新reporter消费历史numeric”的证据范围；初源/报告保留，当前文本改为陈述合同并要求独立registration审计。当前澄清文本的实际独立冷执行与单层审查在[independent-review](independent-review/README.md)单列，不拿旧执行冒称新源已运行。
