# 精确情景采购求解器

只需 Python 3 标准库，在项目目录运行：

```text
python solve.py --input inputs/base.json --output results/base
python solve.py --input inputs/price-change.json --output results/price-change
```

输出目录必须不存在；重复运行时换一个新目录。程序仅读取指定输入，不读取任何旧结果。每次生成完整 `plan.json` 和 `summary.json`，金额均为模拟整数最小单位，预期成本用精确分数表示。采购单价按原料件数计算，而非按包装数计算。

## 共同承诺与时序

在 `common_weeks` 内，枚举同一个下单、装运及生产动作，并同时推进全部场景状态；只要任一场景不可行就排除该动作。场景揭示后，从各自已经承诺的库存、在途和现金状态出发分别优化，不能回改共同阶段。

每周先把本周新单加入到货表，再接收本周到货，检查原料到货后/生产前峰值；随后按 BOM 生产，检查成品生产后/交付前峰值，再扣除需求、计期末持有费。零提前期订单当周可用；超出期末的正订单不进入枚举。现金只包含当周实际收到的销售款，扣除全部当周费用，每个场景分别受信用和末周非负约束。未收销售款另列应收，不抵扣目标成本。

## 最优性依据

这是针对微型实例的有限精确穷举，使用记忆化减少重复计算，不依赖启发式或浮点数。每供应商每种原料的包装枚举上界为共享供应体积容量除以该包装体积；枚举其全部联合向量，并检查供应商共享体积和最小装运体积。二元装运变量也完整枚举，包含最小装运量为零时的空车可能性。

每条产线每产品的枚举上界由工时容量、资格和剩余总需求共同确定，随后检查共享工时和全线合计产量。禁止超出剩余需求的生产不损失可行策略，因为禁止处置且期末成品必须为零。搜索状态包含原料、成品、按到货周记录的在途和现金；现金不作期望化。

共同阶段选择使概率加权总费用最小的共享路径，揭示后每个场景求最小后续成本。所有可能的合法整数决策都在上述有限枚举内；状态转移剔除不满足需求、阶段峰值、库存或现金条件的路径。递归取最小值，因此返回全局最小预期运营成本（概率使用 `Fraction`）。摘要对选中策略逐周重新推进并累计费用，而不读取旧输出。

支持输入中的多供应商、多原料、多产线和多产品数组。有限枚举要求包装件数、原料体积、生产工时为正；公开实例满足此条件。大实例的枚举可能较慢，不宣称大规模求解性能。
