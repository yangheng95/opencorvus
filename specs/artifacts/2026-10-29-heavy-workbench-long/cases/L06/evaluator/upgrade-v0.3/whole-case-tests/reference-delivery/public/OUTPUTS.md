# Execution and output wire contract (development draft)

Input actor packet format l06-current-operation/1 contains week, complete committed event/action/receipt records, history including the current complete event, authoritative post_week_state and decision_view. Events carry demand/supplier_capacity_volume/plant_capacity_hours. No actual future/path identifier is included. Public possible support paths remain available. Random actor execution must use a fixed declared seed so complete same-information action comparisons are meaningful; randomized tie handling is allowed if evaluated under the same internal randomness.

One actor line is {"format":"l06-action-response/1","request_id":"your stable logical request","action":{"order_lots":[...],"truck_on":[...],"production":[...]}}. Request IDs identify original complete payloads. A replay of the same event/action returns the original receipt; a different payload under an old ID is idempotency_payload_conflict. A new ID cannot repeat a completed week. The host commits the actual event/action/receipt and recomputes all derived state before presenting the next week. A terminated actor can reconstruct from the supplied complete prefix without storing a particular optimizer state.

The committed-journal export format l06-committed-journal/1 contains committed plus derived state/weeks. It is a logical export, not by itself proof of real execution. Actual testing separately captures programme source/native argv/input-output transcript, commit boundary/exit and original receipt recovery. A deliberately invalid action returns a neutral week/business diagnostic, never a hidden actual leaf name. Preserve original failed attempts and completed rows on restart.

Mandatory deliverables: submission.json and all source/dependencies; complete policy.json; source-map and explanation; per-path weekly-ledger.csv; complete commitment-policy.csv; report with actual figures and operational recovery/reproduction instructions. Exact finite decimal numbers or exact rational strings are acceptable for derived monetary values; action tensors use strict JSON integers, never bools. Equivalent complete JSON/tables/closed formulas may carry explanations without duplicating every value in prose. Final frozen schema, perturbations and grading metadata remain pending.

Native submission format l06-online-submission/2 has argv with {python}/{project}/{public} placeholders. Controller receives private event sequence on stdin, never worker argv/env or a future file. Native worker receipts record real PID/argv/start/exit; no container or OS confinement claim. The first executed native journal uses SQLite schema2; earlier draft container-only code created no native database.


## Complete current packet and delivered numeric schemas

All event/action quantities, week/counts/cash/state entries are JSON integers (bool is not an integer). CSV array identities use the raw explicit indices. decision_view is a projection of the original post-week state, not a second checkpoint. A packet has exactly format,week,committed,history,post_week_state,decision_view. post_week_state has format=l06-week-state/1,phase=post_week,next_week,raw[raw],finished[product],cash,total_cost_minor,arrivals_by_week[16][raw],receipts_by_week[16+receipt_lag]. It is state after the last committed week, before current arrivals/receipts. decision_view has week,historical_arrivals[raw],historical_receipts,raw_before_new_orders[raw],finished_before_production[product],cash_after_historical_receipts,external (the current event). history contains every committed event plus current event. Each committed item has request_id,week,event,action,receipt; receipt has request_id,committed_week,next_week,cost_minor,cash_minor. The next packet acknowledges the previous commit. On recovery the supplied prefix/receipt is authoritative.

weekly-ledger.csv has path,week,purchase,freight,production,holding,cost,receipts,cash,raw_peak,finished_peak with exactly one row per path/week. commitment-policy.csv has path,week,kind,entity,item,quantity; kind truck uses supplier ID/item empty; order_lots uses supplier ID/raw ID; production uses plant ID/product ID. Include all coordinates including zeros. All actions remain strict integer tensors in policy.json; these derived monetary CSV values may be exact finite decimal or rational scalars.

summary.json includes expected_cost_exact,alternative_exact,saving_exact,components_exact keyed purchase_cost/freight_cost/production_cost/holding_cost,minimum_cash,information_nodes,full_path_count and the truthful native execution/optimization provenance. Monetary scalars may be JSON integers, finite decimals or exact rational strings; equivalent36718.5 and73437/2 are accepted. No bool/NaN/infinity/zero denominator. receivables.json maps each path ID to final_cash,minimum_cash,final_receivable,due_after_horizon (absolute due-week strings to amounts), including every nonzero post-horizon receivable. Report and figure may use complete equivalent tables/JSON to explain these facts, without duplicating values in prose.
