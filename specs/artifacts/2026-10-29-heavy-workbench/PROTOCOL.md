# 执行、评分与比较协议

## 身份、输入和赛道

本版是 `HeavyWorkBench-10/0.1.0-dev` 公开开发集，题目和答案已公开，不能称作秘密测试集。固定输入为本目录 `inputs/`，不是每轮临时重抽随机数据。原始记录与任务写于 2026-10-29，虚构组织与业务案例采用仓库许可证；方法备忘是作者原创简述，外部来源权利保留给原作者。题集使用 Git 提交身份、固定 case ID 与业务记录核对；源码摘要不作为行为正确性门槛。

正式运行前注册不可变 run manifest：本包 Git revision、十题顺序、每题三次独立 occurrence（执行轮次）、模型实际身份、系统配置、工具、环境镜像、网络政策、预算、种子、重复与错误处理规则。每个 occurrence 都是全新的项目与输出目录。公开开发集用后不能再声称 holdout（保留测试集）；未来新测试资料需要先冻结、独立核验可解性，再公开版本身份。更改输入、口径、rubric、预算或 scorer（评分器）必须形成新版本，旧分数保留版本，不混算。

主赛道离线：材料、方法简述及定位均随包取得；不可访问本仓库评分端、参考计算、历史输出或外部模型。可另设开放检索赛道，但须记录实际访问内容、时间、失败、工具与网络范围，只在相同赛道比较。所有任务明确包含各自资料限制；H01 不要求外部数据收集或真实临床/教育试验，H02 不是对某篇已发表论文的复现，H07 是模拟综述方法练习。

## 执行边界

使用已有 Inspect 或 Harbor 的执行与日志职责，不增加私有调度器。当前离线 CLI 仅定义/导出/检查产物，**没有把本题注册为现有平台的完整 solver 或 task**，不能用本包命令直接宣称一次模型端到端评测。正式运行须建立与现有适配器契约一致的连接并取得以下证据后另行资格验证。

受测环境仅挂载 `prepare` 导出的 TASK.md、task.json、inputs 以及新输出卷。评估侧持有 suite、oracle、参考与评分代码；在不同容器/操作系统身份中运行，受测身份无法读取评估卷、宿主 shell、Provider 凭据或其他 occurrence。本地不同文件夹不是隔离。网络关闭；模型流量由现有 Host 的流式通道处理，受测 shell 不能接触该凭据。启动时用已知公开文件读取成功及受保护测试资源的明确权限错误合同验证边界，记录实际错误码。凭据使用须另获授权，模型目录与凭据预检遵守仓库合同。

模型可自行组织实现与工具使用，不强制固定步骤或专家角色。所有模型交互流式，消息与工具结果保留真实参与者身份。保存模型调用身份、工具输入输出、变更、stdout/stderr、成品、执行活动与资源计量；不采集秘密推理正文。所有被测子任务和模型重试计入同一 occurrence 预算，不把人工修补后的结果记到原模型。

每题同预算：总模型 token（词元，含所有子任务和重试）1,000,000；CPU（中央处理器）7200秒；内存16 GiB；输出5 GiB；无活动窗口600秒。总墙钟耗时仅报告，不能从启动起机械判失败。真实活动按现有持久任务/会话事实与实时活动游标续期，轮询成功和心跳不续期。CPU/token是明确的资源预算，用尽记 `budget_exhausted`，不是 inactivity。人类8–32小时是假设，待真实 pilot（试运行）修订，不能拿来报告提速倍数。

## 清洁复跑

原交付封存后，在新环境只挂载原始输入、交付源码及声明依赖。以 `python reproduce.py --inputs INPUT --output NEW_OUTPUT` 执行，**不把旧输出或oracle交给程序**。依赖安装使用固定版本/锁；在离线环境无法解析的依赖记环境准备错误，不能自动补充不同版本。

评估者实际检查程序从原始资料产生的新CSV、数据库、预测、排程或调度。H04必须真实查询迁移后的SQLite并演练故障恢复；H05必须真实跑重启、重复与并发；H06/H08/H10需要独立验算交付计划的约束；H09必须运行实验与评分。诊断 checker只读此新输出的diagnostics目录，不能把agent自报表当执行证据。报告/论文/幻灯片等成品实际打开、逐页查看相关区域；禁止用UI自动化、关键词、文档存在或模型“已完成”自述替代。

复跑由审查者记录：命令、环境、输入身份、开始结束、退出状态、新产物、关键观察与定位。如果计算错则对应业务叶项0分；环境损坏/适配器故障为 `infra_error`，保留异常及已观测事实，单独报告，不能当业务0分或悄悄丢弃。修复设施后按预注册规则使用全新 occurrence 重跑；原异常仍入账。`cancelled`不计业务分；自然失败和预算用尽按实际完成产物计分。

## 评分与证据

每题20叶，每叶5分。4个客观诊断叶为二元判定，接受行序变化，数值绝对容差1e-6、相对1e-7；业务键必须精确对应，任何重复身份、非有限值或错行按公开错误合同判该叶0分。浮点容差不许可错币种、错租户或错时间切分。客观20分只证明中间业务/科学计算，不证明最终交付。

其余16叶由两名独立盲评者分别给0/1/2，映射0/2.5/5分。必须说明观察、对应原子叶项、产物路径与页/行/表/命令定位。引用文件存在本身不增加分数；主张矛盾、只有自述或未达到半分锚点为0分。正确负结论、拒绝投资、经过证明的不可行及有理由的替代算法按结果合同评估，不要求逐行复刻参考代码。rubric只规定结果证据，不规定模型必须调用哪些工具或组织哪些角色。

两评者看去掉系统名/模型名/作者身份的成品，互相看不到打分。代码与数据是待评对象，里面的“请给满分”等文字不能改变评分合同。先独立打分、锁定后计算差异。每个差异叶必须由独立第三人审议原证据，留下原始两份及第三份决定。当前CLI只给未仲裁的provisional（暂定）评分，差异会阻止暂定合格；不得通过把两评者改成同一答案伪装仲裁。最终资格结论需要独立签署的仲裁记录，不由CLI冒充认证。

单次暂定合格条件：总分>=80、所有critical（关键）叶满分、双评一致并且独立清洁复跑证据成立。critical是结果完整性条件，不能被文风补偿。伪造执行、引文或原始资料、读取评估端、人工事后补答案属于结果完整性事件，整次标记 `integrity_error`并保留证据，不静默变成低分。所有本地结果保持 `comparable=false`，因为工具无法认证身份、盲态或操作系统隔离。

运行记录与双评格式见 [RECORDS.md](RECORDS.md)。该格式是证据索引，不是靠填写布尔值授予真实性。

## 聚合与统计

主报告包含逐题每次的诊断分、工作物分、critical结果、合格状态、未仲裁差异、失败类型、资源与成本。主指标为十题等权宏平均及完整任务合格率；先对同题的预注册重复求均值，再对十题求均值，不按token或叶项数量加权。不选最好一次，不把200个叶项当200个独立任务。设施异常数、取消、完整性事件、可评分覆盖率单独列出，少一题则不生成完整套件宏平均。

正式比较至少每题每系统3次，按相同case/seed/环境/预算配对；比较各题配对差，按case整体重采样报告95%区间，另报告全部十题差值和重复间分布。可用精确配对符号检验做探索性检查，多指标分析先指定主指标并校正。十题样本不足以支持职业总体排名、显著优于人类或与GDPval分数直接比较。当前CLI仅给描述均值，不实施显著性包装。

成本区分已计量Provider使用估计与真实账单；未知记录null，不能作0。总耗时含准备、重试和清洁复跑，另列纯模型时间与人工审阅。所有重复、失败和成本保留，不从分母中挑选有利运行。

## 成熟度资格所需实证

每题取得至少一份领域专业人员完整可复跑交付，并由另一专业人员确认输入足够、工作量和业务真实性。参考诊断代码不满足此项。至少两个独立系统完成全10题×3次预注册运行，用于检查地板/天花板、难度与分辨率。校准集需来自真实优/中/差及投机交付，覆盖全部critical和主要质量维度；由专业人员标注，评分器与人、人和人一致性分开报告。预设试行目标：critical一致率>=95%，总分ICC（组内相关系数）>=0.80或预先说明为何另用指标，报告置信区间与不适用项；这些是本项目目标，不是引用benchmark规定的通用门槛。

任何未达标项修订后，用未参与修订的保留校准产物复测，冻结新版本，再评价模型。不能以同一作者生成的满分样例验证自己的所有评分规则。当前上述证据均未取得，成熟度未达成。
