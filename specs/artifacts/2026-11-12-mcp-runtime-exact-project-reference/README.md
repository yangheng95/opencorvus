# 项目连接运行引用的基线证据

[实际授权返回](baseline-runtime-grants.json)来自真实项目配置、已保存会话和生产轮次授权入口。两项目独立，并行执行。主项目的普通编程与多步任务授权在空连接名处报错，另一项目的相同入口将带空格和普通连接合并成一个重复引用。

[实际目录返回](baseline-runtime-catalog.json)来自下一次进程启动。同一持久会话的英文 Chat 无已分配连接，完整配置目录仍复现引用错误及重复引用。

[第一版候选](first-active-runtime-inspection.json)在两个项目真实连接本地匿名服务器后复现新可见的执行 owner 冲突。准确的连接原名 `review-tools` 与 `"review-tools "` 产生相同 owner ID，阻断普通编程和多步任务发布对应工具。

[第二版候选](second-active-runtime-inspection.json)确认另一项目三个连接在两个角色中分别真实执行。主项目在正式权限请求中对空名返回 `providerID` 的最小长度错误。

[最终运行](final-active-runtime-inspection.json)包含两个持久项目中四个角色的准确运行目录和父引用。[本地协议](final-protocol-evidence.json)独立记录最后十四次实际工具调用及 200 回执。[重启读回](restarted-permission-evidence.json)记录两个项目的公开权限历史，[数据库](final-storage-evidence.json)关联相同权限请求、终态和真实响应。
