## Problem Model

The repository's main architectural failure is not file size. The root failure is that ownership boundaries are unclear, so later code creates a new local "truth" instead of reusing the current one. Large files are symptoms when they mix several ownership domains; small files are equally risky when they introduce a second contract.

The repair strategy is therefore source-of-truth convergence:

1. Name the authority for each domain.
2. Remove or rewrite non-authoritative paths in the same change batch.
3. Keep positive tests on the new current contract.
4. Delete tests and docs that encode retired behavior.
5. Reject fallback compatibility unless the user explicitly authorizes a temporary migration window.

## Batch Failure Policy

All remediation batches use the same fail-closed policy:

- If the single authority cannot be named, do not edit product code.
- If a caller cannot migrate without a compatibility path, stop and split the batch smaller; do not add fallback or double-read behavior.
- If focused verification fails, leave the changed contract inactive by reverting only the batch-owned files through patch-level reversal, not broad Git reset.
- If docs, generated artifacts, or tests still encode retired behavior, the batch is incomplete.
- If independent review finds a valid unresolved issue, fix it and rerun the focused verification before commit.

## Review Checklist For Each Repair Batch

- Does the batch name one authority and remove the non-authoritative path?
- Does any fallback, compatibility shim, double-read, or shadow state remain?
- Did the change update docs and tests that encoded the retired behavior?
- Does verification assert positive current behavior rather than only absence of the old path?
- Does the change avoid new UI automation tests?
- Does the change avoid direct Bun, shell, storage, browser, or generated-artifact dependencies at public abstraction boundaries?
- Does an independent read-only agent review the complete diff before commit?

## Explicit Non-Goals

- Do not start by splitting large files just to reduce line counts.
- Do not introduce transitional compatibility layers.
- Do not preserve old tests to justify old behavior.
- Do not broaden scope into unrelated UI redesign.
- Do not claim repository-wide exhaustion of the investigation. The sixth investigation round still found new high-confidence issues.
