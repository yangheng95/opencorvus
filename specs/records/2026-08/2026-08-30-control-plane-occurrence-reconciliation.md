## Evidence-led classification

### Confirmed current execution defects

#### F1. The Task-control heartbeat violates its own bounded-delay contract

`TaskControlDriver` documents that every live Task is requested once per `heartbeatMilliseconds`, including Tasks enabled by a missed edge or another process. The timer callback instead waits for every request in the current sweep to finish before it arms the next timer. Because a request owner can await a full Orchestrator Turn, a Task created after the sweep snapshot can wait for that unrelated Turn plus the nominal interval. Existing Tasks in the same snapshot start concurrently, but the level-triggered backstop is not bounded.

Root cause: timer cadence is owned by a sweep's physical completion instead of the driver's lifecycle. A heartbeat tick must schedule the next tick before it starts long keyed owners; per-Task revisions already coalesce overlap safely.

#### F2. Protocol delivery has same-Project recipient head-of-line blocking

`drainSchedulerMessagesForCurrentProject` iterates Mission recipient IDs, awaits each `drainMissionRecipient`, and only then iterates Task recipients. A Mission drain waits for the exact Session reply completion. `requestSchedulerMessageDrainForProject` coalesces all later signals into one Project Promise. Therefore one long Mission Turn prevents a different Mission or Task inbox in the same Project from reaching its own durable recipient owner. Cross-Project polling is parallel and is not the defect.

Root cause: the physical completion Promise of one recipient was promoted to Project-wide ownership. Protocol facts and leases already supply safety; liveness ownership must be keyed by canonical recipient endpoint, with FIFO inside that key and work-conserving concurrency across keys.

#### F3. Activity-triggered Task wait holds the predecessor lease across a full Task Turn

`triggerTaskWaitFromActivity` claims each wait with a 120-second Automation lease, calls `dispatchTaskLoop`, and only after the full reconciliation returns writes the one-shot tombstone and releases the lease. If the Turn crosses lease expiry and the original due time, the due poller can claim the same active wait and accept a distinct due-wake ingress. The normal due path already demonstrates the correct ownership transfer: persist the exact ingress and one-shot tombstone atomically, then reconcile the accepted ingress.

Root cause: the Automation lease owns long execution instead of only the transaction that transfers authority to one durable Task ingress.

#### F4. Mission non-operator wake admission is not fenced at Message commit

`withMissionExecutionAdmission` is a process-local keyed lock. `admitMissionExecutionWake` reads the current opened closure, then calls a wake whose Message is committed in a later transaction. Another backend can append `closing` between those operations. Automation and Event commit bundles fence their own scheduler ownership but do not revalidate the exact Mission opened event; the direct scheduler-message path also needs the same canonical invariant instead of relying on a later projection conflict.

Root cause: a process-local hint was treated as cross-process terminal authority. The exact opened closure event must be captured at admission and compared inside the Message transaction immediately before the wake facts commit.

#### F5. Terminal Tasks can hide unresolved committed dispatch lineage from recovery

The project sweep includes active/cancelling Tasks and terminal Tasks with an ingress accepted at or after their terminal instant. It does not include a failed/cancelled Task whose only unresolved obligation is a pre-terminal committed dispatch lineage. `complete_task` rejects such a terminal transition, but infrastructure failure and cancellation do not share that precondition. After process loss, `reconcileAbandonedDispatches` is therefore never invoked for the hidden Task and the child occurrence/settlement graph can remain open indefinitely.

Root cause: sweep discovery approximates recoverability from lifecycle plus post-terminal ingress instead of reducing the exact unresolved dispatch facts it is responsible for closing.

#### F6. A persisted Mission `closing` occurrence has no automatic host closer

Mission close first commits `closing`, then acquires the lifecycle lease, performs prompt/child-Task cancellation and finally commits `closed`. Host recovery enumerates incomplete Task projects, pending scheduler Projects and Mission process-recovery markers/incomplete assistants. It neither enumerates `closing` events nor resumes their physical execution close; `recoverMissionProcessSession` treats closing as a terminal fence and returns. A repeated operator abort/archive/delete can resume the close, but restart alone cannot.

Root cause: the accepted close occurrence is durable, but its execution reconciler exists only inside the request route. Automatic recovery may resume only that exact occurrence and its execution cancellation; it must not infer or perform the post-close archive/delete storage mutation.

- Provider logical activity has safe streaming, semantic-idle accounting, Tool-effect unsafe-retry fencing and restart terminalization. Physical attempt ordinal, usage and prompt-composition digest do not yet share one persistent causal identity. ## Implementation plan

1. Add a small process-local keyed level-triggered reconciliation primitive by extracting the already-proven revision-owner semantics from `TaskControlDriver`. It owns only scheduling hints: `request(key)` increments a revision; one owner per key scans to a fixpoint; different keys are independent; finite timer/backoff and disposal remain explicit. No database table or status is added.
2. Keep the Task driver API and reducer unchanged, but make its project heartbeat fixed-cadence: the next tick is armed before starting the current sweep, and each live Task request is started under a valid project re-entry without making the tick await the Task Turn before re-arming.
3. Replace the protocol Project-wide completion tail and serial recipient loops with exact recipient-keyed ownership. A Project scan enumerates due/unanswered recipient keys and requests each independently. One recipient drain remains FIFO and may await its own exact reply; other Mission/Task recipients continue. Delete the old Project tail in the same change—no dual scheduler.
4. Add one canonical activity Task-wait ingress writer. In one immediate transaction, revalidate the claimed current revisions and leases, persist/reuse the activity ingress using the real activity source identity, append each one-shot tombstone, and release each exact Automation lease. After commit, reconcile only the persisted ingress. Failure after commit leaves accepted work for the Task reconciler; failure before commit leaves no ingress/tombstone split.
5. Make Mission wake admission return an exact opened-event authority to the wake commit. Add one transaction assertion in the Mission closure primitive, then call it from the shared Automation/Event wake commit and scheduler-message commit. The assertion checks Mission ID, Session ID, opened state and exact event/operation; it does not create a second status.
6. Extend Task sweep discovery with the exact existing unresolved dispatch-lineage reducer. Include terminal failed/cancelled Tasks only while a committed dispatch lacks its settlement/delivery closure; after reconciliation they naturally leave the set.
7. Move Mission execution cancellation into one canonical closer callable by the route and host recovery. Enumerate exact current `closing` events, reacquire the existing lifecycle lease and finish the same operation ID. Recovery cancels the Mission prompt and active child Tasks and waits for settlement, but never performs `Session.setArchived`, Session deletion or another post-close route mutation.
8. Add focused positive tests: fixed heartbeat while Task A remains gated and Task B appears; same-Project Mission A gated while Mission B and Task C receive delivery; Task-wait activity crosses the former lease/due boundary yet yields one consumed wait/ingress/activation; Mission wake pauses after precheck while another process-style close writes `closing`, then commit returns the typed closed contract and persists no wake; failed/cancelled terminal Tasks with unresolved lineage are recovered and then leave sweep discovery; exact Mission closing events converge once on host recovery while opened-only Missions and archive/delete storage state remain unchanged. Preserve current self-wake exclusion, FIFO, restart and multi-project tests.
9. Update `specs/current/architecture/task-control-plane.md` to state exact scheduling-owner boundaries. Run focused tests, package typecheck, control-state redundancy/lease-owner checks, documentation check and diff check. Do not run UI automation or benchmark.
10. Commission an uninvolved read-only delivery review over the complete diff, tests, evidence and architecture. Repair all valid findings and repeat review until none remain. Commit the scoped changes, fetch and merge the latest upstream, inspect the entire outgoing commit set, rerun affected checks and push.

## Independent delivery review findings and repair plan
