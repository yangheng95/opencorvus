## Impact and release-chain analysis

- Observable state: the maintenance line contains product fixes not yet present on `main`, while all canonical manifests and the public release still identify `0.0.52-beta`.
- Direct trigger: synchronize the canonical version, update the changelog and release record, commit only scoped files, push the maintenance line, then push the immutable release tag.
- Data/control flow: versioned source commit -> immutable tag -> GUI and command-line package matrices -> staged assets and checksums -> GitHub prerelease -> beta update channel -> `opencorvus-release-published` dispatch -> immutable website build/sign/deploy -> public probes.
- Shared runtime surface: the release includes scheduler wake settlement, durable tool-pause renewal, terminal closure for resumed task occurrences, and redaction of transient Provider diagnostics. These touch Task/Mission/Session occurrence recovery and terminal paths; their implementation commits and existing focused tests are already part of the reviewed maintenance history. The release bump itself changes only version projections, changelog, and release records.
- UI surface: the release includes already-reviewed Overlay fixes for right-dock interaction, Work Ledger rename, and single-click tool disclosure. The bump does not change UI source. Public website validation must use the real deployed pages and public endpoints; no UI automation test is added or run.
- Risks: partial platform matrices, release/tag SHA mismatch, update-manifest drift, Registry projection rejection, production deployment policy rejection, cached public download metadata, accidental inclusion of benchmark/user files, or merging an unreviewed remote divergence. Each is checked at its authoritative build, release, Git, or public endpoint.

## Release boundary

The release contains the product history already published on `v0.0.52beta` through `e8e6ca45` plus the scoped `0.0.53-beta` version, changelog, and release-record update. It excludes `packages/opencorvus/script/benchmark/`, benchmark worktrees and evidence, `script/video/`, the abnormal-name untracked file, credentials, databases, and dashboards.

The source maintenance branch is `v0.0.52beta`; the canonical SemVer is `0.0.53-beta`, the product label is `0.0.53beta`, the immutable release tag is `refs/tags/v0.0.53-beta`, and the next maintenance branch is `refs/heads/v0.0.53beta`. After publication verification, the release source is merged into `main` and pushed without rebasing or forcing.
