Each is verified at its owning Git, build, Release, updater, deployment, public-page or database boundary.

## Independent review findings and remediation

1. `build.yml` staged partial artifacts on a draft but its publication job did not require `complete=true`; therefore a failed native matrix could still become a public Release, update the mutable beta channel and dispatch the website. Repair the workflow so only the complete matrix reaches those three irreversible publication steps, retain partial artifacts only on the draft for a repair run, and add a focused positive workflow-contract assertion for that gate.
2. The source version bump and public-package archive check covered `@opencorvus-ai/util`, `@opencorvus-ai/sdk` and `@opencorvus-ai/plugin`, while neither the request nor the release workflow authorized npm registry publication. Narrow the changelog and release record to source/package metadata alignment and explicitly leave npm publication out of scope; do not silently run `--publish`.
3. Both spec indexes used completed-publication wording while this record still reported pending publication. Rename the index entries as release preparation/publication tracking until the immutable Release and website actually converge.

After these repairs, rerun the focused release/workflow contracts, version and documentation checks, workflow YAML parsing and the indexed topology boundary, then obtain a fresh read-only review of the complete staged diff.
