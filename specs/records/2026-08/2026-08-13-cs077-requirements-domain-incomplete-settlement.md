## Root cause and impact

The Requirements collector intentionally starts with empty `requirements` and `decisions` arrays. A natural completed Turn may therefore return zero requirements. The adapter nevertheless writes the syntactically valid empty payload and always returns `terminal_success`; durable dispatch settlement then opens Solution Architect solely from that false success. Prompt instructions and workflow edges cannot validate the producer's domain delivery.

The canonical Artifact is still valuable evidence: it proves what the exact Requirements occurrence registered, decided, selected, and left unresolved. The adapter, not Architect or the workflow projector, is the one settlement authority that can join the collector declaration to the durable Task request, selected Artifact provenance, and completed producer Turn. It must persist the same canonical Artifact, return its exact locator as domain-incomplete evidence when that typed delivery contract is incomplete, and leave the shared frontier rule unchanged.

## Design

1. Add one pure, typed `finalize_requirements` collector tool to the existing Requirements output toolkit and adapter contract. Its declaration contains `status=complete|incomplete`, exact `request_sha256`, the exact registered Requirement IDs it claims to cover, exact selected source Artifact locators, and explicit unresolved items. It is not permission-bearing, does not write a second Artifact, and may be called only once per collector occurrence.
2. At the end of the real streaming Requirements Turn, the Requirements Agent returns only the raw finalization declaration, registered requirements/decisions, and exact producer IDs. It does not return authoritative provenance and does not derive, accept, or expose a delivery status.
3. Resolve the Requirements runner exactly once when the adapter factory is created; production keeps `RequirementsAgent.run` as the sole implementation, while focused tests may inject only those raw facts with IDs of a production-valid Requirements Session and completed assistant Message. No persistence, settlement, or projection seam is introduced.
4. The existing single `persistRequirementSet` publication authority reads the current durable Task request; binds the exact dispatch lineage, Worker Turn descriptor, Task-owned Requirements Session, descriptor-owned user Message, and completed assistant producer Message; reconstructs observed/source locators from that exact durable Turn using `artifactProvenanceForAgentTurn`; validates the raw declaration; and uniquely recomputes the typed coverage receipt. Complete requires the declaration to say complete, at least one requirement, exact request/ID/source equality, every Requirement evidence locator to belong to that durable selected-source set, and no unresolved items. Missing, forged, stale, mismatched, or incomplete declarations produce stable issue codes in the same Artifact rather than throwing or becoming natural-language gates.
5. The same writer transaction persists producer, requirements, decisions, provenance, and recomputed coverage receipt in the canonical RequirementSet payload, then returns `{ locator, deliveryStatus }` from the committed row. The adapter never recomputes or trusts a runner-supplied status; it maps only that writer-owned return value to `domain_incomplete` or `terminal_success`.
6. A writer-owned `deliveryStatus=incomplete` returns `DispatchOutcome.domainIncomplete` with domain `requirements` and that exact locator. Decisions and one arbitrary Requirement do not substitute for a complete receipt. Only writer-owned `deliveryStatus=complete` retains `terminal_success`.
7. Preserve existing post-Turn persistence failure as `partial`; do not fabricate a locator or change infrastructure observation semantics. Coordination handoff remains distinct and writes no RequirementSet.
8. Document that canonical RequirementSet publication and workflow success are separate facts: incomplete coverage is durable evidence but cannot open successors.
9. Current RequirementSet payloads are explicitly `schema_version=2`. Pre-coverage immutable Artifacts cannot acquire a truthful producer or coverage receipt, so database startup reports `DATA_RESET_REQUIRED` under the repository's pre-0.1 reset policy. Runtime readers remain a single strict schema; there is no legacy fallback, fabrication, or dual protocol.
10. The registration tools and canonical RequirementSet writer reuse the same Requirement and Decision field schemas. A value accepted on the collector wire cannot later fail solely because the writer maintains a different length contract.
