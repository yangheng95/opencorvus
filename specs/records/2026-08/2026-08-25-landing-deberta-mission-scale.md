## Impact and root analysis

- Observable state: the landing page's primary composition case is a static six-squad research-to-paper chain. It does not carry the requested model-training Mission, does not expose CUDA/runtime/monitoring/repository work, and offers no interaction that changes perceived scale.
- Direct trigger: replace the featured editorial declaration, extend its catalog-derived view with an optional eighteen-stage expansion, add localized expansion copy, and render the expansion as a native disclosure inside the existing composition card.
- Data flow: `squad-compositions.ts` editorial identities and handoffs -> `generate-public-market.ts` catalog identity/label/role projection -> `squad-compositions.generated.ts` -> `landing-compositions.ts` localized view -> server-rendered landing HTML -> native `<details>` state -> small enhancement script for a temporary magic burst -> scoped CSS motion and layout.
- Why the old path is insufficient: `extras` carries only labels and aggregate counts, so it cannot name owners, handoffs, or eighteen inspectable stages. A separate landing-only array would duplicate the composition authority and allow labels/counts to drift from the Market. The current static list also has no state transition to support the requested three-times reveal.
- Scope exclusions: this is a public-site narrative and interaction change only. It does not start training, provision CUDA, create a live inference service, author the described thirty-page paper, publish a GitHub repository, change Mission runtime scheduling, mutate Expert Squad packages, or add a second website data authority.
- Risks: overstating completed work, confusing stages with unique squads, inventing catalog labels/counts, inaccessible summary behavior, motion that obscures content, a six-to-eighteen mismatch, mobile overflow, bilingual drift, or deployment from a source different from the reviewed commit.
