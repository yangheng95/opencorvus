## Independent audit register

Three independent read-only reviews inspected state/protocol, concurrency/deadlock, and recovery/resilience surfaces before implementation. They agreed that the incident is not a mutex deadlock and not the older lost-terminal-wake defect. It is a semantic lost-progress state: the worker terminal event and wake both exist, but the current Turn can consume the wake using stale nonterminal reasoning and leave `Task=active`, every worker terminal, no pending ingress, no wait, and no root owner.

| --- | --- | --- | --- |

One active orphan also blocks later Tasks in the same directory. | Project the exact canonical lifecycle status/reason/error/summary into the current wake and make execution-control decision obligations unambiguous. ## Implemented convergence

- Exact lifecycle and dispatch-infrastructure occurrences now materialize one normal persisted Message with provider role `user`, `author=orchestrator`, and `agent=orchestrator`. Its Message ID and Text Part ID derive from the exact durable wake ID; its visible body carries the exact wake/fact identity and canonical terminal or infrastructure outcome. A retry strictly validates and reuses that same Message and Part. It does not enqueue another wake, impersonate a worker or user, or create a second scheduler fact.
- Dynamic system context retains policy and authority guidance, while the persisted control Message is the current conversation tail. This removes the old system-only split where the model's last real input was an expired assistant wait. Ordinary operator status/diagnosis input remains a valid prose-only outcome; execution-control ingress retains the same-Turn scheduling/lifecycle decision obligation.
- Project startup restores every interrupted `running` root ingress to `pending` before interrupted worker reconciliation can append or drain later wakes. The later duplicate recovery call was removed, preserving one FIFO authority and one recovery stage.
- Current-process terminal publication remains admitted until Session termination has emitted its lifecycle fact. Scheduler admission still closes first to prevent new work; protocol admission closes only before the final settlement barrier.
- Exact terminal delivery retains its two immediate attempts, then reserves one delayed `engine_queue_completion` owner for the same wake ID and retries in the same runtime with bounded exponential delay. Shutdown leaves or restores `delivery_failed` for the successor bootstrap scanner.
- Event fire claim, preamble, execution, disposition, retry, and renewal now share one non-expired lease fence. Every nonterminal exit schedules recovery for the same fire ID. Admission-close timer delivery is typed and recoverable rather than an uncaught callback.
- Task Queue capacity uses a project-wide durable running-row predicate at both selection and atomic claim. Stream activity increments one process-local monotonic epoch immediately and coalesces persistence to one heartbeat owner per Task; inactivity recovery rechecks the epoch before cancellation.
- Durable Bus retry joins one occurrence-keyed physical owner. Protocol admission closure cancels only that runtime's retry owner and retains durable recovery for the successor, without a second receipt state.
- Process supervision exposes Task-scoped live owner evidence. The real checker uses that current production fact instead of the removed Language Server Protocol runtime.
- Checker failure evidence is metadata-only: exact identities, states, counts, tool names, and error types remain diagnosable, while assistant/reasoning content, tool input/output, and Artifact/Protocol payload bodies never enter stderr.
- Pending cancellation bootstrap no longer re-enters its unfinished Instance while publishing aborted worker lifecycle. The current-project status primitive persists the same Session lifecycle authority directly; no alternate event, wake, or lifecycle store is introduced. Cancellation convergence emits structured stage evidence so future restart stalls identify the exact physical boundary.
- Checkpoint and auxiliary settlement attempts no longer inherit a closing bootstrap lease. Each attempt enters the Task primary root through an independent project identity, while retries continue to converge the same durable receipts.

## Checker reconstruction findings

The first repaired checker revision used the low-level HTTP listener directly. That route is useful for server-unit tests but does not execute the production startup recovery barrier; read-only Task/Event endpoints also intentionally do not force project initialization. Consequently an old `running` root wake appeared permanently stable even though production startup would reconcile it. The checker now starts through `listenWithRecoveredServerRuntime`, requires `recoverStartedTaskExecutions` to succeed before listener readiness, and therefore exercises the same bootstrap contract as the production server and Agent Client Protocol service.

Once that false harness boundary was removed, the checker exposed the independent FIFO inversion recorded above: both old operator wakes ultimately drained, but the second completed before the first because interrupted-worker recovery ran before root-ingress requeue. The bootstrap ordering repair and a focused two-wake restart regression now assert the old head is delivered first and both exact wake IDs reach `drained` in creation order.

The repaired FIFO checker then exposed a second bootstrap defect hidden by the original parent timeout. `engine-task.reconcile-pending-cancellations` advanced through lease acquisition, Session cancellation, queue idle, prompt settlement, and recovered-assistant terminalization, then stopped before lifecycle publication. The cancellation path was calling the independent-project status publisher from inside the current unfinished bootstrap. Switching to the already-defined current-project recovery publisher removed that self-wait: the next real run reached `task.cancelled`, terminalized every ingress, and scheduled the exact checkpoint/auxiliary settlement artifacts. The checker also replaced its fixed 15-second post-terminal settlement deadline with a durable-event activity window; terminal acceptance retains its 15-second service objective, while a physically progressing Git checkpoint is no longer killed by the harness.

That run then exposed a third, separate ownership defect: the checkpoint retry owner survived, but every attempt reused the now-closed bootstrap Instance lease and could never terminalize its receipt. Settlement operations now enter a fresh independent identity for the Task primary root. The succeeding real-provider run completed lifecycle control, successor-runtime FIFO recovery, terminal cancellation, and both exact post-terminal settlement receipts with exit code 0. A later duplicate checker run intended only to improve untruncated result printing was stopped after the already-successful product acceptance; no product conclusion depends on that redundant run.
