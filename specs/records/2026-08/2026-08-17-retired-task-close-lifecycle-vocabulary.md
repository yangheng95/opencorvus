## Observed facts and diagnosis

`task.close.requested` and `task.closed` were declared vocabulary with no producer. Every arm keyed on them was unreachable, so they protected nothing; what they did do was reachable and harmful.

The lifecycle reduction groups both boundary-request types together and throws `conflicting lifecycle requests` when an epoch holds more than one. A single `task.close.requested` row alongside an ordinary `task.cancellation.requested` therefore made *every* projection read for that Task throw — the store projection, the board, and the Task API alike — so the Task could not even be cancelled. The dead vocabulary's only reachable behaviour was to brick the Task it appeared on.

The delivery scan compounded it. `closing` was routed to the same 15-second reconciliation wake as `cancelling`, but with `lifecycle.status === "closing"` explicitly excluded from convergence, and the code's own comment conceded that no converger exists for the boundary in this runtime. That is a state whose entire specified behaviour is to poll forever and surface a gate.

Both partial unique indexes still named the retired types. Index text is part of the schema contract, and index drift raises `schemaResetRequired` rather than being reconciled like a trigger, so narrowing the predicates makes an existing database ask to be reset. An in-place index migration with a fail-closed row assertion was written and verified first; the user then ruled it not worth the machinery for a pre-release beta and chose the reset. That is the cheaper and more consistent answer — the reset path already exists and is already how every other index or column change is absorbed — so the migration was deleted rather than kept as a second upgrade mechanism.

## Canonical repair

1. Remove both retired event types from the lifecycle constants, so the boundary-request family is exactly `task.cancellation.requested` and the terminal family is exactly `task.{completed,failed,cancelled}`. The remaining `requests.length > 1` check keeps its meaning for duplicate cancellation requests.
2. Delete `closing` from the lifecycle projection status union, the `DerivedTaskStatus` input union, the ingress fact-kind union, the ingress projection union, the debug `TaskRootIngressState` schema, and every predicate that enumerated it.
3. Collapse the delivery scan's boundary branch to `cancelling` alone, so the surviving branch is one with a real converger and a real exit; `surfaceUnconvergedTaskBoundary` narrows to that status and keeps its deterministic per-(Task, epoch, status) identity.
4. Drop the `task.closed` alias from `lifecycleKind` and the now-vacuous `task.closed` exclusion from the terminal-reference type set.
5. Narrow both partial unique index predicates and add no migration. An existing database reports index drift and takes the existing reset path; this is a pre-release beta, and adding a second upgrade mechanism for vocabulary that never had a producer costs more than it protects.
6. Converge `specs/current/architecture/task-control-plane.md` and regenerate the OpenAPI/SDK/API-MDX artifacts, since the debug ingress state union is published.
