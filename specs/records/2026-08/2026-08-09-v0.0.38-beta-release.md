## Problem depth and impact analysis

- Observable state: the repository is dirty across several completed work streams, but the aggregate tree is not releasable because three imports target files being removed and the version/changelog still identify the previous release.
- Direct triggers: benchmark retirement removed helper implementations that still had live consumers, and one pending test was created for a helper that was never added. The release request additionally requires the version family and release notes to advance together.
- Data/control-flow root cause: reusable runtime and browser-navigation helpers were stored under a benchmark directory, so deleting the retired benchmark implementation also deleted current dependencies. The stale Mission test has no surviving production contract and cannot execute.
- Why the old path did not root-fix it: deleting the benchmark entry points removed obsolete execution paths, but it did not first separate shared primitives from benchmark-only code or update their callers.
- Contract impact: Provider error messages and bodies gain credential redaction; manual screenshot tools keep their inactivity behavior from a non-benchmark helper; the production Host MCP connection-statistics test remains while benchmark-only checker code is removed; package/Cargo/Tauri/lock metadata advances atomically. The temporary ABSA lab is excluded.
- Tests/docs/delivery: use focused Provider and production Host MCP tests, then repository release-script, version, docs, and type checks. Deleted benchmark-only tests/scripts are not run. Update both spec indexes and the changelog. Release is delegated to the canonical GitHub Actions matrix after the tag push.
- Risks: the combined work originated from multiple tasks, so hidden generated files or stale references could enter the release; full-tree status, ignore checks, diff review, and an independent review mitigate this. Native matrix build is authoritative only when GitHub Actions completes and publishes the prerelease.

## Implementation plan

1. Move the surviving browser inactivity primitive out of the retired benchmark tree and update live imports; remove benchmark-only tests/checkers and the orphan Mission activity test whose implementation never existed.
2. Exclude the local temporary ABSA lab and its task record, and keep the incomplete ignored Mission benchmark WIP record local after its implementation is retired; include all intentional tracked benchmark deletions.
3. Synchronize all release-family metadata to `0.0.38-beta`, promote the Unreleased changelog entries, and update release documentation indexes.
4. Run focused checks, version/docs/type validation, inspect the complete diff and status, then commission an independent read-only review. Repair and repeat if needed.
5. Commit the complete authorized repository change set, verify `origin/main..HEAD`, push `main`, create and push `v0.0.38-beta`, monitor the canonical release workflow, and verify the published prerelease and assets.
