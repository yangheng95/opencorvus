## Problem depth and impact

- Observable failures: latest main run `31579263415` (`typecheck`) and `31579263347` (`generated-artifacts`) fail while regenerating repository artifacts; the latest `test` run has failed Linux/macOS units and critical build while Windows remains active.
- Direct trigger: generation loads every built-in Expert Squad through the production Registry. It rejects top-level `report.md` with the typed error `expert squad package root: unknown top-level entry "report.md"`.
- Root cause: commit `984996b1` placed a one-off generated equity research deliverable inside the immutable package source root. That violates the sole package-definition contract and contaminates every real Registry consumer.
- Why older paths did not root-cure it: historical work repeatedly excluded the untracked report or deleted an earlier committed copy, but a later standalone docs commit reintroduced it. Test-only filtering in `equity-research-skill-closure.test.ts` proves an isolated fixture shape and cannot make the production generator valid.
- Affected control flow: generated Expert Squad payload and market artifacts, OpenAPI/typecheck verification, critical build, cross-platform unit suites, pre-push hooks, native packaging, Release matrix, and website static archive generation all consume or depend on the same production package snapshot.
- Correct repair: delete the generated root report and retain the existing strict Registry. Do not add `report.md` to allowed roots or create generator exclusions; runtime reports remain under project `artifacts/` as the package already instructs.
- Independent unit-test failure: all three operating-system rows completed with `Memory tests require the repository test preload` and refusal to reset the real user database path. History shows the later canonical `script/run-tests.ts` plus `test/isolated-test-entry.test.ts` explicitly awaits runtime setup before importing each selected test, but merge resolution left `package.json` pointing at the older `run-test-files.ts`, creating two runners and bypassing the newer host. Restore the newer runner as the single implementation and delete the superseded runner/test; the database ownership guard remains unchanged.
