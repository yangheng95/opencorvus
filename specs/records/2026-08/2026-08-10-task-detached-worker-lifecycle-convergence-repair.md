## Root-cause and impact analysis

### Observable symptom

The board shows an active Task with four idle nonterminal executions, no terminal reasons, no root continuation, and no Goals. Waiting cannot progress it because there is no pending ingress or executing process.

### Direct triggers

1. The Orchestrator root Turn returns and closes its Instance lease while accepted detached worker Promises continue.
2. Worker terminal status publication and the later Promise completion callback execute with the inherited closing lease.
3. A provider error emits the session-scoped `SessionEvents.Error` contract without an input-message identity, while the bridge applies an execution-lifecycle-only enricher.
4. The Orchestrator selects a direct initial dispatch after committing a virtual workflow binding.

### Data/control-flow root cause

`detachDispatchExecution` detaches Promise waiting but not AsyncLocal execution ownership. The worker Promise, managed-worktree wrapper, terminal status publication, and registered completion callback all retain the caller's Instance context. `Instance.closeLease` correctly rejects new work through that closing authority. The independent project owner primitive already exists, but the detached dispatch path does not use it at the execution or delivery boundaries.

The lifecycle and delivery layers then fail asymmetrically: worker terminal publication is required for canonical completion, while delivery failure is only logged. Bootstrap can reconstruct a missing delivery from an existing terminal lifecycle event, but it cannot recover the observed case because terminal publication itself never succeeded, and it does not provide current-runtime convergence for a post-terminal delivery failure.

`session.error` is a separate contract mismatch in the same completion/diagnostic path: its schema is Session-scoped, yet bridge preparation requires execution input identity. This hides the original provider incident and emits a secondary bridge failure.

### Why existing paths did not root-cure it

- Pure Promise detachment tests prove receipt timing but do not release a real Instance lease before worker completion.
- Fresh worker authority tests await the worker inside one live Instance lease and therefore cannot observe post-parent completion.
- Persistent callback tests cover watcher-owned activity, not intentionally lease-independent detached work.
- Startup reconciliation covers terminal-event delivery loss, not terminal publication loss or current-runtime delivery retry.
- The immutable binding assertion protects durable data but occurs only when lineage is committed, after the model has already chosen a contradictory subject and allocated an attempted physical Session identity.

### Impacted contracts and call sites

- Current-project and managed-worktree dispatch execution ownership.
- Worker terminal lifecycle publication and physical settlement.
- Detached terminal delivery and current-process reconciliation.
- Restart recovery of terminal lifecycle delivery.
- `session.error` persistence and board/process-incident visibility.
- Initial direct/virtual workflow selection after a binding already exists.
- Tests, Task-control benchmark evidence, current architecture wording, and generated documentation only if public schemas change.

The Task runtime directory layout, Task cancellation barrier, UI rendering, model provider protocol, Git checkpointing, and CUDA workload are not root causes and are excluded unless verification exposes a direct regression.

## Benchmark and repair loop

1. Add a production-primitive test that commits a detached worker, releases the parent Instance lease, then completes the worker and requires terminal lifecycle plus one accepted delivery wake within one second. Run it before the repair and retain the exact failure.
2. Cover both current-project and managed-worktree ownership, because both currently call `Instance.provide` from inherited detached context.
3. Make detached execution and terminal delivery use the existing independent initialized-project owner as their single lifecycle authority. Do not weaken closing-lease validation.
4. Make post-terminal delivery failure durable and invoke the same idempotent lifecycle-delivery reconciler in the current runtime; bootstrap continues to call that one reconciler.
5. Correct `session.error` enrichment to its own Session-scoped contract and add a positive persistence test using a real durable Session error event.
6. Strengthen scheduler prompt/tool semantics so a Task with a selected virtual workflow never asks for a direct initial dispatch. Keep the existing immutable database assertion as integrity validation, and return typed binding conflict evidence rather than adding host routing policy.
7. Run focused tests after every change. Then run typecheck, documentation checks, diff checks, and the isolated real HTTP checker until all acceptance metrics pass.
8. Perform self-review and mandatory independent read-only review. Fix every valid finding and repeat affected checks and review until no findings remain.

## Delivery and recovery decisions

- A detached worker owns a fresh initialized Instance lease for the directory in which it actually executes.
- Delivery back to the Task root owns a fresh initialized primary-project lease and uses the existing lifecycle-event idempotency key.
- One reconciliation function remains the only creator of missing terminal lifecycle deliveries; normal completion and bootstrap call the same implementation.
- Closing-lease guards remain fail-closed. No caller is allowed to reuse invalid ownership.
- `agent.execution.lifecycle` remains the only worker lifecycle truth. `session.error` remains a separate visible incident and cannot decide completion.
- Workflow binding remains immutable. Prompt/tool guidance prevents contradictory selection; the database assertion remains the final integrity boundary.

### Repair implementation

- `detachDispatchExecution` now accepts an execution factory and starts it only through an injected independent initialized-project owner. Normal primary-project completion delivery uses the same fully initialized owner contract; after two pre-callback owner failures, a lightweight independent project-identity owner delivers the exact already-settled outcome without rerunning worker execution or project bootstrap.
- Current-project and managed-worktree paths share that detached root ownership; the worktree lease remains scoped around its exact worker run.
- `publishSessionStatus` and restart-safe settled publication now use the existing independent project-identity owner, matching their documented outliving-caller contract.
- Normal completion and bootstrap call `reconcileTerminalAgentLifecycleDelivery`, the single lifecycle-event-keyed wake writer. Delivery failure records `task-infrastructure-error` and retries this same idempotent reconciler once in the current runtime.
- Required `agent.execution.lifecycle` preparation and append failures now propagate after bridge diagnostics, allowing `SessionStatus` to roll back process-local terminal state instead of silently losing the durable fact.
- `session.error` uses a Session-scoped enricher. Worker identity comes from the latest durable Worker Turn descriptor; no input-message identity is invented.
- Immutable workflow conflicts now have `TaskWorkflowBindingConflictError` and a typed `occurrence_not_committed` tool result. Prompt and tool schema both state that `direct` cannot follow a selected virtual workflow.
- A lifecycle wake whose first delivery attempt reached `delivery_failed` is atomically restored to `pending` under the same lifecycle event identity. Its delivery attempt increments and the existing occurrence is retried; accepted wakes remain idempotent.
- `session.error` has one routing path through the global Instance relay. Same-project and managed-worktree events therefore share one host-side persistence call instead of local-plus-global double writes.
- The root-loop completion hook performs one bounded same-runtime retry only for a real terminal lifecycle ingress after its first attempt is durably marked `delivery_failed`; it reuses the exact wake occurrence and the shared reconciler. A second failure remains durable.
- Prompt `finished` now settles only after directory ownership and managed-worktree owner release complete. Cleanup errors reject the finish signal, so worker physical settlement cannot finish early while ownership cleanup continues in the background.
- A cancelled prompt's owner-keyed receipt now has an explicit `pending` / `succeeded` / `failed` settlement outcome. Successful evidence may be reclaimed; failed cleanup evidence remains fail-closed for every later waiter and quarantines that Session from starting a replacement prompt in the same process. Delayed subtree settlement and physical agent-runner settlement therefore receive cleanup rejection instead of treating missing process-local state as success, while owner-specific queue settlement reclaims only successful receipts.
- Every projected worker Turn captures its prompt-generation owner at prompt start/continuation and carries that exact identity through completion, cancellation, and failure. Physical settlement uses only `cancelOwned` or the matching owner receipt; a stale Turn observing a replacement generation fails its invariant instead of cancelling the replacement. A distinct token-guarded settlement reservation remains held from exact cleanup through the required terminal append and is not deleted by normal prompt cleanup, so replacement admission cannot create an ABA gap. Reservation acquisition, cleanup, runtime-resource release, and terminal handoff all participate in the typed settlement-failure contract. Every outcome settles that exact prompt/worktree owner before publishing `completed`, `coordinated`, `aborted`, or `error` lifecycle. The real dispatch checker samples process-owned prompt/receipt state at the terminal protocol append and requires both to be settled, requires replacement admission in that exact window to return `BusyError`, and waits for every detached execution/delivery owner, queue completion hook, and Project Git lock acquire/operate/release lifecycle before deleting its fixture.
- A rejected MCP runtime-resource close releases the exact generation reservation, persists a `worker-runtime / close-runtime-resources` infrastructure Artifact, and throws `WorkerTurnSettlementError` with descriptor evidence. The durable worker lifecycle remains at its real pre-terminal `streaming` fact instead of publishing a false terminal status; detached delivery then emits the exact typed dispatch-infrastructure ingress from that same Artifact.
- Accepted dispatch delivery maps a late `WorkerTurnSettlementError` through the same `DispatchOutcome.infrastructureFailure` constructor as a synchronous failure. Its exact original Artifact locator, Worker Turn descriptor, and committed occurrence recovery authority form one `dispatch_infrastructure_failure` ingress; the terminal reconciler and generic delivery-failure Artifact path are reserved for actual terminal-delivery failures. One continuously registered detached owner awaits execution, delivery, and any recovery, eliminating the previous barrier gap.
- A failed first root delivery of `dispatch_infrastructure_failure` atomically revives that same fact-keyed wake as delivery attempt two; the completion hook launches no parallel occurrence. A second failure stays durable and an exhausted explicit repeat reports `ignored` instead of claiming a root loop started. The supervised pipeline distinguishes pre-callback owner initialization from post-callback owner cleanup and keeps its barrier owner until continuation or typed cleanup delivery settles.
- Wake revival checks `delivery_attempt < 2` inside the same persistence transaction that changes `delivery_failed` to `pending`, so explicit dispatch, completion hooks, and bootstrap reconciliation cannot create attempt three. The detached supervisor records whether its callback has started or settled: pre-callback owner initialization rejection reacquires an owner and continues awaiting the original execution; post-callback owner cleanup rejection creates a separate `settle-detached-pipeline-owner` Artifact and exact typed ingress instead of being relabeled as terminal delivery failure.
