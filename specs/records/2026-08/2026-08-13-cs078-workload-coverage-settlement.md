## Root cause and complete impact

`projectWorkloadInput` resolves selected Goal IDs against the current GoalGraph before the streaming Turn, but it reduces duplicate input IDs to a process-local set and does not persist that projection as the Workload delivery contract. The collector starts with `briefs=[]`; an unknown goal is discarded, a repeated goal overwrites the earlier brief, and no registration receipt survives. Therefore the Agent result cannot distinguish no output, partial output, extra attempted output, or duplicate output.

After the completed assistant Turn, the adapter independently reconstructs Artifact-read provenance and calls a broad append-only helper that writes arbitrary-length `briefs` with only Session/Message IDs. That helper does not assert the producer against the exact dispatch lineage, bind the selected immutable revision identities or publication-time GoalGraph tip, compute coverage, return an exact locator/status, or make publication replay-stable. The adapter discards the inserted ID and always returns `terminal_success`. The generic dispatch-settlement writer then truthfully persists the wrong outcome, so production workflow projection opens Integrity. Prompt wording, schema validity, Session completion, and the dependency graph cannot repair a missing domain-delivery authority.

The affected facts are the collector's exact submissions, the completed producer Turn, immutable dispatch lineage and workflow occurrence, selected Delivery Slice identities/revisions, optional publication-time current GoalGraph membership, Artifact-read provenance, canonical per-dispatch `goal_workload` payload/locator, durable dispatch outcome, startup recovery, and the four Advanced workflow frontiers. Generated SDK routes and UI projections do not define this payload and need no direct change. Integrity and generic workflow projection remain consumers; neither may recompute Workload coverage. The current `reconcileTerminalAgentLifecycleDelivery` behavior is an explicit boundary: after a process cut with a completed assistant Turn but no settlement, it writes one immutable `partial(recover_dispatch_domain_settlement)`; a domain publisher is not allowed to override it.

## Design

### 1. Preserve raw registration evidence

1. Keep `register_workload_brief` as the only streaming structured-output tool and keep it non-permission-bearing. Change its collector from an overwrite map to an ordered list of every schema-valid submission.
2. A first selected revision registration returns `OK`. An unselected or repeated revision returns an explicit tool error but remains in the ordered collector as exact invalid coverage evidence; it is not silently discarded or overwritten. Contract-reference warnings remain advisory and do not authorize completion.
3. The Agent returns only raw brief submissions plus the exact Session and final assistant Message IDs. It returns no authoritative status, selected set, current-membership claim, provenance, or coverage declaration. There is no `finalize_workload` tool because the required cardinality and revision currency are machine-verifiable facts.

### 2. Make one publisher the Workload authority

1. Add one domain-owned `publishGoalWorkload` operation and delete `persistGoalWorkloadForDomainRefs` in the same implementation. No wrapper, compatibility schema, or alternate writer remains.
2. Its caller supplies only Task ID, exact dispatch ID, producer Session/final Message IDs, raw brief submissions, and write time. In one `Database.immediateTransaction`, the publisher first resolves the exact immutable dispatch lineage by Task/dispatch, asserts a `workload_analysis` projected worker, its child Session, Task ownership, `goal-workload-analyst` Session kind, exact completed assistant producer Message/agent, and the lineage's canonical selected revision IDs.
3. Resolve every selected Goal row into `{delivery_slice_id, delivery_slice_revision_id, revision}` through the immutable Goal lineage. In the same transaction, resolve the optional current GoalGraph tip and freeze its exact Artifact locator or `null` when no projection exists. Selected IDs are never expanded to Task-latest: the dispatch lineage is `N`; current membership only determines whether those selected revisions are still current.
4. Reconstruct observed/source Artifact provenance from that exact completed Turn. The runner and adapter cannot supply or forge it.
5. Compute one typed coverage receipt with stable sorted identity arrays: selected subjects, submitted revision IDs, missing selected IDs, extra unselected IDs, duplicate IDs, stale selected IDs, the canonical publication-time `current_revision_ids`, and `current_goal_graph_projection_artifact_locator: EngineArtifactLocator | null`. `EngineArtifactLocatorSchema` only proves locator shape. A shared database-aware GoalGraph receipt validator additionally uses the immutable Workload Artifact's `catalog_revision` as an as-of high-water mark: it loads every same-Task `goal_graph_projection` fact with `catalog_revision < workload.catalog_revision`, calls the existing `resolveGoalGraphProjectionTip(taskID, facts)` to reconstruct the unique successful as-of tip (thereby excluding later `projection:null` conflict candidates), and proves exact locator revision/hash plus equality between that successful projection payload's revision IDs and stored `current_revision_ids`. First publication calls the same transaction-aware resolver over the same visible fact set before assigning the Workload catalog revision. Startup never compares historical receipts to the database's present-day tip. A Task snapshot, resource, wrong-kind Engine Artifact, successful tip already stale at publication, or mismatched revision set is invalid; a legitimate GoalGraph supersession after publication leaves the old receipt valid and immutable. Stable issue codes are `selected_revision_set_empty`, `selected_revision_missing`, `unselected_revision_submitted`, `revision_submitted_more_than_once`, `selected_revision_not_current`, and `current_goal_graph_unavailable`. The last issue is always emitted when the locator is `null`, including the natural no-GoalGraph plus empty-selection case; absence is domain evidence, not an infrastructure exception or a fabricated locator.
6. Receipt status is `complete` only when the selected set is non-empty, each selected revision is submitted exactly once, there are no extras, a current GoalGraph exists, and every selected revision is current at publication. Empty/missing-only cases, including empty selection with no GoalGraph, are `incomplete`; extra, duplicate, stale identity disagreement, or non-empty selected subjects whose currency cannot be proven are `conflict`. Brief prose and counts are never judged by Host code.
7. The strict row schema enforces a deterministic row-local equality, not merely field types or a few implications. Its `superRefine` recomputes the canonical sorted selected/submitted/missing/extra/duplicate/stale arrays and exact issue set from persisted selected subjects, raw submissions, and persisted `current_revision_ids`; every stored array and issue must equal that result. It then derives the only legal status: `complete` exactly for non-empty, one-to-one, current coverage with a non-null locator and no issues; `incomplete` exactly for empty/missing-only coverage (including empty selection plus unavailable GoalGraph); and `conflict` exactly when extra, duplicate, stale, or non-empty current-membership disagreement exists. A null locator requires `current_revision_ids=[]` and exactly one `current_goal_graph_unavailable`; a non-null locator forbids that issue. The database-aware validator from step 5 then proves that the persisted membership source is authentic. Runtime publication/replay and startup integrity both call these same row-local plus relational validators; the exported Zod schema alone is explicitly not claimed to authenticate an external Artifact.
8. Persist strict schema version 2 of the same `goal_workload` kind: raw ordered briefs, exact producer, exact dispatch/lineage/workflow-occurrence binding, exact selected revision subjects, exact Turn provenance, and the recomputed coverage receipt. Remove the old unbound `session_id`/`final_message_id` top-level shape rather than adding a fallback reader. Make `goal_workload` an immutable Engine Artifact fact alongside the existing immutable graph/lineage facts.

### 3. Reject identity drift before coverage computation

1. The publisher resolves the lineage by the caller's exact Task ID plus dispatch ID; it does not accept a lineage locator, selected set, identity, Session parent, or Worker Turn Descriptor from the adapter as facts. A typed `GoalWorkloadPublicationIdentityError` carries one stable code from `dispatch_not_owned_by_task`, `dispatch_adapter_identity_mismatch`, `child_session_identity_mismatch`, `child_session_parent_mismatch`, `worker_turn_descriptor_mismatch`, or `producer_turn_mismatch`, plus the requested Task/dispatch and exact conflicting authority locators where one exists. It writes no Artifact.
2. The resolved lineage must name the `workload_analysis` dispatch adapter and a projected identity whose `sessionKind` is `goal-workload-analyst`. Its child Session must have that kind and be parented by the lineage's exact Orchestrator Session. The descriptor must be for that child Session and exact dispatch, retain the same Task/workflow occurrence/selected revisions/projected identity, and point at the producer assistant Message's exact user parent.
3. The producer Message must be a completed assistant Message in that child Session, have the descriptor's exact `messageAuthority.user_message_id` as `parentID`, and have the descriptor's exact projected agent. This rejects a prior completed Turn from the same reused Session: same Session is not same dispatch/Turn authority.
4. Wrong Task/dispatch, non-Workload projected identity, wrong Session kind or parent, stale same-Session Turn, and descriptor/message drift are wiring or integrity failures, not model coverage results. The adapter maps the typed publisher failure through the existing `partial` infrastructure path with the real completed Session/Message; it does not publish an incomplete Workload receipt or open workflow successors.

### 4. One replay and settlement handoff

1. Define one pure `goalWorkloadPublicationArtifactID({taskID, dispatchID})` using a versioned domain separator, for example SHA-256 over `opencorvus.goal-workload.publication.v2\0<task-id>\0<dispatch-id>`, and an `art_goal_workload_` prefix. Task plus dispatch without the domain separator is forbidden because deterministic identities from different domain publishers must never alias. The Engine Artifact primary key is the physical per-dispatch publication identity.
2. The `BEGIN IMMEDIATE` transaction reads that identity before recomputing current membership. An exact same-dispatch replay validates persisted Task/kind/dispatch/producer/raw submissions and returns the original locator/status. Any mismatch uses the single `GoalWorkloadPublicationConflictError` with stable `code=publication_payload_mismatch` and safe exact fields `{task_id, dispatch_id, artifact_id, mismatched_fields}`; there is no second identity-drift taxonomy. It cannot append another Artifact. A continuation has a new dispatch ID and therefore a new canonical Workload Artifact while retaining the same workflow-occurrence ID and child Session.
3. This ordering intentionally freezes the first committed publication-time GoalGraph receipt. Same-process/concurrent exact publication calls before settlement may reuse it. If the process dies after Artifact commit but before `recordDispatchSettlement`, normal startup recovery permanently records `partial(recover_dispatch_domain_settlement)` for that exact dispatch. Neither the publisher nor adapter may replace it with `terminal_success` or `domain_incomplete`, even when the already-committed Workload receipt was complete.
4. Recovery from that permanent partial is an explicit Orchestrator continuation: `turn.kind=continuation` names the crashed prior dispatch, reuses its bound workflow occurrence and child Session, creates a new dispatch lineage and Worker Turn, and publishes one new per-dispatch Workload Artifact. The new dispatch alone may settle success. The crashed Artifact and partial settlement remain immutable audit evidence; there is no startup domain-republication owner, hidden retry, settlement rewrite, or reader preference that pretends the original dispatch succeeded.
5. The publisher returns `{locator, deliveryStatus: complete|incomplete|conflict}` from the committed or exactly reused row. It is the only owner of delivery status. The adapter has one mapper: `complete -> terminal_success`; either non-complete status -> existing `DispatchOutcome.domainIncomplete` with domain `workload_analysis` and that exact locator. The receipt retains the incomplete-versus-conflict distinction without widening the global dispatch protocol.
6. The existing generic dispatch settlement remains the sole durable workflow-success authority. Add one `settleDispatchOrReturnExisting` authority in `engine/dispatch-settlement.ts` that uses a single `Database.immediateTransaction`: inside that transaction it reads the occurrence, returns the exact existing durable outcome when present, otherwise inserts the proposed outcome, rereads, and returns the committed winner. `orchestrator/dispatch-agent-tool.ts` consumes this returned outcome. There is no read-then-record gap, so a competing startup `partial` wins instead of surfacing drift. Direct low-level `recordDispatchSettlement` with a different outcome continues to raise its existing ordinary outcome-drift `Error`; this plan does not relabel it typed. Domain publication is a required predecessor to adapter outcome selection, not a parallel settlement writer.
7. A publication/validation/database failure after a real completed Turn retains the existing `partial` infrastructure outcome. Coordination handoff remains distinct and publishes no Workload Artifact.

### 5. Enforce the pre-release schema cut at startup

1. Runtime types and readers accept only strict `schema_version: 2`; there is no version 1/legacy union, coercion, inferred receipt, or dual reader.
2. During `Database.Client` startup integrity validation, inspect every `engine_artifact` row whose kind is `goal_workload` before routes or runtimes can access it. Use the same exported strict version-2 schema as the runtime reader; a version-only SQL predicate is insufficient. Invalid JSON, a missing/non-2 version, or any payload that fails the full strict version-2 schema produces `DatabaseUnavailableError` with `code=DATA_RESET_REQUIRED`, operation `Database.Client.dataIntegrity.goalWorkloadCoverage`, and the exact Artifact ID/path in the diagnostic.
3. Immutable old rows cannot be upgraded truthfully because their selected lineage, producer Turn and coverage receipt were never stored. The only supported action under the current pre-0.1 policy is explicit database reset; storage startup owns this decision, while domain readers stay strict and singular.
