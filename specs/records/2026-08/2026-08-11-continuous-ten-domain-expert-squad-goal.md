# Continuous Ten-Domain Expert Squad Goal

## Recall

### User request

- Continue Expert Squad expansion in repeatable batches of exactly ten.
- Domains must be different from every previously shipped Squad and from each other inside the batch.
- The operator initially requested a web checklist for drag-priority and parallel-lane declaration, then explicitly withdrew that feature and delegated domain selection, order, and batching to the implementation agent.
- Every accepted Squad must own a real package-local Skill and dedicated reusable assets. Generic renamed templates or packages without those resources are electronic waste and do not count.
- Add a dedicated Academic Paper Review Squad covering literature investigation, novelty, presentation, logic, factual errors, citation integrity, and hallucination checks.
- Provide a complete Investment Research team with professional financial Skills. Reuse and strengthen the existing Equity Research package rather than create a renamed duplicate when the shipped package already owns that domain.
- Install every repository-hosted shipped Expert Squad by default for each real project. Installation must remain distinct from active-Squad selection.
- Stop the proposed remote automatic search/install feature for now and continue only the batch-generation goal.

### Acceptance criteria

1. Each iteration records exactly ten non-shipped, mutually distinct domains in this specification before implementation. The implementation agent owns the order and may execute independent package paths in parallel.
2. No web checklist, drag-priority control, parallel declaration, candidate-state persistence, or exported generation declaration remains in the product. Its bilingual routes, component, state model, candidate data, dedicated styles, navigation item, and Market call-to-action are removed as one feature boundary.
3. Every Squad contains one scheduler, at least four domain workers, at least three zero-dependency analysis roots, one explicit join, at least one package-local Skill, and dedicated domain assets. Scheduler and all workers project the same exact package Skill.
4. A batch is not shipped from a planning state. It becomes delivered only when all ten source packages pass the acceptance closure, enter the generated payload from the exact Git index, and appear in manifest-derived public facts.
5. The agent autonomously continues with the next non-overlapping batch of ten after a batch is committed and pushed, unless the operator stops or changes the goal.
7. Prefer pinned, reusable open-source Skills with exact commit, source path, license text, adaptation scope, and exclusions. Use clean-room authored Skills only where no suitable reusable source exists, and record the authority and professional-review boundary.
8. Each Squad passes Skill Creator validation, source Registry loading, Manager installation and immutable revision snapshot, scheduler/worker PromptProfileResolver Skill grants, asset-byte closure, and parallel-to-join topology tests.
9. Each completed batch passes an isolated subprocess production HTTP path across Market discovery, detail, install, and settings projection. Payload and public facts regenerate reproducibly from the exact Git index.
10. User Interface removal acceptance uses the real built site to confirm that Market and global navigation expose no checklist entry and that the removed bilingual checklist routes are not generated. No UI automation, DOM fixture, or screenshot assertion is added or run.
11. A non-implementing independent Agent reviews the complete staged batch, provenance, licenses, package quality, tests, generated artifacts, page evidence, and Git boundary. All valid findings are fixed and re-reviewed before commit and push.
12. A Squad missing its dedicated Skill, dedicated asset, executable parallel topology, source closure, real installation path, or acceptance evidence does not count toward the ten.
13. A full project bootstrap reconciles every bundled payload package into the exact project catalog before configuration validation. A fresh project receives the complete payload; a later application payload adds newly shipped IDs and safely updates only bytes still proven to be previously provisioned. Explicitly removed or locally changed packages remain an operator choice and are never silently reinstalled or overwritten. This provisioning does not change `prompt_profile.active`.

### Hard constraints

- The operator's 2026-08-11 override authorizes autonomous implementation of the recorded ten-domain batch. Drafts remain outside the shipped payload and public count until the complete batch passes acceptance; there is no operator-confirmation gate.
- Preserve unrelated dirty-worktree changes. Do not reset, clean, stash, overwrite, stage, or commit parallel work.
- Do not implement remote automatic Expert Squad discovery or installation in this goal.
- High-stakes domains produce traceable evidence packs for authorized human owners and never issue professional advice, approvals, diagnoses, certifications, filings, transactions, dispatches, or regulated operational actions.
- Academic review preserves manuscript authorization, confidentiality, venue AI policy, bounded-search uncertainty, specialist-review needs, and human editorial authority. Investment research remains source-dated analyst work product for qualified review, not personalized advice or trade execution.
- Package author source, generated payload, installed revision, and public fact projection each have one current owner. No fallback package list, shadow installed state, or duplicate writer is allowed.
- Default payload installation uses one validated, atomically written project runtime ledger. Package bytes remain owned by the ordinary Package Manager and Registry; the ledger records only provisioning disposition and last payload digest, never a second package manifest or catalog.
