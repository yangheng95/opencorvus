## Analysis and scope

The 409 is a correct protection for a different live owner, but re-entry into
the exact same prepared local flow is currently indistinguishable from a new
competing authorization. Abandoning a code prompt or failing to open the
browser also leaves the pending executor renewing until its five-minute cap.
Prior fixes bounded pending lifetime and protected single-use exchange, but
did not provide re-entry or explicit pre-exchange cancellation.

Keep the durable flow store as admission authority. On its typed conflict,
resume only the exact same local executor with matching provider/credential
target, scope, method, input digest, generation and live lease. Pending code
flows can resume; already-claimed auto flows can expose the same URL and await
the same in-flight completion. Code exchange replay and settled-flow replay
retain typed refusals. Other processes/scopes/methods/aliases and automatic
refresh retain the existing conflict contract.

Add one exact-flow cancellation operation for pending authorization through
ProviderAuth and both routes. Use existing atomic failPending ownership checks,
stop renewal and dispose the canonical executor; never cancel an exchange
that won the atomic claim. Terminal cancellation is idempotent. Overlay and
CLI release pending authorization on code-prompt cancellation/browser-open
failure. Actual active-exchange conflicts remain visible in human language.
No lease deletion, force replacement, retry loop, token replay or raw credential
mutation is introduced.

Horizontal audit: global/project/CLI/UI callers, browser and device methods,
pending preparation/expiry/cancellation, in-flight exchange/credential commit,
runtime refresh aliases, repeated/concurrent callbacks and process restart all
retain their exact identities. Task/Mission/Session runtime requests use the
existing refresh owner and gain no new authorization path. A restarted/peer
process cannot resume another process's PKCE (Proof Key for Code Exchange)
closure; a real active owner still returns a typed conflict. The visible
message must distinguish that case from rejected account credentials.
