## Analysis and impact

1. Commit `7b662d3f` appended the Task attachment inventory as a second text Part, while the same runner requires exactly one Part identical to its canonical continuation text. Initial Turns avoid this path; initial-source-read checks and fixture-based settlement tests missed the combination. The conflict is deterministic before acceptance, independent of concurrency, model quality or Browser connectivity.
2. Failed dispatch lineage is durable before worker acceptance. `recovery_authority` identifies that failed dispatch for accounting, but the continuation entry point and runner require the latest accepted descriptor's dispatch ID. Returning only failed lineage misleads recovery of an existing Session. The existing `worker_turn` outcome field can carry the exact accepted descriptor snapshot; no new durable protocol or historical rewrite is needed. Session existence alone must not classify a new Turn as accepted.
3. The observed RequirementSet explicitly declared incomplete because implementation, browser interactions, screenshots, volunteer testing and version locking had not happened yet. These are delivery obligations, not by themselves missing requirement definitions. Clarify the existing prompt and typed finalization contract; never remove unresolved items by host keyword matching or force a complete result.
4. Shared production scope: direct `dispatch_agent`, collection `dispatch_agents`, coordination/prior-dispatch and Mission acceptance continuations use common runner/settlement primitives. Intent, Requirements, Architect, Build, design, research, exploration, integrity, workload and delegated workers share them. Mission host-message appends do not use this worker runner. Task terminalization remains explicit Orchestrator behavior, not an automatic consequence of this fix.
5. Retry/restart uses durable descriptors/settlements rather than transient counters. Recovery snapshots must remain immutable; a later accepted Turn still makes an older source stale. Serial and parallel member dispatches retain the same admission fencing; each Task's own attachments and lineage determine its projection, with no cross-project cache. Terminal replay preserves original receipts and cannot reopen an epoch without the existing authority.
6. Risks: adding attachments must change the canonical text and its descriptor digest together; accepted-Turn evidence must retain failed-dispatch attribution; future verification obligations must remain recorded and must not count as completed acceptance. Browser end-to-end/game delivery remains unverified by these backend checks.

## Implementation plan

1. Construct one canonical continuation text including the current Task attachment inventory before materialization. Keep the exact-one-Part and exact-content checks.
2. At the shared final settlement boundary, bind infrastructure failure to the latest accepted descriptor using the existing `worker_turn` field when the failure does not already identify a Turn. In the dispatch exception path, decide current-Turn acceptance from its descriptor identity rather than a preexisting Session. Clarify recovery selection in tool/schema and scheduler instructions: use `worker_turn.current_dispatch_id` when present; only an unstarted worker uses the reserved failed dispatch identity.
3. Clarify requirement-coverage scope in the base requirements prompt, schema/tool descriptions and Advanced requirements overlay. Add a positive settlement test with future implementation/browser/real-player obligations recorded as requirements while coverage is complete.
4. Add streamed production-path regression coverage for attachment-bearing continuation, preparation failure after an accepted Turn, recovery using the returned accepted identity, exact visible text/digest, individual and collection dispatch, and durable re-read. Controlled provider streams are local contract verification, not real-model or browser acceptance.
5. Run focused tests, typecheck, documentation/architecture checks and relevant build. Review full scoped diff; commit only this task, fetch/merge upstream, inspect outgoing commits and push with hooks. Report separately any unperformed desktop restart or real-model/GUI acceptance.
