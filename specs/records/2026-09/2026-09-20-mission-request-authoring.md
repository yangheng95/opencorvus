## Analysis and impact

The direct trigger is a host byte-substring/ordered-fragment gate over user TextParts. Provider replay separately projects FileParts as attachment-index text. The gate rejects every coordinator addition or paraphrase; repeated source-mismatch instructions cause the Mission to retry copying and misdiagnose failure as missing operator input. Prior attachment and worker-continuation fixes did not remove this earlier Task-creation gate. The current latest case has zero child Tasks, so its failure precedes Task dispatch/queue/worker execution and is not evidence of another worker continuation regression.

Remove the gate from both live creation and shared startup/portable-transfer audit, then remove its now-unused module and dedicated tests. All production creators still use the current creation contract. Preserve exact project/Session/Tool identity, Mission opened-occurrence fencing, held-Squad authority, request fingerprint, immutable accepted Tool input and stored request equality. These retain serial/parallel idempotency, restart recovery, terminal replay and cross-project isolation; wording is no longer a host-authorized state transition. Direct user, Control, Work/Chat and Orchestrator creation contracts remain unchanged. Prompt guidance distinguishes operator intent from coordinator-authored delegation and external content without inventing extra authority. Historical rows require no rewrite; an already waiting Mission still needs an explicitly authorized new continuation after deployment.

Risk: removing the mistaken guarantee also requires removing downstream claims that a Mission Task request is literally user-authored. Keep original user messages unchanged, describe the Task request as the creator's execution assignment, and preserve the obligation to follow real user constraints. Attachments remain independent canonical references and are source material, not independent authorization. Updating benchmark wrappers is necessary so they do not reintroduce the same policy during runtime acceptance.
