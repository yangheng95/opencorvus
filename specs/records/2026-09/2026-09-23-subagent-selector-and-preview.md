## Analysis before implementation

The supplied images and the real historical Task at `/ui` show long cards. The canonical activity record and `subagentProgressEvents` are already bounded to `CONVERSATION_AGENT_ACTIVITY_LIMIT` (24), but 24 single-line rows plus the handoff line/header make a thumbnail hundreds of pixels tall. Existing outer Conversation scrolling deliberately owns wheel/follow behavior; restoring an inner card scrollport would conflict with that contract. The full child Session remains available through the progress-card click into the Right Dock.

Real interaction on a running Task reproduces the selector bug: a pointer click first sets `aria-expanded=true` and renders options, then the popup disappears and `aria-expanded=false` within the next screenshot. Keyboard open also closes shortly afterward while another agent streams. The panel passes freshly projected `sessionRecords()` objects as both `options` and `value` to Kobalte Select. Activity and status updates replace those records although the agent Session IDs and names have not changed. Installed Kobalte's `SelectBase` watches flattened option keys; on an options-array change it calls `setSelectedKeys`, whose selection callback closes the popup by default. The panel's `onChange` then also receives a selected record. The previous panel guard correctly kept transcript identity stable, but did not stabilize the selector's option/value identity during unrelated live updates. Ordinary Kobalte form selectors do not share this live-record input and need no change.

The change belongs to local presentation: derive lightweight Agent options from `(sessionID, agentID)` and retain their array/object identities while that ordered list is unchanged. Resolve status text from the current canonical record when rendering an option. The selected option uses the stable list; changing the Session remains an explicit user action. Display the latest four activity items in a card; the underlying bounded record and complete Session transcript remain the data authorities. A new child Session can update the list; running/idle/completed status, text/tool/patch/file updates, retries, restarts and multiple projects do not need another state source. No production scheduler, queue, Task/Mission/Session occurrence lifecycle, route or persisted data change is implicated. Risk: opening a handoff disclosure intentionally reveals detailed content; the compact default preview remains bounded.
