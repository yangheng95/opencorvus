## Findings and impact analysis before changes

1. **Sample configuration cannot enter the product runtime.** The harness writes `<project>/opencorvus.json`; ConfigPaths.assertCanonicalProject rejects that file and requires `.opencorvus/opencorvus.jsonc`. Prior tests merely read the same incorrect filename back, so they missed actual loading. Fix the harness output and validate its generated project with the real ConfigPaths/Config and expert-squad resolver in an isolated test runtime.
2. **Completed long summaries can be unavailable in the display projection.** Conversation transport omits reasoning and defers large completed Tool state; its bounded input projection omits `summary`. Current extraction depends on that view and a tail window. Use the decision's exact public raw Session Message/Part endpoint as the single completion source, validating all identities. No fallback to narrative or truncated input.
3. **Reasoning-only activity is invisible to the observer.** Message part delta events are live-only, not durable protocol events; adding `lastSequence` alone would not fix this. Read canonical unfinished assistant Messages for active Session occurrences, including their persisted reasoning parts, solely to observe progress. Poll timestamps remain irrelevant and reasoning contents are not copied into Inspect result metadata. Audit all ordinary/suite/AutomationBench solver entry points through their shared client.
4. **Poll interval can consume the entire idle window.** Reproduced with timeout=.04 and poll=.1: exactly one status query then OpenCorvusTaskTimeout, despite a completed second observation being available. Validate the configuration before task creation instead of silently changing operator values.
5. **Scoring policy can drift with process environment.** The official rubric reads AUTOMATIONBENCH_STRICT_ASSERTIONS at import; disabling it converts handler exceptions into business failures. Require the actual loaded strict assertion policy and record the invariant, keeping checker errors unscored.
6. **A running evaluation copies mutable squad sources again for each sample.** Editing the selected squad after constructing the solver changes later samples despite the recorded original squad version. Freeze the package bytes when constructing the sample environment and use that one immutable input for every occurrence. Test original and copied version/prompt outputs after editing the operator source.

Cross-cutting audit: no product scheduler/queue/wake defect established; these are harness/config/read-projection mismatches.
