## Analysis before implementation

Observed: adapter.py starts one absolute deadline before POST /task and shares it through polling and terminal projection. Active streaming cannot extend it. solver.py isolates retry directories but reuses requestID from sample UUID alone. A failed Task can select unrelated final text as a fallback. AutomationBench official scoring and sample setup are absent from Inspect.

Triggers/root: long active tasks exhaust a wall-clock budget; repeated solver invocation reuses Task request identity despite a new project; non-completed lifecycles select best-effort assistant text. The earlier adapter addressed wiring and provenance, not an activity-aware observer or stateful benchmark environment. Older benchmark runners do not provide an Inspect dataset/scorer contract.

Impact: generic solver, generic/suite configuration and provenance, request/terminal/error contracts, focused adapter tests and documentation. No product scheduler, queue, wake, restart or terminal convergence defect has been established. This is an observer/identity defect; audit public Task and Mission status projections, Task/Session conversation occurrence binding, retries/epochs, sequential/parallel project ownership and normal/error cleanup. Production runtime scheduling remains untouched unless runtime evidence establishes a defect.

The new benchmark is a local co-located harness: one official in-memory world and loopback Model Context Protocol (MCP) service per sample, project-scoped configuration and a narrow API-only squad. Official rubric functions remain the sole scoring semantics. No private score endpoint is exposed to agents. Local project isolation is not operating-system isolation; publish this limitation and do not call these leaderboard-comparable results. Existing Harbor/external-agent historical integrations are not execution dependencies of Inspect and are not replaced in this task.

Risk/unknowns: exact official package compatibility and current MCP transport must be checked locally; no real Provider behavior or squad reasoning can be established without the explicitly declined model run. Cancellation must close only harness-owned MCP services and preserve Task identities/errors; the adapter must never cancel user-owned product Tasks silently. Timeout is an observation failure, not a business zero. Inputs, original prompts and official checkers must be preserved. No unrelated cleanup.
