## Owning correction

GitHub permits duplicate draft Releases for the same tag and exposes a new draft
to the Release inventory only after a short delay. The single publication claim
now reads the complete paged inventory before mutation: an exact same-run/source
draft is reused, any foreign/duplicate/malformed record fails closed, and creation
occurs only after the inventory proves absence. After one create request, the
same inventory is retried with a bounded backoff; the code never issues a second
create to compensate for visibility delay. The build workflow serializes all
release runs with a repository-wide concurrency group so two supported release
runs cannot race the precondition. No alternate endpoint, fallback writer or
manual publication path is introduced.

### HTTP root and implementation plan

- The signed deployment archive deliberately normalizes every file mtime to
  `1980-01-01 UTC`. Caddy's default file validators use filesystem metadata, which
  cannot distinguish changed same-size mutable documents across such releases.
  Live `/` returns `Last-Modified: Tue, 01 Jan 1980 00:00:00 GMT`; a request with
  that `If-Modified-Since` returns 304. Fresh GET returns current bytes. Equality
  of the prior browser's ETag was not captured and is not asserted.
- Mutable GET/HEAD document paths (directory indexes and `.html`) and the two
  publication pointers (`/downloads/latest.json`, `/expert-squads/catalog.json`)
  must return current bytes with `Cache-Control: no-store, max-age=0`. Remove
  metadata-based conditional request validators on those paths before serving,
  and suppress their metadata response validators. Keep content-addressed Squad
  archives/catalogs/signatures/bundles immutable and retain normal static asset
  and range behavior. No alternate writer, cache-busting URL, content sidecar,
  archive timestamp change or privileged manual server operation is introduced.
- The existing activation test substitutes a Caddy executable and therefore does
  not prove HTTP behavior. Add a non-UI integration test using a real Caddy
  process and the adapted production routing configuration on an isolated local
  listener/root. Verify equal-size 54-to-61 bytes with identical mtimes, old
  conditional requests yielding 200/current bodies, HEAD metadata, both locale
  indexes, pointers, immutable 304 and asset range responses. First reproduce
  failure against the unchanged configuration, then apply the serving correction.
- Local Windows and WSL have no Caddy executable. Use one checksum-verified
  official prebuilt Caddy tool in a retained local tool directory; no package
  installation, dependency resolution or native compilation. The website CI
  must execute the same real HTTP test before deployment with a pinned binary.
- After focused verification, update current serving architecture, obtain the
  required uninvolved read-only review, commit/push via normal hooks and the
  signed workflow. Verify ordinary reload in the same previously cached browser
