## Packaging version mismatch analysis

First build's native service `--version` returned `0.0.0-main-202609210222` although synchronized package/Tauri versions were 0.1.10. `package-local.ts` passed only Cargo placement; build-overlay forwards its environment and `packages/script/src/index.ts` uses a branch/timestamp preview when OPENCORVUS_VERSION is absent. The native CLI packaging owner already has `nativeBinaryBuildEnv`, which derives the version from the canonical package and selects local channel. Reuse that helper in the local desktop package entry, validate explicit override equality with package metadata, and pass it through both native commands. Add positive environment/error-contract tests and document this contract. Stop only the verified current task rustc process, then rerun the original full package command. This prevents delivering mismatched desktop/service versions without changing general developer build semantics.
