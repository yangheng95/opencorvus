## Analysis

- Observable failure: protocol identifiers and meaningful message text have equal weight, run together and consume the short expanded viewport before the reader reaches the body.
- Direct trigger: renderSchedulerParticipantMessage joins every protocol field and body with a single newline. TextPart renders Markdown with standard soft-line behavior (`breaks: false`); ordinary paragraph CSS collapses these line endings. DelegatedContextDisclosure additionally forces a 224px scroll region and a 760px maximum width.
- Root cause: the canonical scheduler prose does not express paragraph hierarchy, and the generic context reading surface discards authored line boundaries and enforces a fixed viewport. The earlier fix only reduced the collapsed toggle's visual emphasis; it did not change these contracts.
- Scope: the one canonical producer feeds both Task root ingress and Mission wake, including request/reply/notification. It continues to produce the exact visible persisted/model message once; body, ownership, correlation, grants and delivery semantics stay intact. Shared context CSS covers main and child transcripts plus progress-card input previews. Ordinary assistant Markdown and code whitespace keep their current rules.
- No scheduling, queue, recovery, concurrency or terminal-state anomaly has been observed: only message serialization/presentation changes are justified. No API/schema/data migration, credentials, new configuration, runtime restart or release is required. Existing historical text is immutable and remains in its original ordering; CSS restores its authored newlines without recognizing protocol keywords.
- Risks: multiline subject/Markdown delimiters, long correlation identities on narrow surfaces, code blocks/lists in body, unwanted blank fixed regions on short input, and drift between model-visible/persisted/display text. Use Markdown literal escaping for the plain subject and a JSON trace block for exact values; preserve message body byte-for-byte inside its own section, natural layout, and shared serialization. Focused non-UI protocol checks verify source/correlation preservation; screenshot review alone owns UI acceptance.
