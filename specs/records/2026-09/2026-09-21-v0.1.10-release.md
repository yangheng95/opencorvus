### Bounded dependency reproduction

Used the real rpm 0.16.0 PackageBuilder and flate2 1.1.1 with deterministic 1/4/16 MiB inputs in an isolated Cargo project. Original gzip(6) builds took 46/255/2632 ms. The observed original write order hashed 16,816,850 / 268,497,788 / 4,295,688,483 bytes respectively, with 31/127/511 short writes; its digest disagrees with one hash of the actual input. This confirms quadratic redundant hashing in the locked dependency, rather than establishing an unmeasured compression-level explanation.

An isolated, checksum-verified copy of rpm 0.16.0 changed only the writer to call the inner write first, hash `buf[..written]`, and return `written`. Actual gzip RPM builds then took 37/125/519 ms. Its stored uncompressed payload digest matches an independently decompressed CPIO archive, whereas the original implementation's does not. Both variants return Ok from the library's `verify_digests`: that routine checks the compressed payload digest but does not verify PAYLOADDIGESTALT. These results establish the dependency defect and candidate correction; they do not prove native Linux installation failure or a measured 200+ MB native bundling improvement. Do not conflate the backup digest defect with corruption of extracted files or the compressed-payload checksum.

Evidence remains under ignored `.scratch/rpm-probe` and `.scratch/v0.1.10-local/rpm-probe-integrity.log` / `rpm-probe-corrected.log`. Cargo uses public dependencies and no model credentials.
