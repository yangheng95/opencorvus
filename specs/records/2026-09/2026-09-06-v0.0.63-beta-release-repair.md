Status: the third source-CI corrections pass the bounded affected matrix, typechecks, schema contract, repository checkers and fresh independent exact-tree review. Hosted source CI, binary publication and website activation remain pending. Public `v0.0.62-beta` binaries exist, but its source checks and repository-dispatched website activation did not fully converge. The immutable release and tag will not be rewritten. This cut repairs the exact failures and publishes a new patch identity only after clean cross-platform and independent review evidence.

## Current-source analysis

### Observable effects and direct triggers

- The website candidate reaches server activation, validates Caddy configuration and creates a database rollback backup. Registry import then compares the candidate Evolution Lab revision with the existing immutable row and detects different package/facts/archive digests for the same namespace, id and version. The deployment health probe receives HTTP 502 and the workflow exits nonzero after rollback.
- Clean Linux generation modifies three tracked artifacts after checkout. This proves the committed tree is not a fixed point of the canonical generator even though the narrower local generator previously passed.
- The unit failures occur only on specific hosted platforms, so they require exact persisted-fact and filesystem-owner analysis rather than weakening tests or treating runner ordering as portable.

### Root control and data flow

- Built-in package source changes must flow through one canonical generator that assigns a fresh internal revision and regenerates every derived payload/registry projection before release. Reusing an old revision creates a real immutable-identity collision in the website database; the server rejection is correct.
- Release validation must invoke the same canonical generation authority as push CI. A helper that checks only a subset of generated artifacts cannot establish release closure.
- The platform failures sit on three durable ownership boundaries: Worktree release, Global Task request/resolution replay, and Task process-binding admission. Each must converge from persisted ownership facts and platform-stable paths/identities. Test-only sleeps, relaxed invariants and compatibility readers are not acceptable fixes.

### Why the prior cut did not root-cause this

- The prior cut validated a generated-artifact helper that did not execute the full root generation workflow. It therefore certified a narrower closure than CI and website import actually consume.
- The prior local matrix ran on Windows. It established broad functional coverage but could not prove Linux filesystem-owner teardown or macOS path/identity behavior. The remote matrix is part of release acceptance and its failures invalidate completion.
- Binary build success proves native compilation and asset publication, not source fixed-point generation, cross-platform unit convergence or website database acceptance.

6. Publish `0.0.63-beta` through the canonical release workflow from the exact verified remote source. Verify tag/source/assets/checksums/updater, wait for the signed website workflow, and manually inspect the real English and Chinese pages plus downloadable assets.
