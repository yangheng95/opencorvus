## Analysis

- Observed: fullscreen ConfigDialog covers the same left edge as the rail. Scheduled is a tab of this shared surface, so the defect also covers General, Squad Market, Usage, About and other settings pages.
- Direct/root cause: the page reserves titlebar height but keeps generic Dialog `left: 0; width: 100%`; the earlier rail relocation only reserved width in pane geometry. App's isolated stacking context also means arbitrarily increasing a descendant rail z-index cannot establish a coherent page boundary against body-level portals.
- Related control flow: Chats and Mission Board only change primaryWorkspaceSurface, leaving an open ConfigDialog in front. Their active states also ignore config state, so the hidden underlying conversation is incorrectly marked selected. The existing non-modal settings dialog already allows outside rail interaction once geometry exposes it.
- Impact: App owns one persistent rail beside a bounded page stack. The existing conversation/project/dock row and ConfigDialogHost are sibling pages inside that stack; the settings host renders an ordinary region, not a body-level Dialog Portal. Keep the underlying conversation mounted but inert/hidden while settings is open, retaining pane geometry and stream state. Reuse closeConfigDialog/native-surface reveal and current config/primarySurface state; no schema, API, persistent-state, scheduling, queue or provider changes. True action dialogs retain their normal modal focus contract; this is global page navigation, not a new modal bypass.
- Risks: covering settings controls instead of reserving width, disabling pointer events on the rail, wrong active state, toggling project-list width shifting settings, portal menu layering, and native surfaces staying occluded after leaving settings. Check these through actual page transitions, including keyboard navigation and rail More menu.

## Plan

1. Mount a page stack next to the existing rail in App. Keep the primary row mounted inside it; render ConfigDialogHost inline as its sibling page when open. Replace fullscreen-dialog CSS with parent-bounded page styles and remove the superseded offset/backdrop rules. Preserve page autofocus, Back/Escape and contextual focus restoration, plus nested dialogs' focus ownership.
2. Route Chats/Mission Board clicks through closeConfigDialog before the existing primary-surface action; derive active rail items from config state and primary surface without a second router.
3. Update architecture, run type/CSS/build/docs checks; start isolated development `/ui`, inspect Scheduled, General, Expert Squads, About/Usage and Mission Board, navigate back through the visible rail, test collapsed project list and dark/light rendering. Record screenshot evidence; no UI automation tests.
4. Stop owned acceptance processes, commit task files, fetch/merge upstream, audit outgoing changes and push with normal hooks.
