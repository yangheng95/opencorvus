## Root cause and correction

`claim-publication` atomically created the draft with the exact workflow run and
source receipt, then `readPublicationOwner` used `GET /releases/tags/{tag}` for
its canonical reread. GitHub returned 404 for that draft while
`GET /releases` exposed it. The correction makes the paged Release inventory the
single read authority for draft and public states, selects exactly one matching
tag, validates the complete owner/prerelease record, and fails closed on missing,
duplicate, malformed or over-bound inventories. MSI and package version projections
remain unchanged apart from the synchronized `0.0.60-beta` identity.

The first 60 run proved a second boundary: a just-created draft is not immediately
visible even in the Release inventory, and GitHub permits another draft with the
same tag. A failed-job rerun therefore created a second same-owner, zero-asset
draft; the corrected uniqueness guard rejected both before upload. Exact duplicate
ID `383089318` was deleted after proving both records had the same run/source
receipt and zero assets; original draft `383088503` and the immutable tag remain.
The next correction must read the complete inventory before creation, reuse an
existing exact-owner draft, create only after a proved-missing result, and wait a
bounded interval for the same inventory to expose a new draft. The build workflow
must serialize release publication runs so two workflow runs cannot race that
precondition. No endpoint fallback or second publication authority is allowed.
