## Evidence

First portable-walker regression run exposed real EPERM contention between concurrent removers (rather than native EFAULT). The shared async helper therefore owns the prior isolated-runtime's bounded five-second EBUSY/EPERM/ENOTEMPTY retry policy; it retries the same manual walk, never ignores an error or switches implementations. This preserves the documented recursive-removal contention contract and removes the duplicate outer-runtime policy. EFAULT remains fatal. Synchronous teardown uses the library's synchronous walk and native error handling. The regression must pass under genuine competing filesystem calls before this repair is considered locally verified.

Windows reproduction on Bun 1.3.14: 150 single removals of nested read-only files succeeded; 150 rounds of eight concurrent removals produced 136 EFAULT results. Identical Node 24.15.0 experiment had all operations succeed. The original isolated session-prompt-idempotency file passed all 13 tests / 21 assertions (86.86 seconds) locally. This reproduces the lower-level defect, not proof of which external handle caused the historical hosted event.

Primary [Bun PR 39710](https://github.com/oven-sh/bun/pull/39710), still unmerged, identifies Windows STATUS_DELETE_PENDING during recursive directory opens, incorrectly mapped to EFAULT on 1.3.14; it covers concurrent deletion and transient external handle holders. [Issue 39708](https://github.com/oven-sh/bun/issues/39708) reports the same hosted single-remover teardown failure. Switching rm to rmSync would retain the defective recursive implementation.

Repair decision: declare the already-locked rimraf 5.0.10 as a direct util dependency (no version upgrade), use its public manual/manualSync tree-walk APIs as the sole shared cleanup implementation on every host. They perform individual filesystem operations rather than Bun's defective native recursive rm. Retain thrown failures, literal paths (glob false) and root protection. Route isolated-runtime removal through the same helper after its existing authority validation, deleting the duplicate retry loop. Add real filesystem regression tests including concurrent removers, nested read-only files, symlink/junction boundary preservation and repeated settled deletion. Application production deletion owners and Task/Mission/Session lifecycle are not changed: no evidence of their cleanup ownership overlap with the failed fixture was found. Parent runner cleanup occurs after child settlement; Instance and process disposal finish before fixture removal.

The lockfile change can trigger the repository's existing website push-path check; no website publication is dispatched or enabled by this task. Native debug/source/tag remain untouched. CI logs use per-file start/done durations and Turbo stream order; full Windows job has a finite 180-minute bound, preserving existing per-file inactivity ownership. Documentation-only classification is computed from the exact Git change range, with docs checks/security still executed and expensive native tests/build/type generation reserved for code changes; compiled Markdown outside docs/specs/root prose remains code.
