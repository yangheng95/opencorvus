## Analysis before implementation

The supplied dark About screenshot and real light source page show author links floating beside a sentence, an eight-row Runtime table with large blank vertical bands, two indistinguishable GitHub buttons for author and repository, and lower-value technical fields consuming the first screen. The current design was composed from generic SettingsRow values; prior readability work protected the long directory value but did not establish visual hierarchy. The runtime facts and update status come from the existing stores and component. A product masthead plus compact key status, with technical facts and shortcuts disclosed below, can improve scanning without inventing facts or removing access. A fresh dark preview also exposed an existing contradiction: the global connection badge was Online while About rendered Disconnected because it used `appStore.config !== null`; About must read the canonical connection status instead.

The real Usage page has 741m as a small unframed total, repeats the exact 741,147,559 Token in an equally weighted five-column metric strip, then uses thin separators and large whitespace before a low-emphasis heatmap. This weakens the primary measured value and the actual period/coverage context. All values are already derived from the canonical `UsageStatistics`; Official Provider data are explicitly comparison-only and must remain separate from local totals. Reorganize only presentation: one prominent period summary, a compact supporting metric strip, and clearer section surfaces for activity, composition, provider mix and model details. Retain zero-data and error states, all exact values, period controls, refresh, and the single reading column.

The Provider screenshot's error is produced when `Provider.refreshModels()` cannot resolve an OpenCorvus Provider key before calling `/models` and `/model/info`. Other Providers being Connected is independent. Architecture explicitly makes this action OpenCorvus-only while `refreshCatalog()` is separate. The generic `Refresh models` menu label makes the expected scope unclear; correct that label, refreshing state and error prefix in both locales. Do not add fallback credentials, broaden the endpoint, or change authentication behavior.

No scheduling, queue, Task/Mission/Session lifecycle, persistence, route or model-streaming logic is implicated. Material risks are hiding technical facts, collapsing official reconciliation into local spend, truncating values at desktop widths, and changing the user's saved theme while inspecting. These are addressed by disclosure, exact-value presentation, independent source sections and isolated theme URL previews.
