## Analysis before changes

Observed: a read-only call to current CompactionHandoff.isValidSummaryMessage accepted finish=length. beforeAssistantCompletion only excludes error, empty continuation and tool-calls; publisher then trusts the same predicate. No reduction check precedes checkpoint publication. requestBudget counts only messages before the helper reader schema is built. The ordinary estimator counts system/tools/media separately. ContextBudget subtracts a capped reservation from input instead of intersecting independent input with context minus actual output, contradicting current provider architecture.

Tool pruning currently only projects history already covered by a checkpoint. Further source inspection confirmed a separate, already-correct summarizer-input reduction: outputs above 1,000 characters become bounded previews with exact reader references. That existing path is reused and verified, not duplicated with a second pruner. Tail candidates include assistant steps but selection/filtering only accept a user boundary, so a long autonomous turn can lose its entire recent working segment. Screenshot summaries retain filenames rather than usable source references. Summary inputs reformat history; preserving exact provider warm prefixes is not compatible with this bounded transcript/visible reader design and is not claimed.

Root causes: checkpoint validity is structural rather than terminal/compression validity; request accounting has two implementations and two envelope scopes; user-only tail reconstruction diverges from assistant-step selection. Oversized persisted results already have bounded previews; the missing safeguard was complete envelope accounting, including subsequent exact-reader steps.

Horizontal audit: native Chat/Work/Mission and Task-root/worker Session occurrences enter the same control owner. Code tracing covers normal reuse, repeated checkpoints, manual requests, overflow recovery, lease recovery and failure/cancellation ownership. Focused runtime tests cover durable lease expiry/recovery, repeated checkpoints, the exact-reader loop, failed controls/atomic publication and fork/project ownership. This run does not simulate an operating-system process restart or every project kind concurrently. No per-kind route, replay or scheduling workaround is introduced. Persisted terminal facts remain authoritative. Parent workspace modifications are outside this repair.

## Plan

1. Centralize normal completion classification, reject truncated/abnormal summaries with a typed error, and make memory reconstruction use the same predicate. Validate net provider-facing token reduction before publishing a checkpoint. Keep the last valid checkpoint on all failures.
2. Extract one pure request-payload estimator from SessionLoop; count system, messages, exact active tool schemas and media in one envelope. Enforce final request capacity after system/parameter hooks using the actual output cap, including reader steps. Correct input/context/output math without learning an alternate limit. Preserve honest estimated-media reporting.
3. Make recent-tail selection and replay share a valid boundary contract for users and completed assistant steps. Retain a proportional recent budget rather than a universal 8K ceiling, while honoring explicit settings and keeping paired tool outcomes together.
4. Budget the summarizer transcript before calling the model. Use the existing exact persisted-result reader for omitted result bodies and authoritative pagination; retain identifiers/outcomes/references and recent evidence. Avoid a second invisible history store or a new generic retrieval tool. If indivisible non-tool input still cannot fit, return an explicit typed capacity failure.
5. Carry canonical attachment references and guidance-reload/current-state caveats in the summary instructions. Keep snapshot/observation authority separate from historical summary facts. Fix obsolete touched compaction checker(s) against the current natural-summary contract.
6. Add focused positive contracts for valid success, output-limit failure, nonshrinking output, complete request accounting, bounded inputs, tail/replay, memory recovery and exact controls. Exercise the real HTTP streaming adapter, processor, database publication, history reconstruction and continuation against a task-owned deterministic local provider (not a claim about live-model semantic quality).
7. Update current architecture and indexes; run focused tests, typecheck, docs/architecture and required push hooks; commit only compaction task files, preserve parent edits, fetch/merge/audit/push.
