2. Complete-file replacement plus a global `conflicting_instruction` Boolean-like claim encouraged broad rewrites and only checked whether any file stopped being a parent prefix. An unrelated README edit satisfied that claim while the actual conflicting prompt remained unchanged; this was reproduced against the production function. .3 also removed working discovery prerequisites when replacing entire role prompts. 3. The actual action owner and decisive negative evidence were not consistently identified. .5 wrote its explicit no-question rule in the executor while the orchestrator asked a question. Its verifier omitted a cancellation email used by the executor and rejected an officially successful action. More generic checklists did not constrain these specific decisions. These behavioral gaps belong in the author's causal method and fresh validation, not a host-side workflow gate.

Existing primitives already solve lossless evidence identity and paging: `artifact_snapshot` captures immutable bytes, `artifact_read` exposes bounded byte chunks/continuations, and the persisted read-fact resolver proves complete same-Turn coverage for an `artifact_read_ref`. Reuse them. Do not modify the general file reader, reformat old business outputs, duplicate the Artifact store, or add a special benchmark reader. The generic edit Tool has fuzzy replacement paths, unsuitable for exact immutable-parent edits; a small exact substring operation in the revision service has a different integrity contract and must not inherit those paths.

Implementation review also found that this module's old path check only rejects POSIX absolute/traversal/backslash forms; it admits `.` and Windows drive/alternate-stream/device syntax before candidate materialization. The repository's existing `isCanonicalProjectRelativePath` already defines the cross-platform contract used by Artifact resources. This is in-scope edit integrity, not a new path policy or an assertion that an escape was exploited.
