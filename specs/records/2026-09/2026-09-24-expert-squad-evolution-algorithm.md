## Analysis before implementation

1. The author received ordinary JSON files whose Tool-output strings occupy long lines. The general reader intentionally clips each line at 2,000 characters and each page at 50 KiB. Increasing a line limit cannot recover those suffixes. Authors also stopped before completing some pages. Original bytes were intact. The feedback publisher recorded no consulted evidence, so publication could not distinguish a fully consumed immutable source from a claimed read. Earlier prompt advice about “read the evidence” changed neither representation nor provenance.
2. Complete-file replacement plus a global `conflicting_instruction` Boolean-like claim encouraged broad rewrites and only checked whether any file stopped being a parent prefix. An unrelated README edit satisfied that claim while the actual conflicting prompt remained unchanged; this was reproduced against the production function. .3 also removed working discovery prerequisites when replacing entire role prompts. The current host check cannot judge semantic conflict and must not pretend to do so.
3. The actual action owner and decisive negative evidence were not consistently identified. .5 wrote its explicit no-question rule in the executor while the orchestrator asked a question. Its verifier omitted a cancellation email used by the executor and rejected an officially successful action. More generic checklists did not constrain these specific decisions. These behavioral gaps belong in the author's causal method and fresh validation, not a host-side workflow gate.

Existing primitives already solve lossless evidence identity and paging: `artifact_snapshot` captures immutable bytes, `artifact_read` exposes bounded byte chunks/continuations, and the persisted read-fact resolver proves complete same-Turn coverage for an `artifact_read_ref`. Reuse them. Do not modify the general file reader, reformat old business outputs, duplicate the Artifact store, or add a special benchmark reader. The generic edit Tool has fuzzy replacement paths, unsuitable for exact immutable-parent edits; a small exact substring operation in the revision service has a different integrity contract and must not inherit those paths.

Implementation review also found that this module's old path check only rejects POSIX absolute/traversal/backslash forms; it admits `.` and Windows drive/alternate-stream/device syntax before candidate materialization. The repository's existing `isCanonicalProjectRelativePath` already defines the cross-platform contract used by Artifact resources. Replace the local duplicate validator with that shared predicate and report `invalid_path` at the exact edit index. This is in-scope edit integrity, not a new path policy or an assertion that an escape was exploited.
