## Analysis before implementation

The persisted Task `tsk_g00VW3XOrY00v1xt9rop` received `task.cancellation.requested` at 2026-09-23 15:54:17.430 UTC, with source `task.cancel`, actor `user`, surface `overlay.work_ledger`, and request ID `72ac6453-34fc-48bf-92de-593660203086`. The backend received a browser preflight at 15:54:17.409 and POST at 15:54:17.410. Our browser-tool transcript shows a click on that Task's title button at 15:54:17.180. The Request then interrupted the streaming `visual-reviewer`; its abort/error events followed the request. This is high-confidence attribution to our page-inspection click, not evidence that the human user pressed Cancel. Neither the server log nor the browser transcript records the final pointer-down target, so the exact interception mechanism remains an inference.

The Work Ledger row's main button shares space with an absolutely positioned hover/focus action rail. Before hover the rail is transparent and noninteractive; hover changes its pointer events and also changes the title body's padding, so the main button geometry changes between targeting and pointer-down. The rail has higher stacking order. This can expose a stop button beneath a pointer intended for the title. The stop button's handler directly invokes the Task/Mission/Chat stop callback after one click. All three tooltips say two clicks are needed, but `WorkLedger.tsx` has no confirmation state and the shared `Button` has no such behavior. The earlier API provenance work correctly recorded the request; it did not prevent a mistaken UI activation.

This is a shared Work Ledger UI interaction defect, not a Task/Mission/Session scheduler or terminal-convergence defect: the Task's cancellation request, terminal event and worker abort have coherent ordering and matching request ID. The same hover rail and one-click handler affect Mission and Chat stop. Other Task cancellation sources (composer, API, Mission lifecycle) have distinct surfaces and are outside this UI repair. The existing cancelled Task has no implicit undo and must not be restarted by this change.

## Plan

1. Give the Work Ledger main button a stable, non-overlapping hit area by replacing the multi-icon hover rail with one narrow actions-menu trigger and reserving that trigger's width inside the row. Keep the same actions in the menu and preserve row bounds and the activity-indicator anchor. Update the panel architecture contract to match.
