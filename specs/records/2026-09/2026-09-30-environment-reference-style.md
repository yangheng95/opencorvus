## Analysis

- Observed: the current header combines a generic Environment title, disclosure, Refresh and Add controls. The body repeats the project directory and mixes permanent facts with setup/tool/commit commands. Its dense six-pixel separators and generic Subagents icon do not reproduce the reference.
- Trigger/root: TaskDirBar's PanelShell owns that information order, while scoped conversation CSS owns its compact geometry. The header's three-column grid receives up to four controls. This is a presentation/ownership issue, not a scheduler, provider, queue or persistence defect.
- Current contracts: Changes uses currentChangeGroups/summarizeChangeGroups; VCS is directory-scoped; agents use the selected conversation's actual child sessions; Sources uses actual Task attachments; Goals/worktrees/tools/deliveries are conditional real resources. Keep these authorities and their complete bounded lists. This task does not broaden source ingestion or invent URL/search evidence.
- Mounting: keep the existing anchored HoverCard and its pin/disclosure lifecycle. Mount the command menu as a child of its content so closing/unmounting the parent disposes it. Use the shared accessible DropdownMenu and owner-aware native-surface occlusion for this HTML menu. Existing Local/branch native WebviewWindow menus remain their sole transport; an HTML stacking number cannot cover a native Browser child surface.
- Impact: TaskDirBar and scoped conversation CSS, plus current panel architecture. No server/API/schema/config-policy changes. Reuse existing translated action labels. Preserve non-Git, disconnected, error and collapsed states, all existing editor/commit/dock entrypoints, and project changes during an open menu.
- Risks: hover closing the panel while entering the child menu, asynchronous native hide completion reopening a disposed menu, clipped/out-of-viewport menu, hidden commands becoming unreachable, misleading empty-section decorations, long names/counters and agent previews overflowing. Verify real interactions/screenshots; native OS restoration is only claimed if exercised in a native host.

Start an isolated development server with persisted presentation data (no model calls), interact with the real page and review screenshots in both themes, including child-menu/editor dismissal and parent mounting.
