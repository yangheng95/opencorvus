Repository search found `ProtocolStore.publishEventSideEffects -> clearTaskLiveReplay` on every completed/failed/cancelled Task. It cleared both payload retention and the per-Task live sequence while retaining the process-wide live epoch. The open HTTP SSE (Server-Sent Events) subscription and frontend each retained the old high-water cursor, so new user/assistant events restarted below it and were dropped. This also applies to Mission-owned reopened Tasks, terminal Tool settlement, parallel Task streams and reconnects; Session-only streams do not allocate Task live sequences. A process restart already changes the live epoch and is correctly handled by expiry. Clearing a payload window must preserve its sequence identity and advance its retention floor.
