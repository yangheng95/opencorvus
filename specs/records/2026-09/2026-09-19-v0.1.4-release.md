## Startup acknowledgement blocker

Attempt 2 failed identically in job `105892045435`. A bounded real-filesystem
probe of the unchanged SDK channel on Linux x64 Bun 1.3.14 reproduced 19
timeouts in 20 atomic publications. Instrumentation showed the temporary-file
rename event, an empty receipt read, then a wait that missed the final receipt
rename. The async-iterator consumer leaves an event-consumption gap while its
file read is in flight; arming one next() before each read did not close it.
A separate Node/Linux already-published probe also held iterator return()
until a 1-second abort, demonstrating a second cleanup dependency on pending
iteration. Windows/Bun and a fast Linux/Bun prepublished probe completed;
those timings did not exclude the shared defect.

Superseded callback experiment (not the final implementation): use one continuously registered node:fs watch
callback for the existing receipt channel. Coalesce reads while remembering
events arriving during a read, close the watcher directly on exact receipt,
typed failure or caller cancellation, and preserve schema/occurrence/PID
contracts. No polling, fallback receipt authority, longer timeout or native
matrix bypass. Focused positive tests cover atomic and prepublished receipts,
independent concurrent launches, cancellation and subsequent launches, on real
Windows and Linux filesystems with Bun plus Linux Node. Existing negative-only
partial/absent receipt assertions in the touched test file will be replaced
by successful complete-receipt observations.

Shared audit: all SDK managed-server starts and native first-run/restart
acceptance share this channel; Task/Mission/Session scheduling begins after
this admission and was never reached in either failed occurrence. Directory
and occurrence identity isolate projects/concurrent launches. Success, failure,
caller abort and repeated startup need explicit watcher cleanup. The separate
Windows process-supervisor ready watcher has its own abort controller and
aborts it before iterator cleanup; it is not the failed SDK channel. Ordinary
HTTP connections and in-process server restart handoff do not consume the SDK
watcher. The repair touches only the shared SDK startup receipt owner.

The existing draft/tag is bound to the original candidate. A repaired source
requires a new candidate; no immutable reference will be silently rewritten.

The callback-only candidate fixed Node's pending iterator cleanup but did not
fix Linux/Bun delivery: the same real atomic probe still timed out, and direct
callback diagnostics showed only the temporary-file creation notification.
Node delivered all four temporary-write/final-rename notifications for the
same operations. Therefore the notification loss is below the iterator, and
the initial iterator-gap diagnosis was incomplete. Replace directory event
watching with one `fs.watchFile` stat observer on the authoritative receipt,
using a local 50ms cadence only during launch admission. This replaces the
event watcher entirely; it is not a fallback or second authority. Direct
receipt reads continue to validate all contents. Node documents stat watching
and listener-specific cleanup at https://nodejs.org/api/fs.html#fswatchfilefilename-options-listener.
The unchanged startup deadline still bounds observation. Repeat the exact
Linux/Bun atomic probe, Linux/Node probe and Windows unit contracts.

The stat-observer candidate passed all 11 Windows receipt contracts and SDK
typecheck. The subsequent Linux command did not execute: WSL returned
