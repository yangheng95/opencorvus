## Diagnosis and impact

The runtime receipt owns no business resource. It names its own process occurrence, but peers interpret its 90-second wall-clock expiry as authority to abandon that process's dispatches. Sleep pauses the 30-second renewal timer; renewal then rejects the expired receipt and permanently poisons the backend occurrence. Project bootstrap inherits that refusal while global database health remains successful. A later restart can recover service but does not correct the original false-death decision.

The former repair fixed Project disposal expiring a sibling Project's owner by sharing a reference count. It retained expiry as the death predicate, so sleep and long scheduling pauses remain broken. The existing operating-system observer already distinguishes exact live, dead/reused and unreadable-but-live physical owners and is used by Session prompt, Project/Workspace recovery and parent supervision.

All production Task-control entrance paths use the same registration and peer observer; normal/terminal scans, retries, serial/parallel tasks and multiple Projects must use that one predicate. Actual work-admission leases still govern exact task occurrences; their expiry does not justify declaring the whole process dead. Network transport recovery and replay of external tool side effects are outside this fix.

## Plan

1. Replace renewable process liveness with a durable physical identity receipt using the existing `runtime_process` storage namespace and columns. Store the exact PID, start identity and occurrence in its owner field. Use the existing permanent-fence representation solely to fit the shared receipt storage; no heartbeat renewal or time-based process death remains. Preserve the receipt when Project references reach zero: Project disposal is not process death. Reopening the same process reuses its identity.
2. Assert exact registered identity and active local reference at Task/dispatch admission. Peer recovery observes the physical owner through the shared OS reader and uses a bounded recheck interval only for scheduling. Alive and uncertain owners remain protected. A missing or pre-upgrade opaque identity is explicitly unresolved; never derive a dead PID, fabricate a migration identity, revive an old expired authority, or reset the database. Historical completed records remain readable; unresolved historical in-flight delivery must report the evidence limitation rather than be silently abandoned.
3. Rename liveness registration APIs to remove lease semantics and update all callers/checker declarations. Preserve business control leases, ownership transactions and immutable lineage identities. Update current architecture.
4. Replace obsolete process-expiry tests with positive identity, Project lifetime, clock-jump, physical child exit and Task activation contracts. Update affected cross-process fixtures to state physical identities. Run real backend/HTTP checks and existing abandonment, Session deletion and prompt recovery neighbors. No UI tests.
5. Synchronize version, changelog and projections; run typecheck, docs and repository hooks; scoped commit, upstream merge/outgoing review and push. Dispatch the canonical native-and-website release once from the exact pushed source and verify its public outputs.
