## Analysis before implementation

The screenshots show heavyweight nested containers, duplicated tabs and citations, large homepage choices and technical error banners. Current source has improved individual agent cards but still distributes visual decisions across surfaces: shared navigation uses accent-filled selection, shared inputs/buttons use broad rounded silhouettes, open disclosures paint a permanent hover fill, settings groups uppercase their labels, and the conversation card remains framed. Sources still have heading/count/index/chip layers.

Direct triggers are ordinary repeated tool calls and multi-agent navigation; this is a presentation issue, not evidence of scheduler, occurrence or termination failure. Source-backed messages, exact Session selection and scroll owners already exist and must remain authoritative.

Material currently repeats the rail background on the titlebar and panel-body with `background-attachment: fixed`; light palette declares `--panel-body-blur: blur(20px)`. Adding another glass overlay would preserve multiple owners and impose unnecessary rendering work. Replace these with one body-owned static background and theme-owned translucent fills; keep menu/dialog backgrounds opaque. VS Code Dark retains its canonical palette and an untextured root.

Scope includes global primitives and the named consuming surfaces. No public API, persistence or model contract change is intended. Agent list/detail introduces only local navigation visibility, retaining parent-owned Session identity. There is no new agent registry or transcript store. API error details remain available; no backend errors are hidden or reclassified.

Prior local fixes did not coordinate layout and primitives. Delivery must therefore replace the responsible rules rather than append another theme stylesheet. Existing scoped duplicate source/card rules that conflict with the shared contract will be removed in the same change.

Risks: wide impact of density/radius changes; text contrast over translucent surfaces; popup legibility; ancestor opacity accidentally compounding glass; remounting a live transcript; stale user settings widths. Use existing primitives and normal page interactions to verify these. Native compositor CPU/GPU totals require device evidence; absence of blur loops alone is not a performance benchmark.
