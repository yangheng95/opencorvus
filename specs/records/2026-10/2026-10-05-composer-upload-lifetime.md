## One operation and one derived count

- Change existing resolveGlobalComposerProject into a synchronous operation-returning interface: readonly {promise:Promise<GlobalComposerProjectResolution>, selectionEpoch:()=>number, isCurrent:()=>boolean}. The exact existing allocation owner supplies the dynamic accepted epoch; its Promise remains the only allocation Promise. Existing-directory mode returns an already fulfilled exact-epoch operation. Admitted Mission/market/submission callers consume operation.promise and do not readmit.
- Extend that same owner with pending/fulfilled/rejected phase. Pending is current only when canonical pointer, existing admission sequence and workspace epoch match. The existing synchronous admission commit updates its accepted epoch in the same batch as the board epoch. Before returning a success receipt, set fulfilled in that same successful operation; finally clears only its global pointer. Fulfilled operation currentness binds the accepted epoch, so pointer release cannot create a consumer gap and a same-epoch no-op cannot cancel a committed upload. Rejection is a terminal non-current operation. Pre-admission validation errors must preserve the explicit rejected-Promise contract rather than leave an immediate byte capture unobserved.
- Replace the independent numeric count and uploadGeneration in ChatComposer with one component-owned live operation collection used by file and folder. Tokens contain only their own identity plus operation reference, not a second draft/source store. Count derives from current live tokens; Submit and toolbar consume that same count. Registration precedes the first await. Each finally removes exactly its own token, and disposal removes the component's own collection.
- File input starts captureComposerFile immediately, resolves/registers its operation synchronously while the allocator work remains a microtask, then awaits bytes plus operation.promise together. Check the token before upload and before chip commit. A late old operation cannot append to a newer epoch; a new token is independent of old completion. Folder registers after successful picker/source validation and follows the same lifetime; cancelling the picker never becomes an upload.
- Main retains its single authored draft migration continuation: capture intent/source draft once, consume the service operation Promise, validate accepted epoch and migrate through the existing draft owner. Its returned operation retains that service's current epoch/currentness; no separate pending admission or allocation owner is introduced. Remove superseded counter/generation/effect machinery rather than keeping a compatibility branch.
- Error ownership uses live token membership plus its accepted/current epoch, not successful-operation currentness: a rejected allocation deliberately reports isCurrent=false, but an actual failure in the still-selected workspace must remain visible. Standard AbortError retains the existing cancelled-action treatment. This reads the same token and canonical epoch, without a parallel error owner.
