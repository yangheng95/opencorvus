## Observable failure and mechanism

The same named JSON bytes containing `原产物不可用` produce a numeric-key JSON object in direct ApiError.summary, but the archive service prints that actual public explanation. The actual Basic Auth wire shape (octet-stream body `Unauthorized`) similarly becomes byte numbers in direct construction. Problem JSON and malformed-JSON plain text also diverge. Empty Uint8Array becomes the misleading displayed object `{}` in both current paths. Request ID remains intact. Full error details repeat the byte-index object, so this is readable-body projection loss, not correlation failure.

HostTransport.request<T> returns TransportResponse<T>, without a separate error-body union. The actual `createTauriTransport` serves Browser and Tauri. Its binary branch intentionally reads Uint8Array on both success and failure; only other unsuccessful response kinds enter readErrorResponse. Changing every non-2xx binary result into JSON while retaining body:T would violate existing callers, including the two decoders that explicitly expect bytes.

ApiError currently formats the incoming body and saves it unchanged. The formatter searches message/error/detail/data.message, then serializes an object. Uint8Array has numeric keys rather than those semantic fields. Archive and browser-preview each compensate with an identical local TextDecoder/trim/JSON parse/text decoder; diff and conversation-artifact do not. Those isolated compensations explain why one service passes while shared formatting remains incomplete.
