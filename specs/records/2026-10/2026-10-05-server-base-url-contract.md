## Failure, trigger and cause

The actual pure probe accepts `not a url` and malformed `http://[::1` through the persisted parser; apiUrl(global/health) then throws TypeError. It also accepts `http://`: api-state first removes trailing slashes, then appends `/global/health`; the mature URL constructor sees `http:/global/health` and produces **http://global/health**, hostname global. No request was sent to this host. A base ending `?mode=DUMMY` or `#DUMMY` accepts but places the intended route inside query or fragment while leaving pathname at the prefix. A genuine `https://example.invalid/prefix/` produces the expected `/prefix/global/health`.

The structural guard checks only nonblank serverUrl. Rust does likewise. Browser/native saves therefore admit these shapes before a later connection probe. The Network input's type=url does not provide the actual admission: Save is a type=button onClick in non-form layout, with no explicit validity operation. Existing save transaction fixes persistence/publication ordering; it cannot establish semantic address validity. Subsequent checkConnection catches a URL/request error and marks offline after persistence, rather than rolling back the saved fact.

The [WHATWG URL Standard](https://url.spec.whatwg.org/#dom-url-url) specifies a mature parser/serializer and distinguishes recoverable validation errors from parser failure; a hand-written URL regex is not an equivalent parser. [HTML constraint validation](https://html.spec.whatwg.org/multipage/form-control-infrastructure.html#constraint-validation) describes explicit/form-validation entrypoints; the current type=button save path is not such a form submission. These sources support the mechanism, not an inferred browser interaction pass. Attempts to retrieve the Fetch specification failed in the documentation reader; this plan does not pretend that fetch behavior was experimentally qualified.

## Recovery decision: one document format, one operational base parser

**Proposed minimum:** retain the current complete-document structural load boundary, and define a single current operational server-base parser shared by save admission and target construction. This is not a second legacy parser: there is one persisted format and one base-use contract. A readable document can contain a saved address that cannot currently be used; keep that exact saved intent visible for correction rather than substituting another server. Unknown/missing/invalid structural preference fields remain errors as today.

Why not tighten all loads: loadSettings precedes onSettingsLoaded; a new rejection there leaves main settingsHydrated false and its API/theme/layout effects gated. It risks blocking normal activation even though the operator only needs to edit a connection value. Current source instead loads the malformed nonblank address, resolves onSettingsLoaded, syncs it to API state, loads locales from UI static assets, and lets checkConnection mark it offline. No locale request depends on configured API base. ConnectionBanner opens the canonical Network settings service; ConfigDialogHost and the connection editor are not guarded by backend config availability. Network always renders ServerConnectionSettingsGroup before proxy settings. Dialog opening can still fail for an independently failing native-surface occlusion owner; this URL change cannot claim to fix that separate subsystem.

The actual local recovery-service probe loads `not a url`, preserves applied/confirmed value and sage theme, observes its API projection TypeError, then corrects through the original save transaction to `https://example.invalid/prefix/`. The memory writer, confirmed snapshot and applied string all agree; theme stays sage and projected URL is correct. This proves the service sequence with memory-native storage. It does not prove mounted Network pixels, live browser reload, native file write or network reconnection. Those remain required in the matrix below.

After repair an old operationally invalid base remains readable and visible, but every target builder raises the same typed local error before constructing a request to another authority. Connection monitoring catches that error as offline. The existing Network correction path saves a valid new base through the original transaction, releasing later valid preference writes normally. Save admission applies to the entire active document: unrelated preference saves while its active base is invalid are rejected until the operator corrects it. No rollback of an already confirmed server is invented, and no silent default, network-success gate, repair storage, migration marker or fallback URL is added. Historical projectComposerIntents entries remain structural identity records, not live request targets; retain them when repairing the active base.

## Proposed operational contract for root review

1. Parse the supplied nonblank string, after outer whitespace trimming, with the host's mature absolute URL parser: JavaScript URL in transport-protocol; existing tauri::Url in Rust. Parse **before** stripping slashes or appending a route. Parser failure is a local typed malformed-base error and must not embed the rejected raw URL in its public message.
2. The operational base is HTTP or HTTPS with a nonempty authority/hostname. This selection follows the actual HostTransport HTTP methods, fetch/EventSource use, server startup URL and saved remote/proxy API purpose; it is not inferred from whether ftp/file/data/javascript happened to construct a Bun Request. Other resource/open-url schemes retain their separate existing contracts.
3. Preserve the base pathname prefix, host, explicit usable port and IPv6 address. Append API/resource paths beneath that prefix using URL components, after the current leading-slash handling, instead of raw concatenation ahead of parse. Request-specific query and project-directory injection retain their existing owner. Encoded pathname pieces must remain URL-parser-owned; do not decode/re-encode by hand.
4. Reject base query and fragment, including explicit empty delimiters if the mature parser preserves their presence. The published base promise is origin plus optional reverse-proxy prefix; requestTarget/transport owns endpoint queries, and a fragment is not an HTTP endpoint path. Current concatenation demonstrably fails to make such inputs bases. Silently discarding them would hide an operator's intent; silently spreading a saved query onto every request would introduce a new authentication/routing policy. No existing base-query/fragment support was found to preserve.
5. Reject embedded user-info for operational bases and direct users to the existing username/password settings. Current apiHeaders owns Basic credentials separately. This is an explicit product contract eliminating competing credential sources, not a claim that the probe sent credentials or every host's Request constructor rejects user-info. Do not copy user-info into those fields or log the supplied URL. Separate Basic password behavior remains unchanged.
6. Parser output is request-time address interpretation, not a rewritten preference identity. Persist the current submitted document values under existing trimming conventions; do not canonicalize historical server keys, default ports or host casing in projectComposerIntents. Mature URL serialization may normalize the actual request, as it already does, but scope keys remain governed by their existing owner. No silent address migration is part of this repair.

Proposed typed TS error: ServerBaseUrlError with a fixed reason among malformed, unsupported_protocol, missing_host, query, fragment, user_info and a safe explanatory message. Exact names/messages and precedence should be finalized in the implementation plan with root, then mirrored by the Rust save boundary. A direct caller must receive the same error category from save/use for the same base. Rust's existing string IPC failure can carry that same safe reason/message without introducing a second native settings envelope; changing public IPC error serialization would be an extra scope requiring evidence.

The structural persisted document type remains unchanged. isNativeCommand(settings.save) should reflect current operational admission using that same parser after its existing structural guard; actual adapters must also enforce it because the type guard is not automatically invoked for every direct native call. Reuse the sole parsing primitive; do not add another per-form URL check or transport-specific policy table. ServerConnectionSettingsGroup can use the existing failed-save presentation; the service must reject before native persistence/onConfirmed. Offline-valid addresses are accepted without checking connectivity.

## Independent empty-username parity defect

TS isOverlayPersistedSettings accepts empty username and transport-protocol's existing positive test explicitly requires it for a server without Basic Auth. Rust validate_overlay_settings groups username with mandatory nonblank fields and rejects the same document. This is a separate direct source-contract mismatch; the current claim of fully equivalent schemas is inaccurate in this detail. It is not reasonable to preserve Rust's obsolete reject as compatibility or delete the TS positive contract to force parity. A separately approved minimal parity repair should remove username from the Rust nonblank group while retaining String/serde type checking, and qualify actual native roundtrip of empty username with blank password. It does not require removing serverUrl/locale/theme nonblank constraints. This record describes the root cause/needed qualification but does not authorize that production edit or claim it completed.
