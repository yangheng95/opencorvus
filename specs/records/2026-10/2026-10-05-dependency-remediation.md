### Root cause and why both changes are required

The installed vulnerable dialect returns a quoted identifier without doubling embedded delimiters. Official beta20 fixes this for SQL identifiers. This repository's own table/column names are static and its application search found no untrusted runtime sql.identifier/alias construction, so no exploited application SQL injection is asserted. Nonetheless the dependency contains the affected public API and must leave the vulnerable range.

The independent pre-existing resource problem remains: upstream SQLiteSession.prepareOneTimeQuery delegates to prepareQuery, and Bun's adapter prepares a native statement without automatically finalizing it after a one-use operation. The local patch supplies the missing ownership distinction. Dropping it during the security update would restore that leak-prone lifetime and can affect Windows file release/strict lifecycle checks. It cannot be replaced with a global close fallback, eager disposal of all prepared statements, or another database connection owner.
