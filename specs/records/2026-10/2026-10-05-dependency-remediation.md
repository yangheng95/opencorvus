## Observable failures and common cause

The lockfiles retain versions inside published vulnerable ranges. Root overrides intentionally force several transitive packages onto exact versions; those formerly selected versions are now behind security patches. A normal package update that ignores those overrides cannot change the resolved implementation. Conversely, blindly forcing new major versions can violate the parents' contracts: the existing Undici override already applies version 6 to parents requesting versions 5, 7 and 8, so this investigation does not claim all parent major compatibility has been established.

The GitHub warning exposes lock/manifest version facts, not an executed attack. Current code and actual package source distinguish callable surfaces from each advisory's additional exploit prerequisites. The prior product fixes did not update these independent dependency owners. An audit-only green result, removing a lock entry without replacing its caller, or disabling a vulnerable feature globally without a qualified product contract would not establish remediation.

This work changes dependency implementation, not scheduler business state. Drizzle is shared by Task/Mission/Session and immutable Automation/Event occurrences, leases, normal/terminal settlement, retries/reopen, serial/parallel execution and multi-project isolation. Its SQLite lifetime adaptation therefore requires actual shared persistence tests before acceptance; no schema/history migration or alternate writer is proposed. Network proxy changes share Provider/research/connectivity dispatchers but do not change model routing or authorize model use.

### Root cause and why both changes are required

The installed vulnerable dialect returns a quoted identifier without doubling embedded delimiters. Official beta20 fixes this for SQL identifiers. This repository's own table/column names are static and its application search found no untrusted runtime sql.identifier/alias construction, so no exploited application SQL injection is asserted. Nonetheless the dependency contains the affected public API and must leave the vulnerable range.

The independent pre-existing resource problem remains: upstream SQLiteSession.prepareOneTimeQuery delegates to prepareQuery, and Bun's adapter prepares a native statement without automatically finalizing it after a one-use operation. The local patch supplies the missing ownership distinction. Dropping it during the security update would restore that leak-prone lifetime and can affect Windows file release/strict lifecycle checks. It cannot be replaced with a global close fallback, eager disposal of all prepared statements, or another database connection owner.
