## Findings before modification

Observable code paths, not model speculation:

1. `compactTranscriptField` discards the middle of text over 30,000 characters. Text Part identity is omitted, and the only compaction reader indexes completed Tool Parts. A later user correction in the discarded span cannot be read by the summarizer. Large tool inputs are similarly reduced without a matching input reader. The previous fix addressed output cursors only.
2. Tool transcript envelopes carry name/status but omit Part ID and call ID for short outputs, failures and pending work. Long completed outputs happen to carry IDs inside their output reference. This asymmetry makes exact trace citation depend on output length.
3. Completed result metadata and structured failure provenance are not fully represented in the transcript. Original facts persist, but a bounded summary cannot invent missing references. Existing Task ReadAgentMessage can retrieve causal evidence; it does not grant the compaction helper this capability.
4. Prompt identifies durable requirements but does not explicitly explain chronological corrections or distinguish quoted tool instructions from authoritative user changes. This is a semantic risk to measure with real requests, not a proven exploit yet.
5. Current success validation checks stop/text/shrink and original anchor. It does not prove semantic preservation. We will not add keyword gates or a second host-owned semantic state to pretend otherwise.

Impact: shared manual, predictive and overflow Session compaction for Chat/Work/Mission/Task-root/worker; original append-only messages, Task authority and visible summary remain canonical. This initial repair does not change scheduling/leases/terminal policy. Existing control, failure and boundary tests must be rerun. Repeated compaction, retry, restart and multi-session isolation are validation dimensions. Operating-system restart and full Task/Mission runtime behavior require separate runtime evidence before being claimed. No public HTTP schema or user interface changes are currently planned. No unrelated dead-code cleanup.

## Research and decisions

Sources read on 2026-10-13; these motivate experiments, not assumed OpenCorvus results:

- [OpenAI compaction](https://developers.openai.com/api/docs/guides/compaction): native compacted windows include opaque state and retained items. Preserve canonical returned state if a provider-native path is ever implemented; do not equate a natural-language summary with it. This task retains the current portable streaming mechanism, rather than adding a parallel non-streaming provider path.
- [Anthropic context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents): bounded high-signal context plus retrievable external evidence; evaluate recall before aggressive compression.
- [Lost in the Middle](https://arxiv.org/abs/2307.03172): vary important fact positions, not just total history length.
- [LongMemEval](https://arxiv.org/abs/2410.10813): score extraction, updates, temporal ordering, cross-message reasoning and abstention separately. Keep probe questions out of summarization prompts to avoid answer-conditioned retention.
- [LongLLMLingua](https://arxiv.org/abs/2310.06839): prompt compression addresses a different token-selection problem; do not remove instruction/provenance tokens solely for a compression ratio.
- [AgentFold](https://arxiv.org/abs/2510.24699): test repeated consolidation and selective retrieval; its trained agent results do not establish quality of this untrained harness.

Decision: first repair deterministic loss at the existing transcript/reader boundary, then tune the single compaction prompt from real failures. Keep original messages as authority, bounded retrieval as evidence access and visible assistant summary as continuation. No synthetic user instructions, shadow memory, fallback summary or regex instruction routing.

## Validation and results

Repeated-run new findings: after two/three checkpoints, exact Tool references point outside the selected head and the reader refuses them; the original immutable facts are still in the same Session. The selected-head reader scope is therefore too narrow for repeated consolidation. Fix by binding its one read map to the current Session's persisted snapshot at compaction dispatch, with the same source resolver and no alternate history store. Reads remain restricted to that snapshot; future and other-Session Parts fail explicitly. Snapshot memory cost grows with Session history and is recorded as a limitation to evaluate, not hidden as semantic safety.

The third text checkpoint and second Tool checkpoint retain the correct later user region with source IDs, and the outgoing Provider audit observes that value in the assistant input; the continuation nevertheless sometimes returns the initial user region. Main execution prompts lack a contract for consuming a checkpoint as a record of intervening user corrections. Add chronology/provenance guidance to the existing shared execution verification fragment, covering Chat/Work/Mission/Task-root and custom worker prompts through LLM.composeSystem. This changes prompt semantics, not message roles, authority storage or orchestration. Tools/quoted text still cannot grant authority. Genuine conflicting current user instructions remain authoritative. Test through the same real continuation path, not a new custom benchmark system.
