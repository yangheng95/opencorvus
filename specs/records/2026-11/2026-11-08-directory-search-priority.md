## 根因与影响

可观察证据：全新隔离 profile、真实开发模式 38920，项目内真实创建 25 个 .hidden/match-N/seed.txt 和一个 m-a-t-c-h/seed.txt；公开 GET /find/file 的 query=match、type=directory、limit=1 返回 `.hidden\\match-0/`。可见目录同样满足原匹配。它是公开目录功能复现，不能称作当前仅查询文件的资源管理器目录搜索复现。

直接触发为 File.search 的 searchLimit=limit*20；数据根因为容量截断早于可见路径优先级。2026-11-02 修复规范索引和同分排序，保留原隐藏偏好及采样，只稳定了这个错误窗口。Ripgrep 默认扫描隐藏文件，索引从真实文件生成目录，故问题进入真实生产路径。

公共契约保持原路径字符串数组、query/dirs/type/limit 和项目所有权；当前架构已有目录隐藏偏好。影响显式目录搜索的 HTTP（Hypertext Transfer Protocol，超文本传输协议）和 SDK 入口。文件、默认混合及显式点路径查询继续原规则；调试命令使用默认混合查询。不改接口、模型工具、配置、数据库、持久格式或迁移。没有调度、队列、唤醒、恢复或终态异常证据；共享在途扫描和项目隔离机制不改。

## 实施方案（修改前）

唯一 File.search 对非隐藏意图的目录，沿已有 hidden 判定分为可见/隐藏候选，各组使用同一原 fuzzysort 匹配与分数降序/同分原路径规则，按可见优先组成结果再取 limit。每组最多保留 limit，不收集无界匹配，删除二十倍采样；不引入第二索引、缓存或匹配器。其他查询使用同一匹配函数和原容量，空查询仍用原 sortHiddenLast。

先增真实 memoryProject 正向测试：隐藏拥挤下返回可见目录、较大窗口的明确隐藏后续项、显式隐藏查询、扩大窗口前缀和公开路由目录参数；保留真实文件及双项目隔离测试。先旧实现取得失败输出，再实现重跑。已读路径均为非 UI 的文件/HTTP 测试，没有组件、DOM（Document Object Model，文档对象模型）或浏览器测试；不新增或运行 UI 自动化。

资源使用新临时项目与全新 OPENCORVUS_HOME，不复制真实用户数据或凭据，不操作用户已有进程/窗口。前态 startup receipt 绑定 PID 22760、38920；后态使用新进程加载新后端。真实桌面 `/ui` 人工浏览、搜索并打开原文件，截图人工查看；目录专用契约由真实公开接口及功能测试验证，分别陈述范围。截图放 specs/artifacts/2026-11-08-directory-search-priority/。本批模型调用额度 0：确定性目录契约不依赖模型，不冒称 Sol 端到端。

风险是组间优先级、组内顺序、超限或项目交叉；原规范索引、匹配库和正向测试覆盖。分组遍历完整目录数组，原实现亦已完整匹配；最多保留两组各 limit 的结果，不声称大规模性能基准已完成。正常 shutdown 本人实例并消费启动句柄至退出，执行文档检查、范围提交、上游合并及正常推送。
