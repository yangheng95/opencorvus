## 实施前根因与影响

隔离桌面 39045 页 137，`inspect` 命中真实内置 `general` 与项目文件 `inspection-demo`（01）；关停自有服务后按刷新，目录和查询仍在，中文页面把含转义路径的 `GET … failed: Failed to fetch` 作为唯一告警（02）。连接监视确认离线后从通用切回，作用域不可用，页面错误地显示「专家团作用域不可用」、要求打开项目，并显示「0 个」（03）。实际项目并未被关闭；公共设置 scope 明确把未连接投影为不可用，旧 UI 丢掉了连接/项目两个原因的区别。已本人复核原图，在线三项 HTTP（Hypertext Transfer Protocol，超文本传输协议）200 对照运行时 schema 及真实项目文件通过，自有进程退出 0。

直接触发是读失败被双重降格：Mission Skill GET 辅助函数用裸 `Error` 重包除退役外的所有错误，丢掉公共传输原始错误对象以及 HTTP 状态、方法、响应体和请求 ID；面板 catch 再只保留字符串。原 `mission_skill.load_failed` 仅用于无技能的分支，已加载过的列表不显示本地化摘要；无首份数据时还会把同一次失败当成第二个空态，旧 Badge 将未读取误报为已确认 0。后者由代码证实，本次前态实页只触发过刷新失败与已离线 scope。作用域反馈错误源于借用专家团标题、共用一种「打开项目」正文，不是技能执行权限、数据丢失或调度故障。

删除两个读函数专属的重包辅助函数，直接消费现 `apiJson`，不建新错误类型或替代传输。面板保留原始 cause，由现 Feedback 显示本地化的一条摘要，展开现 `formatErrorDetails` 投影；没有接受过当前 scope 的目录时不显示计数或空目录，已接受的同 scope 快照及搜索筛选在读失败时继续可见。原 scope 退役仍清除目录，离线反馈使用技能自身标题和恢复连接说明，在线无项目才指向打开项目。保持当前项目与会话请求键、合并并发、失败结算、scope/sequence、显式刷新按钮、目录打开/复制/执行和列表详情导航。中文涉及的目录名称、搜索/筛选、目录标题和空态沿现「多步任务技能」术语；源文件、工具、调用、技能原文保持原值。独立的目录 issue（有效 HTTP 200 中的局部问题）及路径/复制写操作反馈不在本次读取合同内。
