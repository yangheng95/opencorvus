## 修改前分析和影响面

可观察线索是当前中文标题的“项”没有说明计数对象，而英文同键为 path；标题数量来自 summarizeChangeGroups().files，即比较路径身份去重，下方 conversationArtifactFileRows 和审阅 allRows 则按每个来源/比较列出记录。不同来源允许同路径，二者口径并不相同。941 只明确筛选显示数/总记录数，959 复核的是三条不同路径，960 只修路径阅读；均未统一此标题的计数对象。当前问题是展示单位和列表的关系不清，不是已证明的计数、记录丢失或错误相加。

唯一 diff 汇总有意在路径重叠、比较不完整或非文本时保留 nullable 行数，不能直接相加。当前摘要只显示“行数未知”，未说明总数和逐条数字的关系。保持算法，增加总行数无法汇总的可见阅读说明，不从路径、标题或工具正文猜测原因。前态实页仍须确认后才修改产品。

方案将两个标题的数量明确为原列表中的修改记录：主对话使用 fileRows().length，审阅使用 allRows().length；两者均来自同一 groups.flatMap(changes)，不添加状态或记录源。中英 `files.recorded_count` 改为“文件修改 · N 条记录”/“File changes · N record(s)”，数字用当前语言格式。审阅单记录也显示该总数。筛选后的当前数量、真实路径、状态、原始逐次比较、打开当前文件和 nullable 总行数保持。总行数不可汇总时两个面板复用同一语言词条说明逐条查看与避免重复相加。

影响面是共享主对话/Task（任务）文件摘要和审阅；Session（会话）/Task 的原 groups 与比较事实保持。原去重汇总继续服务其余调用，不改公共数据、API（Application Programming Interface，应用程序接口）、SDK（Software Development Kit，软件开发工具包）、数据库、迁移、工具、消息、模型或调度。没有队列/恢复/终态异常证据；出现时按共享机制审计。提问本轮只复核已有实现，不新建兼容或合成消息。已有 recorded-tool-comparison、diff-change-group-identity 属于纯数据合同，本轮不改算法；没有发现本轮目标的 UI 自动化，不新增/运行此类测试。

风险是总数说明的换行高度和窄审阅密度、单记录新标题；须真实查看中英、同文件多记录、单记录、三条不同路径与重命名及刷新。没有自然样本的分支明确不声明视觉覆盖。
