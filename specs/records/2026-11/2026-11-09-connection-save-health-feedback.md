## 根因与影响（实施前）

隔离开发页 39114（`main-DyosuOlU.js`）。网络页面用真实键盘保存 `http://127.0.0.1:39114/missing-prefix`。本机正常健康路由返回 200；实际保存触发带错误路径的真实请求，服务端完成日志记录 HTTP（超文本传输协议）400 和 `DirectoryRequiredError`。同一表单只显示短暂的「Saved」，焦点已掉回网页（图 02）；提示结束后只有稍迟出现、位于页底的全局离线横幅（图 03）。重新打开自建页面确认该地址真实已保存（图 04）。修正为原地址后实际连接正常，表单同样显示「Saved」，键盘焦点也不在原按钮（图 05）。原密码未填写，修改仅发生在隔离页面。未伪造响应或延迟。

设置事务先确认偏好持久化并应用地址，才调用 `checkConnection`。该探测已有真假结果和同归属在线/离线状态；失败在连接服务内部保留原错误、设全局离线并返回 false，组件只用真假判断要不要刷新工作区，随后两个结果都无条件进入同一「Saved」。已有错误分支处理抛出的本地/持久/激活或刷新错误，普通探测失败并不抛出。全局 banner 反映持续离线，设计上延迟出现并且没有该次 Save 的持久回执或具体原因，无法替代表单反馈。另一个直接触发点是保存开始时给已聚焦按钮设置原生 disabled；历史本地地址校验很快，未重现长于浏览器失焦处理的真探测路径。现按钮已有防重入，不必通过卸载或程序聚焦处理。

实施计划：在现探测的最终当前归属失败分支，像已有成功观察一样同步交付 `onUnavailable`，携带原 API 归属和原错误。保留其他调用方的布尔返回、原监视与探测次数、原状态和日志。连接表单沿已有 Save 世代与当前归属接受它，反馈单一联合类型区分原设置错误与已保存但探测失败；失败显示当前语言摘要与原错误 Details，成功仍沿原工作区刷新与 Saved。编辑、再次保存、卸载或原归属失效退出反馈；相同归属之后真正在线时从已有连接状态退休旧失败，不存第二个在线状态。只将 Save 本身改为既有 aria-disabled/aria-busy 忙态，沿已有 saving guard 防重入；地址、用户名和密码输入仍按原方式锁定。未修改地址准入、存储、网络 API/软件开发工具包、协议/数据库迁移、权限、原生启动、发版及模型路径。此为连接设置回执与键盘焦点问题，未发现任务/多步任务/会话执行轮次或队列异常。
