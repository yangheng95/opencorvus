# 定时任务暂停和恢复的回执确认

## Recall

- 用户要求分批持续调查、先落盘、独立实施、真实桌面操作和截图复核、聚焦正向验证、清晰提交、合并上游并推送。本批验收同一定时任务的暂停和恢复、保留原定义和项目、一次条件写以及错误后原地检查。使用独立开发服务和桌面，两个测试定时任务的最早计划时间为 2099 年，无真实模型或凭据。

## 根因与影响

1. 真实基线 `39798/39800` 使用 `main-Bq7ml9PD.js` 和 WebSocket 101。点击所选任务 Pause 时，服务在原定义上提交 `paused` 版本 `atm_g0VahsotC00QUlGwuEEO`，真实 HTTP（Hypertext Transfer Protocol，超文本传输协议）200 回执 `82945406-d31a-424e-b766-e48fab6c313b` 被截断为前 12 字节。界面保留旧 Active 及 Pause 按钮，提示刷新但详情没有直接刷新定义状态的控件。再次点 Pause 用旧版本返回 409 `5c199080-5d54-4fb0-b029-8e5f92e473b0`。线上列表 `4c5d26dd-be41-4080-b610-ba8b8aaf1455` 显示原任务已暂停、原指令及项目不变，同名目录的另一项目任务仍启用。两条历史都是未来待运行 Fire（计划触发记录），各零次尝试及运行。[基线证据](../../artifacts/2026-11-12-automation-status-receipt/README.md)
2. 暂停与恢复只是同一 PATCH 条件写的两个状态值。Overlay（桌面叠层界面）等待响应解析成功后才读回，读失败时保留旧定义并让状态按钮再次提交旧版本。当前通用反馈只记录写异常，没有取得持久状态。原有物理 revisionId（版本标识）正确拒绝陈旧重发；它无法将实际新状态投影回动作发起者。
3. 审计已覆盖全局 HTTP 路由与 Tool（工具）更新入口、项目/全局/会话目标、暂停/恢复、手动运行、计划到期、活动冲突、原版本重发及新连接读取。更新在同一数据库事务里附加不可变定义并移除或建立当前投递 frontier（前沿记录），原计划触发历史保留，条件版本和运行 lease（租约）保护并发。手动运行、重启恢复和 Task/Mission/Session（独立任务/多步任务/会话）执行由其已绑定的 Fire 与各自轮次事实管理。真实基线尚无触发运行、重复投递、唤醒或轮次结算异常，故障位于写成功之后的界面回执。候选补查跨项目、同 ID（Identifier，标识符）精确状态、重复写拒绝、持久定义与当前投递记录。实际活动模型轮次和触发恢复属于本轮证据边界。
4. 影响限详情内暂停/恢复的服务结算、原定义列表投影和本地化反馈。表单创建/编辑、删除、运行、公共协议、数据库结构和调度写契约沿用当前实现。当前列表按全局权威返回完整条目，精确定位只接受同一任务 ID、独立新版本和请求状态。该读取确认当前状态，无法证明与并发写内容完全相同的动作归因。

## 实施与验收

- 暂停/恢复复用同连接回执结算。有效写回执必须是原 ID、有效新 revisionId 及目标状态；不确定时只请求一次现有定义列表，读取同 ID 和已持久的新状态。明确拒绝保留原错误。不自动再发 PATCH，不使用另一个项目或名字确认。把已经确认的当前行交回既有定义列表状态，用原打开版本保护已被刷新读覆盖的更新，结算后列表和详情同步。
- 写和精确确认均不确定时保留真实诊断，当前详情提供本地化「检查状态」读操作，读取进行中保持焦点和反馈。成功使用原详情 ID 和最新定义，失败保留读操作及诊断。明确版本冲突继续由原合同显示。
- 候选使用真实页面验收英文正常恢复及截断暂停、中文完整或截断写及确认读取同时中断、纯读恢复和明确冲突。核对同名目录的项目隔离、一次条件写和正常详情、原指令及零运行。用线上定义及 Fire/Run（运行记录）合同和只读 SQLite 核对定义版本、计划记录和持久投递权威。聚焦 Overlay 服务测试与相关定时版本及运行结算测试，类型、本地化、构建及文档检查通过后提交推送。

首次候选 `main-DXtS8MRX.js` 在实际中文键盘检查期间保留诊断与焦点，现有全页读取条件却用「加载中」替换详情。未确认前详情也仍将旧版本的启用和下一次运行当作当前值。将状态检查期间的详情保留在原位置，状态和下次运行显示「待确认」，读回后原位接受当前定义。其他列表读取仍依原请求逻辑处理。复拍同一英语和中文链路验证。
