## 基线、根因及影响

真实开发基线 `40890/ui/` 加载 `main-CIA78COF.js`。在 1280×720 的英文 100% 桌面，84 项原始列表使用虚拟渲染，视口高 180 像素。第一条 Page Down 后仍为第一条、偏移 0。先按 End 再 Page Up，偏移约 2238，界面仍停在末端。筛选 `review-sample-00` 得九条普通结果，视口高 172 像素，首尾按翻页键时仍分别停在第一条、最后一条，偏移 0 和 127。四次按键分别产生 `querySelector` 的 `SyntaxError`，其中包含触发的真正文件记录键。 [真实基线截图](../../artifacts/2026-11-24-file-review-page-navigation/README.md)

普通和虚拟列表始终使用 Kobalte 集合作为单一焦点与选择管理者，选项键是保存比较身份和完整路径的复合 JSON（JavaScript Object Notation，JavaScript 对象表示法）字符串。Kobalte 在 `PageUp`、`PageDown` 中调用默认委托的 `getItem`，该方法把原始键插入 CSS（Cascading Style Sheets，层叠样式表）属性选择器。合法的复合键包含引号，选择器抛错，原生处理无法得到下一项，因此到不了上一批已修好的 `scrollToFocusedRow`。默认委托还用每个元素的 `offsetTop` 相互比较。虚拟渲染的行分属绝对定位外层，偏移基准不同，且远处行可能尚未挂载。首末跳转直接由集合得键，上一批也只修了得到正确键之后的真实焦点交接。

影响范围包括文件审阅的当前筛选、普通分组和虚拟记录列表，以及两种列表的分页键。记录身份、选择与焦点的区分、预览资源、数据与数据库、公共组件和依赖版本均沿用现有契约。当前证据指向列表委托计算，未见执行轮次、调度、并发或终态异常。输入拦截会与 Kobalte 同时处理同一按键，单独转义也无法恢复虚拟几何。应在现有委托接点替换两种分页目标的计算，复用库提供的其余键和活动集合。

## 实施和验收

由现有筛选结果构造并传入唯一的 Kobalte 列表状态，同时给继承默认行为的委托提供同一集合与原有语言排序器。只覆盖上下翻页键。用当前视口扣除普通列表的实际粘性分组留白和当前行的高度，翻动约一屏并让相邻页保留一行重叠。普通结果比较实际行位置，虚拟结果使用 Virtua 视口、行位置和索引查询，短视口至少移动一项并以当前可筛选集合的首末项为界。几何计算只返回已有记录键，既有滚动、虚拟焦点交接和明确选择继续管理显示状态。

候选用真实英文 100% 和简体中文 160% 验收。84 条与九条列表分别按双向翻页，跨虚拟窗口后检查实际焦点与预览内容，验证连续翻页、边界、方向键、首末、显式选择、斜杠回搜索、少量及零结果，读取正式的磁盘文本确认目标。记录目标、偏移、可视区和截图。保存服务的数据、真实文件下载、聚焦文本匹配及身份契约、类型、本地化、样式、真实构建和文档检查按当前命令运行。
