## 修改前现象、根因和影响

第 313 批在真实派生会话发现 `sample panel.png` 的 100 字节仍正确，持久名称却为 `sample%20panel.png`。本批在 `4832e25db` 上通过实际 `opencorvus acp` 端口 `40078` 提交 `视图 50% #1.png` 的文件 URI 与图片字节，并以 Zed 的查询路径 URI 提交 `计划 50% #1.txt` 的嵌入字节。公开历史 `4f687bde-8cf6-4dd7-8900-dd2971cfa0ca` 记录图片名 `%E8%A7%86%E5%9B%BE%2050%25%20%231.png`，文本名是整个 Windows 绝对路径。预览标题显示同样错误。浏览器建议保存为编码的图片名，并把完整路径转换成用下划线分隔的文本名。原件服务分别返回 100、31 字节，和浏览器下载一起逐字节匹配原文件。显式标签 `保留 %20 标签.txt` 和源文件第二行仍准确，流式回执为 `end_turn`。[真实桌面、持久和下载证据](../../artifacts/2026-11-13-acp-file-uri-display-name/README.md)

直接触发点是 `ACP.parseUri` 把 `file://` 去掉前缀后用 `/` 分隔整个字符串。最后一段仍带 URL（Uniform Resource Locator，统一资源定位符）转义，且可能带查询或片段。`zed://` 的 `path` 参数已由 URL 解析器解码为路径，但同一个 `/` 分隔方法无法识别 Windows 的反斜线。两者把错误名称送进文件部件；随后的字节物化把原数据和该名称交给存储。网页用实际 `part.filename` 作为名称，原件接口用附件元数据产生 `Content-Disposition`，它们忠实暴露了错误。第 313 批传递消息身份的修复发生在通知投影，入口元数据已在更早阶段固化。

图片、嵌入二进制资源和本地资源链接共享此解析；常规提示和注册命令也共用这个输入转换。实际链接的显式 `name` 来自客户端，必须保留字面 `%20`。本地文件 URI 中的行范围仍由当前物化器读取。嵌入字节的 URI 可能来自编辑器的不同操作系统，名称从规范 URI 路径末段取得，不能要求其可作为当前宿主的绝对文件路径打开。实际文件访问继续由现有物化路径负责。项目、原件 URL、内容寻址、权限、模型调用、数据库结构和普通网页文件上传均无需改变。旧记录里的 `%20` 可能是用户真正命名；字节型附件落盘后无法从原 URI 可靠反推，保留已有记录。原件存储仍按实际字节去重，同一已存在对象的下载响应使用先前发布的元数据；每条新的消息保存自己的显示名称。本批不重发或改写原件对象。

一次跨入口实验在网页对话已完成后调用 ACP 重载，返回当前 `chat` 主助手不在 ACP 模式目录。该拒绝发生于恢复模式校验，实际执行已按原消息父级完成，属于另一入口合同。本批的协议重载通过 ACP 原生会话验证，网页用实际持久化聊天检查附件。未观察到调度、并发、恢复执行或终态收敛异常。未知影响是历史数据中这两类错误的数量，调查限定在隔离项目。

## 实施和验收

- 对 `zed://` 查询参数使用现有路径转文件 URI 的步骤，再与 `file://` 共用标准 URL 路径解析。分离最后一个路径段后只对显示名称执行一次解码，保留实际读取 URI 与查询、显式资源名称、消息身份和字节合同。无效 URI 沿解析器的原错误/字面文本处理，名称解析不发起文件读取。
- 用实际 ACP 进程和公开网页复测图片预览、文本展开和两次浏览器下载，逐张复核。核对图片与文本原件字节、浏览器建议文件名、原件响应和公开历史。确认字面 `%20`、非本机路径语法的嵌入字节、显式链接名称与行范围，ACP 原生会话重载携带原图和正文。运行聚焦 ACP 和附件测试、后端类型、文档及架构索引检查，完成正常上游同步与推送。
