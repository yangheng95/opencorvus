## 基线与根因/影响分析

1. 本人隔离开发服务 `40166`、本机流式模型 `40170`，通过公开上传/会话接口和官方 ACP 客户端建立两项目。A 的两份 `shared-note.txt` 分别为 `Uploaded snapshot A1.` 和 A2，B 为 B1；磁盘同名当前文件另有正文。原件内容和项目回执正确，真实桌面逐项展开也正确，但 A 两份协议资源地址相同，B 的地址还指向 A 的当前文件；读该地址得到 53 字节当前正文，与三份上传原件不同。
2. 真实 MCP（Model Context Protocol，模型上下文协议）工具产生五幅各有标签 329–333 的 PNG/SVG 图像，实时/回放内嵌字节正确，来源却全部指向项目 A 的 `tool-result-image.png`。该真实地址读到本人特设的无关 8×8、95 字节图片。证据是实际地址读取、协议数据和规范原件，非标题或模型自述。尚未验证原生编辑器是否据此缓存覆盖，不把潜在影响宣称为已发生事故。
3. 直接触发点为 ACP 用户回放对 `filename` 调用 `pathToFileURL`，工具实时/回放对附件显示名或固定默认名做同样转换。显示名不代表磁盘文件；相对路径还隐式取进程工作目录，丢失会话项目和不可变原件身份。前批修复的是正文/媒体投影，明确将来源 URI 留作本批，故未根治此问题。
4. 生产入口包括 ACP 普通/命令附件持久化后的历史、公开 Chat/Coding/Work 历史及其派生、MCP 工具图像实时和历史。Task/Mission 原件复用同一存储，但 ACP 会话身份及可加载范围仍按现有公共权限，不扩大组织入口。真实 HTTP/file 链接原本就是 resource_link，必须保留其原 URI 与显示名；另一个 editorPath 转 file URI 是真实编辑器路径，不能一起删除。
5. 规范原件由 `/attachment/<projectID>/<name>` 标识并验证媒体元数据和字节；下载路由保留原件和 Content-Disposition 文件名。SDK 当前根类只导出生成类，ACP 只有同一个 SDK 配置而无服务地址。本批在自定义根类增加资源地址解析方法，直接委托其实际传输 `buildUrl`；不改生成文件，不复制 baseUrl，不读私有配置，不把授权头或 URL 用户密码放入协议地址。
6. 数据/公共契约：地址从伪本地文件改为当前服务的真实规范原件 HTTP 地址，内嵌正文和完整 MIME（Multipurpose Internet Mail Extensions，多用途互联网邮件扩展媒体类型）保持原件。已有 data URL 保留其真实自包含来源。原文件名仍在 FilePart、回执、网页和下载响应；ACP 嵌入资源没有标准 name 字段，部分原生客户端可能用内容地址尾段作标签，此显示行为未知，不能用虚构路径、额外消息或忽略的别名参数装饰。
7. 无数据库结构/持久格式变化，无迁移、凭据、Provider 配置、工具授权、调度或并发策略改动。基线流式输入正常完成，当前证据是数据来源投影错误，没有所有权/队列/终态异常证据；若后续出现须立即按共享机制横审。并行项目、重启持久历史和正常终态仍纳入实际验收，不能只看单例通过。
8. 风险：不能将模型准备后图像 URI 当原件；不得丢反向代理前缀、硬编码 localhost、暴露认证信息或把真实外链改写为本机地址。来源服务退出后 HTTP 地址随实例不可达，但内嵌原件仍完整；重启回放应使用当时实际服务地址。当前仅本机无认证验收，外部认证原生客户端访问未验证。

## 实施方案和验收

1. SDK 自定义根类扩展生成根类，以同一传输构建 `resourceUrl`，返回绝对资源地址并去掉用户密码；工厂唯一构造保持。聚焦正向测试普通地址、服务前缀、认证配置下的明确正确地址、真实请求与地址一致。
2. ACP 共用一个来源投影：规范原件引用用 SDK 解析，其余既有内联 data URL 保留真实原 URI。用户 image/text/blob 与工具 image 的实时/回放共同调用；删除仅此用途的假文件地址，真实 editorPath 和 resource_link 合同保留。
3. 以真实 ACP/产品 HTTP 路径的正向测试核来源与原件字节、同名资源、空资源、图像和工具数据；不新增或运行 UI（User Interface，用户界面）自动化。正式 SDK 构建、相关类型、文档和架构检查分别核退出码。
4. 新候选 `40168` 运行同一公开 API/官方协议场景，所有来源实际 GET 并与原件核对，覆盖两项目并行、load/resume/fork、工具实时/回放；正常退出重启同库再验。真实桌面展开同名正文和工具图像，截图人工查看并下载核对原字节。
5. 记录实际结果、失败及范围限制，精确暂存本批文件，保留用户状态；fetch/merge 上游，审查全部待推提交、必要验证后普通 push，继续下一批。不创建版本、标签、发布或拉取请求。
