## 根因及影响面

基线 `main-DC0m8EvP.js`、1280×720、真实 `serve /ui`：侧栏已明确区分 `Workspace · alpha` 与 `Workspace · beta`；先打开 alpha，进入设置 → MCP 连接；回应用点击真实 beta 项目，再进入设置 → MCP 连接。英文两页标题、说明、操作相同，只有服务标识改变；中文 beta 同样只有“当前项目”的指代，无法确认连接、添加或全部删除将针对哪个项目。`GET /mcp/project?directory=…` 对两目录均返回 200、唯一对应定义 `b177-alpha-fixture` 或 `b177-beta-fixture`，均为 `disabled`（真实请求 `c0a021a3-c758-4b6f-99c8-4607a48a5401` 和 `7c91e2e1-94fb-4ca8-9447-5d0481d00b7c`）。这些 fixture 名碰巧带目录线索，任意实际服务名不提供身份保证。应用截图和公开读取一致，未发现跨项目状态错投。

根因是页面标题与说明只描述项目范围，没有呈现现有活动目录。`ConfigDialogHost` 已注入唯一 `activeProjectDirectory`，共享管理面板用同一 `currentDirectory()` 解析目录并为请求设置应用程序接口（API）上下文，项目状态还单独检查连接 authority（服务连接身份）和读取所有权。旧侧栏提示在设置占用侧栏时被隐藏；即使刚访问过产品分配页，也不能借其上下文确认资源管理动作。现有产品/服务商设置的 Disclosure（展开区域）可以展示精确路径；普通摘要中的短目录只用于辨认，不能替代真实完整路径，尤其是两个目录末级相同的情况。直接从渲染调用现有带写入的 `currentDirectory()` 会额外同步 API 上下文，必须使用同一纯目录访问器而不是第二套回退或展示数据源。

修改限 MCP 管理页、其现有项目目录访问与设置样式，保留状态/操作所有权、项目选择、公共接口、工具、权限、运行、SDK（Software Development Kit，软件开发工具包）、持久数据、任务队列和版本。纯展示不另增测试协议；现有共享技能页目录语义仍保持。风险是同名提示被裁切、完整路径错误或项目切换显示前项目路径，及无项目时误报；用实际短提示与完整路径、双语项目切换和同一服务的真实读取验收。

## 实施方案

1. 在项目 MCP 管理说明与分配按钮之间，复用现有设置展开控件、`settings.product.scope_project` 和公共目录格式化。触发器上显示当前目录的项目名称和可见的父路径短提示；展开时显示未改写的完整目录。无目录时保持现有选择工作区提示，不引入虚假路径。
2. 将纯目录选择作为共享管理组件的同一来源；只有现有读写入口继续同步 API 上下文，标题只读取。目录改变时身份及展开状态一起换为当前目录，旧路径不留在新项目。短提示可能因层级结构而相同；完整路径用于确证，不增加列表依赖或后台请求。
3. 真实基线与候选图、可公开的隔离项目读取回执保留在 `specs/artifacts/2026-11-10-mcp-active-project-context/`。完整路径扩展图如果含本机账户目录，仅留本机人工复核；可提交原图使用未展开的短目录区域或使用不含个人身份的测试目录。
