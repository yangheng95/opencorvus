## 根因与影响（实施前）

真实开发基线 `40592/ui/` 加载 `main-CdAkXsS0.js`。打开 96 字节的六行 `handoff.txt` 后在编辑器起独立临时草稿，只将磁盘的六个 LF（Line Feed，换行）改为 CRLF（Carriage Return + Line Feed，回车加换行），正式读取确认文件为 102 字节、内容和新修订正确。桌面「基准版 → 磁盘」显示六行删和六行增，两组可读文字相同。再把磁盘改回 LF 并仅去掉最后一个换行，正式读取 HTTP（Hypertext Transfer Protocol，超文本传输协议）200、95 字节；同一比较重读后把同文字末行标为删除和新增。在「基准版 → 草稿」对照可看到真实新增的第 7 行，说明普通正文差异有效。本人逐张复核三张基线图。[基线截图](../../artifacts/2026-11-23-text-comparison-line-ending-changes/README.md)

直接触发点是 jsdiff 按含行尾的原始文本生成有效删增，`splitDiffLines` 随后把 CRLF、CR（Carriage Return，回车）、LF 统一拆成显示正文，删除了唯一有变化的分隔符信息。共享渲染于是只呈现逻辑行文字，而行标签仍着色删增。现比较视图的文件身份、读取归属、版本和保存处理正确，既有行尾保真修复只保护编辑和持久化，没有提供比较表达形式。

影响限共享比较的呈现。已读取的真实前后文本相同时保留零差异；只有各逻辑行文字相同、至少一个行分隔符不同才适用专门显示。普通正文、额外空白行、已有上下文、局部变化和前后版本身份按原路径显示。保留已记录的正式行统计、快照字节、文件读取、冲突保存、权限、持久格式及现模型和运行链。测试风险包括混合行尾分布相同但位置变动、文件末行和真正空白行混淆、英文技术术语过长挤压窄栏、改动适用范围扩大到其他共享消费者。

## 方案及验收

以现有比较拆行判定逻辑行文字精确相同，再用共享 `readTextLineEndings` 查每行真实分隔符。把相邻且发生相同前后替换的行聚为范围，提供行号、变更前格式、变更后格式和缺少末行换行的实际状态。保留单一 `TextDiffView` 入口，用紧凑、带表头和说明的原生表格呈现纯换行差异；通用逐行比较的原列头和差异只在常规分支显示。格式分类及精确行范围用聚焦纯数据契约验证。现有正式行数统计仍使用原始库行差异。

候选 `40594/ui/` 真实复验六行 LF 到 CRLF、仅末尾移除、CRLF/CR/LF 交错和含普通正文的新差异，实际切换三个比较视图并用原重读动作确认正确快照。简体中文复查术语、末尾状态、表格和键盘操作。用正式内容读取、原字节、隔离 Git 与数据库证明草稿和作用域；截图人工复核、实际构建、聚焦正向测试、类型、双语、样式令牌、文档与架构验证。关闭隔离进程，精确提交、合并上游并普通推送。
