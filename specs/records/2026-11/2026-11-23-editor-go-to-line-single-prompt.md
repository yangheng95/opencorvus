## 根因与影响（实施前）

正式开发基线 `40584/ui/` 加载 `main-BYpTPzfe.js`。打开实际 150 行的 `line-notes.txt`，正文按 `Ctrl+Alt+G` 出现一个原生提示。输入 `130`，焦点在输入中重按仍可见同一个值。点击正文第 8 行，再按同一快捷键时，底部叠出 `8` 和 `130` 两个独立输入，新项获得焦点。Escape 只撤回新面板，底部留下原项；工具栏可聚焦原来的 `130` 并正常跳到该行。正文没有被编辑。已逐张查看四张基线截图。[证据](../../artifacts/2026-11-23-editor-go-to-line-single-prompt/README.md)

工具栏复用保护位于 `onNavigationReady` 回调，查询当前原生行输入，有输入就聚焦，没有才运行 `gotoLine`。`basicSetup` 的原 `Mod-Alt-g` 路径直接调用库的 `gotoLine`；后者每次调用 `showDialog` 新建面板，快捷键从编辑器正文进入时不经过应用已有复用逻辑。先前方案保证了工具栏自身的重复操作，并实测过快捷键初次打开，未覆盖提示保持打开且正文重获焦点后的混用。

影响覆盖共享编辑器的此键绑定，以及工作台「跳转到行」按钮；正文之外的旧按键范围、其他搜索命令、关闭/提交、相对行语法、文件格式、文件写入、接口、数据配置、权限、发布、模型、任务调度和执行轮次均不改变。主要风险是丢失当前行输入、覆盖已有搜索键、或把焦点交给另一个编辑器。接入应只使用当前编辑器的原生提示 DOM（Document Object Model，文档对象模型）。

## 方案及验收

把现有「存在时聚焦，否则创建原生跳行提示」提成共享编辑器命令，由导航回调和编辑器快捷键同时调用。采用 CodeMirror 公开的优先级覆盖原 `searchKeymap` 中关联 `gotoLine` 的绑定，沿用库的键定义、默认作用域和其他搜索键。命令使用现有原生提示和行解析，并将处理完成告知键盘分派。同步 `07-panel`，保留同一活编辑器和 Markdown 源文的现所有权。

候选 `40586/ui/` 以相同长文本复验工具栏、键盘及混用；输入 `130` 后回正文并再调，返回同一提示和值，Enter 跳到第 130 行，重开并输入新值后 Escape 恢复正文焦点。中文用 Markdown 预览按钮切到原源码，再用快捷键复用输入并跳到实际内容；另外实测查找的独立操作。证据来自真实桌面、截图人工复核、实际文件内容接口与已有聚焦纯文本检索、文件身份检查、类型、语言、构建、文档、架构验证。关停隔离实例后提交、合并并正常推送。
