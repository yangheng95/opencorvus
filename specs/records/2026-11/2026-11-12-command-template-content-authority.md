## 修改前现象、根因和影响

真实 `40026/ui/` 与同一开发服务的公开命令入口。`Keep $$, $&, and $ARGUMENTS intact` 进入实际持久正文和流式请求后变成 `Keep $, $ARGUMENTS, and $ARGUMENTS intact`。混合 `$1` 与 `$ARGUMENTS` 的模板对已插入的参数文字又执行一轮替换，导致重复。普通参数与远端提示正文的内联标记各自运行了只打印标记的主机命令。公开会话明确含 `bash: deny` 与 `write: deny`，同一命令入口仍返回真实命令输出。另两轮以隔离项目样本证明普通参数和远端提示能触发本地 `@reference.txt` 读取，文件内容随后出现在真实项目持久消息、浏览器和流式模型请求。没有接触工作区外文件、真实凭据或外部模型。[桌面实拍、请求和流式证据](../../artifacts/2026-11-12-command-template-content-authority/README.md)

根因是执行器用展开后的单一字符串重新解释内容。位置参数先插入，`replaceAll` 随后扫描该结果并把原始参数当作 ECMAScript 替换表达式，因而重写 `$&`、`$$`，也会处理用户写进位置参数的 `$ARGUMENTS`。同一混合正文再送到 `ConfigMarkdown.shell`，以原始 shell 字符串启动 Bun，绕开显式会话 Shell 及模型工具各自的执行权、项目归属、可见回执和进程监督。最后 `resolvePromptParts` 重新扫描混合正文，将参数或 MCP 返回的 `@` 标记提升为本机文件输入；文本文件物化经当前显式输入的主机读取路径。早期输入提示、具名参数、附件及内部空白修复没有改变这一处理顺序。

共用执行器覆盖 ACP、命令行、公开命令和初始化。公开 Mission（多步任务）和投影 Worker（执行代理）入口仍受既有会话归属约束。基线七轮均有准确会话与回复身份且为 `stop`，观察到的缺陷在命令准备及执行边界。命令的公共幂等身份仍在同一外层执行所有者，显式会话 Shell 有自己的持久发生轮次、租约和监督；注册命令的内联执行当前在这些机制之外。本次删除该原始进程路径，既有 Shell 的重试、重启、串并行与多项目合同不迁移到提示准备。显式输入附件、项目配置声明的文件、插件钩子、公开接口、持久格式及既有历史不需迁移。项目配置外部使用内联 Shell 的数量未知。仓库内找到的现行调用为执行器和依赖该行为的幂等测试，公开双语文档承诺命令遵循正常权限。

## 实施与验收

本地配置模板拥有占位符和文件引用声明。用同一占位符语法生成目录提示和单次求值，替换回调插入参数数据。先从原始本地模板提取文件引用，再按同一参数值展开已声明的路径，并把明确文件列表交给现有输入物化。固定路径、模板明确写入的参数化路径、同轮显式附件继续走当前文件输入。普通参数和 MCP 返回正文作为提示文本进入持久消息与流式请求。清除注册命令中隐式的原始 Shell 执行及仅为它服务的解析。执行 Shell 的请求使用已有显式用户动作或受权限约束的模型工具。用户过去配置的内联标记在新轮次作为可见提示文字保存。

风险为声明的文件引用退化、相邻占位符的边界错误、无参和最后位置的既有语义变化、插件或重试重复处理。聚焦验收通过真实公共命令和 ACP 核对字面文本、远端参数、已声明文件读取、显式附件与一次执行的正向身份。用实际 Web 会话续接命令、查看文本与已声明附件，逐张人工复核。重新核持久信息和实际流式模型输入的字节，执行聚焦测试、后端类型、路由、文档、架构索引及正常推送。本批以受控的本机流式参与者测量数据和结算。
