直接根因是同一任务目标在 Environment 和固定 Browser 各维护一个 `createResource`。环境失败仅记日志，按钮依赖成功后非空地址，因此把失败与无目标混为同一缺席；打开固定标签后另一个资源重新读，同一目标能在两处出现相反结论。固定 Browser 的刷新控制只操作已打开的本机 WebView（系统嵌入浏览器）页面，不能读取任务目标；固定标签未挂载时也没有当前架构声明的后台目标读。此前的本机导航、证据读取和作用域保护正确区分了读操作，但没有统一两处相同的目标读或提供目标读重试。检查了目标已保存/未保存、连接与选择变化、公开任务事件到当前浏览器修订、普通浏览器无任务、本机网页与文件/证据读；没有调度、工作队列、Task/Mission/Session 执行轮次或终态异常。后台目标发现是界面读，不安排任何任务执行。服务持久化、任务目标与证据身份、HTTP（超文本传输协议）、数据格式、权限和发布不变。

## 方案与验收

唯一目标读由常驻 OverlayRoot 创建，使用真实选中任务、目录、连接和选择轮次；两处使用同一投影（读取中、已接受、或带原错误的失败），移除两个原消费者各自的请求/错误事实。选择退休应中止旧读并检查响应归属；已有任务目标事件仍是自动刷新触发。首次成功读在该选择范围作为历史基线，之后首次确认的新 ready（已准备）目标仍交给现停靠区所有者展示；证据和本机浏览器依旧仅在可见标签需要时启动。普通 Browser 不连接任务读取。

环境保留可用原入口，当前任务有进行中或失败的读取时带短状态，让用户到同一任务预览看诊断和恢复；真正确认无目标时沿现行为。预览用现 Feedback（状态反馈）显示错误和原诊断，有同一 scope（作用域）显式重试，按钮忙时稳定、避免重复请求；成功后仅在拥有原焦点时交给现地址栏，否则尊重主动移焦。网页 Reload 依旧只刷新网页，实际返回的业务 failed 与读取失败各用其原路径。保留已挂载标签、地址草稿、本机导航、证据校验、已有连接和选择语义。不做后台循环自动重试或 API 改造。

改后真实 `39291` 经 `39293/ui/`：后台首次同一 ready 响应中断；环境失败状态能进入原任务预览，打开不额外读；可展开原诊断，键盘重试一次再失败（多次按键一笔），再重试成功时显示真实已保存目标和合适焦点。核对另一普通浏览器仍是独立标签，中文同一失败/重试可读；如用新保存目标证明自动展示，只在自有同一任务发布新环回 URL，验证历史目标不会抢开，期间不启动任务或外部页面。只声称实际覆盖的 Web 目标读，不把界面无本机浏览器能力的提示当成本机验收。用实际接口/schema、现定向服务检查、类型、双语、CSS（层叠样式表）、构建、文档检查作辅助，保存截图与原始回执、确认只改自有数据并关停服务，然后范围提交及正常推送。
