## 实际根因和影响

隔离 39103 `/ui` 载入 `main-B_4BkdLv.js`。将真实 `single.txt` 复制到以 `/Users/.../absolute-before/wrong-place.txt` 开头的带根目标（01），页面实际回执去掉了 `/`（02），文件在项目内准备好的同名镜像目录，写入 `a3ee1ecf-a1d9-44cb-b054-561fdb8121fa` 200。将两个文件移动到单个反斜线开头的 Windows 根路径（03），同样实际进入项目内镜像（04），两个真实 `PATCH` 200：`077efd7d-85ca-4bd7-9b3c-dafd2048adbf`、`6dfce9fc-4ad2-4b16-914f-df91447cccbb`。测试目录和源内容均属本批；实际卷根解析所指向的两个隔离位置中，基线位置仍只有其原标记文件。四个公开目录结构及七份下载字节与项目内实际文件一致。直接发送同形式的原始目标给公开复制接口，`5c66d462-1a23-4e77-a22d-1fc22bc356ea` 400 `FileInvalidPathError`，原错误数据保留带根字符串。基线服务已正常关闭，原进程退出 0。

直接触发点是四个转移对话框仅校验非空，然后把输入交给项目键规范化函数。该函数按设计用基准目录和一个已知相对路径生成规范键；传入带根字符串时，输入先拼到项目目录后，分隔符和前导根标识已无从恢复。服务 `assertAllowedFilePath` 会拒绝收到的绝对路径，也校验真实权限/父路径，但收到的是已被页面改写的另一条合法相对路径。上批只使确认与执行共用实际来源；目的字段仍在之后走独立的原路径转换，因此未修这个问题。影响文件面板四种文本目的输入；目录拖放、已有路径和选区键并非文本输入，沿原规范化和服务校验。创建/重命名标签为名称，属于另一个合同，旧行为未在本批实证，不更改；编辑器文档引用确有可用绝对路径的独立语义，不改原分类。没有服务路由、请求响应、权限、持久格式、配置、调度/队列/恢复变动，也未见执行轮次异常。

## 实施与验收

从目标项目路径判断服务器语法。在原输入交给项目键规范化之前，分类为 `relative` 或 `rooted`：斜线开头、Windows 反斜线开头及盘符指定都不依赖当前项目，包括盘符相对形式（它依赖该盘当前目录）；非 Windows 下保留原有的反斜线和盘符形状文件名。明确校验的是原始输入，不修剪真实文件名，也不替代服务对相对遍历、权限、链接、存在、冲突和写入的事实。复用现路径模块和其 Windows 盘符语法，保留已有 `normalizeProjectFilePath` 和编辑器分类原合同。新增可选同步 `validateInput` 仅接入共享对话框当前 epoch 的必填/长度检查之后、结算之前，返回本地化字段错误，沿现 `inputError` 与 `confirm` 把焦点留在字段、保留原值，用户编辑清除。四个文本目的共用同一个面板验证函数，以已捕获项目目录为准；字段双语标明相对项目。其它对话框不设置校验，现流程及状态不变。

普通构建后在独立 39104 真页面先重现英文单项 `/...` 和中文批量 `\\...` 输入，验证原值及字段错误、可修正与焦点；同一个确认框分别用 `dest/checked-copy.txt`、`move-dest` 完成一复制两移动，核对成功回执、实际目录及字节。另覆盖盘符和批量取消以说明共享校验。比较两端服务写入及隔离原件、只读项目数据库。纯路径正向契约覆盖 Windows 斜线/反斜线/盘符/网络根、相对 `.`、原字符及类盘符的 POSIX（Portable Operating System Interface，便携式操作系统接口）相对身份；聚焦现文件运输、类型、双语、普通构建、文档与架构检查，不运行界面自动化。本人看所有关键截图，必要时先记录原因再调整重拍。范围提交后正常合并与推送。
