## 基线与根因、影响

1. 在 `127.0.0.1:40206/ui/` 实际打开设置 → Network → Connection，在原服务地址末尾输入 `#review`，焦点仍在地址字段，按 Enter 后页面没有反馈。随后点击同一个区域的 Save，页面立即显示现有的片段错误和 Details，输入值保持原样。这一对照证明校验与保存入口本身可用，缺失发生在键盘事件到提交操作之间。两次截图分别保存。
2. 根因是输入均在布局 section，唯一入口由 `type=button` 的 click 直接调用保存。浏览器没有表单所有者，输入字段没有原生隐式提交。以往验证从 Save 按钮回车，按钮激活是正确的，却不覆盖从输入字段提交。共享保存服务不接 DOM（Document Object Model，文档对象模型）事件，无需改该层或加入全局按键路由。
3. 正常保存先校验、持久化，再启用连接、探测和刷新项目。URL（Uniform Resource Locator，统一资源定位符）已有单一应用校验，并投影五类具名错误。表单需使用 `noValidate`，由原应用验证处理无效值和语言。提交要阻止原生导航。临时忙态使用输入只读保留焦点，继续由原 `saving()` 守卫约束重复提交。鉴于回车提交时输入拥有焦点，继续把所有字段设为 disabled 会使浏览器转移焦点。
4. 影响仅为连接设置页面的键盘与指针交互。Proxy 是独立同级区域，不能包含到连接表单。保留现有持久化事务、作用域切换、离线结果、语言、国际化键、无障碍按钮状态和 Details。不改变公共接口、配置、数据、角色、网络权限、调度和模型流程。未发现执行轮次、队列或终态收敛异常。
5. 风险包括浏览器原生验证代替产品错误、回车从代理字段误提交连接、异步保存夺走焦点、有效地址触发不应有的刷新。使用只包住连接区的标准表单与单一提交函数，复用原有业务守卫。无必要增加截断键盘事件、额外状态、应用侧验证路径或 UI 自动化。
