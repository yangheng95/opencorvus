## 根因、证据和影响

1. 设置中的服务商页面停在项目范围时，通过「文件 → 关闭项目」，实际运行先收到了旧项目目录 `35dd7e41-caa6-4350-8281-3474f78e2c71`，后收到全局目录 `41cc1f35-cf21-402d-8a4f-be59b9751b58`。两次请求分别到达于 04:45:03.880 和 .897 UTC（协调世界时）。最近一次显式重试在 23 秒前已完成；本轮退出后搜索正确显示 0/88，旧项目目录原有 89 项。此前待刷新回执期间离开项目也观察到旧项目目录 `d7663c9b-664b-441b-95a6-4fcb95d1cd27` 与全局目录 `d9139e14-7daf-4e52-9449-889e1de26f9e`。最终结果归属正确，额外读发生于范围发布本身。
2. 文件编辑器 `requestFileEditorTarget` 在确认同一编辑资源、草稿修订和连接所有权后，在同一 Solid `batch` 内关闭文件并执行传入的准入提交。`admitWorkspaceSelection` 在该边界推进 `selectEpoch`；`closeProject` 却在 `await requestWorkspaceSelection()` 后才清空活动目录、工作项和应用程序编程接口（Application Programming Interface，API）的目录。读取方先观察到「新选择轮次、旧目录」，据此启动 `/provider` 和 `/provider/auth` 的项目读取，之后再观察到全局。既有所有权判断只能阻止旧回执覆盖当前投影；服务商行的稳定身份、读重试与回执筛选均无法让这个半完成的状态变成真实导航。
3. 横向检查共同的同步退出路径。标题栏文件菜单与命令面板共用 `closeProject`。删除活动项目后的确认回执和启动丢失目录恢复共用 `leaveUnavailableProject`，其活动目录分支先推进轮次再退役目录，两个写入之间也没有批处理。其仅清理持久目录的分支保留另一个活动工作项。连接切换已在 `prepareFileEditorClose` 的同步确认边界内完成轮次和投影的更新。全局新对话由主入口先准入、再等待设置关闭，之后按已取得的轮次进入全局；保留该多步骤流程。实际切换到另一个项目要等待目标目录检查；Task（任务）、Mission（多步任务）和 Session（会话）选择或创建则以准入轮次约束各自随后进行的服务端读取或提交。保留这些异步准入契约。
4. 影响限于客户端发布一个离开后的范围给仍挂载的读者。任务与会话正常或终态的服务端执行轮次、队列、并行度、重试、恢复与唤醒均不经此提交；启动恢复是目录归属修正。隔离数据库没有任务、会话、模型使用或权限写入。目录记录、已保存的文件、API 路由和响应、凭据、数据库结构与发布流程无变更。项目切换过程中的其他在途工作继续按原所有权判定；本批不变更网络写请求或取消语义。未复现安装版原生窗口的表现。

## 实施与验收

1. 在 `closeProject` 调用既有准入时注册同步提交动作，将清理当前目录与工作项纳入文件离开和选择轮次的同一次批处理。保留保存偏好与随后独立刷新全局配置的顺序。活动项目丢失或删除的即时恢复分支把推进轮次与现有范围清理放在同一个 Solid `batch`。复用已有目录清理和准入边界，保留其他准入调用及持久目录独立清理。
2. 通过真实的 Solid store（状态存储）观察两类服务动作发布的目录、轮次、工作项及 API 读取路径，检查确切的前后范围和持久偏好。先在原实现运行聚焦契约用例，确认能够观察到中间状态，再在候选重跑相关准入、配置归属和目录读取服务测试。
3. 在隔离开发页 `/ui` 的真实桌面保持服务商设置挂载，通过文件菜单退出自有项目。核对退出前项目专属目录，退出后全局范围、搜索结果、配置读取的时间线和真正的响应，复核截图。覆盖退出时已有在途读回的情况，并核对隔离数据库及项目文件。运行类型、构建、渲染器公开面、文档和架构检查。模型、凭据和模型请求均不进入本批实际路径。

### 测试运行器证据

- 默认 Bun 解析 `solid-js` 和 `solid-js/store` 的服务端导出，观察器只有初始读。现有 `meta-project-scope` 的两个跨资源结算服务用例因而超时。同样用例在 `--conditions=browser` 下通过，且实测解析到客户端响应式实现，信号写入触发观察器。原实现经客户端条件运行的新用例分别采集到两次旧目录的中间发布，候选均只采集到项目和全局两次一致发布。广泛启用客户端条件会使当前 Bun `toMatchObject` 比较 Solid 代理时在既有连接投影测试报错，尽管输出字段一致。运行器只为两个需要真实响应式发布的服务文件选择客户端条件。新测试沿用已有帧回调调度夹具，无组件、浏览器和文档对象模型（Document Object Model，DOM）。
