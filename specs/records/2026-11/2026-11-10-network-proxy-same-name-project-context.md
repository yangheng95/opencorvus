## 根因与影响面

真实基线 `main-D6vzJjeu.js`、1280×720。独立 `alpha/Workspace` 与 `beta/Workspace` 的真实 `/project/current` 200（`c1da249a-c69d-4ee0-bcc3-4f800e71669c`、`8faed814-3788-4153-8c87-035afca17a9c`），项目身份不同且各自目录精确。其配置实际都读到 `http://127.0.0.1:31927`，两个用途都关闭。真实英文在 alpha、通过原地选择确认 beta 后，均只显示 `Proxy changes are saved to project: Workspace`；简体中文 beta 同样仅显示 `Workspace`。原展开确能准确显示 beta 完整目录，但必须操作后才能辨认；两个项目的地址或控件没有其他可用于核对的差异。

触发点是 `NetworkPanel` 的目录说明只消费 `projectLedgerDisplayName`，短父路径已经在当前共享 `SettingsProjectScope` 中由同一实际目录派生，但 Network 仍手工渲染旧范围。原代理范围修复解决的是知道「项目级」和展开完整目录；直接选择/配置读回修复解决可达性和时序，均未覆盖折叠时的同名项目。没有项目归属错投：代理的目录、写入请求和真实配置仍使用当前 `activeProjectDirectory` 与连接归属。

影响是代理范围触发器的文字、目录展开和既有焦点目标。保留原代理专用词条、已登记名称、完整目录、连接设置、保存/删除/测试及配置读取和失败恢复。以当前真实目录为唯一来源，短路径只供辨认，可能重名时完整目录仍精确。共享范围的默认词条和通道/MCP 消费不改变。无公开接口、配置格式、数据迁移、权限、执行轮次、调度或发布变动。风险是路径过长、同名路径误取、切项目残留展开，或破坏原选择/重试焦点，用真实两目录与实际读回验收。

## 实施方案

1. 给现共用项目范围显示一个类型明确的现有标签键入口，默认仍用「当前项目」。Network 使用其原代理专用词条并传原项目名来源，替换手工范围/路径控件。作用域按实际目录重建，保留触发器引用用于原选择与重试。
2. 以相同代理配置的两个真实项目验证双语短路径、展开、无项目选择、焦点和配置。隔离传输截断一次真实 beta 配置读取，复验诊断重试完成后焦点仍归目标项目。用原通道和 MCP 视图读一次验证默认标签，均不提交配置。
3. 保存人工复核的原图和公开回执；含本机完整路径的展开图只留隔离目录。类型、双语、正常构建与文档检查。无非界面合同改变，不新增或运行界面自动化。
