## 实施前证据、根因与影响

- 基线 `41960/ui/` 和仅观察页使用的 `41962/ui/` 运行 `main-VWTE4P1X.js`。同项目切到 `review`，同伴观察页已显示 `review`。关闭观察页的环境栏；另页从正式菜单切回 `main`，`bc289414-5735-473d-be8f-2574dba93cc1` 于 UTC（协调世界时） `16:01:02.828` 返回 200。真实磁盘和 Git 均为 `main`。转发保留实时通知，对两个真实 Git 元数据响应只控制正文交付顺序。
- 后台通知触发的 `GET /vcs` `e7505a24-29c7-4ce3-9c86-b7fc6ad71783` 于 `16:01:02.238` 返回 200。后台已读时，实际展开旁观页的环境栏，又发起一组同目录路径和 Git 读取；第二条 Git 请求 `a4d8d500-e9da-4abe-885e-d856cd74b194` 于 `16:01:04.047` 返回 200。仅放行后台响应（`16:01:04.198`）后截图仍显示 `review` 和等待中的控件。放行第二条（`16:01:16.673`）后才显示 `main`。早一轮也观测到两个请求，先到的响应在放行前由客户端等待期限结束。[桌面截图与回执](../../artifacts/2026-11-25-environment-joins-pending-git-metadata/README.md)
- 根因是环境栏的展开副作用无条件调用 `loadMeta`，将仍在进行的同目录、同连接、同选中会话的读取当作过期。现有最新请求所有权可以阻止过期结果覆盖，但展开面板无新业务事实，重复请求使正在返回的最新物理结果失去所有权。真实变更和人工重试仍需要独立的新请求。观察到的是特定冗余读取及其等待时间，上一批整组 Git 请求延迟的其它原因未知。
- 影响限于展开环境栏与相同目标的读取重叠。保留当前目录与连接、相关路径错误和 Git 错误独立发布，保留分支确认、写入接受回执、其他目录、以及工作记录通知和执行路线。该路径没有观测到 Task（任务）、Mission（多步任务）、Session（会话）执行轮次的调度、队列、唤醒或终态异常。接口、持久数据、工作树独立读和 Git 路由都沿现有事实。

## 实施前方案与验收

- 用现有元数据服务的当前读取所有者保留正进行的结算。只让环境栏展开在同连接、目录、选中轮次和目录轮次都匹配时加入它。现有路径和 Git 回执分别更新，完成后退休读取所有者。目录切换、连接替换、写后读、通知、真实重连或人工刷新仍保持原读取入口，能确立新的结果所有权。环境栏没有现行读取时照常读。保留旧请求退出和失败显示协议。
- 在隔离真实桌面复走后台分支通知和打开面板。保持后台响应在途时展开，放行真实响应并查状态，核对同作用域只有这组读取和最新分支可用；在无在途读取时用原人工刷新核对新请求。用已有和新增聚焦服务检查证明跨目录、跨选择、旧结果、错误和刷新结算，用分支/文件路线保留其现有功能。记录请求、截图、实际 Git、空闲数据、类型、构建、文档与架构检查。无模型路径。
