## 根因和影响（实施前）

基线真实服务经 `39600/ui/`，入口构建 `main-cDbxUg_6.js`。用正式 `GET /project/current` 接纳 25 个自有目录；实际 `GET /work-ledger?search=palette-focus&limit=12` 及两次原游标读取分别返回 12、12、1 个不同项目，身份与直接项目清单一致。桌面输入同一词后出现 Load more。原生 Tab 从查询框直接关闭对话框，焦点回顶部 Search；对真实续页错误也相同，键盘进不了 Retry。

鼠标点 Load more 时，代理收到真实中间页 `d98f0d69-6f02-4177-ad0a-9fb5225ca9ee`（2,892 字节），扣留 7.007 秒；结果区保留第一页，但“Loading…”和禁用的 Load more 同时显示，焦点落到页面根。交付后 13 至 02 入列、还可继续，焦点却跳到查询。再点续页，真实末页 `26b5c432-de13-4b81-a7d3-aae632f75377`（260 字节）仅交付首字节；已读结果保留，错误和独立 Retry 出现，焦点再次回查询。本人查看五张基线真实截图。前后直接项目身份与三页完全一致；已关闭自有页、服务和代理。

第一根因：Kobalte 输入收到 Tab 会主动请求关闭下拉并重置输入；全局搜索把下拉的关闭回调直接转成整个 Dialog（对话框）关闭，也没有像对话内搜索那样保护离开输入时的查询。页脚虽在 Dialog 内，不能成为下一键盘目标。第二根因：续页动作使用原生 disabled 切断当前焦点，失败分支再拆下该按钮并在 Feedback 中另建 Retry。既有 `loadMore` 只在动作后焦点落到 body 时送回查询，没有区分中间页仍有原动作和末页真正退休。以前修复保护已有 Retry 等候，没替代两条互斥动作，也未断开 Dialog 对下拉 Tab 的错误关闭耦合。

影响在同一全局搜索 Dialog 内的查询、加载更多、错误详情、重试、退出焦点；共享组合框的普通弹出用法、对话内搜索、侧栏记录、键盘命令、项目与会话数据、公有接口、工作记录游标/查询、权限、配置和发布保持。真实数据及响应按预期分页，无 Task（任务）、Mission（多步任务）、Session（会话）执行轮次、调度、队列、唤醒、重试执行或终态异常证据。前后验收用真实项目目录注册，无模型调用或新对话。

## 方案（修改前）

沿用对话内搜索的受控组合框方式：让现 Dialog 拥有全局搜索关闭，组合框 Tab 不关闭 Dialog、不清查询；搜索输入显式处理未处于组合输入法的 Escape，结果选择、顶部触发、Ctrl/Cmd+K 和页脚 Escape 仍由原入口管理。共享基础组件不变。

同一页脚按钮以现 `ledgerCursor`、`ledgerError`、`ledgerLoading` 显示「加载更多／加载中／重试／重试中」，用 `aria-disabled`、`aria-busy` 与现读取守卫防重复，不移除在用控件。保留原错误 Feedback、详情和已接受列表，动作作为同一页脚节点，不在故障分支换实例；首次无结果的忙态保持原提示。仅当动作实际退出且本操作持焦、当前查询仍拥有响应、焦点已退回页面根时交回输入；完成期间主动移焦不强抢。不新增读取、缓存、定时或写入接口。

用候选真实三页验证 Tab、继续操作、失败后在原位按 Enter、末页焦点交接与退出；完整响应和截短注入只走隔离代理的真实源。英中截图复核，保留项目输入/游标的直连接收结果、终页及样本/隔离库退出证据，跑聚焦非界面工作记录契约和构建、类型、语言、样式、文档与架构检查。原图若含本机绝对路径，仅留下经复核的局部证据。[证据](../../artifacts/2026-11-10-palette-continuation-keyboard/README.md)。

## 首轮实页后的视觉修正

英文实页可从查询 Tab 到可滚动结果列表，再 Tab 到页脚动作。真实中间页成功后原按钮持焦，真实末页错误沿用同一动作；通过键盘展开原解析诊断、回到动作、重试末页，完成时焦点接回查询并可 Escape 回顶部入口。首轮截图同时发现，错误反馈出现时同一个持焦按钮从左侧约 x=210 跳到右侧约 x=1020。把稳定动作放在页脚左下，错误反馈在其右侧；操作顺序相应从重试键到详情再返回，不改请求或焦点所有权。
