## 观察和根因

隔离开发页 `39316/ui/`，真实聊天 `ses_-zUPUdbGpzztei8M6sOd` 绑定自建 Git 项目。实际分支列表返回 200 和 `[{"name":"master","current":true}]`；代理只暂存该目录的真实 GET 响应，请求 `cc3c5ef5-31f4-4d0a-a392-8f3b4fdd145d`。点击分支按钮后尚未有菜单，控件已报告 expanded；第二次点击仍报告 expanded。约九秒后放行，真正菜单突然出现并把键盘焦点从分支按钮移到 `master` 行（图 01–03）。期间未切换分支，现象与 Git 数据、项目健康或模型无关。

直接触发是 `openBranchMenu` 在等待网络前就将 `branchMenuOpen` 置真。第二次调用误把读取状态当成已呈现菜单，只调用 `closeCommandMenuSurface(owner)`；该服务没有找到已打开的同一 owner 因而正常返回，布尔值仍为真，随后第一次读取继续打开。旧项目/连接/选中代次守卫不区分同项目里的打开意图。旧 `branchLoadDirectory` 和 `branches` 只是组件内部重复的在途/列表状态，可能让取消后重开提前消费旧列表；真实列表只由该 GET 返回。写入服务 `switchVcsBranch` 已通过现有 `refreshMetaAfterAcceptedMutation` 刷新当前分支元数据，额外列表读取只写无人读取的临时列表，新菜单原本也重新读取。

## 实施与影响

- 在分支菜单组件内只留一份包含取消控制器的打开意图，区分读取中和提交给共享菜单；真实列表直接由本次读取消费。按钮读取中保持可操作以支持取消，显示本地化进度而不会提前宣布展开。第二次激活、读取中的 Escape、切换同页子菜单、关闭环境、范围退休和卸载都退休原意图；重开创建新的请求，本次项目/连接/选中范围和请求仍有效才展示。保留共享菜单呈现、键盘与原位 Retry；只有当前意图的真实读取失败能显示分支错误。
- `loadVcsBranches` 在唯一现有服务上接受可选 `AbortSignal`（取消信号），沿原 `apiJson` 传递。删除组件缓存和写入后的冗余分支列表读取；现写入、已接受后元数据同步与原按钮错误仍归原所有者。公开应用程序接口、Git 历史、工作树、权限、路径和后端不改。未观察到任务、多步任务或会话执行轮次、调度、队列、唤醒、重启或终态异常；此处只读 Git 元数据和界面打开意图，不改运行状态。

- 风险：迟到旧结果抢焦点、取消再开读取过早、退出上层后误开、按钮文字拥挤或进度无障碍不一致。使用隔离开发页面真实交互核对第二次按钮、Escape、取消再打开、真实当前分支，截图人工复核；接口用实时 `/doc` 校验。用定向纯服务测试验证正确分支身份、真实读取信号传递和既有刷新契约；本批不在项目中创建额外分支或执行切换。无模型或凭据需求。
