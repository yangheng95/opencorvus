## 实施前现象和根因

- 39337 → 39336 的真实 /ui/（main-CeKFPQ9E.js）在收到完整上游 200 后、向浏览器发响应头前只关闭一次连接：一次鼠标点击产生两个实际 PATCH，服务请求 ID 分别为 5e48fdca-ec4d-4580-a2d1-051795b703ec、e1661cd4-0f5d-4e36-8776-5b341b5e5d4b，后者成功返给浏览器，界面正常关闭（图 01–02）。本产品 API 请求和两个宿主共用的实现只调用一次 fetch，没有应用重试；已查 Chromium 连接复用和未收到响应时可透明重发的具体路径，和此次线上事实吻合。没有证明所有网络拓扑或接口都表现相同。
- 为单独检验界面如何处理真正缺失的正文，39340 代理转发同一真实服务的成功响应头，随后只发送 16 个正文字节；上游真实返回 200，响应 1585 字节，请求 ID ff8d4068-0083-4d19-8d6e-a519e7ad902d，真实线只有这一次 PATCH。表单把底层读取异常当作「Could not save … Failed to fetch」（图 03）；取消后同一页面重开仍读到上一次值（图 04）。实际 GET 200（f6619053-2c68-4f6c-8f32-3063f4ea5dcd）及项目磁盘均为 before-partial-receipt-saved，另一个变量保持 independent。测试页、服务与代理已关停。
- 直接触发：fetch 得到响应头，但完整正文不可读；apiJson 只能在完整响应或结构化错误后提供业务回执，底层异常没有写入结论。patchConfig 在完整接受结果或已有 committed 回执才更新 appStore；TaskDirBar 把所有异常统一翻译成保存失败，并继续以旧配置投影打开。后端 project.config.changed 已存在，但界面订阅的 config.changed 只接 Session 配置事件；没有来自项目写入的即时接受投影可以替代缺失的正文。旧的 server-owned settlement 只消除了客户端读超时提前完成的问题，不等同于网络永不截断。既有 409 committed 回执有明确「持久化已完成、运行态后续协调失败」，旧本地表单也没有区分。
- 数据/控制影响：会误报持久化结论、重开读旧值、鼓励用户不必要重发；提交回执、读取归属、项目文件、其他未编辑变量与应用语言均应如实保留。配置 API、schema、写事务、权限、发布和 shell 执行不变。应用语言在渲染时决定反馈，原始诊断按真实内容保留。

## 共享传输审计边界

这是共享的请求重发风险，不能由此次项目配置最后值正确而降级成单一表单异常。初步横向证据：桌面与浏览器复用同一 HostTransport/fetch，HTTP 层没有统一幂等标识，通用服务请求 ID 是请求观测而非重发所有权。项目 PATCH 的值合并与项目归属不能证明两次请求的所有后效等价；Mission 普通/流式输入复用已分配 requestID、Task 面板输入有 request_id、Session 可复用由调用方提供的 messageID，已有各自接受/冲突/恢复契约。尚未完整核实无标识客户端、其余写入口、各执行轮次的接受与终态、重试及重启、串并行/跨项目，以及管理类写操作的真实重放后效。没有观察到任务调度或队列异常，不把本批修复当作共享重发或轮次审计完成；独立继续记录真实接口、持久事实和运行样本。这里不改传输，也不引入第二次自动 PATCH。

## 实施和验收

- 以本地环境表单为明确交付范围。验证提示、已知写入拒绝、已有已提交回执和结果不明用单个结构化反馈渲染；只有业务合同明确拒绝才称未保存。原始传输诊断可展开。收到既有已提交回执呈现「已保存，但应用失败」，用回执接受值作为当前编辑基线，避免诱导再次保存。
- 结果不明时保留表单和当次编辑差量，给用户「核对已保存设置」动作。复用唯一现有项目配置读取和归属机制，让它提供本次读取实际接受的配置，不把旧全局快照当成新事实、不读写另一条路径。只核对发送的字段（含明确删除），保留其他写入来源的无关键；匹配时只确认当前已保存值包含编辑，不声称识别原写请求，并同步接受的配置到表单基线；不同则告知当前值不同且草稿保留，不自动覆盖或重发。读失败保留草稿、显示原诊断及可重试核对；旧项目的晚回包按既有 authority 和选择轮次退役。用户编辑后退役上一轮反馈，仍由明确的保存动作写入。
- 聚焦正向检查覆盖匹配含删除、不同、读取准确返回和已提交回执；真实隔离桌面用响应正文截断复现，点击核对并观察真实 GET、磁盘和重新打开值，同时由另一个自有入口改无关值；再验证已保存值实际不同仍保留草稿及中文提示。允许额外真实读取失败后重试样本，但不得以人为模拟提交回执作为真实端到端验收。完成类型、构建、语言和文档检查；界面通过实际截图人工复核，不使用界面自动化，不需要模型。隔离服务关停后范围提交并正常推送。
