## 根因和影响

`Command.state` 以实例为生命周期只创建一份目录。配置写入和当前 MCP 连接改变后，旧命令的名称、描述、参数提示和项目模板仍由该状态返回。MCP getter 在随后实际读取时仅传项目连接名和提示名，`MCP.getPrompt` 对当前实际配置取连接，未验证它仍是原描述的连接。因此新端点在线前列表报 404，连接后可以把旧元数据与新内容拼在一起。手动断开后旧目录仍试图读取已断开提示，阻断所有命令。`Command.get` 可返回 `undefined`，唯一生产执行方直接访问字段，导致缺失命令返回未处理的异常。

`GET /command`、ACP 会话初始化中的可用命令、ACP 斜杠提交前的目录查询、公开 Session（会话）命令和命令行均受该投影影响。默认命令、配置命令、已读目录中的 Markdown 命令和当前可用 MCP 提示应使用同一当前配置与实际连接。保持旧顺序、名称构造、参数占位符、配置命令字段与流式执行。Task（任务）和 Mission（多步任务）的 MCP 提示绑定来自自身项目、运行合同或专家团作用域，公开 Session 路由已有权限边界。全仓审计其正常、恢复、终态和并发入口，观察到的问题是共享命令目录与实际模板不一致，未观察到 Task/Mission 队列、唤醒或终态异常。ACP 会话建立还先取目录再注册客户端提供的 MCP，影响首轮广播的连接提示。是否修复该入口需以生产客户端接入或可审查的契约证据为准。其余现有角色及凭据生命周期继续使用当前身份与作用域。
