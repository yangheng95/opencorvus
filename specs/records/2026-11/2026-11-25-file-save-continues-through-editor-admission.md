## 实施前根因和影响

真实隔离基线 `main-CQOC7kb7.js`。在实际 `notes/checklist.txt` 输入 `First saved note.`，通过 Explorer 发起改名为 `ready.txt` 并点保存并继续。实际写入 `d0788f4c-a83d-481f-8371-6ee5d6a16df5` 200，原物理文件含完整新正文。由随后后台观察发起的原路径真实读取 `05780156-26ac-4983-b4de-d1783c4222ea` 200 在 17:36:16.859 UTC（协调世界时）被中转暂缓。就在该次后台读尚未交付时，原改名表单展示 `AbortError: File editor admission busy`，保留输入 `ready.txt`。没有路径写入，磁盘仍为原名。17:36:23.669 交付读后，在原表单重试，真实 `fc9f1236-2da2-4f7b-8ec1-9b624adecb52` 返回 200。最终文件正文读 `d573f960-18a1-4f4f-8983-35ecad2a3d3e` 证实两行均已保存。[桌面、真实写入与中转](../../artifacts/2026-11-25-file-save-continues-through-editor-admission/README.md)。

源文件写入发布既有 `File.Event.Edited`。`main` 经工作记录流调用 `requestOpenFileDiskCheck`，按目录、路径及资源身份把该请求交给同一个编辑器。`pendingDiskCheck` 在写入、重读、占用或未保存决定显示期间保留。保存结果提交后，`finishLeaveDecision` 关原决定并同步释放可见缓冲，随后才完成调用方正在等待的 Promise（异步结果）。响应式效果一见决定关闭，先消费待查并令 `reload("disk-check")` 设置忙状态。共享 `prepareFileEditorTarget` 随后从用户同意结果恢复，却在取得原保留之前被正常忙碌校验退回。另有按目录观察代次触发的同资源内容重读，使用同一个编辑器的当前内容所有权，阶段内也要等这一交接。此前回执焦点修复只在实际路径请求已完成后发生，无法处理进入该请求之前的忙碌。

横向审计覆盖共享准备的全部生产入口。新文件目标和重复显式打开（项目文件、绝对附件、引用、文档返回）走 `requestFileEditorTarget`；文件／祖先改名移动与移除走 `admitFileMutation`，批量和拖放也使用该边界；关闭编辑器、普通项目／Task（任务）／Mission（多步任务）／Session（会话）界面选择与准备离开连接均共享同一准备和最新代次。普通批准、主动取消、过期权威／选区、忙碌在入口的其他明确动作、写失败与已完成释放仍各由已有状态表达。被观察到的共性是本地编辑器占用前的后台读可抢先，未触发 Task/Mission/Session 的任何执行轮次。未见调度器、执行队列、运行唤醒、重启恢复或执行终态异常；本轮的两个项目身份、公开只读事件及连接有效性继续按原入口隔离。编辑器自己的主动重新加载使用相同实际文件读取路径，本轮没有其独立可观察的丢失或错误回执，不把其显示合同混入。服务端文件版本、条件写、工作记录协议、权限、持久格式、模型和发布无需修改。

## 实施方案

把当前共享的编辑器占用信号由单一已占用布尔值替换为一条含「准备」与「占用」的当前记录。真正开始等待用户决定的同一个准备所有者持有准备阶段，原保存按钮在此阶段仍可调用原保存路径。页面主动操作使用已有 `fileEditorReserved` 语义，只有已占用阶段才保留原编辑器。`pendingDiskCheck` 与同一文件的被动内容重读在两个阶段均保留观察，实际交接成功时原所有者从准备直接成为占用；取消、过期或失败只由仍持有那条记录的所有者释放。真正需要重读的当前文件随后走原读取；已换目录、文件或权威的旧观察按原身份退休。继续使用当前代次、原草稿 revision（修订）、实际文件范围，以及原忙碌和错误合同。不存在第二份占用或计时器；显式打开与上一批 Explorer 焦点路径仍沿现有原则。

候选实页在同样的中转限制下从确认执行真实保存和改名，确认当前读在释放或目标改变后收敛。用存在的真实目标触发协议冲突并保留再次提交，同时确认已保存内容留在 原文件且独立文件不受影响。用现有文件工作台合同及新增聚焦状态接续覆盖批准、取消和被下一操作取代，实际桌面与接口核对聚焦结果。通过文档、类型、双语和生产构建；对于未单独制造的界面时序如实记录。
