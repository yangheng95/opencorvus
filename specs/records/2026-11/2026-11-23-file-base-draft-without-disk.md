## 根因与影响（实施前）

真实开发页 40480 使用 `main-Bsvhx-pn.js`，在 `inventory.txt` 已加载两行基准文本后从真实编辑器添加未保存行 `Audited locally: 21`。比较初次读取成功。用可逆的单文件移动暂时移开本人创建的磁盘文件；正式 `GET /file/content` 返回 HTTP（超文本传输协议）404 `FileNotFoundError`。此时「Read disk again」后正确显示磁盘读取错误（01）。切换「Base → Draft」虽然选中了正确模式，面板仍只显示磁盘读取错误，编辑器背后可见草稿，当前比较无内容（02）。将原文件逐字恢复并从同一对话框重读，当前仍选「Base → Draft」，原基准两行和绿色新增行实际出现（03）。正式回读恢复 200，比较关闭后编辑器草稿仍在，通过原确认主动放弃本次临时编辑。[真实基线截图](../../artifacts/2026-11-23-file-base-draft-without-disk/README.md)

直接触发是磁盘快照请求尚未成功，用户选只需要已有基准和草稿的模式。`comparisonPair` 在分派模式前要求磁盘已成功读取且可编辑文本，渲染层又把唯一差异视图嵌在 `status === "loaded"` 下。既有请求归属、恢复和磁盘诊断修复正确保证本次磁盘结果，但这两处合并了不同的输入要求。影响是磁盘临时不可用时用户无法核对实际仍保有的草稿内容。程序包、文件写入、归属、公共接口、数据、配置、授权、任务执行（Task、Mission、Session）、队列、恢复和终态流程不参与本缺陷。

## 方案与验收

复用既有基准、草稿和单一 `TextDiffView`。基准→草稿用本来就在当前编辑器的两份文本，独立于磁盘状态计算，两个含磁盘的模式继续要求本次真实可用的磁盘快照。把一次磁盘读取的进度和真实失败/非文本诊断与差异正文并置，保留原重读操作、错误详情、键盘、当前模式、文件身份、草稿归属和授权；文件保存、采用磁盘为新基准的条件与作用保持。没有另设请求、结果缓存或补读路径。

候选 40482 英文用同样隔离文件、真实草稿、实际移动和 404 检查独立本地差异；切到本来需要磁盘的两个模式，显示原读取问题。还原磁盘文件并重复实际读取，核对三个模式的目标数据，原草稿仍保留，明确放弃并校对原文件。用简体中文再运行缺失路径，逐张复核实际屏幕和按键焦点。正常类型、国际化、界面构建与文档检查，必要的原文件工作台聚焦正向检查，并按正式接口、原 Git 文件及隔离数据库确认范围，关闭并提交同步。不使用界面自动化代替实页验收。
