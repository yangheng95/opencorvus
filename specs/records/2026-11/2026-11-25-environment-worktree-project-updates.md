## 修改前根因与影响

基线 `main-tH9P1XWW.js` 在实际 `/ui/` 中确认只有主工作树并显示 `No managed worktrees.`。保持面板打开，真实 `POST /experimental/worktree` 创建 `opencorvus/peer-list-review` 返回 200。后端同项目 `GET /project/current/worktrees` 返回两个实际注册行，第二行标为 `managed`、允许移除，物理 `git worktree list --porcelain` 同时确认主 `main` 与托管分支。原面板仍为确认空，手动点击原 Refresh 后显示真实行并保留其焦点。三个桌面截图和原始服务器响应并列可核对。[证据](../../artifacts/2026-11-25-environment-worktree-project-updates/README.md)。

`Worktree.create` 成功注册实际 Git 工作树后调用 `Project.addSandbox`，已发布包含主目录与项目身份的 `project.updated`。真实 `/global/event` 同时见到该通知及稍后的 `worktree.ready`，而 `/work-ledger/events` 已转发前者。当前面板订阅该统一流时只处理 `work-ledger.file-changed` 用于 Git 元数据。工作树自己靠打开、手动操作、读取失败重试及删除回执读取，缺少已确认列表被项目变化通知触发的读。旧的读取恢复调整处理同次读取的失败、焦点和重试，未让列表接收项目变动。项目记录和通知路由正常，无需新增工作树事件或第二列表来源。

作用范围是可见环境的现有工作树投影。托管工作树内的真实 `/path` 返回该工作树目录，真实列表则返回整个所属仓库且带一条规范 `primary` 行。项目通知目录为项目主目录，因此只判断当前选中目录会漏掉托管工作树内的面板。前端应使用真正读回的仓库主目录而非猜测路径父级。独立项目必须继续隔离。工作树 SDK、公开事件协议、Git 注册表、数据结构、删除授权及既有失败重试契约均无需修改。代码核实按项目精确删除可在物理收敛后发布同一项目通知。此轮直接复现的是创建路径，删除和失败回滚只审阅调用，未操作。外部 Git 命令没有这份项目更新契约。当前隔离仅建了空白对话及标准项目工作树，没有 Task、Mission、Session（任务、多步任务、会话）执行轮次、队列、唤醒、恢复或终态异常证据。

## 实施方案

环境工作树已可读且打开时消费现有统一流的 `project.updated` 通知。同一个规范目录键匹配选中目录或最近接纳的当前仓库 `primary` 行。仍在第一次读取时可以待返回真实主目录后判定兼容通知。在一次读期间记录通知目录，当前代次成功时至多启动一次真实尾随读取。失败走既有的短期自动重读。关闭、项目选择和连接权威变化由同一投影失效机制退休。统一流报连接建立时可见面板也重新读取，以弥补断线期间遗漏；初始化资格只在布尔结论变化时因 Git 元数据触发读取，避免同次重连的常规元数据读再启动一条相同列表读取。

保持原工作树接纳列表、手动和自动读取共用的诊断及焦点交接，保留单项和批量删除回执的显式必要重读。项目更名等其它 `project.updated` 也可能让该项目的可见列表复核一次。由真实路由重新读取与当前权限一致的行，事件不写行数据。更新当前架构中的通知事实，保持现有语言、视觉层、服务端与持久数据格式。

候选从干净的隔离项目和独立对照目录发真实创建，查看首次自动出现、后续兄弟工作树出现和对照目录自身的后续真实行。复用既有服务端真实读取身份和前端通知传输测试。若需控制时序，只在隔离服务传输边界扣留实际响应，记录范围和最终交付。不会通过模板事件造出被显示的行。
