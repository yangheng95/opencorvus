## 实施前证据、根因和影响

40544 /ui/ 返回 HTTP（Hypertext Transfer Protocol，超文本传输协议）200，运行 main-DEARkWWg.js。真实设置页的北区和南区都叫 site-notes，直接父目录都是 operations，另有独名 reference。正式项目、受保护文档和普通笔记分别按三个项目读回；各项目拥有独立身份，正式读取与原始五条笔记和 Git 文件一致。展开时已有 north/operations、south/operations 可见（01）。从当前项目高亮项开始键入 operations/site 仍显示全部三个选项、当前北区未变（03），尝试输入 operations、空格和 south 的整组按键时弹层收起而范围未变（02）。这两个现象作为同一项「没有可输入的项目筛选」的实页证据；此批不把空格导致收起独立归类为缺陷。[基线截图](../../artifacts/2026-11-23-memory-project-picker-search/README.md)

直接触发层为记忆页唯一项目选择器使用 SelectControl，向原语传递名称与完整目录作为类型定位文本，只有已选值和整份选项，既没有路径输入框，也没有按输入派生的候选集合。旧修复已经让同名项在展开及收起时都有区别段，并把完整路径接为可访问描述；它们帮助逐项辨认，未改变选择方式。任务页使用的既有 ComboboxControl 和 matchesSearchTerms 已支持输入及候选筛选。这个差别不由表结构、项目清单丢失、目录比较或记忆数据引起。没有观察到 Session（会话）、Task（任务）、Mission（多步任务）轮次或调度、排队、重试、恢复、并发或终态异常。

影响限记忆设置的项目控件。复用已加载完整项目和当前真实目录，跨名称与路径逐词匹配并统一斜杠。输入只筛选，显式选项确认才改变现有 selectedProjectKey；继续按 locale（界面语言区域）排序并使用既有重连、刷新、接纳与焦点回交。已选同名项的区别后缀仍放在对应搜索字段所在行，单独分配空间，完整真实路径继续可见并提供无障碍说明；因此长项目名不会盖住辨别用路径。已有笔记搜索、受保护文档、应用外侧原项目、权限、配置、接口、开发工具包、schema（数据库结构）、迁移、发布和模型调用不扩展。风险是搜索误改已选范围、空候选无反馈、取消残留草稿冲掉可见选中值、长名称把独立提示挤出，以及变更来向下一个 Tab 停靠点和刷新成功焦点。用实际键盘/鼠标、不同宽度与正式读取确认。
