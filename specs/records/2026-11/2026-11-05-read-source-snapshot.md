## 修改前问题深度与影响分析

可观察线索：920 实际新交付的 read 来源没有保存摘录，921 只能用 search_code 的历史匹配验证该入口。代码当前仍如此。文件被修改后，原来源只能打开磁盘当前内容；真实页面是否足以造成对照困难尚待本轮前态复现，不能把推断当成截图证据。

直接触发点是文本 read 返回 `sources: [fileSource(...)]` 未传递既有 preview。控制/数据流为文件字节→实际分页 raw→首 20 行、既有逐行与总字节限制→`redactInlinePayloads`→metadata；同一工具完成事务将 SourceFilePayload 持久为真实 Part，前端只对有 snippet 的文件显示已有入口。旧 UI 改进只处理已有摘录的可发现性，未改变缺失生产输入。

当前公共合同：来源身份按路径/范围/符号生成，同一真实 assistant Message 内去重；首次保存的 Part 不可变，不因为同一路径后来改变而替换原证据。界面身份包含 Session（会话）、Message（消息）和来源标识。读取范围仍是实际位置，不承诺包含整个文件；摘录是有限的当时预览，不是全文件备份。新回读可以在新 assistant Message 产生自己的来源；同一 Message 重复路径仍遵守已有首次来源合同。

拟定实现仅在前态证实后，将同一已脱敏 preview 传给既有可选 `snippet`。没有新摘要算法、字节限制、存储表、接口、SDK（Software Development Kit，软件开发工具包）、迁移、配置或界面实现；二进制与目录 read 保持原合同。普通文件和附件共用文本路径，保留真实名称、缩进、空行、实际窗口和现有内容脱敏。输入过长时既有分页/首 20 行限制生效，不复制全文件。

风险：真实来源 Part 会多保存一份原有有界预览，这是既有 snippet 合同的用途；模型输入中的来源渲染需复核，不能新增隐蔽消息或另一份合成事实。空文件摘录为空，现有界面只在有内容时显示；已有历史来源不会凭空补造摘录。原始 read 输出与 metadata 不变。未发现调度、队列、唤醒、恢复或终态异常；若实测发现，立即按共享机制横向审计，不能以单场景通过排除。
