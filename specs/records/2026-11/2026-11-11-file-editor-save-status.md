## 实施前证据、根因与影响

真实基线 `39651/ui/`，资源 `main-QgIREy1o.js`，开发服务使用自建隔离 Git 项目。`weekly-review-planning-notes.txt` 正式初读 `1160c1f0-a018-4aba-9815-7aeb01d9e4e1` 200，原两行。右侧 380 像素区域打开文件，实页标题在工具栏截断。键盘在编辑器输入 `Baseline editor status note.` 后，界面只有文件名旁的小星号和启用的 Save；辅助功能树中有 `container Unsaved changes` 与 `text *`，编辑焦点仍在正文。真实 Ctrl+S 保存后，星号消失、Save 恢复不可用，页面没有可读的清洁或成功状态提示；正式 `file.read` `52136b89-b943-4553-a211-a220c8f56e05` 200 确认已保存新增文本。用实际分割条缩到 351 像素，在 `brief.md` 源码输入但未保存，切换预览，那里有 “Preview includes your unsaved edits.” 的额外说明。源代码视图和普通文本没有同等说明。两次正式 Markdown 读取 `8cc967be-d039-4765-8d26-ede4655b4eeb`、`4b4393e2-6454-44bf-a284-648cba314401` 均 200 且字节不变。本人复核四张基线原图；自建页面与服务正常关闭。

根因：文件面板已经从 `writable`、`draft` 与 `savedBaseline` 得到正确 `dirty`，但头部只用它控制星号与保存动作外观；保存状态只临时改变按钮文字，完成后没有面向当前文件的明确状态。Markdown 独立预览提示来自同一草稿，限定在预览的控件行。过去的保存往返和冲突修复正确保护落盘和输入，没有解决文件头的状态反馈。真实写入正确，尚未观察到草稿、路径或持久身份错配。

影响限可写文件的头部状态、现路径行与 Markdown 预览提示；保留文本输入、文件名称、原保存动作、只读状态、路径、错误反馈、草稿和后端条件写入，公共接口、权限、持久数据格式、调度、队列、唤醒、恢复和执行终态不改。风险是把初读或撤销误报成“已保存”、保存旧快照后误认为最新输入已落盘、重复播报预览、状态挤压长名或按钮、改变源码/预览位置或焦点。用实际成功回执和文件字节区分保存与状态。

## 实施方案

以 `writable`、`saving`、`dirty` 与当前 Markdown 模式在原文件头派生一个状态：无未保存更改、正在保存、未保存的更改；Markdown 预览的未保存状态用当前专用提示。首读或撤销只显示「没有未保存的更改」，不声称发生了保存或远端磁盘仍最新。取代原星号和独立预览提示；保留文件头及操作行，把状态放在既有路径下方区域共同呈现，让路径与短状态在空间允许时并列，紧张时自然换行。使用既有本地化和一个新双语清洁状态键；通过 [W3C 状态消息实践](https://www.w3.org/WAI/WCAG21/Techniques/aria/ARIA22) 的 `role="status"` 提供非夺焦更新，不改共享编辑器和保存生命周期。

候选实页英文默认宽度下真实编辑，透明代理扣留服务已成功的写回执；等待中再输入一行，核对「正在保存」、磁盘收到提交时文本；放行后显示「未保存的更改」，再真实保存两行后显示「没有未保存的更改」。简体中文在较窄桌面切换实际 Markdown 源码和预览，复核草稿、语义和空间；编辑后撤销仅回到清洁状态。本人查看截图，根据可读性必要再调整。检查正式读写契约、相邻文件真实字节、纯服务、类型、双语、样式、构建和文档；不增加界面自动化，不使用模型。
