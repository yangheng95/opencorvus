## 实施前实证、根因和影响

自有基线开发页 39166，在侧栏 Create project → Use an existing folder 实际输入 `owned-relative-109`，按 Enter。原对话框关闭，首页显示这个不存在的项目名且一直保留（图 01–04）。真实服务把相对路径解析在本批独立进程当前目录下，`/expert-squad/catalog`、`/expert-squad/search` 等返回 400、`ProjectDirectoryIntegrityError` 的 `missing` 原因；没有触及用户目录。回到原项目后，提交自有根下不存在的绝对 `missing-owned-folder`，对话框同样关闭；项目读返回同一实际 400，缺目录恢复将用户退到无项目首页（图 05）。同一入口填确实存在的 `target-before` 正常切换，Explorer 实际目录和原 note 文件可见，实际 Work Ledger 返回原项目和目标两个项目（图 06–07）。

直接原因：浏览器手填框只校验非空，确认后才调用目录切换。切换先把未经验证的候选发布给设置、已保存目录和 API（Application Programming Interface，应用接口）作用域，清理现选择及作用域读取后，才发真实目录请求；后续加载收集错误，无法回到已关闭输入。相对输入保持原始字符串，服务错误已是绝对目录，既有缺目录恢复的精确路径匹配不能识别它；绝对输入能匹配并退出失效项目，但原工作区已经被替换。先前“活动目录后来消失”恢复合同适用于已经选中的目录，不能防止输入错误被提前发布。两个故障共因是手填确认缺少切换前的目录事实；只加格式校验无法解决不存在的绝对目录。

影响面覆盖两个共同手填入口、确认/取消、当前项目与草稿、作用域读取和持久偏好、真实宿主文件系统、接口文档和 SDK。原生选择器继续用系统目录选择；其它入口的现有项目身份和晚发删除恢复仍沿用各自合同。审计了正常打开、无效输入、后台读和用户重新进入原项目的边界，异常是本地工作区发布顺序，未发现共享 Task/Mission/Session 执行轮次、调度、唤醒、重试恢复或终态问题。新只读确认不依赖这些机制。风险是读到不存在、常规文件、宿主不兼容路径、网络/授权退休、原对话框焦点及已确认后路径再次消失；最后一项继续由真实切换或转换的现有校验负责，不承诺文件系统不会在两次操作间改变。无需持久格式、版本或发布改动。
