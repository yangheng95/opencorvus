## 基线与根因

独立正式页面 40840/ui/ 加载 main-BgWXHtsz.js，正式读取 checkpoint-index.txt 得到 5760 字节，与物理原件一致，128 条正文。英文 100% 在「Go to line」按钮聚焦时按 Ctrl+Alt+G，焦点停在工具栏，未打开输入框。相同快捷键在正文获得焦点时实际打开原生命令输入，提交 97 后第 97 行高亮，内容为 Line 097 confirms the field checkpoint 097.。简体中文 160% 聚焦「在文件中查找」再按同一快捷键，焦点仍在工具栏。 [真实基线原图](../../artifacts/2026-11-23-file-workbench-go-to-line-shortcut/README.md)

CodeMirror 原生搜索键表定义 Mod-Alt-g，已有局部修正将编辑区按键送给单一跳行提示实现。文件面板区域的键盘处理提前跳过带 Alt 的事件；工具栏和 Markdown 预览在编辑器的键表作用域之外，因此不会进入该实现。工具栏点击已经使用 runTextNavigation，先显露保留的源视图，再校验范围和当前导航句柄，最后调用原命令。现行工作台查找、跳行校验和正文回焦处理各自正确，缺少的是面板键盘抵达这个既有动作的链接。

影响限可用文本文件的活动面板与其内部工具栏或预览焦点。文件范围、当前连接、原生文本查找和保存、PDF（Portable Document Format，便携文档格式）及其他非文本资源、失效导航、其他工作台标签和应用级快捷键有各自现行合同。数据读写、后端路由、执行轮次、调度、恢复、终态和发布无影响。

## 实施与验收方案

让共享编辑器从已安装的原生跳行键绑定派生一个专用于文件面板的按键作用域，用 CodeMirror 原有的平台和修饰键识别。文件面板仅在实际文本可导航时提供该键事件，识别后调用原工作台动作，从预览切到正文并按原数据归属核对原生提示。不另建快捷键匹配语法、输入框或数据状态。正文仍使用编辑器原键表。现有工具栏按钮附同一快捷键提示和无障碍声明，保留按钮作为入口。保护合成输入及 AltGraph。记录到现行工作台架构。

实际英文 100% 和简体中文 160% 下，从工具栏不同控件发起并实际跳至第 97 或 42 行。复核源编辑器与工具栏既有按钮的相同行为、重复按键只得到一个原生输入、Escape、就地格式修正、真实 Markdown 预览切源、原查找进入正确位置。独立服务核对所有原项目文件、两库、消息和执行状态。macOS 平台修饰键沿依赖键表，本机为 Windows。聚焦当前编辑器命令和文件合同，完成类型、语言、样式、正式构建、文档、架构索引与正常关停。
