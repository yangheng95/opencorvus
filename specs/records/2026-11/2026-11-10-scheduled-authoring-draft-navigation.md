## 已复现现象、根因和影响（修改前）

隔离基线 `39620/ui/` 使用 `main-TmhB3xCS.js`。从定时页「New automation」进入，实际输入 `Inspect report structure` 和 `Review the isolated report structure and list open questions.`，页面中两者可见；不点 Save 或 Cancel，仅点击设置侧栏 Appearance，再点击 Scheduled tasks，直接回到空列表。重新打开创建表单，Name、Prompt 均为空。再次输入另一组本地文字，按 Escape 回到项目工作区，重开定时页仍为列表，再打开新建也为空。本人复核四张实图。正式 `global.automations.list` 为 HTTP（超文本传输协议）200、空数组（请求 `efb8212c-d396-4ec0-9d72-d470ac1444b7`）；项目身份及结构由运行时声明验证。没有保存、触发执行或接触任何真实用户数据。

直接触发是页签切换或关闭设置改变可见宿主。`ConfigDialogHost` 只渲染激活的 `TabPanel`，实际 Kobalte 组件在失去选择时卸载正文；整个设置又由 `config.open` 的 `Show` 控制。`ScheduledAutomationsPanel` 是唯一作者稿所有者，名字、指令、项目、重复方式、完整日期时间、部分编辑的时间片段及打开时的定义修订都归此子树。宿主用只读页面的生命周期处理了作者稿。新建、建议和编辑的重置，保存失败保留作者输入及同页 Cancel/返回焦点各自已有逻辑；它们不能防止外层卸载。普通应用导航直接复用 `closeConfigDialog`，若让它临时变成拒绝关闭的异步确认，现有调用者中有已改变工作区选择后才关闭设置的路径，不能保证所有调用都能撤销。这也是选择保留原作者稿所有者的原因。

影响限当前设置页中打开的定时编辑器、可见性、连接归属和新建时明确选择的会话目标。项目选择已经保存精确项目标识；编辑已经保存打开时的定义、会话目标和修订标识。新建表单的 `sessionTargetID` 则会随当前会话实时取值；如果跨应用导航后保留表单而不绑定目标，会把原来的「当前会话」悄悄换成另一个。允许跨应用页继续编辑必须将新建的会话范围绑定在显式选择当时。不同连接不能复用原表单：以当前连接读取授权的修订作为挂载身份，旧的本地作者稿不应进入新服务。浏览器刷新、应用关闭、跨服务保存或自动保存不在本批范围。可见性变化不能产生新定时定义、执行、唤醒、任务队列或恢复；基线是实际数据库与真实服务的零定时定义，未发现 Task（任务）、Mission（多步任务）、Session（会话）执行轮次或终态异常。本批不改变调度、生成的应用接口、版本化持久格式、日志发布和模型配置。

## 实施方案（修改前）

将原定时页正文继续作为设置内容里唯一一个定时页签；普通设置页继续按当前方式挂载。定时编辑器用现有 `editing` / `creating` 派生的单一 `showForm` 通知宿主是否还需要保留同一个已挂载正文，宿主保留读取这个派生值的引用，避免复制字段或另外存草稿。正文在设置关闭或别页激活时隐藏，不参与键盘导航；没有作者稿时保持原卸载。设置外壳只有为保留这一正文才在关闭时保持挂载且不可见。使用现 `TabPanel` 的保留挂载与原 `hidden` 语义；在已知使用 `display` 的样式里保证隐藏条件。其它正文、键盘焦点与设置打开、关闭入口保持原合同。检查关闭时日期、时间和时区弹层是否正常退休，必要时只改该表单的确切弹层所有者，不使用全局浮层旁路。

定时页按连接授权修订挂载，退役当前连接时去掉旧作者稿；隐藏期间没有新增定时运行、没有新的定期刷新。只为新建的「会话」显式选择捕获当前会话标识，现编辑仍使用定义快照；新选项目仍沿用现有明确标识和保存合同。保存、回列表、Cancel 及后端的修订校验继续走原路径。没有新持久化状态、并行表单或通用导航确认机制。

候选真实页面以两语实际输入并切设置页、Escape/返回应用和再次进入；检查同一名称、指令、计划和时间草稿、原表单焦点、空编辑、明确退出、弹层和可见性。若能通过本地公开接口正常创建两个空的隔离会话，核对在 A 选定会话范围，导航到 B 后恢复草稿仍明确指 A；不添加虚构消息。必要时用远期隔离定义实际保存验证当前写入合同，只在完成远期校验后操作，决不运行。用运行时接口、数据库、原文件与 Git 证据；使用聚焦正向本地合同、类型、双语、样式、正式构建、文档和架构检查。[运行证据](../../artifacts/2026-11-10-scheduled-authoring-draft-navigation/README.md)。
