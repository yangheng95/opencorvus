## 现象与根因

通过本地代理将三个已完成恢复的真实 HTTP（Hypertext Transfer Protocol，超文本传输协议）200 响应各截断至 12 字节。原服务仍完成恢复。阅读页继续显示多步任务只读和恢复失败。设置归档在多步任务和另一同名项目的 Chat 上均显示失败并保留陈旧归档行。正式精确读取证明三条原身份已恢复、原请求保持完整、两个草稿均为待办且零子任务、Chat 空闲。两个项目相同目录末段下的错误读取返回 404。正常关闭并用同一隔离数据重启后再次通过精确读取和数据库检查。具体回执、读取标识、截图和路径见[基线证据](../../artifacts/2026-11-12-archive-restore-receipt/README.md)。

两个生产入口分别在 `main.tsx` 和 `ArchivePanel.tsx`。它们在三个 owner 服务的 JSON（JavaScript Object Notation，对象数据格式）请求成功后才执行提交后的刷新。客户端丢失完整响应时在持久写已完成、界面尚未投影的边界抛错，两个入口都把不确定传输结果当作未提交结果。工作台变更通知用于失效并刷新对应读取，设置归档动作自己的投影受请求代次保护，不能靠通知证明任意动作的结果。活动列表可能分页、筛选、延迟或失败，也不能证明某个归档身份的当前状态。已有精确读取可独立给出真值，旧恢复路径在回执不完整时没有调用它。

## 共享机制与影响

- Task 的生产路由 `orchestrator.ts` 调用 `EngineService.setTaskArchived`。归档可以关闭执行、暂停 Goal（持续目标）并等待该 Task 的 ingress（接入）和 Session。恢复只事务性清空 Task 留存时间并发布 `TaskUpdated`。同状态请求确认 `true`。已有 `archive-control-identity.test.ts` 检查原 Task 及关闭来源，真实桌面本批覆盖无模型的其他两类。
- Mission 的 `mission.ts` 归档路由经精确关闭身份与 `commitMissionArchiveRetention` 核验 `closed` 和删除意图，再更新原 Session 归档投影。归档与关闭执行相关，恢复只变更留存并保留关闭来源、原请求和旧执行轮次。精确 Work Ledger 读取返回 Mission 和 Session 双身份。Mission 状态接口不包含归档时间。
- Chat 和 Work 共享 `right-sidebar-conversation.ts`。正常归档先关闭原会话的运行再设置归档时间，恢复用同一 Session 持久更新归档时间。真实项目与体验在精确原生读取中同时受约束。通用 `session.ts` 会话更新不属于上述两个生产恢复入口。前端 Chat/Work 缓存需要完整的服务端 Session 元数据。
- 恢复调用串行保持原界面防重入和焦点归属。多个页面或不同项目可独立调用，检查固定原连接、完整目录及身份，读取当前持久状态。已知拒绝及删除冲突维持原错误。结果晚到时仍受连接和入口的请求所有权约束。重试沿原显式恢复交互，客户端不自动重发写入。重启重新读取持久事实。串行重启、多项目隔离及三次真实提交已复现，候选另核验独立项目并行操作。
- 作用域是归档留存的响应与页面投影。无调度、队列、唤醒、模型选择、执行轮次、关闭和重启契约改动。无协议、数据库结构、迁移、发布或版本改动。若在候选出现执行差异，将沿三个 owner 继续调查。实模运行中的现场归档不在本批桌面覆盖内，现有服务测试只证明相应局部契约。

## 实施

1. 在三个 owner 服务的恢复写入边界共用回执结算。有效回执走原提交后的流程。明确客户端拒绝继续传播原错误。连接仍为同一 authority（连接授权范围）且传输或服务结果不确定时，读一次原身份的当前状态。只有完整身份匹配且确认已清除归档时间才沿已恢复路径收敛。现有超时继续约束每次读取。
2. Task 与 Mission 复用精确 Work Ledger 读取及目录比较。Mission 额外匹配调用方原有的 Session。Chat/Work 复用现有原生 Session 读取路径并使用真实完整 Session 更新原有缓存。任何缺失或错误身份都无法确认提交。两入口统一将已选 Work Ledger 记录交给同一恢复分派，沿原有阅读刷新、设置列表清理和键盘焦点流程处理确认结果。
3. 确认失败时同时保留写回执与精确读取诊断，界面中英文显示「无法确认恢复状态」。精确读取仍为归档时保持归档动作与原读状态。已收到明确拒绝时保留现有相应失败文案。所有视图均以真实服务端数据呈现。
4. 运行恢复结算的聚焦正向服务测试、现有 archive control 服务路由契约、Overlay 类型和构建以及文档与架构索引检查。在独立桌面实际使用阅读页和设置归档，并复核正常回执、真实中断后精确确认、无法确认以及中英文、不同项目和焦点。经正式接口和数据库检查原请求、归档状态、模型调用及消息记录。
