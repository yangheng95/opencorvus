# 0.1.51 发布

## Recall

- 用户于上海时间 2026-11-12 要求“发布新版”。公开最新版为 0.1.50，Release 439451149，29 个资源。初始本地提交 `fa7e336e4` 包含另一项已提交的编辑器传输调查，远端 `62f9f0cf7` 正在验证。未发现 0.1.51 标签或草稿。保留当前编辑器修改、四个规格索引中的无关修改、171 个删除及两个本地 Bun 目录。
- 已读 AGENTS、RELEASE、原生打包和 0.1.50 记录。检查自 `v0.1.50` 起 226 个提交的产品增量、核心路由、近期 MCP/编辑器实页证据、三份数据库迁移、远端服务失败日志和依赖告警。搜索定时运行请求、持久请求编号和运行回执合同、Effect 与 XML 解析库的直接及间接使用。

## 准入修复与验收

1. 远端 CI 的审计 `131125916365` 报告 `effect` 4.0.0-beta.83 和 `fast-xml-parser` 5.10.1。前者由 Core 和 Poe 插件依赖，后者由 Azure 存储客户端用于构建和官网。旧锁定版本早于公告修补版本。将 Effect 对齐已修补的 4.0.0-beta.103，根目录统一约束直接和间接依赖。升级现有 XML 解析器约束至 5.12.0。重建冻结锁、审计实际解析树、校验生成物与消费者。参考 [Effect 公告](https://github.com/advisories/GHSA-chp3-j5qr-2vfr)与 [XML 解析器公告](https://github.com/advisories/GHSA-474x-hrwr-fgx4)。
2. `131121022487` 中两个定时手动执行的网络测试在真实 HTTP 请求前访问缺失的 `window.sessionStorage`。引入持久请求身份的 `3a3d3d5cb` 迁移了服务请求，但长等待测试仍没有当前宿主夹具。沿现有服务合同注入测试用会话存储，用真实本地 HTTP 确认传出的请求编号等于等待期间已保存编号，同时验证原延迟及执行回执。生产入口是浏览器和桌面共用的手动运行服务。服务器按请求身份核对同一个执行触发，正常、重试、重启恢复及不同项目作用域保持现有存储与持久执行合同。本轮修正局部测试，不改变自动唤醒、Task（任务）、Mission（多步任务）或 Session（会话）的执行轮次，也不增加真实模型调用。运行定时后端与覆盖层相关合同及远端服务检查。
3. 依据版本增量编写 0.1.51 双语日志，说明数据库自动升级到 13，核对既有数据迁移及受影响的后端、官网、版本和发布检查。并行工作区只通过已验证提交纳入发布。先推送并完成 Intel Mac 预检，核对实际缓存，再从最终冻结提交触发正式 60 分钟流程。
4. 验收五平台的桌面与命令行包、Linux 三种格式、稳定更新、GitHub 与官网双语日志、公开 Windows 包中的设置日志，以及 18 个官网下载链接。保留正式回执和健康历史，独立验收实例正常结清。

发布前复核发现 `mission-resume-delivery-migration` 的历史夹具把整个迁移表交给运行器，却继续期待固定版本 10。真实运行已从 9 升到 13，断言先失败，原来要检查的历史数据没有得到验证。保留 9→10 的独立真实迁移，再把同一实际数据库升级到当前版本，检查前后原会话、任务、回执，既有版本备份和重开结果。迁移声明、数据定义与运行入口保持原实现。

## 本地结果

- Bun 1.4.0 冻结安装通过，已解析的 Effect 与 XML 解析器分别为 4.0.0-beta.103 和 5.12.0。审计实际锁定的 1,747 个包无漏洞。85 项发布、版本与日志合同通过，22 项覆盖层定时运行、定义与多步任务编辑合同通过。新的长等待夹具在浏览器与桌面传输中都证明了同一保存请求编号、真实 HTTP 请求和 17 秒后原回执。
- 四份后端文件共 34 项通过，含真实数据库生产入口与迁移、并行全局对话创建、多步任务创建重读和任务跟进。9→10→13 实际 SQLite 数据、备份和重开验收通过，独立数据库目标检查确认版本 13。文档核对 353 个操作和 20 份当前架构文档。
