## 实施前现象、根因和影响

实际开发 `39583/ui/` 的 `main-U1ElstGg.js`。alpha 真实 Git 目录分支 `review-branch`，服务启动产生三个未跟踪元数据项，实页健康分支、统计和已确认仅主工作树可见；beta 同名但实际非 Git，健康实页明确显示“Git is not initialized”。两项目使用真实创建的空白隔离对话进入同一环境面板，无消息或模型。

实际菜单 Refresh 发两条读。Git `bb5dfb44-e0c8-4c5a-9605-d417353dc9fb` 在源返回 200 后，扣留 3.665 秒再截断；页面把先前分支和工作树一起撤掉，显示“Git status unavailable”和窄栏一词一行的 JSON（JavaScript Object Notation，数据交换格式）解析错误。两路完整刷新能恢复。反向扣留路径 `966f9efb-68f7-4b5a-b258-46128711892d` 4.467 秒再截断，完整 Git 事实已到，界面仍把它丢掉并报同一个 Git 不可用。本人查看七张实际基线截图。按实时接口声明，直连 alpha 与 beta 的路径各为其实际目录，alpha Git 数据与实际 Git 命令一致，beta 明确 `initialized:false`，前后都正确。

根因：两个真实读取虽已并发，却在 `Promise.all` 后才一起写入，任一拒绝都会把 `vcs` 置空、把失败降为同一个字符串。已接纳工作树独立，但它的显示和重读入场要求 VCS 已初始化，因此不相干的路径故障也撤掉整区。原错误容器是为“图标＋内容”布局的两列网格，直接插入文本落在图标窄列。旧工作树与分支菜单修复使用其它读源，不能处理共用 `loadMeta` 的错误投影。

影响覆盖本地元数据读的启动、目录换选、授权重连、配置重读、手动刷新和 Git 动作后读回；不同范围的旧响应不能落入当前项目。同一范围的 Git 快照留作已确认展示，不当作失败后的当前证据去开启 Git 写操作。保留两路路径缺失错误的真实归属及启动恢复语义；提交/切分支/推送已经被服务接受的回执仍独立，不改任何 Git 写入或工作树权限判定。工作树按既有真实独立接口读，失败的 Git 元数据只限缩写入入口。无 Task/Mission/Session（任务/多步任务/会话）调度、队列、唤醒、重启恢复、并发执行或终态异常的运行证据。公共接口、数据格式、持久化、权限和交付配置不改。

## 实施方案

继续用现 store 的 `path` 与 `vcs` 保存各自已接纳事实；同一个当前目录、连接及请求所有者分别公布忙碌与原失败，成功一项立即发布。换范围重置，刷新中保留同范围上一条诊断，当前成功清其自己的诊断。仅一项失败给调用者保留原异常；两项同时失败保留两项原错误，启动目录缺失判断识别组合中的原合同。初始化和项目清理同步现字段。

环境中明确区分路径和 Git 读取失败，使用共享 Feedback 和原错误详情；原菜单刷新改为同一组中始终可找到的单一可聚焦动作，复用现读服务，公布忙碌并防重复。已经接纳的分支与统计保留并明确标记上次确认；没有新鲜 Git 信息时，不扩大初始化、分支切换、提交、推送及工作树删除资格。实际用英中交叉故障、健康非 Git 及键盘恢复进行复核；两路正向服务合同测试、真实接口、样本文件和两个隔离库核对，辅助类型、构建、样式、双语、文档及架构检查。[证据](../../artifacts/2026-11-10-project-path-and-git-read-settlement/README.md)。
