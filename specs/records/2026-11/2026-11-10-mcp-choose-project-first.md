## 根因及影响面

基线 `main-D4izATkL.js`、1280×720。顶层 `New chat` 进入无目录启动器，设置 → MCP 连接显示「Choose a workspace folder / 选择工作区文件夹」的可关闭警告，却仍展示新增、产品分配和连接区。本人点击英文 `Add MCP` 后真实打开远程服务表单，显示名称、类型、传输方式、地址、认证等字段；没有填写、提交或外发。中文同样。现有真正的目录选择动作必须先回应用，打开侧栏创建项目菜单，再选「使用现有文件夹」，实际出现工作目录对话框，取消回到侧栏触发器。文件菜单在此状态没有可用的打开目录入口。页面上的提示本身不具备选择能力。

直接触发点是 MCP 面板在 mode/active 为真时无条件渲染项目管理结构；`reloadCurrentPanel` 沿技能页的通用路径追加无目录通知。数据/控制流根因是缺少已确认项目时仍把前置条件当成可关闭的操作错误，而不是项目限定页面本身的空状态。真正的项目请求和写操作已经使用 `selectedDirectory` / `currentDirectory` 和来源校验；提交入口会提前退出，旧后端从未负责解决视图的死路，不能简单移除校验或通过另一个写入口绕过。目录选择已由工作区服务统一管理，继续复用，不另建目录验证、开项目路由或本地目录状态。

影响 MCP 管理页的新增/删除、项目状态、产品分配入口和面板内的键盘焦点；这些控件只在实际有目录时有意义。技能库的通用提示不改；项目加载、配置、持久格式、权限、远端连接、公开接口、任务调度/执行和发布合同均不改。主要风险是成功后丢焦点或关闭设置、取消后丢入口焦点、切项目后旧的新增草稿落入另一个项目，以及改变有项目正常入口。以同一个公开项目的真实目录验证和手工输入验收，无新增自动化界面测试或无关服务测试。

## 实施方案

1. 用真实 `selectedDirectory()` 选择现有项目页面或无项目提示。无项目时只有明确说明和复用现有 `browseDirectory` 的「选择工作区文件夹」按钮；不再发布可关闭的同义 MCP 通知。现有操作 handler 仍守住实际目录；技能库保留原无目录通知。
2. 共用现有目录验证、授权范围、项目选中和读取。只阻止入口重复打开选择器；取消或失败留在无项目状态。成功后由现有项目状态读自然呈现同一设置页。仍由该操作持有的焦点在取消后回入口，在成功后交给实际项目展开控件；不抢已经转移的焦点。新增草稿随实际项目目录改变而退出并清空，复用已有默认字段。
3. 测试使用当前两个真实隔离项目，不填写 MCP 的认证字段、不变更连接。手工复核中英无目录、取消、确认、项目状态与已有表单。用 `specs/artifacts/2026-11-10-mcp-choose-project-first/` 留可公开的原图和规范回执，含本机完整路径的原图只留隔离目录。检查 overlay 类型、本地化、正常构建和仓库文档。
