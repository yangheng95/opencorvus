## 实施前根因与影响

真实基线 `main-0X-FWmIt.js` 中，两页打开 `notes/checklist.txt`。操作页返回 Explorer，从选中行实际完成 `checklist.txt` → `Checklist.txt`。编辑器被自动激活为新路径。Windows 观察页原大小写的地址仍可读取，服务端两种拼写都接受，打开包含目录可见准确的 `Checklist.txt`，从树显式打开即使用准确新拼写。这说明同伴旧拼写是仍可用的旧地址显示；本批修复的是操作页非显式切换。

操作页回到 Explorer，再把已打开的 `Checklist.txt` 真实改成 `handoff.txt`。改名完成后右侧选中 File，实际键盘焦点在 `handoff.txt` 文本编辑器。对照使用同一菜单改名未打开的 `sibling.txt` → `sibling-reviewed.txt`，Explorer 保持选中，准确新行持焦。目录 `5d18371d-128d-49d3-af5c-148469fb0601` 和两份正文读取均实际返回 200。磁盘只列准确新路径，内容保留原两份独立原文。[桌面与回执](../../artifacts/2026-11-25-file-rename-keeps-explorer-focus/README.md)。

同一文件或祖先命中时，`moveFileItem` 通过既有编辑器占用取得写入许可，真实服务回执提交新的编辑器目标。`prepareFileEditorTarget` 的通用提交把任何非空目标都当作显式打开，推进 `fileEditorRevealRevision`；主界面以该修订主动选中 File。此时 Explorer 已退到不可见，正确的 `capturePathMutationFocus` 因不可见守卫退出。原单项焦点修复只负责已可见 Explorer 内从旧行迁移到新行，不能抵消上游误发的打开意图。未打开的对照没有编辑器目标提交，因此正确继续聚焦。

影响是同一占用入口下现有编辑器的文件与祖先移动，包括单项改名、菜单移动和投递／剪切的路径回执。显式文件和附件打开、已选文档引用的定位和返回，是同一目标事务的合法显式展示调用。关闭、实际成功后的内容读取、未保存决定、冲突、取消、目录与选择权威仍服从原合同。服务端文件改名和读写、窗口所属范围、协作者刷新、路由、事件、数据格式、Git 分支与发布不需改动。没有执行轮次、调度、队列、唤醒、运行恢复或终态异常证据。风险是显式重开丢失定位或焦点、后台更新时文件仍用旧路径、成功 Move 隐藏编辑器未重新加载、脏稿被错误丢弃、父目录移动漏映射后代。

## 实施前方案

让通用准备／提交只发布真实编辑器目标与打开状态。把推进已存在的展示修订移到接受明确文件目标请求的入口中，与已获准的目标提交仍在同一个信号批次内。占用、留离决定、业务回执、同路由原路径映射、原焦点交回器和真实源读取继续沿用。同一路径的显式重复打开仍推进展示修订；移动或改名保留原可见工具所有权，切到文件时显示真实新目标。关闭仍沿既有打开状态使 File 退出。不增加状态、窗口计时器或后端行为。更新当前架构的 File 显式展示与路径回执说明。

候选使用真实服务和独立临时文件。复验打开文件的大小写及普通重命名，实际在树上按方向键继续并显式打开；对已编辑文件做原未保存决定并核对 Cancel 与 Save and continue。将父目录改名再从 File 读取实际子文件，若另测普通 Move 则记录其精确作用域。通过正向文件工作台打开、路径移动及条件写测试，类型、双语、构建和文档检查。根据真实截图修订，证据不足的组合单独记录。
