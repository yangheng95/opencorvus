## 根因与影响（实施前）

40516 实际开发页面加载 `main-B-OESGaL.js`。隔离项目中 `inspection.bin` 是 4096 字节、`empty.bin` 是 0、`non-text.txt` 实际为五字节不可预览数据。键盘进入三个真实项目文件都可直接聚焦唯一下载按钮；英文的普通和空文件画面外观相同，中文的内容识别分支也只显示通用下载提示（01–03）。相应正式读均 HTTP（Hypertext Transfer Protocol，超文本传输协议）200 且二进制响应只有 `type`、`content`，三份正式下载 HTTP 200 的原始字节分别与文件精确相等。普通 `review.txt` 在同页服务读取真实文本和现有修订标识。本人复核了三张真实截图。[截图](../../artifacts/2026-11-23-binary-download-file-size/README.md)

根因是读取已鉴权并得到真实文件状态，早期二进制直接返回空预览而丢弃 `stat` 值，内容识别分支在取得原字节后同样没有投影其长度。空字符串表示没有预览载荷，无法区分零字节与大文件。以同一 `File.Content` 返回二进制 `sizeBytes`，扩展名和 MIME（Multipurpose Internet Mail Extensions，多用途互联网邮件扩展）提前分流复用当前文件的 stat，不为显示大小多读原件；内容检测时用实际已读缓冲区长度。正常文本、内嵌媒体与更新后的编辑返回仍使用同一公共数据类型。SDK 和 OpenAPI 从同一声明重新生成。文件工作台仅在现项目二进制下载空态显示当前成功读取的大小，按语言格式化整数和单位，0 是真实值。

大小记录反映该次文件读取，之后磁盘内容变化可通过现读取刷新；原始下载仍独立读取当前资源。保留路径和权限校验、内容与编码、比较与写入、HTTP 状态、下载错误和键盘焦点，不引入额外请求、配置、持久化状态、旧字段或模型行为。影响包括正式 `file.read`、绝对 `file.readSource` 两个二进制响应以及工作台的非预览下载空态，现写入仍按文本修订合同。其他生成物大小有独立权威数据，无需调整。无任务轮次、调度、队列或终态。风险是误把空载荷当 0、把文本字符数当字节数、显示上一个文件的值、破坏独立原字节请求或忽略双语单位。

## 方案与验收

在现聚焦公开文件读取合同增加同项目和绝对来源的正向检查，覆盖普通二进制、零字节、根据 MIME 提前分流及由内容被判为二进制。继续执行正式原件下载、媒体与文本回归。运行正常生成、SDK 类型、双语、文档、架构和真实 Overlay 构建。40518 真实桌面打开三个已验证原文件，核对英文 `4,096 bytes`、`0 bytes` 和中文五字节，切换文件时值取自当前资源，唯一 Download 按钮继续获得焦点。原始下载用正式字节输出核对，检查项目和数据库后关闭隔离服务，完成范围提交和正常推送。
