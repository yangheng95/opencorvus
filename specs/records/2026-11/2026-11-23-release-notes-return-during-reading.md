## 根因与影响（实施前）

在 `40600/ui/` 的真实开发基线 `main-CP3B8Z5b.js`，设置英文当前 0.1.52 的 All versions 和 Read on website 位于顶部。正常滚动到 Upgrade impact and known limitations 后，两项随正文离屏，只剩底部 GitHub 链接；设置内容区顶部为 36 像素，滚动约 207 像素，原操作栏下缘约为负 45 像素。通过版本筛选打开 0.1.51 后出现相同问题。切换中文并在 160% 桌面缩放阅读真实 0.1.51 末尾，再次只能看到正文、GitHub 链接和设置导航。本人已逐张查看四张基线图。[截图](../../artifacts/2026-11-23-release-notes-return-during-reading/README.md)

直接触发是正常阅读超过上方操作栏。详情和搜索原来共用常规流式工具栏，`.config-content` 收纳整个阅读区并统一滚动，详情没有持续可见的版本内导航；全局返回指向设置外。现有焦点修复负责点击后的标题或版本行，无法给离开视口的操作带来可见入口。影响包括从列表和设置默认安装版进入的同一个详情分支，实际阅读末尾、使用鼠标返回或用键盘连续浏览、在窄桌面高倍缩放时的交互。影响限该详情内的控件布局。两种语言、原正文、官方网站地址、根日志来源、查询、条目顺序与原焦点所有权需保全。服务器接口、持久数据、发布、权限、执行轮次、调度和队列不涉改动。

## 方案与验收

给现有详情工具栏添加专用布局，使同一组显示为已有译文的按钮和链接黏在当前设置滚动区的起始边，使用当前主题背景、层级和间距令牌；搜索工具栏按现有布局滚动。由浏览器布局计算位置，保留现有进入和返回焦点流程。需复核的风险包括长文覆盖、焦点被挡、不同字号下换行、错误附着到嵌套滚动容器和意外修改全局设置。浏览器根据最近滚动视口计算黏附，元素保留原文档流空间。[CSS Positioned Layout §3.4](https://www.w3.org/TR/css-position-3/#sticky-pos)

真实候选 `40602/ui/` 检查英文当前详情和筛选所得历史详情，滚动到实际正文末端仍能点击返回，返回后可见正确条目、原筛选和原生焦点。重复中文 160% 并以键盘在当前位置回到同一历史条目，查看正文起点、中段、末尾、链接、布局与焦点。额外用含正文链接的历史版本检查键盘可达、可见，使用真实页面的本地交互而无需外部导航。共享日志解析与文本搜索聚焦正向测试，界面类型、双语、样式令牌、正式构建、文档和架构检查作辅助。确认两服务的实体项目身份、空记录和正常退出，提交并合并上游后普通推送。
