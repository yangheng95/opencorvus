## 基线、根因及影响

真实开发基线 `40880/ui/` 运行 `main-MWC56o5Z.js`，正式会话有 84 条准确的新增文件快照。英文 100% 搜索 `review-sample` 有 84 项，从搜索向下进入第一条可见的实际行。按 End 后列表由 0 滚到约 2247 像素，最后一条已渲染，但实际焦点退到文档。预览仍在已选首条。用真实鼠标选末条，再按 Home，实际滚回约 0 并出现首条，焦点同样退到文档。简体中文 160% 复现 End 跨越约 2773 像素后一样失焦，真实列表仍有 101 像素可视高度。 [真实基线截图](../../artifacts/2026-11-24-file-review-virtual-keyboard-focus/README.md)

自己的键事件已经由 Kobalte 原生集合正确映射到目标逻辑键，`scrollToItem` 和 Virtua 也正确滚动。Kobalte 的 DOM（Document Object Model，文档对象模型）焦点仍在旧实体行。远距离跳转卸载旧行后，列表的失焦处理把集合标为非活动。新行即使挂载也不会重新取得 DOM 焦点，试图在新行仍被 Virtua 隐藏测量时交接又会过早。已交付的普通列表滚动只覆盖已实际渲染的行。当前虚拟滚动只处理目标索引，不负责新旧行之间焦点持续，随后 Enter 无法选择正确结果。该故障是瞬时界面交互状态。任务调度、队列、数据库或断网恢复等共享执行机制未见异常，记录和预览的选择逻辑是正确的。

影响范围是虚拟审阅列表的非邻近跳转和临近测量期间的键盘选择。保留原列表配置、查询、当前焦点逻辑键、状态、显式选择、滚动顺序、虚拟窗口、数据与读取路径。只有现有真正的列表持焦交互可以发起此交接，若焦点走到其他控件、筛选或工作上下文变化，立即使旧交接失效。

## 实施与验收

在 Kobalte 现有聚焦项滚动回调中识别未渲染或仍隐藏测量的虚拟目标。先把 DOM 焦点交给始终存在的同一列表本身，防滚动选项保持当前实际视口，由原回调继续 Virtua 滚动。只保存短暂的同一列表、变更范围、当前候选行及输入归属。等真实目标已测量且滚入视口，使用实际已渲染行完成焦点交接；虚拟项样式发布和正式滚动结束可以推进同一交接。列表内已有可用实际目标则仍由 Kobalte 自然聚焦，普通短列表保留原契约。交接期间若在同一列表按显式选择键，选择同一个当前目标行。用既有唯一选择函数更新预览，移动焦点本身不更新预览。

在真实英文 100% 和简体中文 160% 用同一组 84 个实际快照，验证从查询进入、End 到末条、Home 反向、原生相邻键和选择、切五条普通结果后既有行为、快速连续按键和主动移开焦点。核对实际文件与比较、截图焦点位置和已有聚焦检查。正式关闭实例，范围提交及上游正常交付。
