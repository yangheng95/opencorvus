## 实施与验收计划

项目内 Chat 与 Work 接受调用方可选的非空 requestID。调用方提供时，使用项目 ID、当前持久 project generation（项目生命周期代次）、规范目录、体验和 requestID 派生稳定 Session ID；没有提供身份时，服务为这次独立创建分配唯一 ID，经过同一创建合同，不把相同内容当作同一个用户意图。实际 app 在构造一次创建请求时总是生成/携带身份；仅存在真实作者草稿时借用现有 composer submission（提交身份），成功沿现有草稿迁移退役；无作者草稿按这次动作生成身份，不能造输入或持久影子。明确下一次独立创建应得到另一会话。

项目内复用 Chat/Work 的唯一 Session 插入和事件权威：先按身份读已接受记录，必须满足当前项目、目录、体验、身份与初始模型合同；精确重发返回已有会话（不重新查当前模型目录），同身份更改提交的模型返回明确 409。验证新模型配置后，打开唯一写事务再次按身份判定并调用现有物理写入和事件路径；不另写 Project、Session 或请求映射表。对已有删除完成事实返回 410；进行中的删除使用现有 fence（数据准入围栏）防止与创建/返回冲突，归档不复活。并行与重启后的精确重发只返回一个持久事实，多项目/体验/代次隔离。未授权去读取或运行真实 Provider；无模型请求的创建回归覆盖上述边界。

验收：实际隔离服务串行/并行重送、不同身份可分别创建、同身份跨项目/体验独立、同身份不同输入 409、重启后的同 ID 与真实数据、归档和删除后的稳定行为；真实桌面查看重送后的侧栏与会话导航并本人复核。现工作台仅在提交目标或发送首条消息时会调用创建，若需要真实模型才可完成该路径，应清楚区分 API 触发、真实页观察和未完成的模型场景。对后端合同运行聚焦服务/持久测试，生成 SDK/文档并检查，正常同步和推送；独立进入全局入口的迁移与真实恢复审计。
