## 基线、根因和影响

- 在正式 `41710/ui/` 的工作记录，两个项目都能显示草稿。对受保护项目选择 `Download Mission project`，界面错误详情显示请求 `7fdba811-31b8-46bc-b017-be2858f3da6b` 返回 500。服务日志对应 `ensureProjectRuleFile` 打开原只读 `.gitignore` 时的 `EPERM`，发生于 `bootstrapContext`，早于 ZIP（压缩归档）构建。原规则和只读属性保留。同一操作对普通项目实际下载 4,388 字节，含五份与当时磁盘逐字一致的当前项目文件、准确的项目/Mission/Session（会话）身份。服务请求 `898013c4-2bf5-480b-abea-61142093e770` 返回 200。[截图和原请求](../../artifacts/2026-11-24-passive-project-archive-download/README.md)
- 两条精确下载路径都落入默认完整运行权限。Mission 按请求目录和 Mission 标识取得持久记录，组装当前任务状态与会话转录。Task 同样先核对当前项目，取得实际任务、看板、持久互动与协议事件、跟踪日志及转录。两条路径共用 `buildProjectArchive`，直接读取 Git 索引与工作区普通文件，并通过 `ProjectRuntimePaths.isSourceArchiveAllowed` 排除运行目录。完整项目启动会追加运行目录的忽略规则和二进制文件属性；下载自身已有运行目录过滤，从文件系统读取实际原文，Git 属性更新对该读取无必要。普通项目的基线压缩包甚至包含运行准备阶段已生成的静态配置。
- 已交付的 Git 删除项修复处理构建阶段的文件缺失，项目归属检查处理记录可访问性，二者都发生在导致本故障的项目准备之后。真实页证据覆盖 Mission。Task 入口受相同权限判定，局部构建器已有真实文件正向检查，当前需要补正式 HTTP（超文本传输协议）入口证据。已核对主动启动、Git 维护与调度调用，各归原入口。当前没有执行轮次、并发调度、队列、唤醒、重启恢复或终态异常的运行证据。
- 风险包括绕过项目归属、读取不同工作区的同名文件、将被忽略文件或运行文件带入 ZIP、使非 Git 或真实文件读取故障失去原错误，以及从已启动看板读出不同的持久证据。现有归属、Git 选择、运行过滤、文件错误、计数、响应头、ZIP 文件结构和快照证据须继续通过。同源规则以当前实际 Git 工作区为准。
