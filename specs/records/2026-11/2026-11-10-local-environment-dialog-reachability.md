## 实施前证据、根因及影响

自有隔离服务 39334 的真实 /ui/，1280×720，main-1In-HNjq.js。实际 GET /config 返回十二个变量、名称和无害脚本文本；打开项目环境菜单时显示 Create local environment（图 01），已有值的对话框标题仍为 Create。真实截图只到第七行的裁边，第十二行、初始化脚本、保存与取消不可见（图 02）。在面板内部滚轮向下三页无视觉变化（图 03）；从首个名称框按 Shift+Tab，焦点到 Save 但按钮仍完全不可见（图 04），按 Escape 可退出，焦点落在页面根节点。中文也显示创建且同样裁切（图 05），辅助功能读取显示仍用「Setup 脚本」；前批图 11 已有该标签及四行就裁边的直接视觉证据。基线没有保存，测试页已关闭，自有服务正常关停。

对话框共享卡片在视窗上下留边并限制最大高度，默认滚动；本表单为保持圆角单独设 overflow:hidden，里面只有按内容展开的网格，操作、错误和所有字段都在同一不可缩可滚区域里。超限后鼠标没有可滚容器，焦点移到控件也不保证其可见。旧卡片截住溢出但没有为滚动的内容分配空间；变量写入逻辑只负责草稿和持久化，不能补偿布局。焦点根因是打开编辑器前关闭了临时项目菜单和环境面板，原菜单项已退出，未给共享 Dialog 提供仍在的归还点。文案根因是菜单及对话框硬用两个同义的创建键，无视已有的项目配置投影；中文词条没有沿用正文已使用的「初始化脚本」。旧代码示例随语言变化但两种语言均有不同平台的用户；本批删除这个跟语言绑定的脚本示例，保留说明中要求采用当前平台 shell（命令解释器）语法及原有用户脚本文本。

影响面限定项目环境菜单、编辑器在行数超过可视高度时的鼠标和键盘交互、两种界面语言的标题和字段含义、保存错误的可见性与对话框关闭后的焦点。共享 Dialog 的其他调用不动。项目变量行键、实际配置差量、项目归属、校验和响应、数据、服务接口、shell 执行与文档发布合同都无需变化；不迁移数据，也未发现调度、并发执行、唤醒、恢复和终态收敛异常。另批再调查实际回执中断。

## 方案和验收

复用共享 Dialog 的固定头、footer 和表单关联：只让现表单字段区域缩放和纵向滚动，保留完整边距、清楚的操作分隔，取消、保存及现有校验结果放在可视 footer，唯一原生 form 仍拥有提交。使用稳定的表单 ID（标识符），保留输入框初始焦点；关闭后经 Dialog 现有 returnFocusTarget 指向仍挂载的环境面板入口，不自建全局焦点逻辑。根据当前配置及打开时的已有基线，菜单与标题共享创建/编辑词条，配套新建/编辑图标；中文字段使用「初始化脚本」，移除语言绑定的 shell 代码示例。共享 CSS 和数据服务均不更改。

在 1280×720 的真实桌面使用十二行配置，人工查看开头、真实滚轮到底、键盘从名称反向到可见保存以及取消后环境入口的焦点；在底部用普通键入更新第十二行，鼠标保存后实际项目配置与文件精确回读，再打开对话框复核；验证中文编辑菜单、标题、初始化脚本与按钮。用短/空配置验证新建入口与短表单不被拉长，且验证空名称的现有提示可见并能纠正。语言、类型、构建、文档检查；非产品逻辑未变，真实接口核对结合前批配置契约测试。记录真实截图和结果、关本人进程、提交并推送。

首轮候选的人工复核发现，移动到 footer 后错误框的图标与文字分成两行（图 16）。原来的项目操作错误网格引用仅在环境面板中定义的列宽变量；门户内的编辑器不在变量作用域。按本批可见提示要求，用项目现有 Feedback 错误组件替换本处标记并占 footer 一整行，复核更改后的真实提示和继续提交。
