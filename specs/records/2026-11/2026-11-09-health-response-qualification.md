## 实施前证据、根因和影响

基线隔离开发页 39117，`main-CXc3k-Yb.js`。直接以 `/ui` 为连接地址时，真实 `GET /ui/global/health` 返回 HTTP（超文本传输协议）200 与 HTML（超文本标记语言）文档；浏览器原解析器拒绝，设置表单正确显示未通过连接检查（图 01），排除了 HTML 被误判。然后在同一真实桌面保存本地代理 39119。代理只将真实 `GET /global/health` 请求误转到同服务 `GET /global/automations`，将原响应原样回传；其它网络路径照原样转发。隔离服务实际返回 200、`application/json` 与 `[]`，原请求标识同时见代理和后端日志。服务端在实际 Save 后完成 `07aa982d-9c88-43d4-8cdd-9aebb6341e64`，随后可见周期探测重复；表单却显示「Saved」（图 02），主界面连接诊断显示「Online · Port 39119」（图 03）。仅执行计划任务的只读列表，没有调度、启动任务或访问其它服务。

直接触发点：`apiJson<GlobalHealthResponse>` 的生成类型只在编译期，真实合法 JSON 可成功解码成任何形状；`checkConnection` 只把 `healthy === false` 判为不可用，所有缺少该字段或字段类型错误的正文继续发布 online 和成功回执。HTTP 200 只证明 HTTP 请求成功，不能替代响应内由生产端发布的布尔健康事实。前批修复只投影既有探测失败；该数据错进成功分支，它无法发现。原版本值使用了 `healthy === true`，因此同一响应还可能显示 Online 同时没有 Core 版本。

在唯一 `checkConnection` 边界、当前归属检查后、版本或运行路径发布前，要求现契约的健康辨别字段是布尔值。无该字段或类型错误返回具名 TypeError，通过原失败、监视、设置诊断、重试/归属路径处理；原 `healthy:false` 的数据库不可用详情和运行路径以及原 `healthy:true` 的成功回执保持。此处只验证决定在线语义的字段，不在 Overlay（用户界面）复制整份服务器健康结构，也不引入第二探测、路由、解析器、开关或状态。接口和生成 SDK、持久偏好、数据库结构、发版和语言资源不改。影响是当前客户端的连接状态和恢复投影，已横向查四类调用，均使用同一判断；未发现任务/多步任务/会话执行轮次的调度、队列、重试、唤醒或终态异常。托管原生环境与真实数据库不可用故障不在本次实页制造范围。
