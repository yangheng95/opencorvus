## 基线与根因

- `41780/ui/` 加载 `main-DPV2Gw9j.js`。项目 `branch-review` 的两个分支均有 `checklist.txt`，内容不同。在一个桌面标签页打开 main 的文件且无草稿，第二个标签页从同一项目会话的环境信息切到 `review`。`8a90ed40-8325-4952-b0c6-7a09aa007313` 返回 200。界面显示 `review`，磁盘、该分支提交和当前正式文件读取都是 `Review branch checklist`，已打开编辑器仍显示 `Main branch checklist` 且报告无未保存改动。手动选择从磁盘重新加载后，同一编辑器显示 `Review branch checklist`。[实际桌面和请求](../../artifacts/2026-11-24-open-file-branch-switch/README.md)
- 在 `review` 编辑器添加一行未保存备注，第二次分支变更通过同一正式端点返回 `main`（请求 `999a878e-b959-4841-9062-6de6c8b0117a`，200）。保存原草稿返回 `FileWriteConflictError`（请求 `c0b752bc-705e-423f-9e3a-54419dda750e`，409）。实际比较显示当前磁盘为 main，草稿仍有 review 原文和备注，磁盘内容保持。该轮用正式端点切换，因为专用浏览器分支菜单出现原生弹层未就绪。截图尺寸异常出现在探针期间，干净文件问题保留真实原图，脏文件比较保留实时界面观察及请求证据。
- 在第二次切换前连接正式全局和工作记录流，均为 200。全局流收到该项目两条真实 `.git/HEAD` 监听通知，后续仍未收到 `vcs.branch.updated`。`Vcs.switchBranch` 通过 Git 改完后直接重置 VCS（Version Control System，版本控制系统）状态。旧的 `VcsBranchRefreshOwner` 被停用，新所有者以刚切换的物理分支初始化，监听回调无法再将其识别为旧状态到新状态的变更。默认不启动实验工作树监听。现有工作记录公共流也不转发规范分支事件。浏览器只在发起切换的标签页重新读取环境元数据。一般文件监听进会话流后只更新目录工具的计数，文件编辑器自动重读所依赖的 `observationKey` 只记录匹配的对话工具改动。三处共同导致没有触发已打开文件重读。

## 影响与实施

- 范围是当前 Git 工作区的规范分支事件、主页面已有公共通知流和当前工作区文件读取。内置分支切换及同一长期所有者已观察到的本机分支变化使用一次既有事件。切换成功后让原 `VcsBranchRefreshOwner` 读取物理新分支并产生通知，避免与原生监听各自产生一条变更。新建 Git 时仍需重新探测原来不存在的所有者。受管工作树及其他项目按事件的目录区分，文件绝对来源、未打开的文件和其他项目的数据保持自身读取边界。项目文件读写仍由现有接口负责，保留成功/冲突合同、草稿写前验收、Git 不强制覆盖规则与模型前置验证。原 Git 初始化生成的配置文件不属于文件内容异常，候选预热后记录其对照状态。此次未发现 Task（任务）、Mission（多步任务）或 Session（会话）执行轮次的队列、唤醒、重试或终态异常。此次不做断开连接期间分支变化的补收承诺。
- 在 `work-ledger/events` 用既有 `work-ledger.changed` 投影同一 `vcs.branch.updated` 和真实工作目录，使用已有非执行元数据序列约定。页面将该事件交给精确目录的文件工作台，不将其解释为工作记录变化。文件工作台把同目录通知纳入现有目录刷新以及活动项目文件的读取代次。打开的干净文件走已有内容重读，脏文件保留编辑并通过现有比较和刷新按钮展示是否需要查看当前磁盘。使用现有项目目录比较、文件目标和请求代次，保留当前双语反馈、写入版本比较与请求归属。
- 聚焦验收在真实切换路由和普通通知流验证两次合法切换的准确目录与分支读取。桌面复验两个标签页干净文件跟随切换、脏文件正文和比较、另一个项目同名文件保持原文。人工查看截图，比较实际磁盘内容、正式请求、工作区和数据库。验证改动涉及的后端事件、元数据和文件工作台服务、类型、语言和真实界面构建。未涉及发消息和真实模型。

首次候选真实桌面复验通过自动更新、脏稿和磁盘版比较、另项目隔离及 409 保全。截图同时暴露窄右侧栏里的布局问题。两个操作与提示共用横排，提示正文被压成七行；保存冲突随后重复显示同一比较入口和更确定的磁盘诊断。现有 `file-editor-compare-feedback` 已用于同一编辑器的比较反馈，负责正文和操作分行。将此布局复用于观察提示，精简已由按钮表达的说明；当前已有可比较的保存冲突或不确定保存结果时，用原确切反馈承接。修改局限于本次反馈触达的布局与副本，按同宽桌面重新实际复验。
