## 实施前证据、根因与影响

隔离开发页 39125（`main-C2y3GRYc.js`）。对 31301 先聚焦代理 Save 后实际 Enter，原配置 PATCH 200（`da9d0a1b-8cef-4c37-ad34-dccaa8ea5b8b`），出现 Saved，但焦点落回网页；随后 Shift+Tab 进入原相邻 Delete（图 01–02），没有激活删除。第二次键盘保存 31302 后立即实际编辑为 31303。实时观察输入元素确实有焦点、值为 31303、保存状态仍是 Saving…，没有模拟延迟或注入页面。随后实际 PATCH 200（`b55a9d33-f37a-4a17-a272-1f1d6382f669`）和 Saved，仍聚焦的输入却回到 31302（图 03）。真实 HTTP（超文本传输协议）读取只确认原提交的 31302，服务端正确保存了开始时的快照，丢失发生在客户端。

根因一：已聚焦原生按钮在忙时设置 native disabled，浏览器执行失焦。根因二：项目 PATCH 完成后，统一服务投影发布确认配置；表单的 effect 无条件覆盖五个输入，未区分自己最近编辑的草稿。原 draftGeneration 在编辑时退休 Test 回执，却未为保存时的草稿采用提供所有权；旧 Saved 同样不区分已提交值与当前新输入。

横向核对共享配置边界：现 scope/authority/selection epoch 检查保护接受配置，项目接口按既有事务和目录隔离真实提交；未观察重试、重复写、项目串线、执行记录或 Task/Mission/Session 轮次异常。其它配置调用者继续接收其正常更新，只有这个面板的本地草稿重置应分开。正常保存、清除与继承、局部校验、错误及代理连通测试使用同一现入参与回执；操作开始、较新草稿、接受当前草稿、作用域改变和卸载均纳入检查。接口、配置文件/数据库、执行调度、权限、版本及发布均不改变。

实施计划：同一现草稿世代标记最后接受的草稿；编辑推进当前世代，只有无未保存编辑、且无代理写入时，现 effect 才用确认配置同步字段。写入成功仍更新原共享配置；若期间没有新编辑，允许同步，保留之前的普通和继承回执。若用户已经编辑，保持当前草稿，显示「已保存刚才提交的代理设置。之后的编辑尚未保存」，新的编辑或操作清除说明；不设第二份配置、无需手动聚焦。保存/删除的忙态合并为一个现写入动作状态，统一三个原按钮的忙态准入；仅 Save 沿同页现模式使用 aria-disabled/aria-busy 保持焦点，Test/Delete 原行为保留。作用域变化退休草稿、回执及原操作所有权，已确认的服务写入继续独立存在。
