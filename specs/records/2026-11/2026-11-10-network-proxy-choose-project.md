## 根因与影响面

基线 `main-D1kKTqFh.js`、1280×720。真实「新对话」进入无目录启动器后，打开 Settings → Network：上半 Connection 正常，Proxy 只显示 `Open a project to configure its proxy.`；简体中文同样只显示「请先打开一个项目，再配置该项目的代理」。实际需要先返回应用，再走侧栏创建项目 → 使用现有文件夹，真实「工作目录」对话框接受隔离目录。打开 `proxy-adjacent` 后再次进设置会回通用页，须重新选网络。两份公开 `/config` 真实 200：`proxy-review` 是 `0ae91211-c929-47bb-b835-5bbf419dadac`，代理 31921；`proxy-adjacent` 是 `e82db932-ab4d-4a3f-95d6-7f6281de89b3`，代理 31922；两个用途均关闭。隔离首轮误把配置放到根目录，真实服务明确返回 `NonCanonicalConfigFileError`；已按 05-config 改用唯一 `.opencorvus/opencorvus.jsonc` 并重跑，未把夹具布置错误当作产品缺陷。

直接触发点是 `directory()` 为空时代理表单用静态 `SettingsEmpty` 取代全部操作。旧方案将项目作用域和表单可用性接入真实目录，防止无项目写入，但没有把已有选择动作接进该空状态。项目已经可由真实 `browseDirectory` 验证并选中；关闭设置返回工作台会自然丢失原标签，不需要新的目录 API（Application Programming Interface，应用程序接口）、新配置写入或导航旁路。MCP（Model Context Protocol，模型上下文协议）已经用这个选择动作且明确处理异步焦点，是相同交互的现有证据。

影响为无项目时 Network 的代理入口，以及两个设置面板共用的目录动作/焦点机制。客户端连接组、代理测试/保存/删除、现有项目权限、配置读取和继承、浏览器与原生宿主的目录验证、项目名与实际目录、写入和持久化合同均不变。没有观察到调度、队列、唤醒或执行轮次异常。风险是对话框重入、取消丢焦点、选择后跳走或显示另一项目的数据、复用改变 MCP 原体验。用真实已拥有的隔离目录、公开只读回执、手工中英操作验证。原生操作系统选择器不在网页验收范围。

## 实施方案

1. 在原代理区的空状态复用设置行，显示项目限定的原说明和「选择工作区文件夹」。动作使用同一个真实 `browseDirectory`；选中后由现有 `activeProjectDirectory` 与配置读取使同一页面转为可编辑状态。不另存项目身份或代理配置。
2. 将 MCP 原有设置内目录按钮的重复准入、动作和仍归原控件所有的焦点交接提取为小的共享设置按钮。取消还给按钮，成功交给各面板现有的项目范围展开控件；若用户焦点已移动或目标已卸载，不接管。保留 MCP 原外观与活动判定，网络代理使用与上方连接保存可区分的次级按钮。
3. 在隔离开发实例真实复核 Network 英中取消与确认、MCP 回归，查两个项目的实际配置和文件、零凭据与模型，保存原图和回执。类型、国际化、正常构建、文档检查；没有非界面合同变更，不新增或运行界面自动化测试。

## 首轮实页复核与补充方案

首版 `main-kH-DSMEs.js` 确认中英选择、取消、焦点与两条实际配置均正确；中文版第一次截图还捕获了项目已显示、字段尚空的中间状态。用隔离代理暂停一条真实 `/config` 200（`55173842-212a-482d-b533-8bea1fb06ddb`）后，真实英文页面能稳定显示 `proxy-adjacent`、空代理字段和可用的 Test/Save。未触发按钮；直接代码证据是 `saveProxy` 把空输入转成 `network.proxy: null`，共享 `patchConfig` 在连接正常时直接提交到当前目录。可能影响预存代理，不可用“读回很快”排除。不是调度、任务或终态异常。

根因是工作区选择先发布新目录，再清旧配置并等待 `reloadProjectScope`；原 `NetworkPanel` 只用目录决定何时挂载编辑器，把未读取的 `config: null` 与已确认的无代理配置同时投影成空字段。`loadConfigInfo` 已验证来源、目录和选择轮次，成功才发布当前配置对象，失败在 `configLoadIssues` 存原诊断；新入口要复用这些事实。设置选择动作的一份进行状态改由调用面板生命周期拥有，以便在按钮因项目选中卸载后仍标记选择尚未完成。待选择完成且原配置对象存在后才打开表单；已经接受的空代理配置对象仍会正常打开空表单。无额外代理配置缓存、加载器或权限策略。对没有可用快照的真实读取失败，使用已有 `Feedback`、错误详情与同一 `loadConfigInfo` 提供重试；客户端连接独立可见。成功重试仍由原控件持有的焦点交给项目范围。该补充不重构跨设置配置存储、全局配置或 Task（任务）/Mission（使命）/Session（会话）选择架构。

最终另验收相同真实响应被暂时扣留时显示本地化加载状态；原样放行后同页出现真正配置。对另一次真实响应只传首字节，验证错误摘要、原诊断、同作用域重试成功及焦点。继续复核原正常英中路径和 MCP，无配置写入或外部请求。
