## 方案与验收

- 同一个 `work-ledger.file-changed` 传输分支承载真实 `file.edited` 和 `file.watcher.updated`，各自保留原来源。监视通知由服务验证绝对原路径属于项目且在 Git 元数据之外，投影规范的项目内相对路径。项目根通知保留原目录级 Git 效果。已确认宿主写入的资源身份字段仍来自原提交回执，监视通知不造文件身份。删除旧的无路径工作记录通知分支并重新生成公开接口和软件开发工具包。
- 主应用沿现有同目录、精确文件／祖先路径和资源匹配入口请求磁盘核对。Git 使用同一个规范文件事件，保留各自连接、可见性和失效范围。资源管理器保留原宿主成员事件判断，也保留现有磁盘读取。编辑器采用原项目文件读取、去重、待完成操作和脏草稿提示；修改只增加已监视的实际外部路径信息，不开启更多监听、不引入轮询。不改变未开启监听时的返回、重连及主动重载合同。
- 在已开启原监视的真实开发窗口核对干净文件保持可见时自动显示外部正文，两页同项目文件中有草稿的页自动显示磁盘提示、精确草稿与原编辑基线，且比较两栏显示真实内容。核对另一文件和同名异项目的原阅读状态、Git 状态更新、原应用写入路径、实际 Windows 事件与服务读取。运行聚焦服务通知、协议、文件及归属检查，复核截图并完成文档、类型和构建。测试只涉及自建文件和公开本地接口。
