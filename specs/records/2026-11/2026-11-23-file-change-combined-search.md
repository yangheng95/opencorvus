40540 的 /ui/ 返回 HTTP（Hypertext Transfer Protocol，超文本传输协议）200，运行 main-DHceUq2y.js。临时 Git 项目通过真实 Snapshot.trackRequired 和 Snapshot.diffFull 生成三个记录：docs/release-checklist.txt 新增、docs/release-notes.txt 与 src/release-helper.txt 已修改。SessionSummary.writeDiff 存入专用工作对话的原始比较，以正常 /session/:sessionID/conversation 读取；截至此处未创建任何消息。正式响应 board.changes 与原始捕获逐字段一致。由于保存格式没有比较分类所需的全部标志，页面仍依现有合同显示行数未知和历史文本预览不可用。结果列表、路径和修改类型来自生产界面与真实持久记录。

在真实页面由摘要进入「查看修改」时展示三条（01）。英文输入 docs/release modified 时为 0 / 3（02），明明 docs/release-notes.txt 同时满足路径和状态；中文输入 已修改 docs\release 时为 0 / 3（03），而同一行确有已修改标签。正反斜杠都经过同一个既有规范化，右上方两条修改统计与左侧摘要仍正确。[前态截图](../../artifacts/2026-11-23-file-change-combined-search/README.md)

FileChangesView.allRows 各自收集比较标签、目的地、已记录的移动起点、显示与实际修改类型以及所属分组。filteredRows 仅用 includes 检查完整输入是否出现在某一条的一个连续片段中。旧修复增加原路径、统一反斜杠和大小写，未改变整段包含式匹配；计数、搜索说明和修改状态控件本身运作如既定。输入可分别表达正确路径和状态，但跨分段或反序都会落空。没有丢失比较事实，也没有执行轮次、调度、排队、恢复、并发或终态异常。

只改审阅搜索的匹配接入、同一控件双语提示及当前合同。沿用原每行可搜索字符串和斜杠规范化，调用现有 matchesSearchTerms；各词须匹配同一记录，顺序可变，仍按字面匹配。状态及非文本为独立筛选条件，计数、选择、清除焦点和当前文件导航用既有实现。分隔空白视为词界，所以带空格的路径也可按词命中，精确路径身份仍在列表和比较上。风险包括跨行误合并、状态类型仍需相应语言、窄侧栏提示变长、回车或清除焦点有变化。没有接口、软件开发工具包、schema（数据库结构）、迁移、配置、数据写入、权限、模型、版本或发布变化。原先术语「正反斜杠」指 / 与反斜杠两种文本拼写。
