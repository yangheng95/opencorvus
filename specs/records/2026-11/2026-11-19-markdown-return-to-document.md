## 实施方案

- 从真实 Markdown 项目文件链接记录源 `FileEditorTarget`、滚动位置与链接在预览内的位置。身份使用链接的已解析路径、原可读文字和在本预览内的顺序，回读时可安全找到原链接并恢复它相对于阅读视口的位置。源内容已改动或链接对照失配时使用此前的滚动位置并把焦点留在可读预览。位置用于同一次真实揭示，确保延迟渲染及用户主动移开的焦点归属使用现有版次与可见性检查。
- 将上一文档记录置于新接受的文件目标中，每一级沿用现有 `FileEditorTarget` 身份、目录、只读源和上一层。跨文档才增加记录，直接打开、关文件、工作区离开按新的目标自然结束阅读链。跟随、回退和取消共享当前 `requestFileEditorTarget` 与草稿准入。回退也是显式正常文件读取，由同一揭示版次等待真实 Markdown 渲染完成，再恢复预览和位置。禁止把历史文件直接交第二个阅读器、跳过草稿确认或添加新的浏览器路由。
- 文件标题前仅在当前有上一文档时提供同一按钮原语与原 `nav-back` 图标，双语提供可访问名称和实际错误摘要。跟随原链接所产生的目标加载错误保留合法返回路径。现有文件定位、保存/放弃确认和初次打开焦点继续使用当前组件。把定位及链式返回的数据合同加入关联聚焦检查。以真实 `40250/ui/` 项目、中文与英文页面、可见返回位置和真实文件回读作验收，并运行类型、双语、构建与目录文档检查。正常清理自有窗口和服务后完成范围提交及推送。
