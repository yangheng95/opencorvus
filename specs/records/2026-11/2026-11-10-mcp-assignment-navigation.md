## 根因、证据与影响面

已验证基线 1280×720 桌面 `/ui`，冻结入口 `main-Ch6FzVz3.js`：MCP（Model Context Protocol，模型上下文协议）连接页在英文写 `Code or Work`，中文仍写 `Code 或 Work`；真实侧栏分别为 `Chat`、`Work` 和「对话」「通用工作」。点 `Chat` 后，第一屏由项目范围、内置工具和技能占据，连接区标题在视口下沿，真实分配控件不可见。进入 `Work` 并向下滚动能看到同一服务。公开真实 `GET /mcp/project` 和 `GET /chat/capability`、`GET /work/capability` 均为 200，项目一致，配置项为 `disabled`，两个产品均可看到且尚未分配。

直接触发点是 MCP 头部的一段普通说明：它硬编码旧产品标签，并且没有可操作的去向。资源管理 `SkillMarketPanel` 和能力分配 `ConversationCapabilityPanel` 各自正确渲染，旧路径只提供正常侧栏导航，因此只修正字符串仍需要用户寻找技能列表下方的目标。宿主已经拥有当前设置 tab、同一活动项目和稳定的页面标题；分配区在懒加载的产品组件内部，且依赖当前项目真实能力响应。固定帧数、猜测延迟或跳转到另一 URL 都不能可靠定位这个区域。产品内部 `code` tab 标识、`chat` 体验标识、`work` 体验标识及它们的路由含义不变。

改动仅限现有设置宿主、MCP 管理面板、产品分配区和两套本地化文本。现有设置导航、项目选择、表单、真实请求、分配、权限、数据库结构、持久格式、SDK（Software Development Kit，软件开发工具包）、终端/桌面桥接和模型交互均无契约修改；不涉及调度、队列、工作执行或终态恢复。关注的回归是两个入口是否明确可辨、目标是否同项目、普通侧栏是否仍按原方式打开，以及慢读取结束后是否抢走主动转移的焦点。纯界面导航不新增正向服务测试；用公开真实读取和实际界面验收，加运行现有 overlay 类型、国际化、构建、文档检查。其他产品页面高度、慢失败恢复以明确的区间焦点所有权处理；提交前复核真实延迟场景。

## 实施方案

1. MCP 头部介绍只说明项目共享定义和分配用途；下方显示两个轻量按钮，动作名插入与设置侧栏共享的当前语言产品标签。连接、删除等动作仍留在原处。
2. 由 `ConfigDialogHost` 走现有设置 tab 切换，捕获这次局部跳转的项目、tab 和源焦点。先让目标页标题接管焦点，再由真实产品分配区挂载时报告可用。只有请求仍是本次跳转、当前项目和 tab 未变、焦点仍由这次跳转持有，才滚动并聚焦命名的连接区。没有成功读取时保留产品页既有加载和错误反馈；离开设置、改变项目、换 tab 或主动把焦点移到别处会退休这次跳转。普通侧栏导航不建立该目标。界面动作不改变配置。

## 验收结果

- 首版 `main-BjlgzIW1.js` 实际导航命中正确区域，但原图揭示按钮仍渲染字面 `{product}`；本地化检查只验证了键集合，不能证明运行时插值。按现有 `{{product}}` 约定改正，动作名明确为打开分配设置，并根据首版目标截图增加现有焦点色与滚动留白。正常重建并用新开发实例实际确认 `main-DC0m8EvP.js`。
- 最终版在英文和简体中文均从管理页用鼠标进入对话分配区，用回车进入通用工作分配区；截图见清楚的区域轮廓，再按 Tab 到真实的首个服务复选框，仍为未分配。普通侧栏打开 `Chat` 保持页首和 tab 焦点。隔离代理只延迟真实 200 回执，未替换数据：工作能力延迟 8.620 秒，主动移焦到搜索框后仍保持页首与输入焦点；对话能力延迟 4.800 秒，切至外观后仍在外观及其 tab 焦点。
- 基线及最终版交互前后，三个公开读取均为 200；实际项目身份相同，同一服务保留 `disabled`，两个产品的已有设置都为可分配且未分配。未连接、未修改分配或删除。两份隔离 SQLite 完整性快检为 `ok`，任务、会话和服务商用量事件计数均为 0；实际服务商目录 88，已连接为 0，不使用凭据或模型。类型、双语（3072 项）、正常构建及渲染器表面检查、文档（353 个操作）通过。未执行 UI 自动化。已关闭本批桌面标签、隔离服务和代理（39467–39469）。
