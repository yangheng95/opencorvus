## 根因与影响

真实 `40450/ui/` 加载 `main-u86mAEBv.js`。键盘两次 Tab 从 Memory & Context 标签经过原设置尺寸手柄到项目按钮。此时北区按钮显示 `site-notes`，实际焦点的无障碍名称为 `Project site-notes`。展开后能区分 `north/operations`、`south/operations` 与独名参考项目。下方向键选南区并回车，焦点正确回到收起的按钮，但它仍显示 `site-notes`、读作 `Project site-notes`。只有下方独立文字显示南区完整路径，既有按钮没有把这段文字引用为说明。两区笔记已独立，三项目的正式身份、文档与笔记读取一致。 [真实基线原图](../../artifacts/2026-11-23-memory-selected-project-identity/README.md)

直接触发是选择回执更新真实目录，通用选择器关闭并将焦点恢复到按钮。数据流已具备准确的 `projectHints()`，但现 `renderValue` 只取 `projectName`，`renderOptionLabel` 才读取区别路径；旁边的完整路径元素只渲染可见文本，没有接上共有选择器现成的 `ariaDescribedBy`。此前修复聚焦展开时选哪个，收起后靠下方路径核对，没有涉及当前按钮值或其描述。

影响仅限记忆页的收起值、焦点上的可访问身份和区分路径排版。项目选择键、原目录事实、项目排序、刷新、弹层键盘、详情范围、活动工作空间、接口与数据格式都沿已有行为。两种界面语言复用其现有「项目」标签，项目名与路径为真实用户数据，按原样呈现。没有 Task（任务）、Mission（多步任务）或 Session（会话）的执行、并发、队列或终态异常。无发布、迁移或模型验收需求。
