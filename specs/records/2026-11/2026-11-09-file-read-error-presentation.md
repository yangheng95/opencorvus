## 根因与影响

已观察现象：b29真实outside.txt的400/FileInvalidPathError在编辑器仍显示Could not load this file及通用路径/访问重试提示，必须展开Details才能看见明确的路径拒绝。直接触发为当前loadFailure有400具名原错误；私有memo只判断404/FileNotFoundError，任何其它原因统一走generic。旧路径为原缺失文件方案只增加missing boolean，未消费现已发布的400路径事实；错误本身被完整保留，不是后端数据丢失或Provider行为。

数据/控制流从真实read资源的loadFailure.error，经现ApiError status/name映射到展示key，t在渲染时跟随当前语言。方案只把旧missing boolean替换为同一memo派生的titleKey/hintKey：404/FileNotFoundError→原missing；400/FileInvalidPathError→新路径不可用提示；其它→原failed。title和hint消费同一派生结果，不新增影子error状态、共享错误协议、文案关键字匹配、路径推断或权限gate（流程门）；保存错误/源文件身份/Details/资源owner/Retry/导航许可保持。

影响覆盖私有memo的唯一两调用、两语言产品正文/标题、共享Feedback展示、现read/source-content加载者、正常/缺失/未知错误和成功资源状态、架构文档/索引/交付。没有函数公共契约、配置、路由、数据库或持久格式变化。Task/Mission/Session occurrence（执行轮次）调度/队列/并发/恢复/终态无异常实证，不改运行机制。UI（User Interface，用户界面）单独改动，不新增任何UI自动化/源文案断言/DOM（Document Object Model，文档对象模型）测试；后端b29检查已通过且实现未变，不无目标重跑。
