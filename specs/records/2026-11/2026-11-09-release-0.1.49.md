## 根因、影响与实施

1. 在唯一测试传输中给 `global/health` 提供当前布尔健康事实，保留其它夹具的确切延迟、失败、项目身份与轮次。覆盖已接纳多步任务、附件并发和替换、过期与取消，以及文件导航后现行回执。生产共享 `checkConnection` 与任务/多步任务/会话的派发、唤醒、数据、重启恢复路径无需修改。失败发生在健康夹具处理，比目录激活回执更早。针对这两个非界面服务文件使用原隔离运行器，使用已有真实健康页面证据验证生产边界。
2. 发布监控共有两个 deadline 入口和父工作流的精确配对等待。唯一 Actions 客户端保留 HTTP 状态，由已建立原始期限的观察循环对 500、502、503、504 进入下一原轮询。覆盖独立/配对网站、原生及其精确父读取和分页 jobs。期限先于新一轮读取或终态判定，越界回到原取消入口。身份/权限/解码错误、初始创建时间缺失、部署和签名错误继续失败。派发和取消的写入不重放，也不改变 attempt、并行包、队列、父子归属、产物完整性或正式 60 分钟。此处是发布控制面，同应用的任务/多步任务/会话调度、项目队列、模型和数据库隔离无共享调用。用真实本机 HTTP 请求在现有合同中重现 500→精确成功及越界取消，正式工作流验证完整实际链路。
3. 双语补丁日志从真实用户可见差异编写，按唯一 `version:bump` 同步版本族。运行冻结依赖安装和审计、受影响后端合同、生成固定点、文档、官网和原推送钩子。临近提交再次合并上游并复核最终增量。调度 Intel 预检，正式手动派发只使用推送的最终 SHA 与 `expected_source_sha`。从原创建时间起共用 60 分钟，必要时只重跑同次失败集合。保留健康历史和历史日志，仅对确证归属且未公开的失败候选执行用户授权的清退。
4. 验收五平台图形界面和命令行安装资源、Linux 三格式、29 公开资源、5 更新平台、实际返回 ID 的官网部署和 18 个下载链接。核对 GitHub、官网中英和正式下载包设置内的同一根日志，使用独立空实例与真实桌面人工截图，服务资源独立结清。新版可见变更以已提交的真实桌面规格为依据，补做本版日志验收。不操作用户在用窗口或实例。待正式结果完成后记录准确结果并提交推送，完整单元测试另外按实际状态报告。
