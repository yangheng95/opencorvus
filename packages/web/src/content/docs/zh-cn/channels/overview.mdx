`packages/channel-runtime/` 把外部平台统一映射为 `platform : channel : thread`。每个 thread 对应一个 OpenCorvus session，后续回复继续使用同一任务上下文。

## 运行 channel-runtime

```bash
cd packages/channel-runtime
cp .env.example .env
bun run dev
```

`registerAdapters()` 只启动已配置的原生 channel，并跳过 planned 条目。

## 消息流

```text
平台 gateway
  -> ChannelAdapter.onMessage(IncomingMessage)
  -> ChannelRuntime.handleMessage()
  -> 创建或复用 session
  -> client.session.prompt()
  -> 返回精确 assistant 响应

OpenCorvus 事件流
  -> ChannelRuntime.handleEvent()
  -> 平台插件自己的 sendText/sendMedia
```

Session、channel link、权限、附件和模型执行仍由 OpenCorvus 统一负责。

## 新增 Channel

- 只有 provider 暴露薄的独立 lifecycle / ingress / outbound contract 时，才能把 planned 条目提升为 ready；禁止复刻另一个应用的 runtime surface。
- OpenCorvus 特有 channel：新增一个原生 adapter，并在原生 factory projector 注册。
- 禁止添加 provider switch、第二份 channel 清单或大规模兼容 runtime。

共享控制项见 [环境变量参考](../reference/env.md)。
