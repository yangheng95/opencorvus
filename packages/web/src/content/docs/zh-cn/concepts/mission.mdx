Mission 把一个长程目标拆成责任清晰、可审查的任务链。

Mission 负责协调结果，它**不是**一个更大的 Agent。每个子任务固定拥有一个精确版本的专家团和一条已选
工作流，而任务依赖、消息、Artifact、证据和生命周期决策都保持可见。

## 协调与执行保持分离

Mission 负责目标与依赖图；具体工作、能力投影和证据仍归属各自真实责任方。

| 责任方 | 拥有什么 | 说明 |
| ------ | -------- | ---- |
| Mission | 目标与依赖 | 跨子任务协调目标，并记录它们的依赖图。 |
| Task | 一项有明确归属的交付 | 一项项目范围内的交付、一个固定专家团版本、已选工作流、相关 Session 与生命周期决策。 |
| Expert Squad | 角色与能力投影 | 具名 Agent、指令、Skills、工具、MCP 访问、选择说明与已声明工作流。 |
| Artifact 与证据 | 精确、可审查的交接 | 带类型的 Artifact 携带来源与精确引用；Host observation 独立于 Agent 总结记录文件与命令事实。 |

## 如何运行

1. **定义目标。**记录所需结果、任务边界与验收条件。
2. **拆成责任明确的任务。**只有当一项交付可以被独立负责、验收或依赖时才拆。为拆而拆只会产生
   没有主人的协调开销。
3. **固定专家团身份集合。**Mission 启动时记录可使用的专家团 ID；之后新安装的能力不会静默扩大这一集合。
4. **每个任务冻结版本。**创建子任务时，一个获准的专家团 ID 会为该任务解析并固定到一个精确能力包版本
   及其已选工作流，在该任务生命周期内保持不变。
5. **运行任务内协作。**具名角色流式产生消息与工具工作，再交接带类型的 Artifact 引用与可见证据。
6. **读证据再决策。**Mission 读取已终止子任务的输出，通过显式验收或依赖任务路径继续。

## 长程为什么撑得住

- **持久组织。**Mission 与 Task 状态持久保存；版本化目标与验收契约保留正在交付和判断的内容。
- **任务权限固定。**一个精确版本的专家团及其已选工作流在任务生命周期内保持固定，任务不能中途
  静默切换专家团。
- **带证据的交接。**带类型的 Artifact 引用、来源、完整读取与 Host observation，让后续工作能检查
  某个决策究竟依据了什么。
- **终态不是终点。**进入 `completed`、`failed` 或 `cancelled` 的任务，在收到真实新输入时会重开——
  发消息本身就是恢复。重开会开启一次新的执行 occurrence，而不是重放旧的，历史仍然可读。
  不存在另外的"重试"或"重规划"控件要去找。

## 真实边界

长程不等于无限执行，也不等于永久无人值守。

无人值守只在本地或托管的 OpenCorvus 运行时在线期间继续。输出质量取决于所选模型、可访问来源、
已安装能力与可用证据。外部影响仍受权限规则约束。Mission 的协调不会抹去 Task 或 Agent 的责任归属。
