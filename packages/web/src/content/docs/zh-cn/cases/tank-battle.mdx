用户提出：**“帮我创建一个坦克大战的网页游戏，要求还原全部的原版游戏体验。”**
记录日期为 2026 年 9 月 18 日，由一个软件交付专家团负责。

这个案例展示分工、衔接和修正过程，不用于证明成本优势、整体成功率或与原版完全等价。

## 实际开展了什么工作

| 工作 | 产出或检查内容 |
| --- | --- |
| 意图解析、需求工程与来源调研 | 19 项可验收要求，确定参考版本、玩法规则和范围边界 |
| 架构设计、工作量复核与界面设计 | 模块与数据契约、影响面评估、像素布局与界面状态 |
| 实现与集成 | 包含地形、敌坦、道具、计分、双人同屏与建造模式的网页游戏 |
| 独立测试 | 规则、数据与可游玩的操作流程 |
| 界面完整性复核 | 真实浏览器观察、截图与交互证据 |
| 系统完整性审查 | 交付物与证据是否支持需求 |
| 编排器 | 衔接工作、汇总产物、记录交付与限制 |

这些工作按依赖交错推进。表格是职责梳理，不是精确时间线或并发量证明。

## 两轮返回实现的修正

**计分与结算。** 复核推动实现修复跨关累计分和结算呈现。
收尾记录描述了进入下一关后再次检查分数保持的过程。

**关卡数据。** 操作者要求从公开、非原版数据抽取渠道复刻地图。
实现替换了 35 关地图与敌坦编成，登记来源，再交给独立角色核对。
这是一次有人工裁定参与的任务。

## 仍需如实保留的边界

收尾报告称 242 项测试通过，但留存报告记录了 241 项通过、1 项失败。
该报告与最终交付的版本关系尚未核清，因此本案例不宣称测试全部通过。

关卡数据可追溯到公开复刻项目，尚未独立证明与原版只读存储器（Read-Only Memory，ROM）数据逐格等价。
格内局部地形、逐辆敌人顺序和后续周目编成仍有简化或推导。
高分画面、铲子道具真实拾取等部分实拍证据缺失。任务状态显示完成，并不会消除这些限制。
