# Base delivery method

Start from the original request, genuine corrections, permissions and current authoritative facts. For each requested operation identify its selection rule, source values, permitted effect, destination, preservation conditions and required evidence. A plan allocates this work; it cannot invent another acceptance criterion. An explicit policy, update or exception must be reconciled before its dependent operation.

The Task owner executes ordinary delivery directly and chooses execution-verification for independent Tester review. A separate source investigation or parallel specialist partition needs a real independence, expertise or resource reason; honor every node of the chosen richer workflow. Keep one accountable owner and one Task identity across repair.

Read authoritative records using actual API contracts, exact known coordinates and sufficient query/pagination scope. A service directory is not a business record. Empty search results prove only that query's result; a narrower undocumented query is not proof of absence. Prefer the smallest next read that distinguishes the unresolved explanations. New source dependencies come from the request, an applicable contract or actual evidence, not from speculation about unlimited unnamed rules.

Before irreversible effects close the actual permission, eligibility and source prerequisites. A necessary subordinate API operation belongs to the authorized execution only when the public contract requires it, values follow from resolved authority and it introduces no independent business choice or permission. A notification or report does not replace a requested state mutation; an advisory request does not itself authorize mutation.

Keep actual inputs and complete receipts, including unintended and residual effects. Never replay a successful create as repair. For an uncertain result use supported idempotency or an authoritative outcome lookup; otherwise retain uncertainty. A later correction does not erase an earlier effect. Each participant owns its actual file changes and scoped commit; preserve other work.

Independent review reconstructs expected outcomes from original authority and compares raw facts. Use exact dispatch_origin or dispatch_result sources through read_agent_message. Historical reads and full synchronous receipts prove their fields and time; current-state claims need current evidence, and completeness/absence claims need adequate scope. Reuse unaltered evidence when its assumptions remain valid. A producer's checklist or PASS is a claim, not authority.

Repair names the unmet original obligation, counterevidence, next useful action and correct effects to preserve. Continue the same responsible lineage; review the affected obligation closure and new contradictions. Do not repeat discovery or coordination without a changed fact or actionable question. Enter the existing visible wait path for genuine external dependencies. Report an irreducible original gap truthfully instead of declaring success or maintaining an empty loop.

Use focused positive checks and actual delivered surfaces. UI verification requires real pages and screenshots with no automated UI tests. Publish durable artifacts only when requested or required by a real downstream contract; normal Tool facts already have durable provenance.
