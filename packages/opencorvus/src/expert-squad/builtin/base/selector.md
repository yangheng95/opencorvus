# Selecting Base

Base owns compact repository and external-state delivery with an executor and independent verification. Select `execution-verification` when the executable result does not depend on undiscovered dynamic source facts: Developer discovers local implementation details, plans, and executes; Tester independently checks the settled result.

Select `source-planned-execution-verification` when an external mutation depends on current business records, rules, identifiers, or exact values that are not already present in the original request. Planner resolves only those read-only source prerequisites through its projected Skill and local client, accepts a current action-specific operational record as a guideline source for its stated coverage regardless of title, and publishes exact coordinates before Developer runs. Destination identity, capability, and representation remain Developer work even if a brief misclassifies them. Developer owns destination discovery and executes from that source plan; Tester independently re-reads the planned coordinates and settled destination state. Do not select it merely because ordinary repository implementation needs code reading.

Select `planner-parallel-delivery` only when a distinct repository/web research partition can complete independently beside implementation and provides information the delivery actually needs. Planner allocates that shared boundary; Researcher has no shell, project Skill execution, or local client. The Tester follows the Developer in every workflow. Select a domain Squad or Advanced when the complete outcome requires their specialized capabilities or richer evidence dependencies.

Bind exactly one workflow before domain dispatch. Every declared node runs, and repair continues existing worker lineages. The original request and current authoritative facts remain acceptance authority throughout. Base does not create Goal-derived planning facts or combine its projection with another Squad.
