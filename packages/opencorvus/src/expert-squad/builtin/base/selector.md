# Selecting Base

Base owns compact repository and external-state delivery with an executor and independent verification. Select `execution-verification` when one execution owner can resolve the required implementation details and current business-source facts within the same bounded delivery: Developer reads sources before mutation, plans, executes, and self-checks; Tester independently checks the settled result and re-reads the decisive sources.

A single external mutation whose source facts serve only that mutation normally uses `execution-verification`, even when the Developer must read several records or services before acting. Use the source-planned workflow instead only when those sources contain conflicting or precedence-bearing authority that must be reconciled before mutation, or the source investigation is substantial enough to be a deliverable of its own.

Select `source-planned-execution-verification` only when source resolution is a distinct semantic dependency worth handing off before execution: conflicting or precedence-bearing authorities must be reconciled, or the source investigation is substantial enough to be a deliverable of its own. Planner resolves only those read-only source prerequisites through its projected Skill and local client, accepts a current action-specific operational record as a guideline source for its stated coverage regardless of title, and publishes exact coordinates before Developer runs. Destination identity, capability, and representation remain Developer work even if a brief misclassifies them. Developer owns destination discovery and executes from that source plan; Tester independently re-reads the planned coordinates and settled destination state. Dynamic values alone do not justify a Planner, and ordinary repository implementation does not use this workflow merely because it needs code reading.

For external mutations, a full Host-recorded created or updated record is operation evidence for independent source-to-result comparison. Use a correct same-record destination read when available; do not require an unrelated collection projection to duplicate the receipt.

Select `planner-parallel-delivery` only when a distinct repository/web research partition can complete independently beside implementation and provides information the delivery actually needs. Planner allocates that shared boundary; Researcher has no shell, project Skill execution, or local client. The Tester follows the Developer in every workflow. Select a domain Squad or Advanced when the complete outcome requires their specialized capabilities or richer evidence dependencies.

Bind exactly one workflow before domain dispatch. Every declared node runs, and repair continues existing worker lineages. The original request and current authoritative facts remain acceptance authority throughout. Base does not create Goal-derived planning facts or combine its projection with another Squad.
