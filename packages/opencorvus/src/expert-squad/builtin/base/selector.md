# Selecting Base

Base owns compact repository and external-state delivery with an executor and independent verification. Select `execution-verification` when delivery has no material dynamic business-source prerequisite before mutation, or when the operation is reversible and one execution owner can safely resolve ordinary current facts within the same bounded delivery. Developer discovers implementation details, plans, executes, and self-checks; Tester independently checks the settled result and re-reads decisive sources.

Select `source-planned-execution-verification` when an irreversible external mutation depends on current source authority absent from the original request. Planner classifies traceable obligations as `execution_authority` values or conditions needed to form or authorize the mutation, `applicable_constraint` rules and their explicit dependencies, or Developer-owned `outcome_semantic` results. An action-specific operational record closes the constraint coverage it states regardless of title; the abstract guideline category is not another blocker. Explicit approvals, prohibitions, eligibility, opt-out, retention, and other authority conditions remain mandatory and cannot be assumed away. Destination identity, capability, targeting, representation, mutation, readback, and contract-required `destination_execution_dependency` steps remain Developer work unless original or observed authority identifies their controlling source. Developer executes operations whose reconciled source prerequisites are resolved; Tester independently re-reads the coordinates, classification, supporting side effects, and settled destination state. Ordinary repository implementation does not use this workflow merely because it needs code reading.

For external mutations, a full Host-recorded created or updated record is operation evidence for independent source-to-result comparison. Use a correct same-record destination read when available; do not require an unrelated collection projection to duplicate the receipt.

Select `planner-parallel-delivery` only when a distinct repository/web research partition can complete independently beside implementation and provides information the delivery actually needs. Planner allocates that shared boundary; Researcher has no shell, project Skill execution, or local client. The Tester follows the Developer in every workflow. Select a domain Squad or Advanced when the complete outcome requires their specialized capabilities or richer evidence dependencies.

Bind exactly one workflow before domain dispatch. Every declared node runs, and repair continues existing worker lineages. The original user-authored request and current authoritative facts remain acceptance authority throughout; agent-authored Task delegation may refine only from user intent, current authority, applicable public contracts, or accepted Delivery Slices, and cannot invent requirements. Base does not create Goal-derived planning facts or combine its projection with another Squad.
