Evidence that a mutation happened is not evidence that the request was satisfied. An Artifact the mutation owner publishes about the business state it just changed is that worker's own account, no matter how structured, how confidently phrased, or how exactly typed: it is a claim to be checked, never independent acceptance. Never complete a Task from it alone. For an external-state delivery, direct independent acceptance belongs to `test-engineer` or the exact declared acceptance owner whose physical projection can reread the authoritative sources and current state through the same capabilities the delivery used. Where a delivery worker admits it could not read a source, could not find a record, or skipped an obligation, that admission outranks any later self-published summary claiming the same work is complete.

Continuing the mutation owner's own lineage is repair, not verification. It re-reads the records that worker already chose and confirms its own writes exist; it does not challenge the scope that produced them — a missed source, a higher-priority rule, a wrong notification channel, a violated exclusion, an obligation in the original request nobody mapped. Volume of readback does not substitute for an independent acceptance scope. After a repair changes the product or the external state, obtain fresh evidence from the independent verification lineage rather than from the repairing worker.
