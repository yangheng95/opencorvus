# Built-in Research Studio

## Fact and Turn Contract

Every projected agent extends the platform Agent-fact and Turn protocol. Research tools and message-owned artifacts record durable evidence without becoming submit/finalizer calls; a normal stream end is only a physical Turn observation; and the visible final assistant message is natural narration of work, limitations, and blockers rather than durable evidence transport. File changes and command results remain Host observations rather than Agent self-reports.

Execution attempts and dispatch lineage are immutable physical evidence identities. Exact Delivery Slice revision IDs are optional work and evidence subjects, never lifecycle or scheduling owners. The Orchestrator judges visible final messages, domain artifacts, tool traces, and Host observations and owns Task lifecycle decisions. Every completion appends one typed `task_completion_decision` artifact that names the exact Orchestrator message/tool part, typed EvidenceLocators, every intentionally delivered Artifact locator, every accepted current Delivery Slice revision ID, and the exact selected workflow ID (`null` only for a direct Task). The selected workflow is inseparably bound to the active package revision: scope, project identity, namespace, manifest ID, version, and package digest. Empty deliverable or accepted-revision lists are truthful only when that Task produced no Artifact deliverables or has no Delivery Slices. Reopen preserves earlier decisions, and the current Task projection joins only the artifact whose timestamp equals the terminal Task timestamp. The artifact does not copy the narrative summary or materialize an acceptance aggregate. This package does not infer an active/current Run or persist workflow step state.

## Expert Contract

Research Studio turns a bounded question or source set into a source-backed analysis that is useful both in the conversation and as a durable project artifact. It supports faithful direct writing from sufficient supplied material, verified synthesis of an existing evidence set, and full external research. Selection requires ownership of the complete requested evidence and delivery surface; the word “report” alone does not establish fit.

Select exactly one manifest workflow before the first dispatch. Every declared node executes exactly once for the Task and only after all declared predecessors have terminal-success evidence. A failed or invalid node result is a visible blocker for the current Task, never permission to repeat the node.

`research-studio-planner` defines the research charter. It fixes the question boundary, audience, definitions, subquestions, source hierarchy, freshness rules, comparison dimensions, and stopping conditions before external discovery begins.

`research-studio-researcher` collects durable evidence against that charter. It prefers primary sources, records citation-ready findings and dates, separates fact from inference, surfaces source disagreement, and marks unknowns instead of inventing them.

`research-studio-analyst` turns the accepted evidence into an explicit claim-and-evidence matrix, comparisons, conclusions, limitations, and unanswered questions. When the request depends on data or calculations, it owns executable analysis, canonical result tables, stable claim identifiers, reconciliation, algorithm validation, and positive verification evidence before Fact Check begins. It does not write or publish the final report.

`research-studio-fact-checker` independently verifies the analyst's exact post-computation load-bearing claims, source mappings, numerical reconciliation, and method evidence and records supported, corrected, or unresolved verdicts with durable evidence.

`research-studio-writer` is the only final-delivery agent and uses the Build runtime template as Research Studio's package-owned final owner. It runs only after its declared predecessors succeed, loads the report-quality and visual-design Skills, fills the package's fixed report template from accepted evidence, and continues its own exact bound lineage when report delivery is physically interrupted; it never replaces another node's evidence, recomputes an accepted quantitative claim, or allocates a second writer occurrence. It derives every presentation from one structured report model. For a substantial browser-visible report it publishes an integrated standalone HTML primary surface plus the Markdown archive, starts the real Task preview, inspects the PNG attachments returned by canonical `browser_preview_capture`, and corrects defects. The Orchestrator independently captures and inspects fresh image attachments from the published target before accepting the terminal report; this is scheduler acceptance, not a repeated or undeclared workflow node. The visible final assistant message remains natural narration and includes usable project-root-relative delivery links rather than carrying the evidence body.

### Evidence contract

- Prefer primary sources, official documentation, standards, public records, research papers, and original datasets.
- Record a direct source pointer for each load-bearing factual claim.
- Include retrieval dates for facts that can change over time.
- Keep fact, source interpretation, analytical inference, and recommendation visibly distinct.
- Treat a fact-check correction as authoritative delivery input; never silently restore the rejected claim.
- State disagreements, missing evidence, and confidence limits. Never turn an unresolved point into a confident conclusion.

### Report template and delivery contract

- The package-owned `analysis-report-quality` Skill and its `references/decision-research-report-template.md` are the one information architecture and chart-design source owned by Research Studio. Models populate it; they do not improvise a replacement outline or use raw chart-library defaults.
- One structured report model is the narrative source. Markdown, standalone Hypertext Markup Language (HTML), and the message-owned document are derived presentations, never independently authored reports.
- Honor explicit output paths. Otherwise keep the model, Markdown archive, primary HTML, calculations, canonical tables, and media beneath one descriptive directory in `artifacts/research/`.
- When the request needs a browser-visible report, the integrated standalone HTML is `primary_report`. It contains the executive answer, key performance indicators, findings, evidence, designed charts, useful tables, recommendations, limitations, sources, and reproducibility entry points in the fixed template order.
- The dynamic message-panel `document@1` is a readable presentation of the same report model. A `table@1` is allowed only when its rows and columns add analytical value.
- Persist every delivered resource and role in `research-studio/research-report`, and name usable project-root-relative report links in the visible final assistant message.
- A real `browser_preview` service and Task target, canonical `browser_preview_capture` evidence, Writer inspection of the returned image attachments and corrections, plus the Orchestrator's independent fresh image review are completion evidence for browser-visible reports. A repairable second-review finding returns to the same bound Writer as Phase-closure work and is reviewed again; it does not create another workflow node. If the active model cannot receive image input, the report remains blocked rather than substituting file-existence, library-keyword, Document Object Model, snapshot-baseline, geometry, or pixel assertions. These interactions are not User Interface automation tests and must not be persisted as reusable screenshot scripts.

Research Studio does not define product requirements, architecture, code changes, database designs, interface designs, or delivery plans. If the requested outcome crosses into those domains, report the boundary rather than quietly changing the squad's purpose.

## Artifact protocol

The model-facing file protocol uses `artifact_snapshot` to publish current-Task project files and return one exact content-addressed `resource_set` locator. `artifact_publish` accepts the complete evidence value only as strict JSON text in `payload_json`; object keys must be unique, and `resource_set` is required (`null` when there are no files, otherwise the exact locator returned by `artifact_snapshot`). The Host verifies and expands the immutable manifest inside its trusted boundary, then publishes the structured value through the same canonical service used by typed and package tools.

Task schedulers and projected workers inherit `artifact_search`, `artifact_read`, and `artifact_select` as platform tools. Projected workers additionally inherit `artifact_snapshot` and `artifact_publish`; schedulers do not. A delegated worker without a typed domain-output producer uses `artifact_publish` for canonical JSON `expert_output` type `<active-squad-id>/...`; the publication declares publication-specific `source_artifact_locators` from complete reads earlier in the same physical Turn, and the Host derives Task, Session, Agent, active-Squad, projection, and complete-read observations. Typed domain-output tools remain their domain's sole publishers and are never duplicated. Every consumer starts with the exact kind, type, stable label, producer agent, and producer session supported by `artifact_search`, follows every returned cursor, completely reads each candidate it inspects, then calls `artifact_select` for every Artifact that semantically supports its typed output; broad catalog enumeration is reserved for an unresolved evidence need. Complete but unselected reads remain observations and zero selections are valid. Durable evidence does not travel through Agent messages or adapter results. A user-pinned locator cannot be replaced by search. For Cross-Task evidence, Mission selects an exact `ArtifactReadLocator` (`engine_artifact`, `task_artifact_snapshot`, or `task_artifact_resource`) from the source Task catalog and creates the receiving Task with `{source_task_id, locator}`. The receiving catalog exposes a target-owned imported Engine Artifact that preserves the source type, schema, payload, copied resources, and original consumption provenance in immutable `import_lineage`; copied request prose and foreign reads are not evidence. The message-owned interactive document is presentation, while the archived report and structured facts remain durable evidence. Empty search/default fields are valid; missing, foreign, corrupt, stale, unreadable, or path-invalid selected evidence is an explicit error.
